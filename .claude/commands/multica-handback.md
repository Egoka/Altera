Задача: **$1**. Причина остановки: **$2**

По `docs/multica/operating-model.md` §5 и §7 работа останавливается, а вопрос уходит владельцу
через `docs/backlog/owner-blockers.md`, а не решается по месту.

1. Определи категорию: код / тест / среда / неоднозначный контракт / конфликт / права /
   квота или бюджет / отмена. Для вопроса владельца отдельно укажи, какое решение отсутствует.
2. Сформулируй вопрос владельцу так, чтобы он читался без этого чата: что именно неизвестно,
   какое решение блокируется, какие варианты видны и чем каждый подтверждён в источниках.
   Своего варианта как решённого не предлагай.
3. Покажи подготовленную запись для `docs/backlog/owner-blockers.md` и **спроси разрешения**
   перед записью в файл.
4. Подготовь handoff, который читается без этого чата:
   - задача/цель, authorization и scope, actor/run, стадия;
   - baseline, ветка, полный HEAD, dirty fingerprint, изменённые файлы и diff;
   - сделано, осталось, сохраняемые решения и отвергнутые гипотезы;
   - AC-ID, ссылки на evidence и `trace_ref`, ограничения экспорта trace;
   - `check_id → число последовательных неуспехов`, включая попытки прошлых run;
   - причина остановки, наблюдаемое условие возобновления, проверка отсутствия активного
     дубликата и следующий разрешённый шаг.
5. Отдельно запиши native run outcome, stage outcome и task acceptance. Остановка run не
   означает завершение стадии или принятие задачи.

Не переходи к следующей задаче. Восстановление остановленной работы — отдельное решение.
