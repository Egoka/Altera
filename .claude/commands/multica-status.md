Собери фактическое состояние цикла. Только факты из файлов и git, без выводов из планов.

1. **Готовые задачи**: `grep -l '^- \*\*Статус\*\*: готова' docs/backlog/tasks/*.md` — перечисли с
   ролью-исполнителем и параллельностью.
2. **Задачи в работе**: тот же поиск по статусу `в работе`.
3. **Активная кодовая цепочка**: текущая ветка, незакоммиченные изменения в `server/`, `web/`,
   `packages/`. Если их больше одной — это конфликт по operating-model §5, назови его.
4. **Незакрытый ритуал**: планы в `docs/plans/` без парного отчёта в `docs/reports/` с тем же
   слагом. План без отчёта означает невыполненную работу, даже если код закоммичен.
5. **Блокеры владельца**: количество задач со статусом `решение владельца: Q-NN` и ссылка на
   `docs/backlog/owner-blockers.md`.
6. **Состояние проверок**: напомни одной строкой, что `pnpm test` завершается успехом при нуле
   тестов, поэтому шаг наблюдения в цикле сегодня слеп.

Выведи компактной сводкой. Ничего не меняй.
