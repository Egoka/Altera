# Altera — правила проекта

Культурная publishing-платформа: журнал о культуре, искусстве, фотографии, музыке,
спорте и путешествиях. Монорепозиторий pnpm: `web` (Nuxt) + `server` (GraphQL API).

**Главное правило: истина — код, а не документация.** Значительная часть `docs/`
описывает намерения, а не состояние; `docs/architecture/database_architecture.md`
устарел полностью (описывает `password_hash` и целочисленные `id`, которых в схеме
нет). Проверяй утверждения по коду, прежде чем на них опираться.

## Продуктовые рамки (ревизия 2, зафиксированы владельцем 2026-09-06)

- **Ориентир — The Atlantic.** Конкурентный журнал на разные темы человеческой жизни для
  широкой публики: актуальный и интересный контент, а не только шесть культурных тем.
- **Четыре аудитории:** посетители (без аккаунта), читатели (бесплатный аккаунт), авторы
  (платная подписка), администраторы (owner, admin, editor, moderator, analyst).
- **Подписка определяет роль.** План free выдаётся при регистрации → читатель; standard →
  автор с правом создавать и публиковать; pro → автор повышенного грейда с постоянным
  Pro-баллом в рейтинге (буст на сутки отменён журналом §21.15–16). Донатов и подписки на автора нет — вся экономика на
  планах. **Первый запуск — бесплатный** (журнал §24.1, §25.1): при регистрации — читатель; базовые
  авторские возможности открываются бессрочно при первом «Создать статью», без оплаты и одобрения; платные подписки, цены и обработка платежей
  (Т-Касса первой — §8.14; 54-ФЗ) — отдельный этап после проверки ценности; 152-ФЗ — с первого
  этапа; цены — гипотезы (§8.12).
- **Выдача рейтинговая, лента одна.** Рейтинг статьи учитывает соответствие теме, давность,
  рейтинг автора, сигналы вовлечённости и постоянный Pro-балл (AI-оценка и буст на сутки из
  ADR-0043 отменены журналом §21); главная — три подборки одной ленты (главный топ, «Новое»,
  «Популярное», журнал §22), до запуска движка — по дате. Персонализации нет — список одинаков
  для всех. Редакционной витрины и второго контура нет.
- **Каждая статья проверяется AI-агентами перед публикацией** с бинарным результатом и
  причинами (без балла — журнал #41); прошедшая проверку публикуется автоматически, ревьюер
  (роль moderator) ведёт ручную ветку после отказа AI или снятия с публикации (журнал #8, #14);
  жалобы — отдельный отложенный разбор.
- **Чтение бесплатно для всех.** Возможность paywall закладывается в модель данных и шаблоны
  как зарезервированная, но не проектируется.
- **Роли:** reader, author, editor, moderator (= ревьюер), analyst (только чтение
  статистики), admin, owner (= супер-админ; владельцев может быть несколько, «не ноль» —
  журнал #10, §26.7). Управление админами и статистика — разделы админки с первого этапа.
- **Закладки** («сохранённые статьи») доступны любому аккаунту.
- **Статья:** автор присваивается автоматически; первым шагом — категория (= рубрика
  `Section`) и теги; тело собирается из блоков-компонентов. Каталог блоков — отдельный
  проход, сейчас не проектируется.
- **MIT относится к коду, а не к контенту.** Права на материалы остаются у авторов.
- **Двуязычность — полные переводы материалов** (ru/en) с общими метаданными и hreflang.
- **Ресурсы:** один разработчик плюс AI-агенты. Аудитория пока нулевая.

Ревизия 1 (гибридная модель с редакционной витриной, правило-арбитр «никогда за право
публиковаться», «без алгоритмов») отменена 2026-09-06. **Источник рамок — ADR-0043**; этот
раздел — его копия для агентов, при расхождении главнее ADR. **Выше ADR — рабочий журнал
решений владельца** `docs/decisions/role-review-working-log-2026-09-08.md` (гейты Г1–Г9; фаза 2 спецификаций
завершена 2026-09-09, свод открытых вопросов — `docs/spec/OPEN-QUESTIONS.md`):
он отменил AI-оценку и балл, буст на сутки (теперь постоянный Pro-балл), словесное объяснение
позиции, «ровно одного владельца», секции главной по рубрикам; заменённые ADR помечены строкой
статуса, ADR-0047+ по журналу ещё не написаны (задача T-108). Решения ревизии 2 — ADR-0034…0046;
заменённые ADR ревизии 1 помечены строкой статуса. Роадмап — ревизия 3 (2026-09-09, бесплатный
запуск): `docs/issues/00-roadmap.md`; исполнимые задачи — `docs/backlog/`.

**Multica.** Перед планированием или началом исполнения любой задачи агент читает операционную
модель `docs/multica/operating-model.md` и актуальный бэклог `docs/backlog/README.md`. Задача
берётся только в статусе `готова` (его ставит владелец), с закрытыми зависимостями и
проверяемыми критериями; одновременно продуктовый код меняет одна цепочка; автопилоты
включаются только по чек-листам `docs/multica/autopilot-checklists.md`. Текущее состояние
очереди, назначений и расписаний живёт в Multica и сюда не копируется.

## Структура

```
server/   GraphQL API: Yoga + Prisma + PostgreSQL (Neon) + Redis
web/      Nuxt 4 / Vue 3, Tailwind 4, FishtVue, i18n ru/en
docs/     plans/ (планы работ) · reports/ (отчёты по планам) · prompts/ (промты)
          vision/ (целевая архитектура) · issues/ (роадмап) · decisions/ (ADR и журнал)
          spec/ (поштучные спецификации: реестры, шаблоны, страницы, роли, админка)
          backlog/ (исполнимый бэклог: эпики E-, задачи T-, блокеры Q-, будущие этапы F-)
          multica/ (операционная модель сквада Multica и чек-листы автопилотов)
          guides/ · status/ · architecture/ · queries/
```

## Команды

```bash
cd server && pnpm dev            # API на http://localhost:4000/ (ts-node)
cd web && pnpm dev               # Nuxt dev-сервер
pnpm format:fix && pnpm lint     # перед коммитом
cd server && npx prisma migrate dev --name <имя>
cd server && npx prisma studio
```

`pnpm test` завершается успехом, **не выполнив ни одного теста** — тестов в проекте нет.
Pre-commit хук вызывает `npm run format && npm run lint && npm run test`; `format` — это
проверка, а не форматирование, поэтому запускай `pnpm format:fix` заранее.

Локально Node 24, в CI Node 20. Пакетный менеджер pnpm.

## Переменные окружения (server)

`DATABASE_URL`, `DATABASE_URL_UNPOOLED`, `REDIS_URL`, `JWT_ACCESS_SECRET`,
`JWT_REFRESH_SECRET`, `JWT_ACCESS_TOKEN_EXPIRY`, `JWT_REFRESH_TOKEN_EXPIRY`,
`MAGIC_LINK_EXPIRY_MINUTES`, `MAGIC_LINK_BASE_URL`, `FRONTEND_URL`, `CACHE_TTL`, `PORT`.
Без `JWT_ACCESS_SECRET` и `REDIS_URL` сервер падает при импорте модулей.

## Архитектура сервера

- **Точка входа** `server/src/server.ts`: GraphQL Yoga поверх `node:http`, эндпоинт —
  корень `/`, CORS только на `FRONTEND_URL`, разрешён единственный метод `POST`, включён
  `useCSRFPrevention` (клиент обязан слать защитный заголовок), в production —
  `blockFieldSuggestions`.
- **Схема собирается автоматически** (`graphql/schema.ts`): все `*/schema.graphql` и
  `*/resolver.*` внутри `src/graphql` сливаются через `@graphql-tools/merge`. Новый
  домен = новая папка с парой файлов, регистрировать вручную ничего не нужно. Общие
  типы пагинации, сортировки и фильтров живут в `graphql/root/schema.graphql`.
- **Контекст** (`src/prisma.ts`): `{ prisma, currentUser, redis }`. `currentUser`
  восстанавливается из `Authorization: Bearer <access token>`; невалидный токен даёт
  `null`, а не ошибку.
- **Права** — только через `src/exceptions/permissions.ts` (`ensureAuthenticated`,
  `ensureHasRole`). Проверка прав живёт в резолвере, не в интерфейсе.
- **Админские запросы** — через хелперы `src/utils/admin.ts`: валидация пагинации,
  сортировки, дат и поиска, построение `where`/`orderBy`, кеш-ключи, логирование.
  Стандарт описан в `docs/guides/admin_query_standards.md`.
- **Кеш** — Redis с TTL из `CACHE_TTL` (по умолчанию 6 часов), кеш-ключи объявляются
  константами в начале резолвера. При любой мутации инвалидируй все связанные ключи.
- **Жизненный цикл материала**: `draft → review → published → archived`. Автор владеет
  переходами своих материалов (`requestReview`, `revertToDraft`, `archiveArticle`),
  админ переводит любой материал в любой статус (`setArticleStatus`). Подробнее —
  `docs/guides/article_workflow.md`.

## Архитектура веба

- Nuxt 4 со структурой `web/app/`: `pages/`, `components/` (по доменам: `article/`,
  `admin/`, `header/`, `pages/start/` и т. д.), `composables/`, `stores/`, `types/`,
  `middleware/`, `layouts/` (`default`, `admin`, `auth`).
- `web/app/query/**` — GraphQL-операции обычными шаблонными строками, реэкспорт через
  `query/index.ts`. **Клиента GraphQL в проекте нет**, эти строки пока никуда не идут.
- Стили: Tailwind 4 через vite-плагин, токены и `@font-face` — в
  `web/app/assets/css/main.css`, тёмная тема через `@nuxtjs/color-mode` (класс на
  `html`). Базовая типографика в `main.css` закомментирована.
- i18n: `@nuxtjs/i18n`, локали `en` (по умолчанию) и `ru`, стратегия
  `prefix_except_default`, словари в `web/i18n/locales/`.
- UI-библиотека FishtVue подключена модулем и настраивается в `nuxt.config.ts`.

## Что в проекте сломано или отсутствует

Это не список задач, а предупреждение: не принимай перечисленное за работающее.

- **Веб и API не соединены**: нет GraphQL-клиента, нет runtime API URL, страницы живут
  на статических фикстурах. Из 35 операций фронта большинство не валидно против
  серверной схемы.
- **Роли расходятся**: на фронте `user|admin`, на сервере `reader|author|editor|admin`.
- **Редактора нет.** MDC не установлен, `Article.body` — обычная строка. Формат контента
  ещё не выбран.
- **Дыры в доступе**: `article(slug)` отдаёт черновики и архив любому вызывающему;
  `user.email` есть в публичном типе; `web/app/middleware/auth.global.ts` и `admin.ts`
  закомментированы целиком; rate limit отсутствует везде.
- **Почты нет**: magic link печатается в лог сервера.
- **Сессии неполные**: refresh-токен выдаётся, но нет ни обновления, ни отзыва, ни
  выхода, ни хранения сессии.
- **Redis обязателен** при импорте, без деградации; ключ кеша админского поиска не
  включает поисковый запрос, инвалидация местами использует блокирующий `KEYS`.
- **Нет в модели данных вообще**: комментарии, медиа, версии материалов, подборки,
  SEO-поля, локали и переводы, подписки, тарифы, платежи, промокоды, аудит-лог,
  просмотры. `featuredArticles` возвращает просто последние опубликованные,
  `popularArticles` — свежие за период, счётчики всегда нули.
- **Ни одного теста**, `prisma:seed` ссылается на несуществующий `seed/seed.ts`,
  CI гоняет пустой `pnpm test` и маскирует падение старта через `timeout 2s … || true`.
- `/_ipx/...` отдаёт 500 на всех пробах: в собранном `web/.output` отсутствует нативный
  бинарник `sharp`; сами статические файлы (`/images/*.png`) отдаются с 200.
- Прод-сборка веба (`node web/.output/server/index.mjs`) под локальным Node 24 отвечает 500 на
  каждом SSR-маршруте (ошибка импорта `vue` без default-экспорта); dev-режим не затронут.
- Целевая архитектура и дорожная карта приняты 2026-09-05: `docs/vision/`, `docs/issues/`,
  `docs/decisions/`; устаревшие документы помечены плашкой «Исторический документ».
- Основание пересмотрено 2026-09-06 (ревизия 2, ADR-0034…0046): `docs/vision/01,02,04,06,07`
  переписаны, `03,05,08` — по разделам, роадмап и файлы этапов — ревизия 2; файлы этапов
  ревизии 1 и промт первой фазы помечены как исторические.

## Планы и отчёты — обязательный ритуал

Каждая работа по плану оставляет в репозитории два файла. Это не бюрократия: по паре
«план + отчёт» позже восстанавливается, что задумывалось, что реально сделано и каким
коммитом.

1. **Перед началом работы** план сохраняется в `docs/plans/ГГГГ-ММ-ДД-имя.md`. Дата —
   день создания плана. В шапке обязателен базовый коммит (`git rev-parse --short HEAD`),
   иначе непонятно, к какому состоянию кода план относился. Работа по неописанному
   плану не начинается.
2. **После завершения** создаётся отчёт `docs/reports/ГГГГ-ММ-ДД-имя-report.md` с тем же
   слагом и датой завершения. **План не считается выполненным, пока отчёта нет** — даже
   если код уже написан и закоммичен. Отчёт обязателен и для частично выполненного, и
   для отменённого плана.
3. Файлы ссылаются друг на друга: план — на будущий отчёт, отчёт — на план и на коммиты
   работы.
4. В отчёте раздел «Как проверено» содержит выполненные команды и их результат.
   Утверждение «работает» без фактической проверки в отчёт не попадает.
5. Планы не переписываются задним числом. Решение изменилось — новый план или запись
   «отклонение» в отчёте.

Форматы и структура обоих файлов описаны в `docs/plans/README.md` и
`docs/reports/README.md`. Эти пути **перекрывают** пути по умолчанию из любых навыков
планирования (например `docs/superpowers/specs/`): в этом проекте планы живут только в
`docs/plans/`.

## Правила работы

- **Коммиты — conventional commits**, тип из списка в `commitlint.config.js`, scope в
  нижнем регистре, заголовок до 100 символов, без точки в конце: `feat(admin): …`.
- **Ветки**: `server/*`, `web/*`, `docs/*`; pull request открывается в `app`. На `app`
  напрямую не коммить.
- **Форматирование** задаёт Prettier: без точек с запятой, без trailing comma, ширина
  120, отступ 2 пробела, `bracketSameLine`. Не спорь с ним вручную.
- **Язык**: документация и комментарии в проекте — русские, идентификаторы и сообщения
  GraphQL-ошибок — английские.
- **Схема данных**: миграции Prisma создаются только осознанно и с именем; при любом
  изменении enum помни, что в базе уже есть данные.
- **Не выдумывай состояние.** Если утверждение о проекте не подтверждено кодом,
  помечай его как допущение. Не сообщай о готовности, не выполнив проверку.
- **Секреты** (`.env`, ключи, строки подключения Neon и Redis) не попадают в репозиторий
  и в вывод.
- Проектные решения оформляются как ADR в `docs/decisions/`, целевая архитектура — в
  `docs/vision/`, дорожная карта — в `docs/issues/`, исполнимые задачи — в `docs/backlog/`
  (одна задача — один файл, статус `готова` ставит владелец). Устаревшие документы помечаются
  как исторические, а не переписываются молча.
- **Спецификации** — в `docs/spec/` по шаблонам из `docs/spec/_templates/`: одна сущность —
  один файл, каждая строка реестра в `docs/spec/00-registries/` обязана иметь файл (строка без
  файла — недоделка). В спецификациях нет оценок в человеко-днях и разделов «что не делаем» —
  порядок этапов живёт в `docs/issues/00-roadmap.md`, исполнимые задачи — в `docs/backlog/`.
