# Altera — адаптер Claude Code

Полные общие инструкции находятся в [AGENTS.md](AGENTS.md). Перед планированием или
исполнением также прочитай:

- [операционную модель](docs/multica/operating-model.md) — стадии, полномочия, один writer,
  остановка и выпуск;
- [правила проекта](docs/development/project-rules.md) — источники, технические соглашения,
  Git, формат и ритуал;
- [контракты артефактов](docs/development/artifact-contracts.md) — AC-ID, evidence, handoff и
  независимая приёмка;
- [проверки](docs/development/testing.md) — актуальные команды, CI и ограничения;
- [бэклог](docs/backlog/README.md) и файл задачи — если работа выбрана из очереди.

Иерархия продуктовых источников: журнал владельца → `docs/spec/` → ADR → vision. Текущее
состояние подтверждается кодом, конфигурацией и свежим evidence, а не планом. Прямое письменное
поручение владельца с конкретным scope может разрешить работу без выдуманного статуса `готова`.

План в `docs/plans/` и парный отчёт в `docs/reports/` обязательны по форматам README этих
каталогов. Проверка привязывается к полной ревизии и dirty fingerprint. Завершение ответа, run,
стадии и приёмка задачи различаются. Две последовательные неуспешные попытки одного `check_id`
останавливают проверку в стадии; новый run счёт не сбрасывает.

Секреты не читаются без необходимости и не попадают в репозиторий, вывод, evidence или trace.
Продуктовые решения и открытые вопросы владельца не разрешаются догадкой. Наличие инструкции,
hook или профиля агента не доказывает runtime enforcement; его реализация относится к M4.

Полная версия этого файла до миграции сохранена [без изменений](docs/development/sources/2026-09-13-claude-original.md)
и сопоставлена в [migration ledger](docs/development/migration-ledger.md). Активные уникальные
правила перенесены в документы выше; исторический файл используется для аудита, а не как
источник текущих фактов.
