# Altera — правила проекта

Культурная publishing-платформа: журнал для широкой публики. Монорепозиторий pnpm:
`web` (Nuxt 4 / Vue 3) + `server` (GraphQL Yoga + Prisma + PostgreSQL + Redis).

**Главное правило: истина — код, а не документация.** Значительная часть `docs/` описывает
намерения, а не состояние. Проверяй утверждения по коду, прежде чем на них опираться.
`docs/architecture/database_architecture.md` устарел полностью.

---

## Иерархия источников

Порядок старшинства при любом расхождении:

1. **Рабочий журнал решений владельца** `docs/decisions/role-review-working-log-2026-09-08.md`
   (гейты Г1–Г9, фаза 2 завершена 2026-09-09). Главнее всего.
2. **Спецификации** `docs/spec/` — поведение; свод открытых вопросов `docs/spec/OPEN-QUESTIONS.md`.
3. **ADR** `docs/decisions/` — продуктовые рамки ревизии 2 в ADR-0043; заменённые журналом ADR
   помечены строкой статуса. ADR-0047+ ещё не написаны (задача T-108).
4. **Vision** `docs/vision/` — целевая архитектура; `00-reality-check.md` даёт срез кода, но сам
   отстаёт от журнала (ревизия — T-109).

Продуктовые рамки здесь **не пересказываются**: копия расходится с источником. Читай ADR-0043 и
журнал. Продуктовые решения принимает только владелец.

## Порядок работ

- **Операционная модель сквада** `docs/multica/operating-model.md` — стадии, evidence, единственный
  writer продуктового кода, действия, требующие решения владельца. Читается перед планированием
  или началом любой задачи.
- **Бэклог** `docs/backlog/README.md` — задача берётся только в статусе `готова` (его ставит
  владелец), с закрытыми зависимостями и проверяемыми критериями.
- **Роадмап** `docs/issues/00-roadmap.md` (ревизия 3, бесплатный запуск).
- **Автопилоты** включаются только по `docs/multica/autopilot-checklists.md`, решением владельца.

## Слой исполнения агентов

`.claude/` версионируется и является такой же частью правил, как операционная модель:

- `.claude/agents/multica-*.md` — десять ролей сквада как субагенты. Проверяющие роли
  (`multica-tester`, `multica-reviewer`) намеренно лишены права правки кода.
- `.claude/commands/` — `/multica-start`, `/multica-stage`, `/multica-status`, `/multica-handback`.
- `.claude/hooks/ritual-check.sh` — блокирует завершение захода, в котором менялся продуктовый
  код без плана и отчёта.
- `.claude/settings.local.json` — личные переопределения, не версионируется.

## Структура

```
server/   GraphQL API: Yoga + Prisma + PostgreSQL (Neon) + Redis
web/      Nuxt 4 / Vue 3, Tailwind 4, FishtVue, i18n ru/en
docs/     plans/ · reports/ · prompts/ · vision/ · issues/ · decisions/
          spec/ · backlog/ · multica/ · guides/ · status/ · architecture/ · queries/
```

## Команды

```bash
cd server && pnpm dev            # API на http://localhost:4000/ (ts-node)
cd web && pnpm dev               # Nuxt dev-сервер
pnpm format:fix && pnpm lint     # перед коммитом
cd server && npx prisma migrate dev --name <имя>
```

`pnpm test` завершается успехом, **не выполнив ни одного теста** — тестов в проекте нет.
Pre-commit хук вызывает `format && lint && test`; `format` — это проверка, а не форматирование,
поэтому `pnpm format:fix` запускается заранее.

Локально Node 24, в CI Node 20. Пакетный менеджер pnpm.

## Переменные окружения (server)

`DATABASE_URL`, `DATABASE_URL_UNPOOLED`, `REDIS_URL`, `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`,
`JWT_ACCESS_TOKEN_EXPIRY`, `JWT_REFRESH_TOKEN_EXPIRY`, `MAGIC_LINK_EXPIRY_MINUTES`,
`MAGIC_LINK_BASE_URL`, `FRONTEND_URL`, `CACHE_TTL`, `PORT`.
Без `JWT_ACCESS_SECRET` и `REDIS_URL` сервер падает при импорте модулей.

## Архитектура сервера

- **Точка входа** `server/src/server.ts`: Yoga поверх `node:http`, эндпоинт — корень `/`, CORS
  только на `FRONTEND_URL`, разрешён единственный метод `POST`, включён `useCSRFPrevention`,
  в production — `blockFieldSuggestions`.
- **Схема собирается автоматически** (`graphql/schema.ts`): все `*/schema.graphql` и `*/resolver.*`
  внутри `src/graphql` сливаются через `@graphql-tools/merge`. Новый домен = новая папка с парой
  файлов, регистрировать вручную ничего не нужно.
- **Контекст** (`src/prisma.ts`): `{ prisma, currentUser, redis }`; невалидный токен даёт `null`.
- **Права** — только через `src/exceptions/permissions.ts`, в резолвере, не в интерфейсе.
- **Админские запросы** — через `src/utils/admin.ts`; стандарт в `docs/guides/admin_query_standards.md`.
- **Кеш** — Redis с TTL из `CACHE_TTL`; ключи объявляются константами в начале резолвера, при
  любой мутации связанные ключи инвалидируются.
- **Жизненный цикл материала**: `draft → review → published → archived`;
  подробнее `docs/guides/article_workflow.md`.

## Архитектура веба

- Nuxt 4, структура `web/app/`: `pages/`, `components/` по доменам, `composables/`, `stores/`,
  `types/`, `middleware/`, `layouts/`.
- `web/app/query/**` — GraphQL-операции шаблонными строками. **Клиента GraphQL нет**, эти строки
  никуда не идут.
- Стили: Tailwind 4 через vite-плагин, токены и `@font-face` в `web/app/assets/css/main.css`,
  тёмная тема через `@nuxtjs/color-mode`.
- i18n: локали `en` (по умолчанию) и `ru`, стратегия `prefix_except_default`, словари в
  `web/i18n/locales/`.

## Чего в проекте нет — не принимай за работающее

Полный срез — `docs/vision/00-reality-check.md` (сам отстаёт, ревизия — T-109). Самое опасное:

- **Веб и API не соединены**: нет GraphQL-клиента и runtime API URL, страницы на фикстурах.
- **Ни одного теста.** `pnpm test` зелёный при нуле тестов; CI маскирует падение старта через
  `timeout 2s … || true`. Зелёная проверка ничего не доказывает.
- **Роли расходятся**: на фронте `user|admin`, на сервере `reader|author|editor|admin`.
- **Редактора нет**: MDC не установлен, `Article.body` — строка, формат контента не выбран.
- **Дыры в доступе**: `article(slug)` отдаёт черновики и архив любому; `user.email` в публичном
  типе; middleware `auth.global.ts` и `admin.ts` закомментированы; rate limit отсутствует.
- **Почты нет**: magic link печатается в лог. **Сессии неполные**: нет обновления, отзыва, выхода.
- **Нет в модели данных**: комментарии, медиа, версии, подборки, SEO-поля, локали и переводы,
  подписки, тарифы, платежи, аудит-лог, просмотры. Счётчики всегда нули.
- Прод-сборка веба под локальным Node 24 отвечает 500 на каждом SSR-маршруте; `/_ipx/...` — 500.

## Планы и отчёты — обязательный ритуал

1. **Перед работой** план в `docs/plans/ГГГГ-ММ-ДД-имя.md`, в шапке обязателен базовый коммит
   (`git rev-parse --short HEAD`). Работа по неописанному плану не начинается.
2. **После завершения** отчёт `docs/reports/ГГГГ-ММ-ДД-имя-report.md` с тем же слагом.
   **План не считается выполненным, пока отчёта нет** — даже если код закоммичен. Отчёт обязателен
   и для частично выполненного, и для отменённого плана.
3. Файлы ссылаются друг на друга.
4. Раздел «Как проверено» содержит выполненные команды и их фактический вывод. Утверждение
   «работает» без проверки в отчёт не попадает.
5. Планы не переписываются задним числом: решение изменилось — новый план или «отклонение» в отчёте.

Форматы — `docs/plans/README.md` и `docs/reports/README.md`. Эти пути **перекрывают** пути по
умолчанию из любых навыков планирования.

## Правила работы

- **Коммиты — conventional commits**, тип из `commitlint.config.js`, scope в нижнем регистре,
  заголовок до 100 символов, без точки: `feat(admin): …`.
- **Ветки**: `server/*`, `web/*`, `docs/*`; pull request открывается в `app`. На `app` напрямую
  не коммить. Push и слияние — решение владельца.
- **Форматирование** задаёт Prettier: без точек с запятой, без trailing comma, ширина 120, отступ
  2 пробела, `bracketSameLine`. Не спорь с ним вручную.
- **Язык**: документация и комментарии русские, идентификаторы и сообщения GraphQL-ошибок английские.
- **Миграции Prisma** создаются осознанно и с именем; при изменении enum помни, что в базе есть данные.
- **Не выдумывай состояние.** Неподтверждённое кодом помечай `[ДОПУЩЕНИЕ]`. Не сообщай о
  готовности, не выполнив проверку.
- **Секреты** (`.env`, ключи, строки подключения Neon и Redis) не попадают в репозиторий и в вывод.
- **Спецификации** — в `docs/spec/` по шаблонам `docs/spec/_templates/`: одна сущность — один файл,
  каждая строка реестра `docs/spec/00-registries/` обязана иметь файл. Оценок в человеко-днях и
  разделов «что не делаем» в спецификациях нет.
- Устаревшие документы помечаются как исторические, а не переписываются молча.
