# Российский CDN перед altera.ru

- **Статус**: сравнение от 2026-09-19. Провайдер не выбран: выбор зависит от провайдера кластера
  и S3 (Q-01) и от домена (карта, раздел 8).
- **Как собрано**: страницы цен и документация провайдеров, открытые 2026-09-19. Цены и
  поведение кеша Yandex Cloud CDN перепроверены отдельно. Остальные данные взяты из
  документации провайдеров по ссылкам ниже. «Не проверено» означает, что источник не
  открылся или не отвечает на вопрос.
- **Карта инфраструктуры**: [README.md](README.md).

## 1. Вывод

1. **Российский CDN нельзя настроить так же, как Cloudflare.** Ни у одного провайдера не
   найден обход кеша по наличию конкретной cookie. У Yandex Cloud CDN (и, по документации, у
   MWS) режим «Как у источника» кеширует ответ без `public` и `max-age` на время по умолчанию из
   настроек ресурса. Значит, ответ с `Cache-Control: private` там **закешируется**
   ([Yandex, кеширование](https://yandex.cloud/ru/docs/cdn/concepts/caching)).
2. **Корень домена.** CDN подключается через CNAME, а на корне `altera.ru` CNAME поставить
   нельзя. Yandex не рекомендует ANAME: пропадает геобалансировка.
3. **Предлагаемая схема на старте.** HTML `altera.ru` отдаётся напрямую с Gateway кластера в РФ.
   Кластер и читатели находятся в одной стране, а публичные списки кеширует Redis (ADR-0019).
   Через CDN идут два поддомена:
   - `static.altera.ru` — сборка Nuxt, в Nuxt через `app.cdnURL`;
   - `media.altera.ru` — публичные варианты изображений из S3.

   Персональные ответы при такой схеме в CDN не попадают вовсе. HTML переводится за CDN позже,
   если этого потребует нагрузка, с явными правилами «не кешировать» по путям.

4. **Провайдер CDN — тот же, что у кластера и S3.** Тогда трафик из источника бесплатный или
   дешёвый. Если это Yandex Cloud — Yandex Cloud CDN. Если Selectel — Selectel CDN. Если
   провайдер без подходящего CDN — VK Cloud CDN как недорогой вариант с Terraform.

## 4. Что это значит для кода

1. **Анонимные посетители без cookie.** Опция Yandex «не кешировать запросы с Cookie» становится
   безопасным способом отделить залогиненных, если у анонимного читателя cookie нет совсем.
   Сейчас так и есть: аналитики с cookie нет (ADR-0027), тема хранится в `localStorage`. Правило
   на будущее: никаких cookie у анонимных посетителей, включая согласие на cookie (OPEN-QUESTIONS
   #3). Хранить его в `localStorage`.
2. **Публичные страницы рендерятся анонимно.** ADR-0023 п. 3 предписывает SSR обменивать
   refresh-cookie на access. Для кешируемых маршрутов SSR должен её игнорировать, а персональные
   части грузить клиентским запросом к `/api` (он не кешируется). Тогда HTML одинаков для всех,
   и ошибка правил CDN не выдаст чужие данные.
3. **Очистка по тегу есть только у Cloudflare.** Адаптер очистки CDN для российского провайдера
   переводит теги ADR-0019 в список URL: материал, его рубрика, теги, автор, главная локали,
   варианты медиа. Лимиты очистки (1 запрос в минуту у Yandex) требуют очереди с упаковкой путей.
4. **`Cache-Control` пишется даже там, где CDN его не читает.** На Cloudflare заголовки
   управляют кешем, на Yandex — нет. Поэтому на российском CDN правила «не кешировать» задаются
   явно по путям, а TTL — в настройках ресурса.

## 5. Подводные камни

- Лимиты очистки: Yandex и EdgeCenter — 1 запрос в минуту по 10 путей, Selectel — 10 выборочных
  очисток в час. Снятие материала закрывает медиа в CDN с задержкой очереди.
- Selectel через 14 дней долга отключает ресурс с очисткой кеша, через 30 дней удаляет.
- Cloud.ru и EdgeCenter работают только с юрлицами. Пока у проекта нет юрлица, их можно не
  рассматривать.
- Часть провайдеров, похоже, работает на одной сети: Cloud.ru прямо называет тариф «CDN-Видео»,
  списки городов у Selectel, Timeweb и CDNvideo совпадают почти дословно. Это вывод по
  совпадениям, провайдеры его не подтверждали.
