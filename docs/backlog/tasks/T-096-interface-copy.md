# T-096: Тексты интерфейса, писем первичного потока и правил публикации в общей формулировке

- **Эпик**: E-14 Дизайн-система и i18n
- **Статус**: кандидат
- **Параллельность**: да: не меняет продуктовый код
- **Роль-исполнитель**: редактор и бренд-стратег
- **Участники стадий**: ревью — независимый ревьюер; документация — хранитель документации
- **Навыки**: Редактура, тон издания

## 1. Результат
Единый глоссарий и тексты для страниц запуска, экранов состояний, писем входа и решений; правила публикации описывают общие критические категории причин отказа без порогов.

## 2. Источники
- Журнал: §24.3, §25.13
- Спецификации: `docs/vision/01-product.md`, `docs/spec/20-public/legal-content-rules.md`, `docs/spec/10-flows/register-and-login.md`
- ADR: не применимо

## 3. Границы и явно исключённое
- Входит: Тексты как артефакт в `docs/` для переноса в словари.
- Не входит: Юридические тексты (Q-07); шаблоны рассылок (F-05).

## 4. Зависимости и что разблокирует
- Зависит от: нет
- Разблокирует: T-095

## 5. Критерии готовности и способ проверки
1. Каждая страница запуска имеет утверждённые тексты состояний — проверка: таблица покрытия в артефакте.
2. В правилах публикации нет порогов и внутренних признаков — проверка: ревью.

## 6. Доказательство результата
Артефакт с текстами, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».

## 7. Пометки
Все утверждения — по спецификациям; кодовых фактов, требующих отдельной проверки, не заявлено.
