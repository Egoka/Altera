# T-114: Адаптер внешнего сборщика ошибок по Sentry-протоколу (GlitchTip/Sentry)

- **Эпик**: E-13 Наблюдаемость
- **Статус**: зависит: T-089
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор; тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Node.js, Sentry-протокол, docker-compose, Vitest

## 1. Результат
Рядом с `noop` есть адаптер сборщика ошибок по Sentry-протоколу, совместимый с собственным GlitchTip/Sentry; локально сборщик поднимается в docker-compose; адаптер выбирается конфигурацией окружения.

## 2. Источники
- Журнал: §28.6, §34 п. 3, §34 п. 5
- Спецификации: `docs/spec/80-observability/`
- ADR: ADR-0011

## 3. Границы и явно исключённое
- Входит: адаптер, конфигурация, локальный сервис в docker-compose, тесты.
- Не входит: развёртывание сборщика на сервере в РФ — вместе с хостингом (§34 п. 1, T-103).
- Сохраняемый контракт: `noop` и история `backend.error` из T-089 (утверждены §34 п. 5).

## 4. Зависимости и что разблокирует
- Зависит от: T-089
- Разблокирует: T-103 (подключение в проде)

## 5. Критерии готовности и способ проверки
1. Ошибка сервера с драйвером Sentry-протокола попадает в локальный сборщик без ПДн и секретов — проверка: интеграционный тест.
2. Драйвер `noop` остаётся значением по умолчанию — проверка: тест конфигурации.

## 6. Доказательство результата
Проверки по критериям §5, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».
