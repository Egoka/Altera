# T-021: Модуль почты с транспортами `smtp`/`console`/`fake` и письмо со ссылкой для входа

- **Эпик**: E-04 Вход, сессии и лимиты
- **Статус**: зависит: T-019
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор (интерфейс транспорта); тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Node, SMTP, шаблоны писем

## 1. Результат
Модуль `mail` с интерфейсом транспорта и реализациями `smtp`, `console`, `fake`; каждое письмо записывается в историю (адрес, тема, содержимое) и получает события `mail.queued` / `mail.sent` / `mail.failed`; письмо со ссылкой для входа отправляется через модуль, а не печатается в лог.

## 2. Источники
- Журнал: #43, §27.6, §28.8
- Спецификации: `docs/spec/40-admin/mail.md`, `docs/spec/10-flows/register-and-login.md`, `docs/spec/00-registries/events-and-logs.md`
- ADR: ADR-0024

## 3. Границы и явно исключённое
- Входит: Транспорты, история писем, письмо входа; тексты писем — `[ДОПУЩЕНИЕ]` до прохода почты (F-05).
- Не входит: Шаблоны, частота, согласия на рассылки, приветственное письмо (F-05); реальный провайдер (Q-01).

## 4. Зависимости и что разблокирует
- Зависит от: T-019
- Разблокирует: T-022, T-032, T-051, T-059, T-074, T-080, T-088

## 5. Критерии готовности и способ проверки
1. Письмо входа появляется в истории писем и в локальном приёмнике (`smtp`) — проверка: Playwright + запрос истории.
2. При недоступном транспорте фиксируется `mail.failed` и `PROVIDER_UNAVAILABLE: mail` — проверка: тест с `fake`, возвращающим ошибку.

## 6. Доказательство результата
Тесты транспорта, запись истории, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».
