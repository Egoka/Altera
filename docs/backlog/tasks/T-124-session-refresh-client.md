## 1. Результат

Вошедший пользователь не теряет сессию через 15 минут: BFF обменивает refresh на новый access при SSR и по ответу `UNAUTHENTICATED`, ротация refresh атомарна, а одновременные запросы нескольких вкладок не выглядят как кража.

Доработка по итогам независимого ревью 2026-09-26: T-023 (ALTE-97, PR #168).

## 3. Границы и явно исключённое

- Входит:
  - Вызов `refreshSession` из BFF при SSR и после `UNAUTHENTICATED` с одной попыткой повтора запроса.
  - Ротация refresh — условным обновлением по `tokenHash` (сравнение и замена), проигравший параллельный обмен получает исход повторного предъявления либо новый токен победителя, но не «unknown».
  - Один общий обмен в BFF на сессию: параллельные запросы вкладок не порождают ложный reuse.
- Не входит:
  - Лимит «до 10 устройств» `[ДОПУЩЕНИЕ]` — отдельно после утверждения.
  - Перенос access-токена из тела ответа в cookie целиком — только если архитектор признает это частью ADR-0023; иначе отдельная задача.
- Сохраняемый контракт: Мутации `refreshSession`, `logout`, `logoutAll`; хранение refresh только хэшем; отзыв по `sid` на каждом запросе.

## 5. Критерии готовности и способ проверки

- **AC-1**: через 16 минут после входа (время подменено) страница кабинета открывается без повторного входа; проверка: Playwright на реальном сервере.
- **AC-2**: два параллельных `refreshSession` с одним токеном дают одну успешную ротацию, второй не получает новую пару; проверка: тест на PostgreSQL.
- **AC-3**: одновременные запросы двух вкладок после истечения access не завершают все сессии; проверка: тест BFF.
