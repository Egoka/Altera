# T-049: Переходы статусов: подача → AI-проверка → автопубликация или доработка; повторная подача → ручная ветка

- **Эпик**: E-08 Проверка и публикация
- **Статус**: зависит: T-015, T-048, T-040
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор; тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: GraphQL Yoga, Prisma, конечные автоматы

## 1. Результат
`submit` проверяет рубрику, обложку, имя и хэндл, лицензии изображений; первая подача → `ai_check`; результат «публиковать» → `published` сразу с окном перередактирования; «не публиковать» → возврат автору с причинами; повторная подача после отказа AI → `review` без нового AI; `withdraw` → `draft`; события `translation.submit/withdraw`, `translation.published`.

## 3. Границы и явно исключённое
- Входит: Мутации переходов и инварианты; тесты всех переходов.
- Не входит: Ручные решения ревьюера (T-050); перередактирование (T-044).

## 4. Зависимости и что разблокирует
- Зависит от: T-015, T-048, T-040
- Разблокирует: T-043, T-044, T-046, T-050, T-051, T-052, T-075

## 5. Критерии готовности и способ проверки
1. Каждый переход из таблицы `write-and-publish.md` покрыт тестом; недопустимые переходы → `CONFLICT`/`FORBIDDEN`.
2. Повторная подача после отказа AI не создаёт задание AI — проверка: тест.

## 6. Доказательство результата
Тесты переходов, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».

Все утверждения — по спецификациям; кодовых фактов, требующих отдельной проверки, не заявлено.
