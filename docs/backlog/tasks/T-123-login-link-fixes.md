## 1. Результат

Вход по одноразовой ссылке не создаёт сессию заблокированному администратором аккаунту ни одним путём, работает при переходе из веб-почты (`Sec-Fetch-Site: cross-site`) и оставляет в браузере refresh-cookie, так что возвращённая T-022 проходит приёмку.

Доработка по итогам независимого ревью 2026-09-26: T-022 (ALTE-57, PR #164).

## 3. Границы и явно исключённое

- Входит:
  - `acceptConsent` проверяет архив аккаунта так же, как `verifyMagicLink`: административный архив — без сессии, самостоятельный — ограниченная сессия (`limited`).
  - Обмен токена на `/auth/verify` не отклоняется BFF как межсайтовая мутация, когда пользователь пришёл по ссылке из письма; защита от CSRF для остальных мутаций сохраняется.
  - После успешного входа через `/auth/verify` браузер получает httpOnly refresh-cookie (сейчас `Set-Cookie` внутреннего подзапроса теряется).
  - Одноразовость токена атомарна: пометка `usedAt` условным обновлением с проверкой числа строк.
- Не входит:
  - Обновление access-токена на клиенте — T-124.
  - Лимиты частоты — T-125.
  - Имя нового аккаунта — T-126.
  - Вход по паролю — T-115.
- Сохраняемый контракт: GraphQL-операции `verifyMagicLink`, `acceptConsent`, исходы `archived_admin`/`archived_self`, cookie-имена и флаги ADR-0023.

## 5. Критерии готовности и способ проверки

- **AC-1**: `acceptConsent` с действующим токеном административно заблокированного аккаунта не выдаёт сессию и отвечает как `verifyMagicLink` для этого исхода; самостоятельно архивированный получает только ограниченную сессию; проверка: серверный тест на оба исхода.
- **AC-2**: открытие ссылки из письма с заголовками межсайтового перехода завершает вход; межсайтовая мутация, не являющаяся обменом токена, по-прежнему отклоняется; проверка: тест BFF и Playwright с `Sec-Fetch-Site: cross-site`.
- **AC-3**: после входа через `/auth/verify` в браузере есть httpOnly refresh-cookie; проверка: Playwright на реальном сервере (не на моке BFF).
- **AC-4**: два параллельных обмена одного токена создают не больше одной сессии; проверка: тест на PostgreSQL.

## 7. Пометки

- [ФАКТ: `server/src/graphql/auth/resolver.ts:329-360`] `acceptConsent` вызывает `completeLogin` без проверки `archivedAt`; ветка `archived_admin` в `verifyMagicLink` (`:291-309`) токен не гасит.
- [ФАКТ: `web/server/utils/sessionCookie.ts:127`, `web/server/api/graphql.post.ts:24-33`] мутация с `sec-fetch-site: cross-site` отклоняется; `web/app/pages/auth/verify.vue:75-99` делает обмен на SSR, и h3 пересылает заголовки исходной навигации.
- [ФАКТ: `web/server/api/graphql.post.ts:51-55`] refresh-cookie ставится на внутреннем подзапросе, тело уже без `refreshToken` (`sessionCookie.ts:102-108`).
- [ФАКТ: `server/src/graphql/auth/resolver.ts:89-91,114`] чтение токена и `usedAt` — отдельными запросами.
- [ДОПУЩЕНИЕ] способ исправления межсайтового обмена (промежуточный экран с кнопкой или исключение для обмена токена) выбирает архитектор; промежуточный экран заодно защищает от почтовых сканеров.
