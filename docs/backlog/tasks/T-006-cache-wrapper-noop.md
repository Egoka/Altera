# T-006: Кеш-обёртка Redis/`noop`, инвалидация без `KEYS`, ключи со всеми аргументами

- **Эпик**: E-01 Инженерная база и честный CI
- **Статус**: кандидат
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор (интерфейс обёртки); тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: ioredis, GraphQL Yoga, Vitest

## 1. Результат
Сервер стартует без `REDIS_URL` в режиме `noop`; инвалидация по тегам без блокирующего `KEYS`; ключи кеша включают все аргументы, включая поисковый запрос; черновики и архив не кешируются.

## 2. Источники
- Журнал: прямого решения нет; задача техническая (границы — спецификации ниже)
- Спецификации: `docs/vision/00-reality-check.md`, `docs/spec/50-access/visibility.md`
- ADR: ADR-0019

## 3. Границы и явно исключённое
- Входит: Модуль кеша и его использование в существующих резолверах.
- Не входит: Изменение схемы данных; новые резолверы.

## 4. Зависимости и что разблокирует
- Зависит от: нет
- Разблокирует: нет прямых зависимых задач

## 5. Критерии готовности и способ проверки
1. Старт `server` без `REDIS_URL` успешен, запросы отвечают — проверка: env без переменной + curl.
2. В коде нет вызова `KEYS` — проверка: grep.
3. Тест: два разных поисковых запроса не получают один кеш-ключ.

## 6. Доказательство результата
Тесты Vitest, вывод старта без Redis, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».
