# T-050: Очередь ручной проверки `/admin/review`: закрепление, доработка, ручная публикация, отказ, снятие

- **Эпик**: E-08 Проверка и публикация
- **Статус**: зависит: T-049, T-018, T-069
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: дизайн — дизайнер; тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Nuxt 4, FishtVue, GraphQL Yoga

## 1. Результат
Ревьюер берёт материал в работу (`in_review`), возвращает на доработку с рекомендациями (`rework`), публикует вручную (сразу публично, в том числе вопреки AI), отклоняет окончательно, снимает опубликованное с публикации; заметки к блокам; автор виден именем и хэндлом без e-mail; точное число прочтений; события #24, #25, #69, #70.

## 2. Источники
- Журнал: #12, #14, #16, #18, #44, #51, §25.6, §26.4, §26.5
- Спецификации: `docs/spec/40-admin/review-queue.md`, `docs/spec/10-flows/moderation.md`, `docs/spec/30-account/author/review-history.md`
- ADR: не применимо

## 3. Границы и явно исключённое
- Входит: Раздел и мутации ревьюера; очередь проверок имени/аватара.
- Не входит: Жалобы (F-06).

## 4. Зависимости и что разблокирует
- Зависит от: T-049, T-018, T-069
- Разблокирует: T-072

## 5. Критерии готовности и способ проверки
1. Все строки состояний `review-queue.md` воспроизводимы — проверка: Playwright.
2. Закреплённый материал недоступен для решений другому ревьюеру (`CONFLICT`) — проверка: тест.
3. Ручная публикация делает материал видимым гостю немедленно — проверка: e2e.

## 6. Доказательство результата
Playwright, тесты, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».
