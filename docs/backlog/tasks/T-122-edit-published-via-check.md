# T-122: Правка опубликованной статьи через проверку

- **Эпик**: E-08 Проверка и публикация
- **Статус**: зависит: T-040, T-049
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор (обязательно); тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Prisma, GraphQL Yoga, очередь заданий, Playwright

## 1. Результат
Автор правит опубликованную статью в копии; публичной остаётся прежняя версия, новая публикуется после AI-проверки; при отказе правка уходит в ручную ветку ревьюера; на проверке одновременно одна правка.

## 2. Источники
- Журнал: §41, #9, #14, §28.3
- Спецификации: `docs/spec/00-registries/access-matrix.md` #19, `docs/spec/30-account/author/article-edit.md`, `docs/spec/85-media-and-binary/article-covers.md`

## 3. Границы и явно исключённое
- Входит: копия правки, статусы, событие правки опубликованной статьи.
- Не входит: окно «перередактировать» (не меняется, §41 п. 5).

## 4. Зависимости и что разблокирует
- Зависит от: T-040, T-049
- Разблокирует: T-066 (смена обложки после публикации)

## 5. Критерии готовности и способ проверки
1. Пока правка на проверке, читатель видит прежнюю версию — проверка: e2e.
2. Отказ AI оставляет прежнюю версию и отправляет повторную подачу ревьюеру — проверка: тест.
3. Вторую правку нельзя подать, пока первая на проверке — проверка: тест.

## 6. Доказательство результата
Проверки по критериям §5, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».
