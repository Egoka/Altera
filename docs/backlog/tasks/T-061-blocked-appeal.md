# T-061: Оспаривание блокировки `/auth/appeal` и решение сотрудника

- **Эпик**: E-09 Публичные страницы
- **Статус**: решение владельца: Q-05
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: дизайн — дизайнер; тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Nuxt 4, GraphQL Yoga

## 1. Результат
Заблокированный при входе получает форму оспаривания по токену без сессии; одно обращение на аккаунт; сотрудник восстанавливает или подтверждает блокировку с уведомлением; события `user.appeal.submit/decide`.

## 2. Источники
- Журнал: #48, §26.9
- Спецификации: `docs/spec/20-public/blocked-appeal.md`, `docs/spec/10-flows/archive-account.md`
- ADR: не применимо

## 3. Границы и явно исключённое
- Входит: Страница, мутации, решение в карточке пользователя.
- Не входит: Письмо о решении — тексты (F-05).

## 4. Зависимости и что разблокирует
- Зависит от: T-022, T-073
- Разблокирует: нет прямых зависимых задач

## 5. Критерии готовности и способ проверки
1. Повторное обращение → `CONFLICT` — проверка: тест.
2. Все строки состояний `blocked-appeal.md` воспроизводимы — проверка: Playwright.

## 6. Доказательство результата
Тесты, Playwright. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».

## 7. Пометки
Форма показывает категорию причины блокировки — названия категорий не заданы (§26.9).

## 8. Требует решения владельца
