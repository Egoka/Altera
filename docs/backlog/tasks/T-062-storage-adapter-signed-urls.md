# T-062: Адаптер хранилища S3 с локальной реализацией, раскладка ключей, подписанные ссылки

- **Эпик**: E-10 Медиа
- **Статус**: решение владельца: Q-01
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор (обязательно); тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: S3 API, подписанные URL, Node

## 1. Результат
Интерфейс хранилища с реализацией S3-совместимого провайдера и локальной для разработки и CI; ключи без персональных данных и имён файлов; публичные варианты опубликованных материалов — прямые ссылки, оригиналы и медиа непубличных материалов — только подписанные ссылки после проверки прав; доступ следует за статусом материала и аккаунта; `PROVIDER_UNAVAILABLE: storage`.

## 2. Источники
- Журнал: #28, §29.3
- Спецификации: `docs/spec/85-media-and-binary/storage-layout.md`, `docs/spec/85-media-and-binary/access-and-signed-urls.md`
- ADR: ADR-0008, ADR-0011

## 3. Границы и явно исключённое
- Входит: Адаптер, ключи, подписанные ссылки, локальная реализация.
- Не входит: Конвейер (T-063); выбор провайдера — владелец.

## 4. Зависимости и что разблокирует
- Зависит от: T-016, T-027
- Разблокирует: T-034, T-063, T-076

## 5. Критерии готовности и способ проверки
1. Ссылка на оригинал без подписи → отказ — проверка: тест.
2. Архивирование материала закрывает публичные ссылки на его медиа — проверка: тест.

## 6. Доказательство результата
Тесты с локальной реализацией, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».

## 7. Пометки
Интерфейс и локальная реализация не требуют решений; реальный провайдер — Q-01.

## 8. Требует решения владельца
Q-01 — Провайдеры и хостинг (см. `docs/backlog/owner-blockers.md`). Почему без этого задача не готова — в разделе 7.
