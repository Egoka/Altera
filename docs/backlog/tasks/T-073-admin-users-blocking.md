# T-073: Пользователи: карточка с аудитом чтения, блокировка = архив с предупреждением о плане, экстренная блокировка, восстановление

- **Эпик**: E-11 Админка I
- **Статус**: решение владельца: Q-05
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: дизайн — дизайнер; тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Nuxt 4, FishtVue, GraphQL Yoga

## 1. Результат
Раздел `/admin/users`: список с маскированным e-mail, карточка с полным e-mail (аудит чтения), признак базового авторства, статьи, сессии (`admin`/`owner`), архив аккаунта с категорией причины и объяснением, предупреждение о действующем плане, экстренная блокировка, восстановление без возврата статей, отзыв сессий, смена e-mail сотрудником; события `user.archive/restore`, `user.sessions.revoke`.

## 2. Источники
- Журнал: #4, #6, #22, #30, #48, #50, §26.6, §26.9, §27.1, §28.7
- Спецификации: `docs/spec/40-admin/users.md`, `docs/spec/10-flows/archive-account.md`, `docs/spec/10-flows/email-change-and-recovery.md`

## 3. Границы и явно исключённое
- Входит: Раздел, мутации, каскад архивирования статей и закрытие медиа.
- Не входит: Оспаривание (T-061); удалить навсегда (T-076).

## 4. Зависимости и что разблокирует
- Зависит от: T-069, T-029, T-045, T-023
- Разблокирует: T-061, T-076

## 5. Критерии готовности и способ проверки
1. Открытие карточки пишет `admin.read.personal` — проверка: тест.
2. Блокировка архивирует статьи с актором-сотрудником, автор их не восстанавливает — проверка: тест.
3. Все строки состояний `users.md` воспроизводимы — проверка: Playwright.

## 6. Доказательство результата
Playwright, тесты, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».

## 7. Пометки
Блокировка требует одну из четырёх категорий причины — их названия не заданы.

## 8. Требует решения владельца
