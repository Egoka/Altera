# T-026: Единый модуль проверок прав: роль, базовое авторство, исключения, `ensureActiveAuthor`

- **Эпик**: E-05 Роли и проверки доступа
- **Статус**: зависит: T-011, T-017
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор (обязательно); тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: GraphQL Yoga, TypeScript

## 1. Результат
Все резолверы используют один модуль проверок по `permission-checks.md`: роли из enum, вывод `author` из базового авторства/выдачи, индивидуальные исключения, право публикации как отдельное; `PLAN_LIMIT`/`FORBIDDEN` по словарю; матрица `access-matrix.md` покрыта тестами на строки первого запуска.

## 2. Источники
- Журнал: #7, #8, #13, #46, §25.1
- Спецификации: `docs/spec/50-access/permission-checks.md`, `docs/spec/00-registries/access-matrix.md`, `docs/spec/70-plans-and-billing/role-derivation.md`
- ADR: ADR-0035 (частично заменён журналом Г5–Г5b), ADR-0037

## 3. Границы и явно исключённое
- Входит: Модуль и замена `ensureHasRole`; тестовая матрица.
- Не входит: Отдельные исключения (T-028); строки матрицы платности и жалоб (F-01, F-06).

## 4. Зависимости и что разблокирует
- Зависит от: T-011, T-017
- Разблокирует: T-027, T-028, T-029, T-030, T-037, T-038, T-039, T-045, T-052, T-069

## 5. Критерии готовности и способ проверки
1. Каждая утверждённая строка матрицы этапа 1 имеет тест «роль × действие → разрешено/запрещено» — проверка: список в отчёте.
2. `ensureHasRole` больше не вызывается напрямую — проверка: grep.

## 6. Доказательство результата
Тесты матрицы, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».
