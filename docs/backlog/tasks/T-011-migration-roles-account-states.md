# T-011: Миграция: `Role` из семи значений и состояния учётной записи

- **Эпик**: E-03 Модель данных v2
- **Статус**: кандидат
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор (план миграции с данными); тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Prisma-миграции, PostgreSQL, enum с данными

## 1. Результат
Enum `Role { reader author editor moderator analyst admin owner }` — единственный источник ролей; у пользователя есть состояние архива с актором и снимком его роли, признак служебной записи; существующие пользователи сконвертированы.

- ADR: ADR-0003 (частично заменён ADR-0035, ADR-0042), ADR-0042

## 3. Границы и явно исключённое
- Входит: Enum ролей, поля состояния аккаунта (архив, актор, роль актора, дата), признак служебной записи; конверсия текущих ролей.
- Не входит: Категория причины блокировки — ждёт названий (Q-05, T-073); сессии (T-012).

## 5. Критерии готовности и способ проверки
1. Миграция применяется на копии базы с данными без потери строк — проверка: репетиция по T-020 или на локальной копии.
2. GraphQL-enum `Role` совпадает с Prisma — проверка: контрактный тест.
3. Фронт не содержит собственного словаря ролей `user|admin` — проверка: grep.
