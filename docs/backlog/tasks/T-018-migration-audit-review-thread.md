# T-018: Миграция: неизменяемый аудит и переписка по статье с заметками к блокам

- **Эпик**: E-03 Модель данных v2
- **Статус**: зависит: T-015
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор; тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Prisma-миграции, PostgreSQL (ограничения на изменение)

## 1. Результат
`AuditLog` только на добавление: актор, роль, время, сущность, действие, поля до/после, автоматический контекст чтения ПД; `ReviewMessage` — двусторонняя переписка по версии (решения, рекомендации, ответы автора); `ReviewNote` — заметка к блоку, привязанная к ревизии, с отметкой «решено».

## 2. Источники
- Журнал: #6, #16, #59, §25.6, §27.5
- Спецификации: `docs/spec/80-observability/audit-vs-logs.md`, `docs/spec/40-admin/audit-log.md`, `docs/spec/30-account/author/review-history.md`
- ADR: ADR-0032

## 3. Границы и явно исключённое
- Входит: Схема аудита и переписки.
- Не входит: Интерфейсы (T-043, T-079); запись аудита из резолверов (T-029 и задачи доменов).

## 4. Зависимости и что разблокирует
- Зависит от: T-015
- Разблокирует: T-020, T-028, T-029, T-043, T-050, T-070, T-079

## 5. Критерии готовности и способ проверки
1. `UPDATE`/`DELETE` по таблице аудита отклоняются — проверка: тест на уровне базы или прав роли приложения.
2. Заметка к блоку ссылается на ревизию и идентификатор блока — проверка: ревью схемы.

## 6. Доказательство результата
Миграция, тесты. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».

## 7. Пометки
Аудита самого аудита нет (§27.5).
