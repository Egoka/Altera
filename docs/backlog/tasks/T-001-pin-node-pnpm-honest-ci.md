# T-001: Пин версий Node и pnpm, честный CI

- **Эпик**: E-01 Инженерная база и честный CI
- **Статус**: кандидат
- **Параллельность**: да: только конфигурация репозитория и CI, продуктовый код не меняется
- **Роль-исполнитель**: релиз-инженер
- **Участники стадий**: архитектура — нет; тестирование — тестировщик; ревью — независимый ревьюер; документация — хранитель документации
- **Навыки**: GitHub Actions, pnpm, Node, ESLint, vue-tsc

## 1. Результат
В репозитории есть `.nvmrc` и `engines`, одна версия pnpm, CI собирает `web` и `server`, запускает `vue-tsc`, линт и тесты; `pnpm test` падает при нуле тестов; старт сервера не маскируется `|| true`.

## 2. Источники
- Журнал: §20.19
- Спецификации: `docs/vision/08-operations.md`, `docs/vision/00-reality-check.md`
- ADR: ADR-0031

## 3. Границы и явно исключённое
- Входит: Конфигурация CI, `package.json` (`engines`, скрипты), `.nvmrc`, ESLint ignores для `.output`.
- Не входит: Тесты как таковые (T-002); docker-compose (T-003); прод-сборка веба (T-004).

## 4. Зависимости и что разблокирует
- Зависит от: нет
- Разблокирует: T-002, T-004, T-104

## 5. Критерии готовности и способ проверки
1. CI завершается ошибкой, если `pnpm test` не выполнил ни одного теста — проверка: временно пустой набор → красный CI.
2. CI выполняет `pnpm --filter server build`, `pnpm --filter web build`, `vue-tsc --noEmit`, `pnpm lint` — проверка: лог CI.
3. Локальная и CI-версии Node совпадают с `.nvmrc` — проверка: `node -v` в логе CI.
4. Шаг запуска сервера не содержит `|| true` — проверка: grep по workflow.

## 6. Доказательство результата
Зелёный и заведомо красный прогоны CI (ссылки на прогоны в отчёте); отчёт по ритуалу с «Как проверено». Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».
