# T-089: Внешний сборщик ошибок через адаптер и собственная история `backend.error`

- **Эпик**: E-13 Наблюдаемость
- **Статус**: решение владельца: Q-01
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор; тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Интеграция со сборщиком ошибок, Node

## 1. Результат
События `error.unhandled`, `backend.error`, `page.error` пишутся в собственную историю с группировкой и отправляются во внешний сборщик с инфраструктурой в РФ через адаптер с реализацией `noop`.

## 2. Источники
- Журнал: §20.19, §28.6
- Спецификации: `docs/spec/80-observability/error-collector.md`
- ADR: ADR-0011

## 3. Границы и явно исключённое
- Входит: Адаптер и история.
- Не входит: Выбор сборщика — владелец.

## 4. Зависимости и что разблокирует
- Зависит от: T-086
- Разблокирует: T-081

## 5. Критерии готовности и способ проверки
1. Ошибка фронта `page.error` попадает в историю — проверка: тест.
2. С адаптером `noop` система работает без внешнего сервиса — проверка: тест.

## 6. Доказательство результата
Тесты. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».

## 7. Пометки
Все утверждения — по спецификациям; кодовых фактов, требующих отдельной проверки, не заявлено.

## 8. Требует решения владельца
