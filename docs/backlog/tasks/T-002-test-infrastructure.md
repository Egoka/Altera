# T-002: Тестовая инфраструктура: Vitest в server и web, Playwright smoke

- **Эпик**: E-01 Инженерная база и честный CI
- **Статус**: зависит: T-001
- **Параллельность**: да: добавляет тестовую обвязку и первые тесты, продуктовый код не меняет
- **Роль-исполнитель**: тестировщик
- **Участники стадий**: архитектура — нет; разработка — разработчик (подключение); ревью — независимый ревьюер
- **Навыки**: Vitest, Playwright, GraphQL schema tooling

## 1. Результат
В `server` и `web` настроен Vitest; есть первый контрактный тест SDL (схема собирается, публичные типы не содержат `email`); настроен Playwright со smoke-сценарием открытия главной; CI запускает всё это.

## 2. Источники
- Журнал: #6
- Спецификации: `docs/vision/08-operations.md`, `docs/spec/50-access/visibility.md`
- ADR: ADR-0031, ADR-0018

## 3. Границы и явно исключённое
- Входит: Конфигурация Vitest и Playwright, первый контрактный тест, smoke-тест, скрипты `test` в обоих пакетах.
- Не входит: Полное покрытие доменов (в задачах доменов); e2e-сценарии запуска (T-112).

## 4. Зависимости и что разблокирует
- Зависит от: T-001
- Разблокирует: T-112

## 5. Критерии готовности и способ проверки
1. `pnpm --filter server test` и `pnpm --filter web test` выполняют ≥ 1 тест и проходят.
2. Контрактный тест падает, если в публичном типе `Author`/`User` появляется поле `email` — проверка: временное добавление поля.
3. Playwright smoke открывает `/` и проверяет заголовок — проверка: прогон в CI.

## 6. Доказательство результата
Вывод `pnpm test` обоих пакетов, прогон Playwright в CI, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».
