# T-115: Вход по паролю: регистрация с паролем, подтверждение адреса, сброс и смена пароля

- **Эпик**: E-04 Вход, сессии и лимиты
- **Статус**: зависит: T-021, T-022, T-024, T-116
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор (обязательно); тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Prisma-миграции, хэширование паролей, GraphQL Yoga, Nuxt 4, Vitest, Playwright

## 1. Результат
Пользователь регистрируется и входит любым из двух взаимозаменяемых способов — по одноразовой ссылке (без пароля) или с паролем; при регистрации с паролем адрес подтверждается письмом до первого входа; забытый пароль сбрасывается письмом; аккаунты без пароля входят по ссылке.

## 2. Источники
- Журнал: §34 п. 6–9
- Спецификации: `docs/spec/20-public/login.md`, `docs/spec/10-flows/register-and-login.md`, `docs/spec/50-access/session-lifecycle.md`, `docs/spec/50-access/rate-limits.md`
- ADR: ADR-0022 (частично заменён журналом §34)

## 3. Границы и явно исключённое
- Входит: хранение хэша, регистрация с паролем, письмо подтверждения, вход по паролю, сброс и смена пароля в кабинете, лимит попыток.
- Не входит: OAuth; реальная доставка писем — после выбора SMTP-провайдера (§34 п. 2).
- Сохраняемый контракт: вход по одноразовой ссылке (T-022).

## 4. Зависимости и что разблокирует
- Зависит от: T-022, T-021, T-024, T-116
- Разблокирует: нет прямых зависимых задач

## 5. Критерии готовности и способ проверки
1. Регистрация по ссылке и с паролем обе создают аккаунт; при регистрации с паролем вход до подтверждения адреса невозможен — проверка: e2e.
2. Аккаунт без пароля входит по ссылке — проверка: e2e.
3. Сброс пароля идёт письмом; ответы не раскрывают существование аккаунта — проверка: тест.
4. Попытки входа ограничены лимитом, утверждённым владельцем — проверка: тест.

## 6. Доказательство результата
Проверки по критериям §5, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».
