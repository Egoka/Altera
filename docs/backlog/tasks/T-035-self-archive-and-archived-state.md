# T-035: «Удалить аккаунт» = самостоятельное архивирование, экран `/me/archived` и самовосстановление

- **Эпик**: E-06 Кабинет читателя
- **Статус**: решение владельца: Q-09
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: дизайн — дизайнер; тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Nuxt 4, GraphQL Yoga

## 1. Результат
Архивирование аккаунта по подтверждению: немедленное, каскадно архивирует статьи; при следующем входе — экран состояния с восстановлением; восстановление возвращает только аккаунт, статьи автор возвращает вручную; события `user.archive.self`, `user.restore.self`.

## 2. Источники
- Журнал: #4, #50, §5.2, §25.7
- Спецификации: `docs/spec/30-account/reader/delete-account.md`, `docs/spec/30-account/reader/archived-state.md`, `docs/spec/10-flows/delete-account.md`
- ADR: ADR-0014 (частично заменён ADR-0036)

## 3. Границы и явно исключённое
- Входит: Страницы `/me/delete`, `/me/archived`, мутации.
- Не входит: Административная блокировка (T-073); удаление навсегда (T-076).

## 4. Зависимости и что разблокирует
- Зависит от: T-022, T-015
- Разблокирует: нет прямых зависимых задач

## 5. Критерии готовности и способ проверки
1. После восстановления статьи остаются в архиве — проверка: тест.
2. Все строки состояний обеих страниц воспроизводимы — проверка: Playwright.

## 6. Доказательство результата
Тесты, Playwright. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».

## 7. Пометки
Противоречие этапов: `routes.md` #40 и `delete-account.md` относят `/me/delete` к этапу 3, а `routes.md` #73 и `archived-state.md` — к этапу 1; без самостоятельного архивирования состояние `self` не возникает.
