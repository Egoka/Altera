# T-079: Аудит `/admin/audit`: два уровня видимости, фильтры, экспорт без ПД

- **Эпик**: E-12 Админка II
- **Статус**: зависит: T-069, T-018
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: дизайн — дизайнер; тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Nuxt 4, FishtVue

## 1. Результат
Служебная роль видит записи своей зоны, `admin` и `owner` — весь журнал; фильтры по коду, актору, субъекту, периоду, `requestId`; экспорт без полей с ПД; просмотр аудита не аудируется.

## 2. Источники
- Журнал: #37, #39, §27.5
- Спецификации: `docs/spec/40-admin/audit-log.md`
- ADR: не применимо

## 3. Границы и явно исключённое
- Входит: Раздел.
- Не входит: Признак «критичная запись» (§26.1, Q-08).

## 4. Зависимости и что разблокирует
- Зависит от: T-069, T-018
- Разблокирует: нет прямых зависимых задач

## 5. Критерии готовности и способ проверки
1. Все строки состояний `audit-log.md` воспроизводимы — проверка: Playwright под ролями.
2. Просмотр аудита не создаёт записи — проверка: тест.

## 6. Доказательство результата
Playwright, тесты. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».
