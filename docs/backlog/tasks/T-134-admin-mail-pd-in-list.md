## 1. Результат

Список писем не отдаёт содержимое и полный адрес без записи чтения ПД; содержимое открывается только карточкой с аудитом; письма с секретами любого шаблона не повторяются из админки.

Доработка по итогам независимого ревью 2026-09-26: T-080 (ALTE-95, PR #167).

## 3. Границы и явно исключённое

- Входит:
  - `body` в списке всегда `null`; полный `recipientEmail` в списке — маска либо `admin.read.personal` (§28.7).
  - Признак «письмо с секретом» у шаблона (или записи), включая `email_change_code`; повтор таких писем запрещён.
  - Проверка «уже повторено» и отправка атомарны.
  - Кнопки повтора — по праву `job.retry`, а не по роли `owner`.
- Не входит:
  - Обезличивание копий при удалении аккаунта (§28.8) — вместе с `/me/delete` (§35 п. 1).
- Сохраняемый контракт: Запросы `adminMails`, `adminMail`, мутация повтора; аудит `admin.read.personal`, `admin.mail.search`.

## 5. Критерии готовности и способ проверки

- **AC-1**: запрос `adminMails { items { body } }` возвращает `null` для всех строк; проверка: контрактный тест.
- **AC-2**: открытие списка с полным адресом пишет `admin.read.personal` либо адрес маскирован; проверка: тест.
- **AC-3**: письмо `email_change_code` не повторяется (`canResend = false`, мутация отклоняет); проверка: тест.
- **AC-4**: два параллельных повтора одного письма дают одну отправку; проверка: тест на PostgreSQL.
