# T-022: Регистрация и вход по ссылке: `/login`, `/auth/verify`, экраны состояния

- **Эпик**: E-04 Вход, сессии и лимиты
- **Статус**: зависит: T-012, T-021, T-009
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор; дизайн — дизайнер; тестирование — тестировщик; ревью — независимый ревьюер; SEO — SEO-специалист (`noindex`)
- **Навыки**: Nuxt 4, GraphQL Yoga, i18n

## 1. Результат
Единый сценарий регистрации и входа по ссылке из письма: страница входа, подтверждение по токену, выбор основного языка при регистрации, переходы в состояние архивированного аккаунта (`/me/archived`) и оспаривания блокировки (`/auth/appeal`); события `auth.link.requested` / `auth.login` / `auth.login.failed`, `registration`.

## 2. Источники
- Журнал: #4, #48, §5.2, §20.11
- Спецификации: `docs/spec/10-flows/register-and-login.md`, `docs/spec/20-public/login.md`, `docs/spec/20-public/verify.md`, `docs/spec/30-account/reader/archived-state.md`
- ADR: ADR-0022, ADR-0024

## 3. Границы и явно исключённое
- Входит: Страницы и резолверы входа; ответы без перечисления аккаунтов.
- Не входит: Ротация сессий (T-023); лимиты (T-024); сама страница `/me/archived` (T-035); страница оспаривания (T-061).

## 4. Зависимости и что разблокирует
- Зависит от: T-012, T-021, T-009
- Разблокирует: T-023, T-024, T-030, T-035, T-061, T-101

## 5. Критерии готовности и способ проверки
1. Все строки состояний `login.md` и `verify.md` воспроизводимы — проверка: Playwright по таблице состояний.
2. Ответ на запрос ссылки одинаков для существующего и несуществующего адреса — проверка: тест.
3. Архивированный аккаунт после входа попадает на экран состояния — проверка: e2e.

## 6. Доказательство результата
Playwright-сценарий flow #1, тесты резолверов, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».
