# T-119: Раздел админки «Обращения» и статус обращения в кабинете

- **Эпик**: E-12 Админка II
- **Статус**: зависит: T-059
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор; тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Prisma, GraphQL Yoga, Nuxt 4, Playwright

## 1. Результат
Обращения в поддержку разбираются в отдельном разделе админки «Обращения»; пользователь видит статус своего обращения («принято / отвечено») в кабинете; ответ фиксируется событием `support.request.answered`.

## 2. Источники
- Журнал: §37 п. 2, п. 13, §28.3
- Спецификации: `docs/spec/20-public/contact.md`, `docs/spec/00-registries/admin-sections.md`, `docs/spec/00-registries/events-and-logs.md`

## 3. Границы и явно исключённое
- Входит: раздел админки, статус в кабинете, событие.
- Не входит: шаблоны писем (F-05).

## 4. Зависимости и что разблокирует
- Зависит от: T-059, T-069
- Разблокирует: нет прямых зависимых задач

## 5. Критерии готовности и способ проверки
1. Сотрудник видит очередь в разделе «Обращения» — проверка: e2e под ролями.
2. Пользователь видит статус своего обращения — проверка: e2e.
3. Ответ пишет событие `support.request.answered` — проверка: тест.

## 6. Доказательство результата
Проверки по критериям §5, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».
