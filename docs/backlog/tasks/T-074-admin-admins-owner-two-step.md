# T-074: Администраторы: служебные записи, роли, назначение `owner` в два шага, деактивация, исключения, архив служебной записи владельцем

- **Эпик**: E-11 Админка I
- **Статус**: зависит: T-069, T-028, T-021
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: дизайн — дизайнер; тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Nuxt 4, FishtVue, GraphQL Yoga

## 1. Результат
Раздел `/admin/admins`: создание отдельной служебной записи `admin`/`owner` (не повышение читателя), смена и снятие роли `owner`, назначение владельца в два шага, отзыв и деактивация с инвариантом «не ноль владельцев», индивидуальные исключения, архив служебной записи только `owner`; события `user.create.staff`, `user.role.change`, `role.assign.owner`/`role.revoke.owner`/`owner.deactivate`.

## 2. Источники
- Журнал: #7, #10, #46, #47, §26.7
- Спецификации: `docs/spec/40-admin/admins.md`, `docs/spec/10-flows/appoint-admin.md`, `docs/spec/50-access/escalation-and-demotion.md`
- ADR: ADR-0042 (частично заменён журналом Г1–Г2)

## 3. Границы и явно исключённое
- Входит: Раздел и мутации; письмо входа новой записи.
- Не входит: Судьба служебной записи после снятия роли (OPEN-QUESTIONS #8, Q-08) — временное допущение спецификации.
