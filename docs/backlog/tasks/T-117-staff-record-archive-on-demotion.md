# T-117: Архивирование служебной записи при снятии роли

- **Эпик**: E-11 Админка I
- **Статус**: зависит: T-074
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Prisma, GraphQL Yoga, Vitest, Playwright

## 1. Результат
При снятии роли служебная запись архивируется; вернуть роль можно только через восстановление аккаунта владельцем; временное поведение T-074 («остаётся служебной без прав») заменено.

## 2. Источники
- Журнал: §37 п. 8, #4
- Спецификации: `docs/spec/50-access/escalation-and-demotion.md`, `docs/spec/40-admin/admins.md`

## 3. Границы и явно исключённое
- Входит: доработка модуля служебных записей и раздела `/admin/admins`, аудит.
- Не входит: остальные правила T-074.

## 4. Зависимости и что разблокирует
- Зависит от: T-074
- Разблокирует: нет прямых зависимых задач

## 5. Критерии готовности и способ проверки
1. Снятие роли архивирует запись и отзывает сессии — проверка: тест.
2. Возврат роли возможен только восстановлением аккаунта владельцем — проверка: тест прав.

## 6. Доказательство результата
Проверки по критериям §5, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».
