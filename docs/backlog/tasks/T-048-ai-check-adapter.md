# T-048: AI-адаптер проверки допустимости (`real`/`fake`) с бинарным результатом и причинами

- **Эпик**: E-08 Проверка и публикация
- **Статус**: решение владельца: Q-06
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор (обязательно); тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Интеграция с LLM-API, адаптеры, тесты с `fake`

## 1. Результат
Интерфейс адаптера AI-проверки; `fake` — детерминированные вердикты по фикстуре; `real` — провайдер по решению владельца; результат бинарный «публиковать / не публиковать» с текстом причин по категориям правил публикации; запись в журнал AI-процессов, событие `ai.decision`; при недоступности — `PROVIDER_UNAVAILABLE: ai`, задание повторяется; ручного повтора вердикта нет.

## 2. Источники
- Журнал: #9, #40, #41, #42, #52, #56, §24.3, §27.4
- Спецификации: `docs/spec/10-flows/write-and-publish.md`, `docs/spec/40-admin/ai-processes.md`, `docs/spec/20-public/legal-content-rules.md`, `docs/spec/80-observability/error-dictionary.md`
- ADR: ADR-0039 (частично заменён журналом #41, §21), ADR-0045 (частично заменён журналом #8, #14)

## 3. Границы и явно исключённое
- Входит: Адаптер, `fake`, запись результатов, интеграция с очередью.
- Не входит: Правила проверки (содержание) и провайдер — решения владельца; AI в рейтинге — нет по #41.

## 4. Зависимости и что разблокирует
- Зависит от: T-047, T-041
- Разблокирует: T-031, T-049, T-067, T-078

## 5. Критерии готовности и способ проверки
1. С `fake` статья с фикстурой «отказ» получает комментарий с причинами по категориям — проверка: тест.
2. Текст для проверки не содержит имени и e-mail автора — проверка: тест экстрактора.
3. Стоимость записывается так, что доступна только агрегатом — проверка: контрактный тест API раздела.

## 6. Доказательство результата
Тесты с `fake`, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».

## 7. Пометки
`fake` можно сделать без решений владельца; `real` — нет.

## 8. Требует решения владельца
Q-06 — Правила AI-проверки допустимости (см. `docs/backlog/owner-blockers.md`). Почему без этого задача не готова — в разделе 7.
