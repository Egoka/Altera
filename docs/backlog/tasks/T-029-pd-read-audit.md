# T-029: Аудит чтения персональных данных: автоматический контекст на любой странице с полным e-mail

- **Эпик**: E-05 Роли и проверки доступа
- **Статус**: зависит: T-018, T-026
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор; тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: GraphQL Yoga, Prisma

## 1. Результат
Любой административный запрос, возвращающий полный e-mail или иные ПД, пишет `admin.read.personal` с актором, временем, разделом и действием автоматически; сотрудник ничего не вводит; `moderator` не получает e-mail автора.

## 2. Источники
- Журнал: #6, #51, #59, §28.7
- Спецификации: `docs/spec/80-observability/audit-vs-logs.md`, `docs/spec/40-admin/users.md`, `docs/spec/50-access/roles/moderator.md`
- ADR: не применимо

## 3. Границы и явно исключённое
- Входит: Обёртка резолверов админки для ПД; тесты.
- Не входит: Экран аудита (T-079).

## 4. Зависимости и что разблокирует
- Зависит от: T-018, T-026
- Разблокирует: T-073, T-080

## 5. Критерии готовности и способ проверки
1. Запрос карточки пользователя `admin` создаёт запись `admin.read.personal` — проверка: тест.
2. Запрос карточки материала `moderator` не содержит e-mail автора — проверка: контрактный тест.

## 6. Доказательство результата
Тесты, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».

## 7. Пометки
Все утверждения — по спецификациям; кодовых фактов, требующих отдельной проверки, не заявлено.
