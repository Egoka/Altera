# T-106: Внешняя проверка доступности `/health` с уведомлением владельца и администратора

- **Эпик**: E-17 Прод в РФ, бэкапы и релиз
- **Статус**: решение владельца: Q-01
- **Параллельность**: да: не меняет продуктовый код
- **Роль-исполнитель**: релиз-инженер
- **Участники стадий**: ревью — независимый ревьюер
- **Навыки**: Мониторинг доступности

## 1. Результат
Внешний сервис проверяет `/health` регулярно и уведомляет владельца и администратора при недоступности.

## 2. Источники
- Журнал: §28.5
- Спецификации: `docs/spec/80-observability/health-and-alerts.md`
- ADR: не применимо

## 3. Границы и явно исключённое
- Входит: Настройка проверки.
- Не входит: ничего сверх результата; смежное — в задачах эпика

## 4. Зависимости и что разблокирует
- Зависит от: T-104, T-088
- Разблокирует: нет прямых зависимых задач

## 5. Критерии готовности и способ проверки
1. Имитация недоступности приводит к уведомлению — проверка: репетиция.

## 6. Доказательство результата
Запись о репетиции. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».

## 7. Пометки
Все утверждения — по спецификациям; кодовых фактов, требующих отдельной проверки, не заявлено.
