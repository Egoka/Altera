# T-047: Очередь фоновых заданий в базе и исполнитель в процессе API

- **Эпик**: E-08 Проверка и публикация
- **Статус**: зависит: T-019, T-086
- **Параллельность**: нет: меняет продуктовый код
- **Роль-исполнитель**: разработчик
- **Участники стадий**: архитектура — архитектор (обязательно); тестирование — тестировщик; ревью — независимый ревьюер
- **Навыки**: Node, Prisma, планировщик, идемпотентность

## 1. Результат
Задания (AI-проверка, обработка медиа, письма, выгрузки, истечения) исполняются воркером в процессе API со статусами, попытками, `originRequestId`; события `job.failed`/`job.stuck`; повтор и отмена только по правам (`job.retry`/`job.cancel`).

## 2. Источники
- Журнал: #34, #36
- Спецификации: `docs/spec/40-admin/jobs.md`, `docs/spec/80-observability/health-and-alerts.md`, `docs/spec/80-observability/request-tracing.md`
- ADR: не применимо

## 3. Границы и явно исключённое
- Входит: Модель исполнения заданий, интерфейс постановки, ретраи.
- Не входит: Экран `/admin/jobs` (T-077); отдельный процесс воркера — не требуется на первом запуске `[ДОПУЩЕНИЕ]`.

## 4. Зависимости и что разблокирует
- Зависит от: T-019, T-086
- Разблокирует: T-034, T-048, T-063, T-068, T-077, T-088, T-090

## 5. Критерии готовности и способ проверки
1. Задание с ошибкой переходит в `failed` после исчерпания попыток и пишет `job.failed` — проверка: тест.
2. Зависшее задание помечается `stuck` по таймауту — проверка: тест с подменой времени.

## 6. Доказательство результата
Тесты, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».

## 7. Пометки
Число попыток и таймауты — по `jobs.md` `[ДОПУЩЕНИЕ]` там, где спецификация их не задаёт.

## 8. Требует решения владельца
нет. Число попыток и таймауты — по `jobs.md` `[ДОПУЩЕНИЕ]` там, где спецификация их не задаёт.
