# T-003: Локальное окружение: docker-compose с PostgreSQL, Redis и почтовой заглушкой

- **Эпик**: E-01 Инженерная база и честный CI
- **Статус**: готова
- **Параллельность**: да: не меняет продуктовый код
- **Роль-исполнитель**: релиз-инженер
- **Участники стадий**: ревью — независимый ревьюер; документация — хранитель документации
- **Навыки**: Docker Compose, PostgreSQL, Redis

## 1. Результат
Одной командой поднимается PostgreSQL, Redis и локальный приёмник писем; `server` и `web` запускаются на них без внешних сервисов; руководство запуска в `docs/guides/` описывает порядок.

## 2. Источники
- Журнал: прямого решения нет; задача техническая (границы — спецификации ниже)
- Спецификации: `docs/vision/08-operations.md`
- ADR: ADR-0011, ADR-0019, ADR-0024

## 3. Границы и явно исключённое
- Входит: `docker-compose.yml`, `.env.example`, руководство запуска.
- Не входит: Прод-окружение (T-103); выбор почтового провайдера (Q-01).

## 4. Зависимости и что разблокирует
- Зависит от: нет
- Разблокирует: нет прямых зависимых задач

## 5. Критерии готовности и способ проверки
1. `docker compose up` поднимает три сервиса — проверка: `docker compose ps`.
2. `cd server && pnpm dev` отвечает на `POST /` с `{ __typename }` — проверка: curl.
3. Письмо входа видно в локальном приёмнике — проверка после T-021; до этого — в консоли.

## 6. Доказательство результата
Вывод `docker compose ps` и curl в отчёте. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».

## 7. Пометки
[ДОПУЩЕНИЕ] Локальный приёмник писем — любой контейнер с SMTP и веб-интерфейсом; это не выбор провайдера для прода.
