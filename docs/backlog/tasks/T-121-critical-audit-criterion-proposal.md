# T-121: Предложение критерия «критичной» записи аудита

- **Эпик**: E-11 Админка I
- **Статус**: кандидат
- **Параллельность**: да: не меняет продуктовый код
- **Роль-исполнитель**: архитектор
- **Участники стадий**: ревью — владелец (утверждение)
- **Навыки**: Аудит, реестр событий

## 1. Результат
Владелец получил перечень кодов аудита, которые считаются критичными для блока дашборда (§26.1); после утверждения критерий становится правилом.

## 2. Источники
- Журнал: §26.1, §37 п. 15
- Спецификации: `docs/spec/40-admin/audit-log.md`, `docs/spec/00-registries/events-and-logs.md`

## 3. Границы и явно исключённое
- Входит: предложение по кодам реестра с обоснованием.
- Не входит: реализация признака (T-069, T-079).

## 4. Зависимости и что разблокирует
- Зависит от: нет
- Разблокирует: признак критичной записи в T-069 и T-079 после утверждения

## 5. Критерии готовности и способ проверки
1. Каждый код предложения есть в реестре событий — проверка: сверка.
2. Владелец утвердил — проверка: запись в журнале.

## 6. Доказательство результата
Проверки по критериям §5, вердикт ревью. Отчёт по ритуалу проекта (`docs/reports/`) с разделом «Как проверено».

## 7. Пометки
Задача заведена по решениям владельца в гейте блокеров 2026-09-26. Предлагает архитектор, утверждает владелец (§37 п. 15).
