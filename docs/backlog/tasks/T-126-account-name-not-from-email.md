## 1. Результат

Новый аккаунт создаётся без имени, производного от e-mail, а у существующих аккаунтов такие имена очищены; публичное имя задаёт сам пользователь до первой публикации.

Доработка по итогам независимого ревью 2026-09-26: T-013 (ALTE-36, PR #54); строка регистрации перенесена в T-022.

## 2. Источники

- ADR-0018 п. 3 («e-mail в хэндл, имя и адреса не попадает»); ADR-0004
- Журнал: §25.4
- Спецификации: `docs/spec/30-account/reader/profile-edit.md` (имя обязательно перед первой публикацией)
- Находки ревью: `docs/reports/2026-09-26-in-review-acceptance-report.md` (строка T-013)

## 3. Границы и явно исключённое

- Входит:
  - Регистрация не записывает в `name` локальную часть e-mail.
  - Миграция данных очищает имена, совпадающие с локальной частью e-mail своего аккаунта.
  - Публичные ответы (`user(handle)`, `AuthorProfile`, ленты) не показывают пустое имя как текст; вместо него — хэндл по правилам страницы автора.
- Не входит:
  - Экран правки профиля и проверка имени — T-031.
  - Закрытие публичного `user(handle)` — отдельная задача.
- Сохраняемый контракт: Поля публичных типов без ПДн (ADR-0018 п. 1); уникальность хэндла.

## 4. Зависимости и что разблокирует

- Зависит от: нет

## 5. Критерии готовности и способ проверки

- **AC-1**: регистрация по ссылке на `ivan.petrov@example.test` не создаёт имени `ivan.petrov`; проверка: серверный тест.
- **AC-2**: после миграции ни у одного аккаунта имя не равно локальной части его e-mail; проверка: тест миграции на PostgreSQL.
- **AC-3**: публичная страница автора без имени показывает хэндл, а не пустую строку и не e-mail; проверка: тест резолвера.
