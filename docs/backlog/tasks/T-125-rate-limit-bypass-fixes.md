## 1. Результат

Лимиты по адресу нельзя снять подставленным заголовком `X-Forwarded-For` или обойти повтором поля под алиасами в одном GraphQL-документе; утверждённый механизм T-024 (журнал §36 п. 3) работает как задуман.

Доработка по итогам независимого ревью 2026-09-26: T-024 (ALTE-100, PR #181); обход алиасами затрагивает и T-059.

## 3. Границы и явно исключённое

- Входит:
  - BFF берёт адрес клиента, добавленный доверенным прокси платформы, а не самый левый элемент `X-Forwarded-For` от клиента.
  - Исключение «loopback = системный вызов» убирается либо сужается до вызовов, которые `rate-limits.md` §3 называет системными (воркер, вебхук), с проверкой их происхождения.
  - Плагин считает каждое вхождение поля с правилом, а не уникальные имена полей; при превышении отклоняется весь документ.
  - Отчёт и receipt T-024, которых нет.
- Не входит:
  - Числовые пороги — T-116 (журнал §36 п. 1).
  - Неприменённые корзины (`account.mutation.user`, `media.upload.user`, `search.*`, `appeal.form.ip`) — отдельная задача по мере появления этих операций.
- Сохраняемый контракт: Код `RATE_LIMITED` с `retryAfter`, лог `rate_limit.hit`, текущие значения порогов `rate-limits.md`.

## 5. Критерии готовности и способ проверки

- **AC-1**: запрос через BFF с `X-Forwarded-For: 127.0.0.1` или случайным адресом попадает в корзину настоящего адреса клиента; проверка: тест BFF и серверный тест плагина.
- **AC-2**: документ с N алиасами `requestMagicLink` или `createSupportRequest` расходует N обращений корзины; проверка: тест плагина с алиасами.
- **AC-3**: системные вызовы из `rate-limits.md` §3 лимитом по адресу не ограничиваются, прочие loopback-запросы — ограничиваются; проверка: тест.
- **AC-4**: в `docs/reports/` есть отчёт T-024 и receipt `docs/reports/tasks/T-024.{json,md}`; проверка: файлы в `app`.
