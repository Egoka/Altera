## 1. Цель

У владельца есть одна карта инфраструктуры Altera: что работает сейчас, что требуют принятые
документы, как в них ложатся новые вводные (Kubernetes для всего, включая базу; два домена;
Cloudflare перед altera.com; российский CDN перед altera.ru), какие решения остаются за ним и
какие задачи из этого следуют. Для altera.com готова конфигурация кеширования Cloudflare как код,
которую можно применить после покупки домена и создания зоны. Для altera.ru есть сравнение
российских CDN с рекомендацией.

## 2. Контекст

- Прод в РФ, Neon только для разработки — ADR-0011; медиа в S3 РФ — ADR-0008; CDN перед медиа и
  404 после снятия — `docs/spec/85-media-and-binary/access-and-signed-urls.md`.
- `docs/vision/08-operations.md` §14 прямо исключает Kubernetes и CDN на старте — новая вводная
  владельца это меняет.
- Текущий хостинг: API на Render Free (Oregon), Neon Free (US East), фронтенд не опубликован —
  `docs/development/render-neon.md`. Dockerfile и манифестов развёртывания в репозитории нет.
- Сервер принимает один `FRONTEND_URL` и один `MAGIC_LINK_BASE_URL` (`server/env.example`,
  `server/src/server.ts`), поэтому два домена требуют правок кода.
- Выбор S3 обсуждается в этом же чате; Q-01 открыт.

## 3. Шаги

1. Прочитать документы об инфраструктуре: vision 02 и 08, ADR-0002, 0004, 0008, 0011, 0019,
   0023, спецификации наблюдаемости, медиа и бэкапов, журнал §21.21, §28, §29, эпик E-17,
   `render-neon.md`, конфигурацию CI, compose, Nuxt и сервера.
2. Проверить домены по whois.
3. Проверить по документации Cloudflare ограничения бесплатного плана: правила кеша, ключ кеша,
   обход кеша по cookie, очистку, Origin Rules, Tiered Cache.
4. Собрать карту `docs/infrastructure/README.md`: как есть, требования, новые вводные и конфликты
   с документами, целевая топология в Kubernetes, два домена, общие правила кеширования, решения
   владельца, задачи-кандидаты.
5. Описать Cloudflare для altera.com (`docs/infrastructure/cloudflare-altera-com.md`) и написать
   Terraform в `infra/cloudflare/`.
6. Сравнить российские CDN (исследование в параллельном агенте) —
   `docs/infrastructure/ru-cdn.md`.
7. Проверить Terraform (`terraform fmt -check`, `init -backend=false`, `validate`), форматирование
   репозитория (`pnpm format`).
8. Отчёт, коммит, pull request в `app`.

## 4. Критерии готовности

- **AC-1** Карта содержит состояние «как есть» с источниками, требования с источниками, целевую
  топологию и список решений владельца. Проверка: ревью файла.
- **AC-2** Каждый конфликт новых вводных с принятыми документами назван с номером документа и
  пункта. Проверка: ревью.
- **AC-3** Terraform Cloudflare проходит `terraform fmt -check` и `terraform validate` на
  провайдере v5. Проверка: команды с кодом выхода 0.
- **AC-4** Российские CDN сравнены по цене и функциям, у каждого факта есть источник или пометка
  «не проверено». Проверка: ревью.
- **AC-5** `pnpm format` проходит. Проверка: код выхода 0.

## 5. Что сознательно не входит

- Dockerfile, Helm-чарт, манифесты Kubernetes, workflow деплоя — это следующие задачи.
- Правки продуктового кода (`Cache-Control`, два сайта, очистка CDN).
- Запись новых решений в журнал и правка ADR — делает владелец или синхронизация по его поручению.
- Покупка доменов, создание зон, применение Terraform.

## 6. Риски

- Цены и функции провайдеров меняются. Снимаем датой проверки и ссылками на источники.
- Ограничения планов Cloudflare. Снимаем проверкой по актуальной документации.
- Утверждения о 152-ФЗ и трансграничной передаче — не юридическая консультация, помечаются как
  вопрос юристу.
