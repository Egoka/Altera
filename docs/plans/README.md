# Планы работ

Здесь лежит каждый план, по которому в проекте выполнялась работа. Папка обязательная:
работа по плану не начинается, пока план не сохранён сюда файлом.

У каждого плана есть парный отчёт в `docs/reports/` с тем же именем-слагом. Пара
«план + отчёт» позволяет позже восстановить, что задумывалось, что реально сделано и
каким коммитом.

## Имя файла

```
docs/plans/ГГГГ-ММ-ДД-краткое-имя.md
```

Дата — день создания плана, слаг — в нижнем регистре через дефисы, латиницей:
`2026-09-05-connect-web-to-api.md`.

## Шапка файла

Каждый план начинается блоком:

```markdown
# <Название плана>

- **Дата**: ГГГГ-ММ-ДД
- **Ветка**: server/api
- **Задача**: T-NNN | прямое поручение владельца
- **Authorization**: <статус `готова` и файл задачи | ссылка/цитата письменного поручения и границы>
- **Базовый коммит**: <полный SHA HEAD на момент создания>
- **Исходное дерево**: clean | dirty: <ссылка на diff и SHA-256 затронутых файлов>
- **Отчёт**: docs/reports/ГГГГ-ММ-ДД-краткое-имя-report.md (заполняется по завершении)
- **Статус**: черновик | утверждён | выполняется | завершён | отменён
```

Базовый commit и dirty fingerprint обязательны: одного HEAD недостаточно, если дерево изменено.
Прямое поручение владельца может разрешить этот конкретный план без создания или изменения
статуса задачи; его scope и authorization фиксируются явно.

## Содержание

1. **Цель** — что станет возможным после выполнения.
2. **Контекст** — почему сейчас, что уже есть в коде (со ссылками `файл:строка`).
3. **Шаги** — по порядку, каждый проверяемый.
4. **Критерии готовности** — список стабильных AC-ID с наблюдаемым результатом и способом
   проверки; переименование между run не сбрасывает историю.
5. **Что сознательно не входит** в этот план.
6. **Риски** и чем их снимаем.
7. **Стадии и handoff** — actor/run, вход и evidence каждой стадии; при остановке — branch/HEAD,
   dirty fingerprint, сделанное и остаток, решения, trace_ref, счёт неуспехов по `check_id`,
   причина и проверяемое условие возобновления.

План различает окончание run, результат стадии и приёмку задачи. Переход разрешён только по
актуальному evidence предыдущей стадии на проверяемой revision. Формат evidence —
`docs/development/artifact-contracts.md`.

Планы не редактируются задним числом. Изменилось решение — либо новый план, либо
явная запись «отклонение» в отчёте.
