## Что чиню

Доработка по итогам независимого ревью 2026-09-26 возвращённой T-058 (ALTE-105, PR #187).

1. **Открытый редирект `/offline?from=`** — `web/app/composables/useOfflinePage.ts:86,115`:
   проверка `startsWith("/")` пропускает `//evil.example` и `/\evil.example`, а
   `window.location.assign` уводит читателя на чужой хост и по кнопке «Попробовать снова», и по
   событию `online`.
2. **403 показывается страницей 500** — `web/app/error.vue`: всё, кроме 404, рисуется
   `ServiceServerError` с кодом запроса, хотя `middleware/admin*` отвечает 403 «нет доступа».
3. **`requestId` переиспользуется** — `web/app/error.vue:25`: `useState("service.requestId")`
   инициализируется один раз на SPA-сессию, и вторая ошибка показывает код первой.

## Шаги

1. Вынести из `useOfflinePage` чистую функцию разбора `?from=`: значение принимается только как
   путь своего источника. Разбор — правилами WHATWG (как у браузера), наружу отдаётся
   нормализованный путь. Отклоняются `//…`, `/\…`, схемы, управляющие символы и результаты,
   которые после нормализации снова становятся протокол-относительными.
2. `error.vue`: развести 404, 403 и 5xx. 403 получает свою страницу отказа в доступе
   (`components/service/Forbidden.vue`) без кода запроса; `serviceRequestId` перестаёт считать код
   для любого статуса ниже 500 (журнал §28.4 — код только для технического сбоя).
3. `error.vue`: серверное значение `requestId` из `useState` принадлежит одному отказу —
   экземпляр страницы забирает его при создании и отпускает после гидратации; следующая ошибка
   берёт свой код из отказа или остаётся без кода.
4. Ключи локалей `service.forbidden*` в `ru.json` и `en.json`.
5. Проверки: юнит-тесты разбора и обработчика ошибок (RED на baseline-коде подтверждается),
   Playwright на `/offline?from=` и на 403 из `middleware/admin`; полные `format`, `lint`, `test`,
   `typecheck`, `build`, прогон браузерных сценариев.

## Границы

- Service worker не входит (журнал §35 п. 3, этап 3).
- Сохраняемый контракт: маршруты `/offline`, `error.vue`, `no-store` только для 5xx
  (`web/server/plugins/error-cache-control.ts` не меняется).
- Пороги, провайдеры, продуктовые правила не задаются.

## Риски

- Новая страница 403 не заведена в реестре `docs/spec/00-registries/pages.md` — это вопрос
  хранителя документации, в отчёт идёт как остаток, реестр здесь не правится.
- Отмена `requestId` для клиентских статусов затрагивает и 410: он приходит не в `error.vue`
  (`publicFeed.ts`), поведение не меняется — проверяется существующими тестами.
