# Ограниченный запуск постоянных адаптеров

Прямое поручение владельца: завершить приёмку runtime, подключить постоянные Claude/Codex
adapters и сборщик результатов. Дополнение: сократить необязательные проверки и закончить запуск.

Результат этого прохода — два настоящих запуска через постоянные профили Multica, привязанные
к конкретной ревизии и native run, с наблюдением завершения процесса и записью результатов
фиксированной проверки в существующий gate. Это приёмка инфраструктуры запуска; продуктовые
задачи и полная автономия всей очереди требуют отдельного подтверждения.

1. Зафиксировать проверенные исходники adapter/collector/runtime и подготовить отдельные
   приватные registry, policy, snapshot и run directories для каждого запуска.
2. Выполнить стадию Codex с исходной моделью gpt-5.6-terra/medium. Проверить доступность
   контекста проекта и trace, получить настоящий native terminal outcome и trusted check receipt.
3. Выполнить стадию Claude с исходной моделью claude-opus-4-6/medium. Независимо проверить
   контекст проекта и trace; сопоставить результат с фактическими процессными доказательствами.
4. Сохранить исходные и новые настройки профилей, результаты проверок и ограничения приёмки.

Модель работает с read-only snapshot. Фиксированную проверку запускает внешний сборщик.
Текст ответа модели не является доказательством прохождения команды. Новые credentials,
замена моделей, доступ к секретам, запись в продукт, merge/deploy и включение всех autopilot
не входят в этот проход. Три существующих autopilot остаются на паузе до отдельной приёмки.

Browser runtime уже прошёл отдельную ограниченную проверку с настоящим Playwright (acceptance 8).
Её исходные доказательства сохраняются; они не заменяют native completion этих двух запусков.
Расширенная матрица восстановления, crash recovery и публикация продукта отложены по поручению
владельца сократить объём. Наблюдаемые ошибки сохраняются; повторный запуск их не стирает.
