# Совместимость native-конфигурации Multica

Дата: 2026-09-14. Baseline: `1ab094023da349de051f560420689a9e8d5b0118`.
Основание: поручение владельца исправить совместимость и запустить автономию.
Ветка `docs/agent-loop-autonomy`, основное дерево; пользовательский `pnpm-lock.yaml` вне scope.

## Решение и порядок

1. Добавить явную политику `codex-mcp-map-selected-v2`: из managed-блока переносить только
   `required_servers`, проверяя выбранные серверы прежними строгими validators. Остальные
   серверы не исполняются; каталог фиксирует количество исключённых серверов без их значений.
   Старый режим сохраняет прежнее поведение. Пустой выбранный roster запрещён.
2. В новом режиме учитывать глубину многострочных массивов вне managed-блока; маркеры внутри
   незакрытого массива/строки, дубликаты и неверный синтаксис остаются отказом. Лимит managed
   таблиц нового режима 32, общий лимит размера сохраняется.
3. Проверить регрессии, воспроизвести фактический generated config локально без запуска модели.
4. Закрыть предыдущую неуспешную попытку только по подтверждённому native terminal и
   достоверному отсутствию runtime; сохранить историю и ограничения gate.
5. Установить согласованное deployment, выполнить native canary, собрать terminal evidence.
   Включать очередь после доказанного полного прохода, не по одному успешному unit test.

## Критерии

- AC-1: v2 принимает реальную форму Multica и переносит только выбранные инструменты.
- AC-2: v1, проверки выбранных инструментов, границы filesystem и защита секретов сохранены.
- AC-3: постоянный адаптер проходит инициализацию; native outcome и acceptance записаны отдельно.
- AC-4: перед включением очереди проверены отсутствие дубликатов и сбор результата.

Scope: `scripts/agent-runtime`, `scripts/agent-loop`, их тесты, локальное deployment и парный
отчёт с evidence. Источники: operating-model, artifact-contracts, native-runtime-pilot.
Продуктовые изменения и публикация сообщений другим людям не входят в эту задачу.
