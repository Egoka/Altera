# Синхронизация задач T-001, T-002, T-005 с фактическим состоянием

- **Дата**: 2026-09-09
- **Ветка**: docs/platform-design
- **Базовый коммит**: 2f1f3ce
- **Отчёт**: docs/reports/2026-09-09-backlog-fact-sync-report.md (заполняется по завершении)
- **Статус**: завершён с отклонением

## 1. Цель

Файлы задач T-001, T-002 и T-005 перестают расходиться с кодом: закрытые критерии помечены со
ссылкой на выполненную проверку, незакрытые названы явно. Владелец принимает решение о статусе
`готова`, видя фактический остаток работы, а не исходную формулировку.

## 2. Контекст

Заход «честные проверки» (`docs/reports/2026-09-09-honest-checks-report.md`, коммиты 8dac22a и
2f1f3ce) выполнил часть T-001 и T-005 по прямому поручению владельца, а также, как выяснилось при
чтении, значительную часть T-002. Статусы задач при этом не менялись: `готова` ставит владелец.

Задача, чей файл описывает как предстоящую уже выполненную работу, нарушает §4.4 операционной
модели: критерий перестаёт быть проверяемым утверждением о будущем результате. Исполнитель такой
задачи начнёт делать сделанное.

Отдельно обнаружена нестыковка: T-005 объявляет «Зависит от: нет», но её критерий 2 проверяется
«curl после T-004». Критерий, не проверяемый до выполнения другой задачи, не удовлетворяет §4.4.
Изменение зависимости — продуктовое решение о scope, поэтому оно не вносится, а выносится
владельцу.

## 3. Шаги

1. В §5 каждой из трёх задач добавить блок «Фактическое состояние на 2026-09-09» с построчной
   разметкой критериев: закрыт / частично / не закрыт, со ссылкой на отчёт и на команду проверки.
2. В §7 «Пометки» добавить `[ФАКТ: ...]` со ссылкой на коммиты работы.
3. В T-005 добавить `[ВОПРОС ВЛАДЕЛЬЦУ]` о критерии 2 и зависимости от T-004. Зависимость и
   критерий не переписывать.
4. Подготовить запись для `docs/backlog/owner-blockers.md` и внести её только с разрешения
   владельца.
5. Статусы задач, `matrix.md` и `ready-candidates.md` не менять: перевод в `готова` — отдельное
   решение владельца по конкретной задаче.

## 4. Границы

Входит: разметка фактического состояния критериев в трёх файлах задач, вопрос владельцу.

Не входит: перевод задач в `готова`; изменение зависимостей, границ и критериев; правка
`matrix.md`, `ready-candidates.md` и раздела «Текущее состояние»; любая работа по продуктовому коду.

## 5. Проверка

- `grep` по трём файлам показывает блок фактического состояния и пометки.
- Статусы задач не изменились: `git diff` не содержит строк `- **Статус**:`.
- `pnpm format`, `pnpm lint`, `pnpm test` — код 0 (проверки не затронуты).
