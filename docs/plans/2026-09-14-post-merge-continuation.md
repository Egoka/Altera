# Продолжение очереди после merge

- Baseline: `85d3af44b20e4ddae6adc7f67cb87c8192d1d186`.
- Основание: запуск в 22:00 MSK завершился `busy` после merge PR #26, ссылаясь на ручной Done.
- Разрешение: ранее согласованное восстановление потерянных стадий и запуск полной цепочки; поручение владельца устранить текущую остановку.
- Scope: действующие инструкции Multica, операционные документы, восстановление текущего parent.

1. Сверить run, PR, обязательные стадии и активные исполнения.
2. Разделить закрытие исполнения и ручной native Done. После merge автоматически назначать
   недостающую приёмку/финализацию, а после подтверждения освобождать слот.
3. Сохранить настройки до изменения, применить уточнение с readback без изменения расписаний.
4. Возобновить текущий parent одним событием, проверить native run и продолжение очереди.
5. Опубликовать документы и парный отчёт через PR с обязательными проверками.

Merge сам по себе не доказывает приёмку. Условная фраза владельца «если всё готово — сливай»
не считается отказом от независимого ревью. Грязный checkout сохраняется; новая задача
получает отдельный чистый checkout от app, если прежний занят чужими правками.
