## 1. Что требуется

Аватар после базовой технической обработки применяется публично сразу, без ожидания проверки;
предыдущая версия сохраняется; рецензент возвращает её с записью аудита; удаление аватара даёт
инициалы; служебные записи аватара не имеют.

Критерии готовности из файла задачи (§5) и карточки ALTE-147:

1. После загрузки новый аватар виден гостю без ожидания проверки — проверка: e2e.
2. Откат ревьюером пишет запись журнала и возвращает предыдущую версию — проверка: тест.
3. Удаление аватара показывает инициалы; служебные записи остаются без аватара — проверка: тест.

Решения владельца: журнал §29.5 (аватар применяется сразу, предыдущая версия сохраняется, откат
рецензентом аудируется), §25.4 (аватар необязателен; проверка имени и аватара), §25.2 (служебные
записи публичного профиля не имеют), §33 п. 3 (числовые пороги конвейера утверждает владелец, до
утверждения загрузка пользователям не открывается). Спецификации:
`docs/spec/85-media-and-binary/avatars.md`, `docs/spec/30-account/reader/profile-edit.md` §4, §7,
`docs/spec/85-media-and-binary/upload-pipeline.md` п. 1–6, `image-variants.md` §3 (аватары — свой
набор квадратных размеров), `docs/spec/00-registries/access-matrix.md` #48, #120,
`docs/spec/00-registries/events-and-logs.md` #85.

## 3. Шаги

1. **Квадратный набор вариантов.** `AVATAR_VARIANT_WIDTHS = [64, 128, 256, 512]` в
   `media/limits.ts` с пометкой `[ДОПУЩЕНИЕ]` (`avatars.md` п. 3). `planVariants` и
   `thumbnailWidthFor` принимают набор ширин параметром, конвейер получает его через
   `MediaProcessingDeps.variantWidths`; по умолчанию — матрица статьи. Новой колонки «вид медиа»
   не заводится: назначение файла определяет связь в базе (`storage-layout.md` п. 3).
2. **Кадрирование.** `ImageProcessor.cropSquare(bytes, rect)` на `sharp`; квадрат задаёт автор
   (`x`, `y`, `size` в пикселях исходника), без аргумента берётся наибольший центральный квадрат.
   Кадр применяется до карантина, поэтому мастер аватара уже квадратный, а конвейер снимает с
   него EXIF и делает варианты обычным путём.
3. **Приём аватара** — `server/src/media/avatars.ts`: проверка размера и типа по содержимому,
   пороги `limits.ts` на исходнике, проверка прямоугольника кадра, приём в карантин и
   **синхронная** обработка тем же `runMediaProcessing`. Очередь здесь не нужна: «применяется
   сразу» (§29.5) означает готовую запись к ответу мутации, а отказ содержимого должен вернуться
   автору ошибкой, а не молчанием. Дедупликация по `sha256` в медиа статьи не должна подхватывать
   аватар — условие поиска исключает файлы, связанные как текущий или предыдущий аватар.
4. **Применение, удаление, откат** — `server/src/account/avatar.ts`: `prevAvatarId` получает
   прежний `avatarAssetId`; удаление ставит `deletedAt` записи и обнуляет обе связи
   (`avatars.md` п. 8); откат рецензента возвращает предыдущую версию, отвязанная запись
   становится сиротой (`retention-and-orphans.md`), `avatarCheckStatus` переходит в `rejected`,
   пишется `profile.check` (#85) с `verdict: reverted`. Служебная запись получает `FORBIDDEN`
   (§25.2), архивированная и ограниченная сессия — тоже.
5. **API** — `server/src/graphql/avatar/{schema.graphql,resolver.ts}`: `uploadAvatar(file, crop)`,
   `removeAvatar`, `revertAvatar(userId, reason)`; поля `AccountUser.avatar` и
   `AccountUser.previousAvatar`. Права: свои (`profile.update` #48), откат — `moderate`
   (матрица #120: `moderator`, `admin` `[ДОПУЩЕНИЕ]`, `owner`). Лимит `media.upload.user`
   применяется после прав (`permission-checks.md` §2 п. 3). Признак `MEDIA_UPLOAD_ENABLED`
   закрывает и эту точку входа (журнал §33 п. 3).
6. **Публичный показ.** `author(handle)` и каталог авторов берут адрес из вариантов записи
   аватара, `photoUrl` остаётся запасным для старых данных. Любое изменение аватара сбрасывает
   теги кеша `author:{handle}` и `home` — иначе «виден сразу» не выполняется.
7. **Проверки.** Юнит-тесты кадрирования и квадратного набора на настоящем `sharp`; тесты
   применения, удаления, отката и прав с двойниками; контракт схемы; e2e
   `web/tests/e2e/65-avatar.spec.ts` — автор загружает аватар, гость видит его на `/authors/{handle}`
   без участия рецензента (для этого сценария API поднимается с `MEDIA_UPLOAD_ENABLED=true`).
