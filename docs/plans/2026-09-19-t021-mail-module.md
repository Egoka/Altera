## Утверждённый дизайн

1. Синхронный mail-service: `MailMessage` и событие `queued` создаются одной вложенной записью
   Prisma (атомарно), затем вызывается транспорт и фиксируется `sent` либо `failed`. Используются
   модели T-019; очередь T-047 не задействуется.
2. Транспорты `smtp` (nodemailer; локально Mailpit из `docker-compose.yml`), `console` (письмо не
   доставляется, остаются только безопасные метаданные в логах сервиса), `fake` (тестовый, умеет
   падать). В production неявный `console` не подставляется.
3. Письмо входа отправляется через сервис из `requestMagicLink`. В истории — `sanitizedBody`, где
   ссылка заменена пометкой `[секрет не показывается]` / `[secret not shown]` `[ДОПУЩЕНИЕ]`.
   В логах нет адреса, темы и содержимого: только `mailId`, `template`, `status`, `provider`,
   `messageId`, `errorClass`.
4. Ошибка транспорта: история `failed` с классом ошибки, лог `mail.failed`, ответ
   `PROVIDER_UNAVAILABLE` с `provider: "mail"` и текущим `requestId`.
5. Не входит: GraphQL `adminMails` (T-080), реальный провайдер (Q-01), шаблоны/частота/согласия (F-05).
