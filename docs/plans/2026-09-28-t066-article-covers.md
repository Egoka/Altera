## 1. Что входит

1. Обложка — связь `Article.coverAssetId` с записью медиа; одна на материал, общая для языковых
   версий (ADR-0002): поле лежит на `Article`, а не на `ArticleTranslation`.
2. Фокусная точка обложки (`MediaAsset.focalX/focalY`) и кадрирование по ней под соотношения
   карточек лент; смена фокуса перегенерирует затронутые варианты (`image-variants.md` §2 п. 3, §5).
3. Подача без обложки → `VALIDATION_ERROR` (`article-covers.md` п. 2, `article-edit.md` §4).
4. Карточки лент показывают собственную обложку материала; дефолтных заполнителей у
   опубликованного материала нет (§29.1, `article-covers.md` п. 4).

## 2. Что не входит

- Правка обложки опубликованного материала без снятия с публикации — противоречие
  `article-covers.md` п. 5 с матрицей #19 (Q-12), явно исключено постановкой.
- `CoverUploader` в редакторе: страницы `/me/articles/{id}/edit` нет (T-040, который эта задача
  разблокирует), а загрузка файла через BFF `/api/graphql` сейчас идёт только JSON-телом —
  multipart в прокси не поддержан. Тем же порядком T-065 оставил загрузчик аватара задаче
  страницы (T-031). Эта задача отдаёт API и показ обложки, интерфейс загрузки — T-040.
- OG-вариант 1200×630 (`article-covers.md` п. 3 `[ДОПУЩЕНИЕ]`): без метатегов (T-100) он
  никем не читается, генерировать его заранее — хранить неиспользуемые объекты.
- Архив и удаление навсегда (п. 6–7): уже закрыты `storage/access.ts` и T-067/T-068.

## 3. Решения реализации

**Соотношения кадра.** `article-covers.md` п. 3 требует обрезку под `lede`, `large`, `small`
(`06-design-system.md` §5). Числа берутся из действующей вёрстки `web/app/components/article/Card.vue`:
`lede` — 2:1, `large` и `small` — 3:2. Два разных соотношения, а не три: `small` и `large`
совпадают, и по `image-variants.md` §2 п. 5 одинаковые кадры разного размера различаются
значением `sizes`, а не отдельными файлами. Метки кадра в наборе — `lede` и `large`.

**Фокусная точка** — доли стороны в `[0, 1]`, по умолчанию центр. Кадр считается ровно как
CSS `object-position`: `left = (W − w) · focalX`, `top = (H − h) · focalY`. Тогда предпросмотр в
браузере (`object-fit: cover` + `object-position`) совпадает с тем, что нарежет `sharp`, и
вторую реализацию той же арифметики на вебе заводить не нужно.

**Где считаются кадры.** Варианты-кадры собираются тем же шагом конвейера, что и базовые
(`media/variants.ts`), по списку меток в `VariantGenerationDeps.crops`. Обычное медиа кадров не
получает. Набор запоминает фокус, с которым нарезан: смена фокуса делает прежние кадры
негодными, и повтор пересоздаёт их, не трогая базовые варианты и мастер.

**Ключи вариантов-кадров** — `{год}/{месяц}/{assetId}/{метка}-w{ширина}.{формат}`: метка в ключе,
чтобы кадр и базовый вариант той же ширины не переписывали друг друга.

**Мутация.** `setArticleCover(articleId, assetId, focal)` ставит обложку и фокус и синхронно
доводит кадры до готовых: редактору нужен предпросмотр сразу, как аватару (журнал §29.5).
`assetId: null` снимает обложку у неопубликованного материала.

**Подача.** Проверка — в действующей мутации подачи `requestReview` (`submitTranslation` из
`article-edit.md` §4 появится с T-049): нет обложки или её запись не готова → `VALIDATION_ERROR`
с полем `cover`.

**Лента.** `FeedItem.cover` меняет тип со строки (наследие `articles.featuredImage`, которое
никто не заполняет) на `FeedCover { variants, alt }`. Карточка выбирает кадр по своему варианту
и строит `<picture>` через `MediaPicture`; `NuxtImg` из карточки уходит (ADR-0030 п. 2).
Заполнитель карточка показывает только по явному признаку — его ставит кабинет автора
(`article-covers.md` п. 4), ленты — никогда.
