## 1. Что требуется

Из мастер-файла создаются размытый заполнитель, thumbnail и адаптивные варианты в AVIF и WebP по
централизованной матрице; веб выводит их компонентом с `<picture>`, `srcset`/`sizes` и единым
`alt`; `/_ipx/` не используется.

Критерии готовности из файла задачи (§5):

1. Для тестового изображения созданы оба формата всех размеров матрицы — проверка: тест.
2. В прод-сборке нет запросов к `/_ipx/` — проверка: Playwright + grep.

Источники: журнал §29.4 (форматы AVIF и WebP), §29.10, §29.12 (матрица — отдельный проход),
§33 п. 2 (временная матрица — ширины ADR-0030), §33 п. 3 (числовые параметры предлагает
архитектор, утверждает владелец; до утверждения загрузка пользователям не открывается);
`docs/spec/85-media-and-binary/image-variants.md`; `docs/2026-09-09-media-upload-processing-notes.md`
п. 2–4; ADR-0030.

## 2. Что уже есть на baseline

- `server/src/media/` (T-063): приём в карантин, проверки содержимого, мастер без EXIF,
  статусы `uploading → queued → processing → ready`, задание очереди `media.process`,
  пороги в `limits.ts` с пометкой `[ДОПУЩЕНИЕ]`, признак `MEDIA_UPLOAD_ENABLED`.
- `server/src/storage/keys.ts`: `variantKey({ assetId, createdAt, width, format })` и
  `VARIANT_FORMATS = ["avif", "webp"]` — раскладка ключей вариантов уже описана.
- `server/src/storage/access.ts`: публичен только вариант готового медиа; мастер — нет.
  Значит у каждой готовой записи должен быть хотя бы один вариант, иначе показывать нечего.
- `server/prisma/schema.prisma`: `MediaAsset.variants Json @default("[]")` — колонка есть,
  пишущего кода нет; GraphQL-поле `variants: JSON!` отдаёт её как есть.
- `web/nuxt.config.ts`: `image: { provider: "none" }` (T-004) — `/_ipx/` уже не подключается;
  проверка провайдера закреплена `web/tests/image-provider.test.ts`. Своего компонента
  `<picture>` для пользовательских изображений нет: карточки выводят `NuxtImg` с адресом строкой.

## 3. Шаги

1. **Матрица.** Числа — в `server/src/media/limits.ts` рядом с существующими `[ДОПУЩЕНИЕ]`
   (один файл на все пороги конвейера): ширины 480/960/1440/2000 (журнал §33 п. 2), ширина
   заполнителя 48 (заметка владельца п. 2 — «начиная примерно с 48 × 48»), качество кодирования
   вариантов. Логика выбора — `server/src/media/variant-matrix.ts`: ширины не больше мастера
   (`image-variants.md` §5), thumbnail — наименьшая ширина матрицы, чтобы не вводить число,
   которого владелец не утверждал.
2. **Генерация.** Порт `ImageProcessor` получает `createVariant` и `createPlaceholder`,
   реализация — `sharp-processor.ts`. Шаг конвейера — `server/src/media/variants.ts`:
   идемпотентный проход по плану, уже существующие объекты не пересоздаются.
3. **Конвейер.** `runMediaProcessing` после мастера генерирует варианты и пишет их в запись
   (`MediaAssetStore.saveVariants`). Частичная ошибка сохраняет полученную часть набора и
   оставляет запись в `failed`; повтор доделывает недостающее, не трогая мастер
   (`image-variants.md` §2 п. 8).
4. **GraphQL.** `variants` отдаётся с публичными адресами вариантов: в базе лежат ключи
   (смена провайдера меняет домен, не ключи — `access-and-signed-urls.md` п. 9), адрес строится
   из `STORAGE_MEDIA_BASE_URL` при чтении.
5. **Веб.** `web/app/utils/mediaVariants.ts` — разбор JSON и сборка `srcset`;
   `web/app/components/media/Picture.vue` — `<picture>` с источником AVIF, запасным WebP,
   `sizes` от места использования, размытым заполнителем и единым `alt` из медиафайла.
6. **Проверки.** Тесты матрицы и конвейера на двойниках; тест на настоящем `sharp` — оба формата
   всех ширин матрицы (критерий 1); тесты утилиты и компонента в вебе; сценарий Playwright и
   grep по прод-сборке — запросов и ссылок `/_ipx/` нет (критерий 2).

## 4. Границы

- Входит: генерация вариантов и компонент вывода.
- Не входит: ручное AI-улучшение (F-04); черновик `alt` моделью (T-048); перевод карточек и
  страниц на медиа из базы (T-056, T-066); подписанные ссылки на медиа черновика в редакторе
  (`access-and-signed-urls.md` п. 5); кадрирование по фокусной точке и задание перегенерации
  (`media.update.meta`, `media.regenerate`) — отдельные задачи эпика.
- Числовые параметры остаются `[ДОПУЩЕНИЕ]` до утверждения владельцем (журнал §33 п. 3);
  загрузка пользователям по-прежнему закрыта признаком `MEDIA_UPLOAD_ENABLED`.
