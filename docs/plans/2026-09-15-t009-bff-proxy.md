# T-009: BFF-прокси GraphQL в Nuxt

- **Дата**: 2026-09-15
- **Ветка**: web/t009-bff-proxy
- **Задача**: T-009 / ALTE-18
- **Authorization**: native issue `01a0a229-4cb0-7411-825e-0cfca06ab26e`, поручение оркестратора
  `01a0a299-89ad-76a0-b664-427f47430356`; scope — Nitro-маршрут `POST /api/graphql`, приватный адрес API
  в `runtimeConfig`, composable, ограничение CORS и CSRF-заголовок; cookie-сессии исключены
- **Базовый коммит**: `741470846a5db8b28e8a77a70160a32b6fda4f1c`
- **Исходное дерево**: clean
- **Отчёт**: `docs/reports/2026-09-15-t009-bff-proxy-report.md` (заполняется разработчиком по завершении)
- **Статус**: утверждён

## 1. Цель

Создать единый same-origin вход в GraphQL для браузера и SSR: клиент вызывает только Nuxt
`POST /api/graphql`, а Nitro пересылает JSON-запрос в GraphQL Yoga по серверному адресу. Адрес
upstream не попадает в `runtimeConfig.public`, Nuxt payload или `.output/public`; BFF добавляет
обязательный заголовок CSRF Yoga. Решение сохраняет GraphQL Yoga и сгенерированный schema-first
контракт, не реализуя сессию из T-023.

## 2. Контекст и источники

- `docs/spec/00-registries/routes.md`, маршрут № 65: канонический адрес BFF — `POST /api/graphql`.
- `docs/backlog/tasks/T-009-bff-proxy-runtime-config.md`: два критерия задачи — браузерный
  `{ __typename }` через BFF и отсутствие адреса API в публичном бандле.
- `docs/decisions/ADR-0020-keep-graphql-yoga.md`: транспорт остаётся GraphQL Yoga, клиент должен быть
  минимальным и работать через BFF.
- `docs/decisions/ADR-0023-client-session-storage-bff.md`: браузер использует same-origin BFF,
  upstream URL остаётся серверным, Yoga требует защитный заголовок. Cookie, refresh/access rotation и
  Origin/Sec-Fetch-Site-проверка мутаций относятся к последующей сессионной работе и не реализуются здесь.
- `docs/vision/02-target-architecture.md` § 2, § 4.4, § 4.5: Nuxt владеет BFF/CSRF, API — резолверами и
  проверками прав.
- Фактический baseline: `server/src/server.ts` принимает GraphQL на `/`, включает
  `useCSRFPrevention()` и задаёт CORS через точный `FRONTEND_URL`; `web/nuxt.config.ts` пока не содержит
  `runtimeConfig`, а `web/server/` и GraphQL composable отсутствуют.
- Nuxt 4 регистрирует `server/api/*.post.ts` как method-specific API route; приватные ключи
  `runtimeConfig` доступны только серверу, если не размещены под `public`. Для server route конфигурация
  читается через `useRuntimeConfig(event)`: <https://nuxt.com/docs/4.x/guide/going-further/runtime-config>.
- H3 допускает проксирование, но прозрачный proxy переносит входные credentials; поэтому на этом этапе
  выбран буферизованный JSON-hop с явным allowlist заголовков: <https://h3.dev/utils/proxy>.

## 3. Архитектурное решение

### 3.1. Рассмотренные варианты

1. **Рекомендуется: JSON BFF с явным allowlist через `$fetch.raw`.** Nitro читает GraphQL JSON,
   отправляет его на фиксированный URL из приватного config и вручную передаёт только безопасные
   request/response headers. Это не переносит браузерные cookie и upstream `Set-Cookie` раньше T-023,
   позволяет сохранить HTTP status и GraphQL envelope и не раскрывает URL в ошибке.
2. **Прозрачный `proxyRequest`.** Короче и поддерживает streaming, но по умолчанию переносит входные
   `Cookie` и `Authorization`; для текущей границы пришлось бы тщательно фильтровать обе стороны. Streaming
   и multipart upload задачей не требуются, поэтому этот вариант отклонён.
3. **Прямой GraphQL-клиент браузер → API.** Отклонён: раскрывает адрес API, создаёт cross-origin контракт
   для каждого клиента и противоречит маршруту № 65 и ADR-0023.

### 3.2. Компоненты и интерфейсы

```text
browser / Nuxt SSR
        |
        | POST /api/graphql, JSON { query, variables?, operationName? }
        v
web/app/composables/useGraphQL.ts
        |
        v
web/server/api/graphql.post.ts
  - useRuntimeConfig(event).graphqlApiUrl
  - allowlist request headers
  - x-graphql-yoga-csrf: bff
        |
        v
server/src/server.ts (GraphQL Yoga, endpoint /, CORS FRONTEND_URL)
```

- `web/nuxt.config.ts` получает **приватный** ключ `runtimeConfig.graphqlApiUrl`. Ключ не помещается в
  `runtimeConfig.public`; runtime override — `NUXT_GRAPHQL_API_URL`. Значение — полный URL GraphQL endpoint,
  например локальный `http://127.0.0.1:4000/`; маршрут не дописывает пользовательские path/query fragments.
- `web/server/api/graphql.post.ts` существует только для POST благодаря суффиксу файла. Он принимает JSON
  object с обязательным непустым `query: string`, опциональными `variables` и `operationName`; неверный body
  получает безопасный HTTP 400 без вызова upstream.
- Upstream request всегда POST. BFF задаёт `content-type: application/json`, совместимый `accept` и
  `x-graphql-yoga-csrf: bff`. Из входного запроса разрешён только `authorization`, если он присутствует;
  `cookie`, `origin`, `host`, `x-forwarded-*` и произвольные браузерные headers не пересылаются. Это оставляет
  место access-token flow, но не реализует его хранение или обновление.
- Из upstream response BFF возвращает status, JSON body и `content-type`. Он не прокидывает CORS headers,
  `set-cookie` и hop-by-hop headers. GraphQL `data` и `errors` не преобразуются: HTTP 200 с `errors` остаётся
  GraphQL-ошибкой, а не локальным успехом.
- Отсутствующий/невалидный `graphqlApiUrl` даёт HTTP 500; сетевой отказ upstream — HTTP 502. Клиентский текст
  и response не содержат upstream URL. 4xx/5xx, полученные от Yoga, сохраняют status и безопасный GraphQL body.
- `web/app/composables/useGraphQL.ts` экспортирует типизированную функцию на базе
  `TypedDocumentNode<TResult, TVariables>`. Она сериализует document через `print` из `graphql`, вызывает
  относительный `/api/graphql` через `useRequestFetch()` и возвращает `ExecutionResult<TResult>`. Composable
  не читает private config и не принимает абсолютный endpoint. Он не бросает исключение только из-за поля
  GraphQL `errors`; transport errors `$fetch` остаются исключениями вызывающего кода.
- `server/src/server.ts` сохраняет `cors.origin = process.env.FRONTEND_URL`, `credentials: true` и только POST.
  Wildcard, отражение произвольного Origin и второй клиентский origin не добавляются. `FRONTEND_URL` в e2e
  равен адресу запущенного Nuxt.
- BFF route не кешируется: мутации и персонализированные ответы используют тот же endpoint. Кеш публичных
  SSR-страниц остаётся отдельным решением.

## 4. План реализации

### Шаг 1. Зафиксировать RED для приватной конфигурации и BFF-контракта

**Файлы:**

- создать `web/tests/e2e/graphql-bff.spec.ts`;
- изменить `web/playwright.config.ts`.

1. Настроить Playwright `webServer` на два foreground-процесса: GraphQL API на `127.0.0.1:4000` с безопасными
   test env и Nuxt на `127.0.0.1:4173` с `NUXT_GRAPHQL_API_URL=http://127.0.0.1:4000/`.
2. В браузерном контексте отправить `POST /api/graphql` с `{ "query": "{ __typename }" }` и ожидать
   HTTP 200, отсутствие transport error и `data.__typename === "Query"`. До реализации маршрут должен
   вернуть 404 — это ожидаемый RED `t009-bff-playwright`.
3. Через Playwright request context проверить CORS API: с `Origin: http://127.0.0.1:4173` ответ содержит ровно
   этот `access-control-allow-origin`; для постороннего Origin заголовок либо отсутствует, либо остаётся равным
   разрешённому Nuxt origin, но никогда не отражает постороннее значение и не становится `*`. Наличие
   `x-graphql-yoga-csrf: bff` отдельно проверяет targeted upstream-spy test из шага 2: успешный JSON POST сам по
   себе недостаточен как доказательство header, потому что non-simple content type тоже проходит CSRF guard.

### Шаг 2. Добавить private runtimeConfig и Nitro route

**Файлы:**

- изменить `web/nuxt.config.ts`;
- создать `web/server/api/graphql.post.ts`;
- при необходимости создать небольшой server-only helper в `web/server/utils/`, только если он нужен для
  независимого unit-теста валидации body/URL; не создавать общий client/server config module.

1. Добавить `runtimeConfig.graphqlApiUrl` вне `public`, с локальным non-secret default и runtime override
   `NUXT_GRAPHQL_API_URL` по соглашению Nuxt.
2. Сначала добавить targeted tests для валидации: missing/malformed URL, malformed body, upstream unavailable,
   GraphQL response со смешанными `data`/`errors`, обязательный `x-graphql-yoga-csrf: bff`, отсутствие forwarding
   для `cookie`/`set-cookie`.
3. Реализовать минимальный handler и явный header allowlist. Для `$fetch.raw` включить обработку non-2xx без
   автоматической потери upstream GraphQL body и явно перенести status на ответ BFF. Не логировать body,
   authorization или полный upstream URL.
4. Запустить targeted Vitest и `t009-bff-playwright`; RED должен перейти в GREEN без изменения критерия.

### Шаг 3. Добавить типизированный composable

**Файлы:**

- создать `web/app/composables/useGraphQL.ts`;
- создать `web/tests/useGraphQL.test.ts` либо расширить Nuxt runtime-test из шага 2.

1. Написать failing test со сгенерированным `TypedDocumentNode`: он проверяет относительный URL, POST body с
   напечатанной операцией и variables, а также возврат полного `ExecutionResult` с `data` и `errors`.
2. Реализовать `useGraphQL` без нового GraphQL client dependency и без ручного дублирования generated types.
3. Проверить типизацию операции с variables через `pnpm --filter nuxt-app run typecheck`; запрещены `any` и
   type assertions для обхода несовместимости.

### Шаг 4. Автоматизировать запрет утечки адреса API

**Файлы:**

- изменить `.github/workflows/pull_request.yml` в job `web-checks`.

1. Собирать web с уникальным не-секретным marker URL в `NUXT_GRAPHQL_API_URL`.
2. После build выполнять recursive fixed-string grep только по `web/.output/public`. Найденный marker — fail;
   отсутствие — pass. Не искать по всей `.output`: server bundle обязан содержать приватный runtime default.
3. Не выводить реальные deployment URL и env values в CI/evidence.

### Шаг 5. Полная проверка и handoff

1. Запустить targeted Vitest и Playwright для T-009.
2. Запустить `pnpm codegen --check`, `pnpm format`, `pnpm lint`, `pnpm test`,
   `pnpm --filter nuxt-app run build`, `pnpm --filter nuxt-app run typecheck` и
   `pnpm --filter nuxt-app run test:e2e`.
3. Повторить marker grep по `web/.output/public` на фактически собранной revision.
4. Создать `docs/reports/2026-09-15-t009-bff-proxy-report.md` с точными командами, exit code, числом сценариев,
   revision/dirty fingerprint, значимым выводом и ограничениями каждого check.
5. Передать тестировщику branch, полный HEAD, diff и evidence. Реализация не считается принятой до отдельной
   тестовой стадии и независимого review.

## 6. Что сознательно не входит

- httpOnly/Secure/SameSite cookie, refresh/access token lifecycle, rotation и logout — T-023;
- Origin/Sec-Fetch-Site policy для мутаций с cookie и CSRF token собственного BFF — T-023;
- изменение GraphQL schema, резолверов, permission checks или codegen pipeline;
- GraphQL batching, multipart upload/subscriptions и WebSocket proxy;
- кеширование GraphQL endpoint, retries мутаций, rate limits и observability;
- публикация frontend и изменение Render/Neon окружений.

## 7. Риски и меры

- **Утечка credentials прозрачным proxy.** Использовать явный allowlist; cookie и Set-Cookie покрыть
  отрицательными тестами.
- **Утечка server URL через config/error/bundle.** Ключ только private, клиент всегда использует relative URL,
  ошибки санитизируются, marker grep входит в CI.
- **GraphQL error ошибочно принят за успех.** Composable возвращает весь `ExecutionResult`; тест содержит
  envelope с `errors`, отчёт отдельно проверяет `data` и `errors`.
- **E2E случайно проверяет mock вместо API.** Playwright поднимает фактический `server/src/server.ts`; успешный
  `{ __typename }` проходит существующий Yoga CSRF plugin.
- **T-009 незаметно реализует часть T-023.** Cookie не пересылаются и не выставляются, token refresh отсутствует;
  будущая T-023 меняет эту границу отдельным планом и повторной security-проверкой.
- **Существующая общая проверка падает не из-за T-009.** Сохранить точный вывод и отличить inherited failure от
  регрессии; две подряд неудачи одного `check_id` останавливают стадию по общему контракту.
