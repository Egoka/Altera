## Цель

Одной командой запускать локальные PostgreSQL, Redis и Mailpit, а в руководстве дать серверу и вебу только локальные адреса зависимостей.

## Контекст

Сервер загружает dotenv при старте (`server/src/server.ts:1`) и требует `REDIS_URL` при импорте (`server/src/redis.ts:3-12`). `server/env.example` уже описывает нужные серверные переменные, но содержит несогласованные с Compose заглушки. В рамках T-003 продуктовый код не меняется. Mailpit соответствует локальному приёмнику с SMTP и веб-интерфейсом из `docs/vision/08-operations.md` §2 и ADR-0024; это не решение о production-провайдере.

## Шаги

1. Создать `docker-compose.yml` с именованным томом PostgreSQL, healthchecks и портами PostgreSQL, Redis, SMTP и веб-интерфейса Mailpit.
2. Согласовать `server/env.example` с локальными Compose-учётными данными; оставить только примеры и заглушки, без реальных секретов.
3. Создать `docs/guides/local-development.md`: запуск/остановка, копирование env, команды запуска server/web, GraphQL curl и адрес Mailpit; прямо зафиксировать, что письмо до T-021 остаётся в консоли.
4. Проверить конфигурацию через `docker compose config`, поднять сервисы, зафиксировать `docker compose ps`; запустить сервер против Compose, проверить POST GraphQL curl и остановить только созданные сервисы.
5. Выполнить обязательные repository checks и оформить отчёт с фактическим evidence.

## Критерии готовности

- **AC-1**: `docker compose up -d` поднимает ровно PostgreSQL, Redis и Mailpit; проверка `docker compose ps`.
- **AC-2**: `server` с примером локального окружения отвечает на POST `/` GraphQL-запросом `__typename`; проверка curl.
- **AC-3**: репозиторные `pnpm format:fix`, `pnpm lint`, `pnpm test` завершаются успешно.
- **AC-4**: руководство описывает запуск, локальные адреса зависимостей и ограничение почтового сценария до T-021.

## Что сознательно не входит

Прод-окружение, выбор production-провайдера почты, изменения GraphQL/почтового кода, миграции и подключение web к API.

## Риски

Порты могут быть заняты локальными процессами; перед запуском проверяются только нужные порты. Compose не гарантирует готовность схемы Prisma: для server dev в руководстве будет явно указан отдельный локальный шаг миграции. Mailpit не доказывает доставку, пока T-021 не добавит SMTP-транспорт.

## Стадии и handoff

Исполнитель создаёт конфигурацию, руководство и evidence на одной проверенной revision; независимый ревьюер принимает актуальный diff и отчёт. Если любая проверка дважды подряд неуспешна, работа останавливается с `check_id`, выводом и условием возобновления по `docs/multica/operating-model.md` §5.
