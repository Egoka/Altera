## Критерии готовности

- Все файлы из шагов 1–5 существуют, самостоятельны и не ссылаются на диалог.
- Каждый файл этапа содержит восемь обязательных разделов; каждый ADR — шесть разделов
  шаблона; каждый контур в `02` §4 описан по одному шаблону.
- Скрипт проверки относительных ссылок по `docs/**/*.md` и `CLAUDE.md` не находит битых
  ссылок; все упоминания `ADR-NNNN` указывают на существующие файлы.
- В `docs/vision` нет строк «на подтверждение», «шаг 3 промта», «ожидает ответов».
- `git status` содержит только документацию и `CLAUDE.md`; кода, миграций и задач нет.
- Отчёт содержит выполненные команды проверки и их результат.

## Что сознательно не входит

- Код приложения, миграции Prisma, сиды, конфигурация CI — всё это работа этапов роадмапа.
- Разбивка этапов на исполнительные задачи — только после отдельного подтверждения владельца.
- Переписывание README и публичных текстов — пункт этапа 1.
- Переписывание устаревших документов: только пометка «исторический».

## Риски

- **Объём**: около 50 файлов документации. Снимается порядком написания (сначала ADR как якоря,
  затем документы, ссылающиеся на них) и проверочным скриптом ссылок.
- **Расхождение документов между собой**: снимается таблицей владения темами (каждая тема
  описана в одном документе, остальные ссылаются) и списком решений, зафиксированным до
  написания.
- **Непроверяемые утверждения о законах и провайдерах**: помечаются `[ДОПУЩЕНИЕ]` со ссылкой
  на источник и гейтом «проверить перед этапом».
- **Хук pre-commit**: коммиты документации делаются с `--no-verify`, поскольку `pnpm lint` и
  `pnpm format` падают на состоянии веба; это фиксируется в отчёте.
