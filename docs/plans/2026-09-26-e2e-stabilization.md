# План: стабилизация браузерных проверок (2026-09-26)

Прямой запрос владельца. С 20.09.2026 PR сливаются в `app` автоматически по зелёному CI, поэтому
нестабильная джоба «Браузерная проверка веба» либо задерживает нужное, либо пропускает лишнее.

## Исходные данные

- 200 последних прогонов workflow «Checks»: 54 упали, 53 из них — в «Браузерной проверке веба».
- Разбор логов `gh run view --log-failed` и артефактов `playwright-artifacts` (trace, снимок, error-context).

## Шаги

1. Статистика: таблица «тест → сколько раз упал → на каких коммитах → текст ошибки»; отделить
   нестабильность от настоящих регрессий веток и волны одновременных слияний.
2. Первопричины по trace: порядок запросов, навигаций и гидратации.
3. Локальное воспроизведение на собственной базе `altera_e2e` в контейнере Postgres проекта
   (порт 25432), `--repeat-each` и разные `--workers`.
4. Исправление причин: детерминированное ожидание гидратации вместо повтора `pushState` до
   случайного совпадения адреса; ожидание запроса вместо мгновенной проверки счётчика. Баги
   продукта — отдельным коммитом.
5. Защита от повторения в CI: запуск workflow вручную (`workflow_dispatch`) и прогон новых и
   изменённых спеков с `--repeat-each`.
6. Доказательство: несколько подряд зелёных прогонов CI на ветке и многократный локальный прогон.
7. Отчёт в `docs/reports/`, слияние PR обычным merge-коммитом, удаление ветки.

## Ограничения

- Чужие изменения и ревью задач In review не трогаются.
- `test.fixme` и ретраи — только как временная мера с объяснением в отчёте.
