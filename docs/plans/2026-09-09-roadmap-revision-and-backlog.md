# Ревизия роадмапа и исполнительный бэклог Altera для Multica

- **Дата**: 2026-09-09
- **Ветка**: docs/platform-design
- **Базовый коммит**: 9066ba2
- **Отчёт**: docs/reports/2026-09-09-roadmap-revision-and-backlog-report.md (заполняется по завершении)
- **Статус**: завершён

## 1. Цель

После завершения фазы 2 (заходы 1–9, гейты Г1–Г9, журнал §24–§29) превратить утверждённые
решения, действующие спецификации и сознательно отложенные темы в последовательный, атомарный
и исполнимый бэклог, пригодный для чтения одной задачи без старого чата, для передачи между
стадиями (архитектура → разработка → тестирование → ревью → релиз) и для безопасного включения
автопилотов Multica после отдельного подтверждения владельца.

Проход **не** реализует продукт, **не** создаёт задачи в Multica, **не** включает автопилоты и не
меняет их роли.

## 3. Шаги

1. Этот план.
2. Скелет `docs/backlog/`: README (индекс и правила), шаблоны задачи и эпика,
   `owner-blockers.md` (Q), `future-stages.md` (F).
3. Эпики `docs/backlog/epics/E-NN-*.md` и атомарные задачи `docs/backlog/tasks/T-NNN-*.md`
   бесплатного запуска — по одному файлу, с десятью обязательными полями.
4. `matrix.md` (задача → роль → навыки → проверка → зависимости), `coverage.md` (решение / реестр /
   OPEN-QUESTIONS → T/E/F/Q), `ready-candidates.md` (первые кандидаты в готовые).
5. `docs/issues/00-roadmap.md` — ревизия 3; плашки на этапные файлы ревизии 2.
6. `docs/multica/operating-model.md`, `docs/multica/autopilot-checklists.md`; ссылка и правило в
   `CLAUDE.md`.
7. `docs/decisions/README.md` — указатель по строкам статуса; ADR-0045 — строка статуса;
   врезки «Расхождения с журналом Г1–Г9» в `docs/vision/*`.
8. Скрипт проверки ссылочной целостности и формата; отчёт ревизии; коммит без push.

## 4. Критерии готовности

- Все восемь результатов прохода существуют в репозитории и связаны ссылками.
- Скрипт проверки: 0 битых путей, 0 неразрешённых `T-/E-/Q-/F-`, 0 циклов зависимостей,
  0 задач со статусом «готова», у каждой задачи все обязательные поля.
- Каждое решение журнала (#1–59, §24–§29) и каждая тема §2 `OPEN-QUESTIONS.md` имеют строку в
  `coverage.md`.
- Отчёт с разделом «Как проверено» и списком блокеров владельца.

## 5. Что сознательно не входит

Реализация продукта; задачи в Multica; включение автопилотов; переписывание vision и ADR;
ADR-0047+; новые продуктовые правила, лимиты, цены, провайдеры; переоткрытие гейтов;
редактирование заметок владельца и untracked-файлов других сессий.

## 6. Риски и чем их снимаем

| Риск | Снятие |
|---|---|
| Задача «выглядит исполнимой», но ждёт решения | статус `решение владельца: Q-NN` обязателен, если в источниках есть «отложено» или `[ВОПРОС ВЛАДЕЛЬЦУ]` |
| Изобретение параметров при декомпозиции | в задачах только ссылки на спецификации; числа — только те, что есть в журнале |
| Битые ссылки на 156 файлов спецификаций | скрипт существования путей перед коммитом |
| Дубли между эпиками | `coverage.md` строится от источников, а не от задач: один источник → перечень задач |
