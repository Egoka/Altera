# Перестройка промта в готовые к копированию блоки

- **Дата**: 2026-09-13
- **Ветка**: docs/platform-design
- **Базовый коммит**: 134a2c7
- **Отчёт**: docs/reports/2026-09-13-design-prompt-copyable-report.md
- **Статус**: выполняется

## 1. Цель

Превратить `docs/prompts/altera-design-references.md` из документа, из которого нужно выбирать
куски, в набор **готовых блоков: выделил блок — вставил в Claude Design**. Порядок блоков равен
порядку сообщений в одном разговоре с дизайнером.

## 2. Контекст

- Сейчас файл (коммит `b488bea`, 730 строк) смешивает три несовместимых слоя: текст, который
  надо отдать дизайнеру; служебные ссылки на источники проекта; рассуждения о том, почему
  ограничение именно такое.
- Дизайнер не может открыть `docs/spec/20-public/home.md`, поэтому пометки `[ФАКТ: …]`,
  `[ДОПУЩЕНИЕ]` и пути внутри промта — шум для него и ценность для проекта. Их место —
  в комментарии рядом с блоком, а не внутри блока.
- Таблица подачи §0 описывает порядок словами («вставь §1 + §2»), то есть требует от владельца
  собирать сообщение вручную из разделов.

## 3. Шаги

1. Разделить файл на три части: **I — инструкция** (как пользоваться, что приложить),
   **II — промты** (только копируемые блоки), **III — справочник** (разборы референсов,
   реестр, источники, правила пополнения).
2. Каждый копируемый блок обернуть в ограждение, чтобы в просмотрщике была кнопка копирования;
   ограждение из четырёх обратных апострофов, чтобы внутренние одиночные не ломали разметку.
3. Из текста блоков убрать служебное: пути к файлам проекта, `[ФАКТ: …]`, `[ДОПУЩЕНИЕ]`, ссылки
   вида «§N». Внутри блоков ссылаться только на то, что дизайнер видит: номера промтов, имена
   артбордов, уровни границ.
4. Перед каждым блоком дать строку комментария: что это за промт, какие источники проекта за ним
   стоят, что приложить к сообщению.
5. Собрать состав блоков: контекст и границы; вывод медийных паттернов; вывод остальных
   паттернов; UI-кит; страницы группами; тёмная тема; обзор; приёмка.
6. Перенести без потери содержания всё, что было в §1–§7: продуктовые ограничения, границы трёх
   уровней, характер, токены, типографику, сетку, медиа, движение, доступность, стоп-лист, метод
   вывода паттернов, слоты, кит, страницы, референсы, приёмку.
7. Проверить: число промт-блоков, сохранность ссылок референсов, отсутствие путей проекта внутри
   блоков, сохранность всех артбордов `D1`–`D12`, `K1`–`K6`, `P1`–`P14`.

## 4. Критерии готовности

- Каждый промт лежит в ограждении и копируется целиком одним действием.
- Внутри ограждений нет путей `docs/…`, нет `[ФАКТ:`, нет `[ДОПУЩЕНИЕ]`, нет ссылок «§».
- Все 12 паттернов, 6 артбордов кита и 14 страниц на месте.
- 19 ссылок референсов сохранены.
- Трассируемость не потеряна: у каждого блока в комментарии названы источники проекта.

## 5. Что сознательно не входит

- Изменение содержания задания: состав паттернов, кита и страниц остаётся прежним, меняется
  только форма подачи.
- Продуктовые решения и правка спецификаций.
- Подготовка демонстрационного контента и изображений — отдельная задача.

## 6. Риски

| Риск | Чем снимаем |
|---|---|
| При перестройке потеряется часть содержания | Шаг 6 перечисляет всё переносимое поимённо; шаг 7 проверяет счётом артбордов и ссылок |
| Потеряется трассируемость к спецификациям | Источники выносятся в комментарий перед блоком, а не удаляются |
| Блоки станут несамостоятельными | Промты нумеруются как последовательные сообщения одного разговора; каждый начинается с напоминания о границах |
| Ограждение сломается о внутренние апострофы | Ограждение из четырёх обратных апострофов |
