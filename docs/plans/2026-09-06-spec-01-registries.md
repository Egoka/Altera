# Заход 1: реестры второй фазы

- **Дата**: 2026-09-06
- **Ветка**: docs/platform-design
- **Базовый коммит**: a3c3235
- **Отчёт**: docs/reports/2026-09-06-spec-01-registries-report.md
- **Статус**: завершён, ожидает гейт Г1 (отчёт — docs/reports/2026-09-06-spec-01-registries-report.md)

## 1. Цель

Восемь реестров в `docs/spec/00-registries/` и таблица компонентов рейтинга в
`docs/spec/60-ranking/README.md` — полные, построчные, в статусе «на утверждении», чтобы
владелец мог утвердить или вычеркнуть каждую строку (гейт Г1), а заходы 2–9 работали только с
утверждёнными строками.

## 2. Контекст

Основание ревизии 2 принято заходом 0 (коммиты `31ec4ed`…`a3c3235`): ADR-0034…0046,
`docs/vision/01,02,04,06,07` целиком и `03,05,08` по разделам, роадмап 0–5. Карта маршрутов —
`06-design-system.md` §5, матрица прав — `04-roles-and-access.md` §2, разделы админки —
`02-target-architecture.md` §4.3, планы — `07-commerce.md` §2, события — ADR-0032, ADR-0027,
`04-roles-and-access.md` §5. Колонки реестров — `docs/spec/00-registries/README.md`; колонки не
меняются.

## 3. Шаги

1. `routes.md` — все маршруты: публичные, кабинет, админка, инфраструктура, dev.
2. `pages.md` — одна строка на страницу (30–40).
3. `admin-sections.md` — разделы админки, включая предложенные сверх обязательных.
4. `access-matrix.md` — роль × действие × данные (80–120 строк).
5. `events-and-logs.md` — скелет событий, логов, ошибок с правилами кодов.
6. `plans.md` — free, standard, pro, грант, промокод.
7. `flows.md` — пользовательские маршруты (8–12).
8. `roles.md` — восемь строк.
9. `60-ranking/README.md` — таблица компонентов рейтинга.
10. Проверка: уникальность номеров, заполненность колонок, существование путей к шаблонам и
    ADR; отчёт; коммит; остановка на Г1.

## 4. Критерии готовности

- Ни одной пустой ячейки, кроме статуса строк, зависящих от владельца (`(В?)`).
- Каждая строка имеет путь будущего файла по карте `docs/spec/README.md`.
- Номера уникальны внутри реестра.
- Предложенные сверх обязательного разделы и страницы отмечены и обоснованы в отчёте.

## 5. Что сознательно не входит

- Сами спецификации (заходы 2–9); каталог блоков (отдельный проход).
- Оценки, приоритеты, порядок работ.

## 6. Риски

- Реестр окажется неполным — снимается правилом «новая строка по ходу заходов добавляется в
  статусе черновик и попадает в отчёт».
- Слишком много строк для построчного утверждения — группировка по типу и этапу в таблицах,
  чтобы владелец мог утверждать блоками.
