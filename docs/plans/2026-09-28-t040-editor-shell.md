# T-040: обвязка редактора `/me/articles/{id}/edit` — план

- **Дата**: 2026-09-28
- **Задача**: T-040 / ALTE-151, эпик E-07 «Кабинет автора и обвязка редактора»
- **Источник**: `docs/backlog/tasks/T-040-editor-shell.md`
- **Спецификации**: `docs/spec/30-account/author/article-edit.md`,
  `docs/spec/85-media-and-binary/article-covers.md`; журнал §6.7, §25.3, §25.6, §29.1, §41;
  ADR-0001, ADR-0007, ADR-0017, ADR-0029, ADR-0033
- **Baseline**: `origin/app` `a990b782d335512dff12212042f064a7b5d22e4f`
- **Ветка**: `web/t040-editor-shell`, рабочее дерево `.worktrees/t040`

## 1. Что входит

Обвязка редактора языковой версии — первый писатель, который работает от
`ArticleTranslation`, а не от наследной строки `articles`.

1. **API версии**: `translation(id)`, `saveTranslation(id, baseRevisionId, patch, kind)` с
   `CONFLICT` на устаревшей базовой ревизии (ADR-0033), `submitTranslation`,
   `withdrawTranslation`, `revisions`, `restoreRevision`, `setTaxonomy`, `setSlug`
   (`article-edit.md` §4, §7).
2. **Страница** `/me/articles/{id}/edit`: верхняя панель со статусом и индикатором сохранения,
   баннер состояния, метаданные (заголовок, лид, обложка, рубрика, формат, теги), область
   блоков, боковая панель (ревизии, SEO, проверка), липкие действия на телефоне
   (`article-edit.md` §5, §6, §9).
3. **Автосохранение** каждые 10 с при изменениях, ручное сохранение снимком, диалог конфликта
   «открыть свежую / сохранить копию как ревизию» (§4, §8).
4. **Подача на проверку** с проверками обязательных полей (рубрика — §25.3; обложка — §29.1;
   заголовок и текст) и отзыв (§7).
5. **Режим чтения** по `readOnlyReason`: истёкший план, `rejected`, `ai_check`, `in_review`,
   архив (§4, §8).
6. **Обложка из редактора**: `CoverUploader` поверх `uploadMedia` T-063 и `setArticleCover`
   T-066; для этого BFF `/api/graphql` учится пропускать `multipart/form-data`.
7. **SEO-поля**: описание и слаг до первой публикации (§5 зона 5).

## 2. Что не входит

- **Состав блоков** и их интерфейсы — T-041 и проход `docs/spec/95-blocks/` (Q-02, ADR-0017).
  Область блоков здесь — контейнер `BlockCanvas` над документом `@altera/content`: абзацы
  правятся как текст, каталог узлов и панель вставки придёт отдельным проходом. Прямо
  исключено постановкой.
- **Переходы статусов после подачи** — T-049: подача переводит версию в `review`, как это уже
  делает `requestReview`. Ветка AI-проверки (`ai_check` → автопубликация или ручная ветка)
  принадлежит T-049 и T-048; редактор только показывает состояние `ai_check` режимом чтения.
- **Правка опубликованной без снятия** (`saveTranslationPublished`, журнал §41) — T-122.
- **Вторая языковая версия** (`createTranslation`, `regenerateTranslation`, §7 спецификации) —
  F-09 / T-046. Переключатель языковых версий показывает существующие версии и не создаёт новых.
- **Панель проверки** с вердиктом и историей, заметки рецензента к блокам и `resolveReviewNote`
  — `review-history.md` и §25.6 закрываются задачами панели проверки; вкладка «Проверка» здесь
  показывает состояние версии и ссылку на историю.
- **Сравнение версий, AI-перевод** (F-09), **вход по `?token=`** из письма о снятии на доработку
  (`routes.md` #68) — письма отложены журналом §34 и §25.13.

## 3. Решения реализации

### 3.1. Наследная строка `articles` и trigger `t015_sync_legacy_article`

Trigger синхронизирует `article_translations` из `articles` при записи в `title`, `slug`,
`dek`, `body`, `excerpt`, `featuredImage`, `status`, `publishedAt` и сам заводит ревизию. Пока
API писал только в `articles`, это работало. Редактор пишет в языковую версию, и любое
последующее обновление `articles.status` (архив из кабинета, `setArticleStatus` админки)
перезаписало бы текст автора наследными значениями.

Решение: миграция добавляет в функцию trigger проверку параметра сеанса
`altera.legacy_sync`. Писатель «от языковой версии» ставит `SET LOCAL "altera.legacy_sync" =
'off'` внутри своей транзакции и сам держит наследную строку в согласии с версией — пишет в
`articles` те же `title`, `dek`, `excerpt`, `body`, `status` и не плодит вторую ревизию. По
умолчанию параметр не задан и trigger работает как раньше.

`articles.body` — строка, и зеркало кладёт туда сериализованный документ. Так стороннее
срабатывание trigger (например, из `archiveArticle`) вернёт документ без потерь: функция
`t020_legacy_body_to_document` разбирает строку, которая сама является документом каталога.
Плоский текст на его месте терял бы заголовки и изображения.

Зеркало ведётся только для версии исходной локали (`article.sourceLocale`): наследная строка
одна на материал, второй языковой версии в ней места нет (F-09).

### 3.2. Конфликт ревизий

`saveTranslation` сравнивает `baseRevisionId` с последней ревизией версии. Расхождение —
`CONFLICT` с `entity: "revision"`, `expected` — идентификатор свежей ревизии, `actual` —
присланный. Редактор по `expected` предлагает открыть свежую версию или сохранить свой текст
копией: «сохранить копию как ревизию» делает обычное сохранение от свежей базовой ревизии.

### 3.3. Автосохранение

Каждые 10 с при наличии изменений (`article-edit.md` §4 `[ДОПУЩЕНИЕ]`), не чаще; ручное
сохранение — по кнопке, с пометкой `manual`. Пустое изменение сохранение не запускает. Офлайн
— черновик остаётся в форме, баннер сообщает об отсутствии сети, попытка повторяется на
следующем тике.

### 3.4. Маршрут

`{id}` — идентификатор языковой версии (`article-edit.md` §3, `routes.md` #36). Каталог
страниц `web/app/pages/me/articles/[slug]` переименовывается в `[id]`, ссылки кабинета и
переход после создания черновика ведут на `translation.id`.

### 3.5. Загрузка файла через BFF

`uploadMedia` принимает файл multipart-запросом GraphQL. Маршрут `/api/graphql` читает тело
как JSON, поэтому обложку из браузера сейчас загрузить нельзя (это отмечено планом T-066).
Маршрут учится: при `content-type: multipart/form-data` сырое тело уходит наверх как есть с
тем же заголовком, токен доступа подставляется из cookie, проверка происхождения мутации
сохраняется, добавляется заголовок `x-graphql-yoga-csrf`.

### 3.6. Справочник рубрик и форматов

`sections`/`formats` закрыты правом `taxonomy`. Редактору нужен свой перечень: запрос
`authoringTaxonomy` отдаёт действующие рубрики с описанием и форматы автору и `editor`.
Архивированная рубрика в перечень не попадает, но у материала остаётся видимой как выбранная.

## 4. Порядок работы

1. Миграция параметра `altera.legacy_sync` и её тест на настоящей базе.
2. Серверный модуль `server/src/translation/editor.ts` и модуль GraphQL
   `server/src/graphql/translation/`.
3. Тесты сервера: конфликт, подача без обложки, режим чтения, права, ревизии.
4. BFF multipart и его тест.
5. Операции GraphQL веба, codegen.
6. Страница и компоненты редактора, i18n ru/en.
7. Тесты веба: состояния баннера, конфликт, блокировка подачи.
8. Playwright `web/tests/e2e/40-editor-shell.spec.ts`: конфликт двух вкладок и строки
   состояний §8.
9. Общие проверки: `pnpm format`, `pnpm lint`, `pnpm codegen --check`, `pnpm test`,
   `pnpm --filter server run build:ci`, `pnpm --filter nuxt-app run build`, `typecheck`.
