# Подготовка штатного Autopilot Multica

Дата: 2026-09-14. Baseline: `fb6a43cfb7cc30663e613ff2d232f8ba4784f0d4`.
Основание: владелец согласовал штатные runtime и ALTE-10, затем поручил настроить всё,
оставив включение автопилотов за ним. Эта работа не запускает агентов/автопилоты.

## Изменения

1. Сохранить безопасный snapshot настроек; проверить отсутствие активных run.
2. Вернуть тестировщика на штатный Codex, ревьюера на штатный Claude с прежними моделями,
   effort и concurrency=1. Отключить экспериментальные профили, архивировать непотреблённый
   ticket ALTE-11 и освободить только его gate slot. ALTE-11 отменить, сохранив историю.
3. Выделить `.worktrees/autopilot` на ветке `codex/autopilot-start` от подготовленного HEAD;
   направить local_directory проекта туда в режиме in_place. Основное дерево и личный
   незакоммиченный lockfile не изменять. Рабочую ветку текущей сессии сохранить.
4. Обновить описание проекта и инструкции запуска: штатный native режим, без заявления
   принятой OS-изоляции/collector-gate, один implementation parent, независимое review,
   остановка после двух неуспехов. ALTE-11 исключить из восстановления.
5. ALTE-4 закрыть только после сверки независимого принятого review и неизменности пяти
   целевых спецификаций. Обновить repo metadata с сохранением источников.
6. ALTE-10 сделать единственной Todo без запуска: сохранить AC T-001, заменить устаревший
   перечень отсутствующего актуальным исходным состоянием и требованием свежих CI evidence.
7. Сохранить расписания, all paused, отсутствие новых run; подготовить зависимости checkout
   и проверить format/lint/tests. Записать парный отчёт и простую инструкцию включения.

## Приёмка подготовки

- AC-1: два агента используют online штатные runtime, модели/роли сохранены.
- AC-2: единственная Todo — ALTE-10; ALTE-4 принят по существующему evidence; ALTE-11 исключён.
- AC-3: отдельный checkout содержит все инструкции; основной user diff сохранён.
- AC-4: три autopilot paused, расписания сохранены, новые run не создавались.

Это принятие конфигурации перед стартом. Сквозное выполнение реальной задачи и фактическая
защита от параллельного dispatch проверяются после включения; их здесь нельзя объявлять passed.
