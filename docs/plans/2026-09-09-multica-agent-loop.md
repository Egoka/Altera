# Автономный цикл Multica: доступ к коду, очередь, лёгкий конфиг

- **Дата**: 2026-09-09
- **Ветка**: docs/platform-design
- **Базовый коммит**: 82e1abd
- **Отчёт**: docs/reports/2026-09-09-multica-agent-loop-report.md (заполняется по завершении)
- **Статус**: утверждён

## 1. Цель

Проект Multica «Altera» (`1ff3917d-4c10-4303-a671-406c1fda9613`) выполняет цикл
Perceive → Reason → Act → Observe без ручного перезапуска на каждом шаге: у агентов есть
рабочий доступ к коду, очередь непуста, контекст запуска соответствует состоянию репозитория,
а конфигурация ролей не содержит устаревших фактов и разбора прошлых инцидентов.

## 2. Контекст

Владелец 2026-09-09 попросил пройти весь workspace Multica (`squads`, `agents`, `skills`,
`autopilots`, `projects`, `issues`) и перенастроить окружение под практики Agent Loop.
Обход показал, что сквад, десять агентов, тридцать один навык и три автопилота созданы и
содержательно написаны, а цикл стоит по четырём причинам.

**Act невозможен.** Ресурс проекта «Исходная рабочая папка Altera»
(`/Users/egorbondarenko/WebstormProjects/Altera`) отдаёт «Local daemon isn't reporting an ID yet
— the agent can't open this directory» и отрисован приглушённым; `Settings → Repositories` пуст,
GitHub не подключён. Рабочего доступа к коду нет ни одним путём.

**Perceive читает устаревшее.** Описание проекта — срез 2026-09-05 (`server/api`, `e1b9a97`) —
раздаётся «as context for every run» и утверждает «no tests», хотя тестов сейчас 24
(`server/tests/`, `web/tests/`). Промпт разработчика отдельно утверждает, что у `web` и `server`
нет `test` скриптов; они добавлены сегодня (`server/package.json`, `web/package.json`).
Во всех промптах стек назван «Express 5», тогда как сервер — Yoga поверх `node:http`
(`server/src/server.ts`).

**Очередь пуста.** 112 задач лежат файлами в `docs/backlog/tasks/`; доска Multica: Backlog 0,
Todo 0, In Progress 0. Автопилот «очередь разработки» берёт только задачи в статусе `Todo`
и не имеет права их создавать, поэтому даже включённым делает тихий no-op. Ни один из трёх
автопилотов ни разу не запускался.

**Observe не закрывается.** `ALTE-2` и `ALTE-3` висят в `In Review` с 5 сентября, хотя работа
по ним выполнена: `ebb0305` — предок текущего `HEAD`. Оркестратор отработал по `ALTE-2` девять
запусков со статусом «Succeeded», не сдвинув состояние.

Дополнительно: инструкции сквада 9 875 символов, промпт оркестратора 9 257, из них около 2 000 —
дословно продублированный разбор инцидента маршрутизации `ALTE-2` и особенности `CLI v0.4.40`
(установлена v0.4.42); в постоянный системный промпт вшит инвариант одной задачи. Число попыток
в Multica — три, в `docs/multica/operating-model.md` §5 — две.

## 3. Шаги

1. Привести `CLAUDE.md`, `docs/multica/operating-model.md` §7 и `.claude/settings.json`
   к разрешению от 2026-09-05; отметить фактическое состояние в
   `docs/multica/autopilot-checklists.md`.
2. Запушить `docs/platform-design` в origin, открыть pull request в `app`; слияние вынести
   владельцу отдельным подтверждением.
3. Подключить репозиторий в `Settings → Repositories`; убрать неработающий ресурс локальной
   папки из проекта.
4. Переписать описание проекта Multica по фактическому состоянию с датой среза и коммитом.
5. Завести свойство `Задача бэклога` и семь issue по готовым задачам; T-110 в `Todo`,
   остальные в `Backlog`; закрыть `ALTE-2` и `ALTE-3`.
6. Создать навык `altera-project-rules` и подключить его всем десяти агентам; сократить
   инструкции сквада и промпты ролей, убрав из них то, что живёт в репозитории, и устаревшие
   факты; привести число попыток к двум.
7. Почистить навыки и назначения MCP; заполнить `Settings → Profile → About you`.
8. Включить автопилоты по одному: актуальность контекста → очередь разработки →
   восстановление работы.
9. Перевести T-110 в `Todo` и наблюдать первый запуск.

## 4. Критерии готовности

- `pnpm format:fix && pnpm lint && pnpm test` — три нуля, 24 выполненных теста.
- `git ls-remote --heads origin docs/platform-design` возвращает ветку; PR открыт.
- Ресурс GitHub в проекте активен, ресурс локальной папки удалён.
- Доска: `Todo` — ровно T-110, `Backlog` — шесть, `In Review` — пусто, `Done` — две.
- Ни в одном промпте не встречаются `ALTE-2`, `server/api`, `Express 5`, `v0.4.40`,
  «трёх попыток» — проверяется чтением каждого поля после сохранения.
- После перевода T-110 в `Todo` появляется run назначенного агента и комментарий с
  результатом, ревизией и выполненными проверками.

## 5. Что сознательно не входит

- Слияние pull request в `app` — отдельное подтверждение владельца.
- Перенос остальных 105 задач бэклога в Multica.
- Машинная проверка счётчика попыток: правило остаётся текстовым.
- Эндпоинт `/health` и проверка связности с Redis (эпик E-13).
- Облачные рантаймы: цикл живёт, пока включён MacBook-Air-Egor.local.

## 6. Риски

| Риск | Чем снимаем |
|---|---|
| Агенты получают чекаут без сегодняшней работы | PR открывается до подключения репозитория; до слияния очередь держится на одной документной задаче |
| Снятие гейта на push и merge расширяет радиус ошибки | условия выпуска в §7 сохраняются: релиз-инженер, независимое ревью актуальной ревизии, план восстановления |
| Сокращение промптов теряет полезное правило | сокращаемое не удаляется, а переносится в навык `altera-project-rules`, который читают все роли |
| Три автопилота, включённые разом, дают конкурирующие запуски | включение по одному, очередь — только после наблюдаемого первого запуска |
