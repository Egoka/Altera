# Пакет промтов фазы 2: перебазирование основания и поштучные спецификации

- **Дата**: 2026-09-06
- **Ветка**: docs/platform-design
- **Базовый коммит**: c328133
- **Отчёт**: docs/reports/2026-09-06-phase-2-prompt-package-report.md

## 1. Цель

После выполнения в репозитории лежит всё, что нужно, чтобы запустить вторую фазу
проектирования по заходам: промт перебазирования основания под ревизию 2 продуктовых рамок,
программа заходов с гейтами владельца, каркас `docs/spec/` с шаблонами и описанием реестров,
промт первого захода (реестры) и шаблон промтов остальных заходов. `CLAUDE.md` отражает
ревизию 2, чтобы ни одна следующая сессия не проектировала поверх отменённых решений.

## 2. Контекст

Первая фаза (2026-09-05, коммиты `8cedcc9`…`c328133`) дала `docs/vision/00..08`,
ADR-0001..0033 и роадмап, но глубина легла неравномерно: модель данных — 992 строки, карта
маршрутов — 23 строки (`docs/vision/06-design-system.md:105-127`), админка — 18 строк
(`docs/vision/02-target-architecture.md:142-159`), кабинетов по ролям нет. Владелец ждал
поштучной проработки. Причина — промт первой фазы (`docs/prompts/fable-platform-design.md`):
«главный результат — роадмап», «один файл на контур», давление на сокращение, оценки.

Сегодня владелец дал видение, которое отменяет основание ревизии 1: подписка определяет роль
(free/standard/pro), выдача рейтинговая с pro-бустом на сутки, одна лента без витрины, донатов
нет, платежи в первом этапе, AI-проверка каждой статьи, чтение бесплатно с зарезервированным
paywall, роль `analyst`, закладки, ориентир The Atlantic. Расхождения с документами проверены
построчно (см. `docs/prompts/fable-rebase-2026-09-06.md`, раздел 1).

## 3. Шаги

1. `CLAUDE.md`: раздел «Продуктовые рамки» → ревизия 2; `spec/` в структуре; правило о
   спецификациях; строка в «Что сломано» о незавершённом перебазировании.
2. Плашка «Исторический документ» на `docs/prompts/fable-platform-design.md`.
3. Каркас `docs/spec/`: `README.md`, `_templates/{page,admin-section,flow,role,ranking,policy}.md`,
   `00-registries/README.md` (колонки восьми реестров и правило полноты), `95-blocks/README.md`.
4. Промты: `docs/prompts/fable-rebase-2026-09-06.md` (заход 0), `docs/prompts/phase-2-program.md`
   (программа и общий блок правил), `docs/prompts/fable-spec-01-registries.md` (заход 1),
   `docs/prompts/fable-spec-NN-template.md` (шаблон заходов 2–9).
5. `docs/README.md`: папки `spec/` и `prompts/` в индексе.
6. Проверка ссылок и слов-маркеров, отчёт, коммиты.

## 4. Критерии готовности

- Все пути, упомянутые в новых файлах, существуют в репозитории.
- В разделе «Продуктовые рамки» `CLAUDE.md` слова «контур», «витрина», «арбитр», «без
  алгоритмов» встречаются только в пометке об отмене ревизии 1.
- Каждый шаблон в `_templates/` содержит все разделы, на которые ссылается общий блок правил
  (минимальные объёмы, обязательные строки состояний).
- Промт перебазирования содержит пакет вопросов владельцу и гейт Г0 до ревизий vision.
- `git status` перед коммитом: staged только файлы этого плана; чужие незакоммиченные файлы
  (`.design-sync/`, `docs/plans|reports/2026-09-06-design-sync-tokens*`, `.gitignore`) не
  затронуты.

## 5. Что сознательно не входит

- Само перебазирование `docs/vision/`, ADR и роадмапа — это заход 0 для Fable по промту.
- Промты заходов 2–9 поимённо — собираются из шаблона после утверждения реестров (гейт Г1).
- Каталог блоков конструктора — отдельный проход по слову владельца.

## 6. Риски

- Сессия перебазирования прочитает старые «Продуктовые рамки» из `CLAUDE.md` и получит
  противоречие с промтом — снимается шагом 1, который выполняется первым.
- Шаблоны окажутся слишком тяжёлыми для реальных страниц (120+ строк на каждую) — снимается
  правилом «пустой раздел = одно предложение с обоснованием», а не пропуск.
- Ответы на вопросы захода 0 изменят состав реестров — поэтому реестры (заход 1) идут только
  после гейта Г0.
