## Что уже есть и чего нет

Каталог авторов (T-055) выдаёт публичный тип `CatalogAuthor` без e-mail, роли и плана, а лента
рубрики и тега живут в `feed(scope:)`; в `feed/schema.graphql` прямо записано, что лента автора
получит своё значение в T-057. Хроника по месяцам с однорядными раскладками ритма автора
(`AUTHOR_RHYTHM`, `groupByMonth`, `buildFeedGroups`) уже собрана дизайнерским заходом.

Самой страницы нет: `web/app/pages/authors/[slug].vue` рисует захардкоженный мок одного автора
и демо-ленту главной, а «о себе» выводит через `v-html`. На сервере остались черновые
`Query.author(handle): User`, `articlesByAuthor` и `authorStats`, которые отдают полный публичный
`User` и не знают ни архива аккаунта, ни истории хэндлов, ни локали.

## Что делаю

### Сервер

1. Новый модуль `server/src/graphql/author/` — тип `AuthorProfile` и запрос `author(handle)` по
   `author.md` §4: `id`, `handle`, `name`, `bio`, `avatar`, `links[] { kind, url }`, `grade`,
   `publishedCount`, `firstPublishedAt`, `redirect` (прежний хэндл → нынешний, 301). Аргумента
   локали у запроса нет, поэтому счётчик и дата первой публикации считаются по всем языкам:
   условие существования страницы (§1) тоже общее для локалей.
2. Аккаунт без опубликованных материалов и неизвестный хэндл — `NOT_FOUND` (404); архивированный
   аккаунт — `ARCHIVED`, из которого страница делает 410 (§8, журнал §28.2). Поля `isArchived`
   публичный тип не заводит: у снятого аккаунта страница показывает только текст «страница автора
   недоступна» и профиль отдавать нечего.
3. `links[]` собираются из `socialLinks`: пары «вид → адрес», только `http`/`https`; остальное
   отбрасывается, чтобы в разметку не попал адрес со скриптом.
4. `FeedScope` получает значение `author`, запрос `feed` — аргумент `handle` (имя из §4). Лента
   автора: только `published` версии локали, порядок по дате, страница `FEED_PAGE_SIZE`, подпись
   `by_publication_date`, `redirect` по истории хэндлов и `ARCHIVED` для снятого аккаунта.
   Пустая лента локали — не отказ, а состояние «пусто» (§8).
5. Черновые `author`, `articlesByAuthor`, `authorStats` из `user/` удаляются: их единственным
   потребителем была старая операция страницы автора, а публичный `User` не удовлетворяет §4.
6. Кеш — общий, `readThroughPublicCache`, тег `author:{handle}` (его уже сбрасывают публикация и
   архивирование материала, `buildArticleCacheTags`), TTL `publicList`, как у прочих публичных лент.

### Веб

7. Операция `GetAuthorPage($handle, $locale, $page)` переписывается на `author` + `feed(scope: author)`.
8. `ReadingAuthorHeader` — шапка §5 зона 2: аватар или инициалы, имя, `ProBadge`, хэндл, «о себе»
   текстом (не `v-html`), ссылки на соцсети с `rel="nofollow noopener noreferrer"`, «публикуется
   с {месяц год}», число материалов.
9. Страница `authors/[slug].vue`: шапка, подпись панели ленты «по дате публикации», хроника по
   месяцам из однорядных групп ритма автора, `EmptyState` с переключателем языка для пустой
   локали, `Pagination`, `ErrorState` с `requestId`, 404 и 410 по §8. 301 на канонический хэндл.
10. Строки словаря `authorPage` в `ru.json` и `en.json`; мок и `HeaderUser` уходят.

## Чего не делаю

- Подписки на автора: `FollowButton`, `followAuthor` / `unfollowAuthor`, `followerCountShort` —
  этап 3 и F-10, прямо исключены §3 задачи. Модели подписок в базе нет.
- `title`, `canonical`, `hreflang`, Open Graph и JSON-LD `Person` (§10) — это T-100, задача
  которой прямо названа «Meta, canonical, hreflang, Open Graph и JSON-LD на публичных страницах»
  и которая зависит от T-057. Страница ставит только `title`, как соседние публичные страницы.
- Ссылок «редактировать профиль» и «карточка в админке» (§5 зона 2, §7): страницы `/me/settings`
  в проекте нет, идентичность сессии на вебе не подключена (`auth.global.ts` закомментирован,
  T-023). Ссылка на несуществующий адрес хуже её отсутствия; остаток фиксируется в отчёте.
- Сортировки `?sort=rating|date` (§3) — после запуска движка рейтинга, журнал §22.5.
- Записи автора в `sitemap.xml` (§10) — T-099.
