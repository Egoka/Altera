# Честные проверки: тест-раннер, область линта и CI без маски

- **Ветка**: docs/platform-design
- **Базовый коммит**: 6b6e972
- **Отчёт**: docs/reports/2026-09-09-honest-checks-report.md (заполняется по завершении)
- **Статус**: завершён

## 0. Основание

Задачи T-001 и T-005 находятся в статусе `кандидат`. Владелец поручил работу прямым указанием
в сессии 2026-09-09 — это «явное письменное подтверждение владельца для конкретной задачи»
по `docs/multica/operating-model.md` §4.1. План покрывает часть T-001 (честный CI) и часть
T-005 (область линта); полный объём обеих задач шире и остаётся за ними.

## 1. Цель

Шаг наблюдения в цикле перестаёт быть слепым: `pnpm test` выполняет настоящие тесты и краснеет
при поломке, `pnpm lint` проверяет исходный код вместо сборочного вывода, CI не маскирует падение
старта сервера, pre-commit-хук репозитория проходит без `--no-verify`.

## 2. Контекст

Установлено в этой сессии командами:

- `pnpm test` → `pnpm -r test`; ни `server/package.json`, ни `web/package.json` не объявляют
  скрипт `test`, поэтому команда завершается успехом при нуле тестов.
- `pnpm lint` падает всегда: `eslint.config.mjs:14` игнорирует `dist`, `.nuxt`, `coverage`,
  `node_modules` и `server/src/generated`, но **не** `.output`. eslint разбирает минифицированные
  чанки `web/.output/public/_nuxt/*.js` и выдаёт сотни `no-unused-vars`.
  `.prettierignore` `.output` уже содержит — расхождение только в eslint.
- `pnpm format` показывает 4 неотформатированных файла в `web`.
- `.github/workflows/pull_request.yml` заканчивает проверку сервера строкой
  `timeout 2s pnpm start || true`: падение старта не делает CI красным.
- Следствие: pre-commit `format && lint && test` не проходит ни на одном коммите.

Что уже есть для тестов: `web` содержит `@nuxt/test-utils` в зависимостях. `server` тестовых
зависимостей не имеет.

Пригодная для тестов чистая логика, проверено чтением:

- `server/src/exceptions/permissions.ts` — `ensureAuthenticated`, `ensureHasRole`, без обращений
  к базе и Redis.
- `server/src/utils/admin.ts` — `validatePagination`, `validateSort`, `calculatePagination`,
  `getCacheKey`; из `../prisma` импортируется только тип `GraphQLContext`, поэтому побочного
  подключения к Redis при импорте не возникает (проверяется запуском теста).
- `web/i18n/locales/{ru,en}.json` — паритет ключей двух локалей.

Ограничение: `server/src/redis.ts` создаёт подключение на импорте и бросает исключение без
`REDIS_URL`. Тесты не импортируют этот модуль.

## 3. Шаги

1. **Линт**: добавить `**/.output/**` и `**/.data/**` в `ignores` файла `eslint.config.mjs`.
2. **Формат**: выполнить `pnpm format:fix`, зафиксировать изменившиеся файлы.
3. **Тесты сервера**: `vitest` в devDependencies, `server/vitest.config.ts`, скрипт
   `test` и `test:watch`; тесты `server/tests/permissions.test.ts` и `server/tests/admin.test.ts`.
   Каталог тестов вне `rootDir: src`, поэтому `tsc` их не собирает.
4. **Тесты веба**: `vitest` в devDependencies, `web/vitest.config.ts`, скрипт `test`;
   тест `web/tests/i18n-locales.test.ts` — паритет ключей `ru`/`en` в обе стороны.
5. **Проверка на честность**: каждый новый тест ломается искусственной поломкой исходника,
   поломка откатывается. Тест, который не краснеет, доказательством не является.
6. **CI**: в задании `test-server` поднять сервисы `postgres` и `redis`, заменить
   `timeout 2s pnpm start || true` на запуск сервера с ожиданием готовности и запросом к
   эндпоинту; падение старта делает шаг красным. Задание `test` дополнить запуском тестов.
7. **Локальная проверка CI-шага**: тот же запуск сервера повторяется локально против Redis и
   PostgreSQL в Docker. Без выполненного запуска утверждение «CI станет красным» в отчёт не идёт.
8. **Pre-commit**: убедиться, что `npm run format && npm run lint && npm run test` проходит, и
   сделать финальный коммит без `--no-verify`.

## 4. Границы

Входит: конфигурация линта, тест-раннеры и первые тесты, CI-задание, форматирование
затронутых файлов.

Не входит: полный объём T-001 (пин версий Node и pnpm), полный объём T-005 (запрет `console.log`,
удаление мёртвого кода), e2e-сценарии T-112, покрытие тестами продуктовой логики, соединение веба
с API, исправление найденных дефектов доступа.

Тесты пишутся под **существующее** поведение. Если тест обнаружит дефект, дефект фиксируется в
отчёте и возвращается владельцу, а не «исправляется» правкой продуктового кода в этом плане.

## 5. Проверка

- `pnpm lint` — код 0.
- `pnpm format` — код 0.
- `pnpm test` — выполняет тесты, показывает их число, код 0.
- Каждый тест продемонстрированно краснеет при поломке исходника (вывод в отчёте).
- Локальный запуск сервера против Docker-сервисов: сервер отвечает на запрос, при отсутствии
  Redis шаг падает с ненулевым кодом.
- Финальный коммит проходит pre-commit без `--no-verify`.
