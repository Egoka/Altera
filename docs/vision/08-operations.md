## 3. Сиды

`prisma db seed` — идемпотентный скрипт (`upsert` по слагам): владелец (`owner`), редактор,
модератор, аналитик, автор standard и автор pro (ручные гранты), читатель; рубрики, четыре формата,
теги; планы free/standard/pro; десять материалов во всех состояниях, включая `ai_review` и
`review`, с AI-вердиктами от фейкового адаптера, один с английской версией, один с бустом,
закладки, одна жалоба, конфигурация рейтинга по умолчанию. Тот же сид используется в тестах и e2e. Для бенчмарка поиска —
отдельный генератор 10 000 материалов.

## 4. Миграции с данными и откат

Правила — `03-data-model.md` §2–3: миграции только с именем; `ADD VALUE` отдельной
миграцией; переименования через `RENAME`; деструктивные шаги (M11) — только после скрипта
проверки; `prisma migrate diff` пуст — шаг CI; `migrate deploy` — шаг релиза с автоматическим
дампом перед ним; откат — forward-миграция или восстановление дампа. Репетиция каждой
миграции с данными — на копии прода.

## 6. Тесты (ADR-0031)

| Уровень | Инструмент | Что проверяет | С этапа |
|---|---|---|---|
| Контракт | скрипт валидации операций, `codegen --check`, проверка SDL | все операции валидны; в публичных типах нет ПДн | 0 |
| Резолверы | Vitest + PostgreSQL в контейнере + сид | права, видимость черновиков, статусные переходы, инвалидация кеша, лимиты | 0–1 |
| Пакет `content` | Vitest | схема, рендер (снимки), экспорт round-trip | 1 |
| Миграции | `migrate reset` + `migrate diff` + сид в CI; дамп-репетиция вручную | схема без drift; бэкфиллы на пустой базе | 1 |
| E2E | Playwright + Mailpit + фейк-провайдер | вход, оплата плана на фейке, отправка через AI и человека, оспаривание, конфликт, офлайн, истечение подписки | 0 smoke, далее по этапам |
| Качество | axe, Lighthouse CI | WCAG AA, бюджеты | 3 |
| Нагрузка | скрипт (k6 или autocannon `[ДОПУЩЕНИЕ]`) | p95 поиска, десять соавторов (6) | 3, 6 |

`pnpm test` падает при нуле тестов; покрытие строк не цель.

## 7. CI

Workflow на PR в `app` и на push в `app`:

1. `setup`: Node из `.nvmrc`, pnpm одной версии, кеш.
2. `lint` (`.output` и `.nuxt` в ignores), `format`, `typecheck` веба (`vue-tsc`) и сервера.
3. `codegen --check`, валидация операций.
4. `test`: сервер (с PostgreSQL-сервисом), веб, пакет `content`.
5. `migrate`: `migrate reset` на сервисе, `migrate diff` пуст, сид.
6. `build`: сервер и веб; запуск сервера → `GET /health = 200`; запуск собранного Nuxt →
   `GET / = 200`.
7. `e2e`: Playwright smoke на сиде.
8. с этапа 3: `quality` — axe и Lighthouse CI с бюджетами.

Никаких `|| true` [ФАКТ: сейчас `.github/workflows/pull_request.yml:64-65`]. Цель — до 10 минут
`[ДОПУЩЕНИЕ]`. Деплой — отдельный workflow на push в `app` после зелёного CI: дамп базы →
миграции → выкладка API → выкладка Nuxt → smoke по `/health` и `/`.

## 8. Наблюдаемость

- Логи: структурированный JSON (ADR-0032), уровни, идентификатор запроса из Nuxt в API; без
  ПДн и токенов; ретенция 30 дней у хостинга.
- Health: `GET /health` на API (база, Redis при включении) и на Nuxt; внешняя проверка
  доступности раз в минуту с уведомлением владельцу `[ДОПУЩЕНИЕ: сервис проверки]`.
- Ошибки: сборщик с группировкой и уведомлениями; фронт отправляет ошибки рендера и запросов.
- Метрики: на старте — SQL-отчёты (публикации, прочтения, подписки, платежи, рейтинг) и
  метрики хостинга (CPU, память, соединения); Prometheus-экспорт — при потребности.
- Фоновые задачи (AI-вызовы, пересчёт рейтинга, продления и истечения подписок): очередь в
  базе внутри процесса API; метрики глубины очереди и возраста старшего задания; уведомление
  владельцу при возрасте выше порога `[ДОПУЩЕНИЕ: 1 час]` и при недоступности AI-провайдера.

## 9. Обработка ошибок

Словарь кодов и маскирование — ADR-0032. Фронт: по коду показывает состояние
(`06-design-system.md` §6); `NOT_FOUND` → 404, `FORBIDDEN` → 403, `RATE_LIMITED` → пояснение и
время, `CONFLICT` → баннер редактора, `INTERNAL_ERROR` → идентификатор запроса для письма в
поддержку.

## 13. Процедуры последней инстанции

- Утрата доступа владельца: доступ к базе и скрипт назначения `owner` по e-mail с записью в

## 14. Что сознательно не делаем

- Kubernetes, микросервисы, очереди сообщений: один API, один Nuxt, один скрипт по расписанию.
- Мультирегиональность, CDN на старте (при необходимости — CDN провайдера перед S3).
- Внешние SaaS-аналитику и APM за рубежом.
- Собственный стенд «staging» с полной копией прода: превью на анонимизированной ветке.
