## A. Семь вопросов, которые меняют архитектуру

### A1. Где будут жить персональные данные в проде — с учётом 152-ФЗ?

**Что зависит.** Хостинг базы, Redis, объектного хранилища и почтового провайдера; текст
политики персональных данных; момент, когда можно открывать регистрацию.

**Контекст.** Сейчас база — Neon [ФАКТ: `server/prisma/schema.prisma:6-10`], у которого нет
региона в РФ, README обещает Vercel и Render. Продуктовые рамки требуют ЮKassa/Т-Кассу и
соблюдение 152-ФЗ, а статья 18 ч. 5 152-ФЗ требует, чтобы запись, хранение и обновление
персональных данных граждан РФ велись в базах на территории РФ. E-mail и имя автора —
персональные данные. Это противоречие между «фиксировано: Neon» и «фиксировано: 152-ФЗ».

**Варианты.**
- (a) Прод-база и хранилище — в РФ (Yandex Cloud, Selectel, VK Cloud, Timeweb и т. п.), Neon
  остаётся для разработки и превью-веток. Перенос данных при Prisma-схеме — дамп и восстановление.
- (b) Оставить Neon и принять риск осознанно, зафиксировав это в ADR.
- (c) Отложить до появления первых реальных пользователей, но спроектировать так, чтобы
  перенос был операцией на один вечер.

**Рекомендация.** (c) до открытой регистрации, затем (a). Дизайн этапа 0 и 1 не должен
опираться ни на что Neon-специфичное (serverless-драйвер `@neondatabase/serverless` сейчас в
зависимостях, но не используется [ФАКТ: `server/package.json:28`, поиск по `src`]).

**Цена промедления.** До открытой регистрации — нулевая. После — перенос с живыми
пользователями плюс переписывание согласий.

### A2. Открытый контур: публикация мгновенная или через проверку?

**Что зависит.** Смысл кнопки «Опубликовать», статусная модель языковых версий, роль
модератора, очередь в админке на этапах 1–2, объём модерации на одного человека.

**Варианты.**
- (a) Мгновенная публикация, постмодерация по жалобам и выборочно.
- (b) Каждый материал открытого контура проходит `review` (статус уже есть в коде
  [ФАКТ: `server/prisma/schema.prisma:101-106`]).
- (c) Уровни доверия: первые один-два материала автора идут через проверку, дальше —
  мгновенно; модератор может вернуть автора на проверку.

**Рекомендация.** (c). При нулевой аудитории это почти бесплатно, защищает от спама и
юридических рисков (чужие тексты и изображения), и не превращает право публиковать в право
«после одобрения редакции» для состоявшихся авторов. Правило-арбитр не нарушается: проверка не
продаётся и не отменяется деньгами.

**Цена промедления.** Средняя: решение нужно к началу этапа 1, потому что определяет
статусы и права.

### A3. Модель контента: подтвердить ProseMirror-JSON (TipTap) вместо MDC?

**Что зависит.** Тип поля `body`, рендер материала на сервере, редактор, версии, переводы,
совместная работа, миграции контента. Самое дорогое решение проекта.

**Контекст.** README и `package.json` обещают MDC [ФАКТ: `README.md:15`, `package.json:4`],
но в коде MDC нет: `Article.body` — строка [ФАКТ: `schema.prisma:73`], зависимостей
`@nuxtjs/mdc`/`@nuxt/content` нет [ФАКТ: `web/package.json`]. Переходить не с чего — выбор
делается с чистого листа.

**Рекомендация.** Хранить материал как JSON-дерево ProseMirror (редактор TipTap для Vue 3),
рендерить на сервере собственным рендерером JSON → Vue-компоненты дизайн-системы, экспортировать
в Markdown/HTML для переносимости. MDC не брать. Обоснование, сравнение по критериям промта и
цена отката — в `02-target-architecture.md`, раздел 4.1. Коротко: схема ProseMirror — это и
есть «граница свободы» автора (чего нет в схеме, того не существует), у неё есть путь к
совместному редактированию через Y.js, а авторы-гуманитарии не будут учить синтаксис компонентов.

**Цена промедления.** Максимальная: без этого решения не начинается ни модель данных
этапа 1, ни редактор.

### A4. Языки и URL: русский без префикса и обязательны ли обе версии?

**Что зависит.** Схема URL (её нельзя менять после первых внешних ссылок), модель
`ArticleTranslation`, hreflang, i18n интерфейса.

**Контекст.** Сейчас `en` — локаль по умолчанию без префикса, `ru` — под `/ru`
[ФАКТ: `web/nuxt.config.ts:80-81`]. Для продукта с российским платёжным контуром и русскоязычной
редакцией это выглядит случайностью, а не решением.

**Предложение.** Русский без префикса, английский под `/en`. Перевод — необязательная вторая
версия материала: у каждого материала есть `sourceLocale`, а переводы добавляются по мере сил.
Слаг — свой у каждой языковой версии; canonical — у каждой версии свой; hreflang связывает
сёстры. Метаданные (автор, рубрика, теги, обложка, дата первой публикации) общие.

**Вопросы.** (1) Русский по умолчанию — верно? (2) Перевод необязателен — верно? (3) Нужен ли
редакционный контроль качества перевода как отдельный статус (`translation_review`) или
достаточно общего `review`?

**Цена промедления.** Высокая для URL (нужно до этапа 1), средняя для остального.

### A5. Кому принадлежит текст: права редактора и судьба материалов при удалении автора

**Что зависит.** Матрица прав, аудит правок, лицензия на контент в оферте, поведение
`updateArticle`, модель блокировки и удаления аккаунта.

**Предложение.**
- Редактор **может** править чужой материал только в редакционном контуре (заказные и
  отобранные для витрины материалы) и материалы в статусе `review` — с сохранением ревизии и
  видимой автору историей правок. Опубликованный материал открытого контура редактор править
  не может; может только снять с публикации с указанием причины (модерация).
- Блокировка автора: аккаунт заморожен, материалы остаются опубликованными (если сама
  блокировка не за нарушение в материалах — тогда снимаются).
- Удаление аккаунта: персональные данные анонимизируются; материалы открытого контура по
  умолчанию **снимаются в архив** (права у автора), с возможностью для автора выбрать «оставить
  с подписью „автор удалил аккаунт“»; заказные редакционные материалы остаются по условиям
  договора.

**Вопросы.** Согласны ли с границей прав редактора? Согласны ли с «архив по умолчанию» при
удалении?

**Цена промедления.** Средняя: нужно до этапа 2 (витрина) и до текста оферты.

### A6. Таксономия и адреса материалов

**Что зависит.** Схема URL, модель `ContentType`, навигация, SEO.

**Контекст.** Сейчас `ContentType` — одновременно и рубрика, и префикс адреса
`/{type}/{article}` [ФАКТ: `web/app/pages/[slugTypeContent]/[slugArticle].vue`], а фикстуры
смешивают темы («National Security», «Спорт») и форматы («Article», «Memoir», «Analysis»)
[ФАКТ: `web/app/pages/authors/[slug].vue:47-49,70-72,93-95`, `MegaMenu.vue:111-225`].

**Предложение.** Три оси: **рубрика** (тема: культура, искусство, фотография, музыка, спорт,
путешествия — задаёт префикс URL и навигацию, управляется редакцией), **формат** (эссе, обзор,
фоторепортаж, интервью — атрибут материала, не в URL), **теги** (свободные, автором).
Адрес материала: `/{рубрика}/{слаг}`, английская версия — `/en/{section}/{slug}`. Автор —
`/authors/{handle}`. Идентификатор материала в адрес не выходит; история слагов хранится для
редиректов.

**Вопросы.** Рубрики — это шесть тем из описания продукта? Нужен ли формат как отдельная ось?

**Цена промедления.** Высокая: адреса.

### A7. Первый платный продукт и платёжный провайдер

**Что зависит.** Модель `Customer/Subscription/Payment/Payout`, юридические тексты, порядок
этапа 4, интеграция (ЮKassa или Т-Касса), выплаты самозанятым.

**Варианты первого продукта (все проходят правило-арбитр).**
- (a) Поддержка автора: разовые донаты и подписка на автора с комиссией платформы. Деньги —
  за голос конкретного человека по его согласию, не за доступ; открытый контур остаётся
  бесплатным. ✔
- (b) Подписка на редакционную витрину и её архив (заказные материалы, рассылка). Деньги за
  редакционную работу. ✔
- (c) Платные отдельные редакционные материалы. ✔ (но при нулевой аудитории самая слабая).
- (d) Ничего до появления первых десятков авторов и читателей; этап 4 идёт после этапа 3.

**Рекомендация.** (d) по срокам, (a) как первый продукт, потому что он прямо работает на
ближайшую цель «первые авторы», не требует paywall и даёт авторам причину приводить читателей;
(b) — второй. Провайдер: ЮKassa — как более документированный вариант с готовыми выплатами
самозанятым; Т-Касса — равноценная альтернатива, выбор не влияет на модель данных, если
провайдер спрятан за адаптером.

**Цена промедления.** Низкая: нужно к началу этапа 4, но текст оферты и политики ПД нужны
раньше (до открытой регистрации), и они должны допускать будущие платежи.

## B. Решения по умолчанию (ответьте только там, где не согласны)

Отсортированы по цене промедления: сверху то, что вшивается в модель данных этапа 1.

| № | Решение по умолчанию | Почему так |
|---|---|---|
| B1 | **E-mail автора никогда не публичен.** Из публичного типа `User` он уходит; для связи с автором позже появится форма через платформу | Персональные данные, спам, 152-ФЗ |
| B2 | **Roles**: `reader`, `author`, `editor`, `moderator`, `admin`, `owner` как enum; «подписчик» — не роль, а состояние активной подписки; «гость» — отсутствие сессии. Автор — любой, кто заполнил профиль автора (имя, о себе), без одобрения | Роль отвечает на «что можно делать», подписка — на «за что заплачено»; смешивать нельзя |
| B3 | **«Избранное»** — ручной отбор редакции с позицией и сроком (`EditorialPick`); **«популярное»** — число уникальных прочтений за 7 дней, метрика подписана прямо на сайте («по прочтениям за неделю»); персонализации нет | Соответствует «без алгоритмов» буквально; объяснимо читателю |
| B4 | **Контуры в ленте**: главная = редакционная витрина сверху (отборы) + отдельный, явно подписанный хронологический поток открытого контура. Смешанной ленты нет. Материалы витрины, отобранные из открытого контура, остаются бесплатными | Иначе читатель не отличает редакционный выбор от самопубликации |
| B5 | **Блоки первого редактора**: абзац, заголовки 2–3 уровня, цитата, список, изображение с подписью и атрибуцией, разделитель, ссылка. Галереи, видео/аудио, врезки, колонки, embed — этапами 3–5 | Достаточно для эссе и фоторассказа; каждый блок — отдельная стоимость |
| B6 | **Граница свободы автора**: автору доступны только *семантические* варианты (тип блока, размер изображения обычный/широкий/на всю ширину, тип цитаты), дизайн-системе — всё визуальное (цвета, шрифты, отступы, рамки). Правило: настройка допустима, если меняет смысл или чтение, а не внешний вид, и каждое значение — именованный вариант, а не число или цвет | Единственный способ удержать журнал единым при чужих руках |
| B7 | **Медиа**: S3-совместимое хранилище в РФ (см. A1), варианты изображений генерируются при загрузке, оригинал хранится; поля лицензии и атрибуции обязательны; ответственность за права — на загрузившем, это фиксируется в оферте | Дешевле, чем IPX на лету с внешним источником; закрывает вопрос чужого контента |
| B8 | **Сессии**: refresh-сессии хранятся в базе с ротацией и отзывом; access-токен 15 минут; выход и «выйти везде»; magic link с лимитами по e-mail и по IP; письма — через SMTP-провайдера с РФ-контуром | Сейчас отзыв невозможен в принципе |
| B9 | **Redis** становится необязательным кешем с деградацией; на этапах 0–2 кеш можно держать выключенным | Один разработчик, нулевая нагрузка; обязательный Redis — лишняя точка отказа |
| B10 | **GraphQL Yoga остаётся**; единый контракт — схема сервера, типы фронта генерируются (`graphql-codegen`); клиент минимальный (`graphql-request` + `useAsyncData`) | Смена транспорта ничего не даёт, а стоит перепис резолверов |
| B11 | **FishtVue остаётся в админке**; публичный сайт — собственная небольшая библиотека компонентов на Tailwind по дизайн-системе | Публичному сайту нужна типографика, а не виджеты |
| B12 | **Magic link — единственный вход** на этапах 0–3; OAuth (Яндекс ID, VK ID) не раньше этапа 3 и только если появится измеренная потеря на входе | Меньше поверхности атаки и кода |
| B13 | **Поиск** — полнотекстовый PostgreSQL (`tsvector`, конфигурации `russian` и `english`); внешний движок только при измеренной проблеме | Десятки тысяч документов PostgreSQL держит без труда |
| B14 | **Сообщество на запуске**: жалобы на материал — да; комментарии и реакции — нет (возможно, никогда); письмо в редакцию — форма; рассылка — с этапа витрины | Модерация комментариев для одного человека дороже всего остального |
| B15 | **Аналитика**: собственный счётчик прочтений без профилирования, без внешних трекеров на старте | Нужен только для «популярного» и метрик этапов |
| B16 | **Юридические тексты** (оферта, политика ПД, лицензия на контент, правила публикации) нужны **до открытой регистрации**, а не до денег | Персональные данные появляются с первым автором |
| B17 | **Демо-страницы** (`/components-showcase`, `/fonts-showcase`, `/test-error`) уходят из продакшена в отдельный маршрут только для dev | Не должны индексироваться |

- Выбор конкретного облачного провайдера в РФ (после A1).
- Провайдер почты (после A1; кандидаты — Unisender, SendPulse, SMTP Яндекс 360).
- Конкретные цены тарифов — только гипотезы и способ проверки (этап 4).
- Формат рассылки и её частота.
- Стоит ли открывать API для партнёров (не раньше этапа 6).
