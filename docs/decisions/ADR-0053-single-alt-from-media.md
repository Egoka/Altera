# ADR-0053: Единое alt из медиафайла; AI-описание генерируется при загрузке

- **Статус**: принято 2026-09-14
- **Этап**: 1

## Контекст

При размещении изображений в статьях нужно значение `alt` для доступности и SEO. Журнал §29.11
и §29.13 (2026-09-09, уточнение пост-Г9) устанавливают единственный источник `alt` и механизм
его генерации. Нужен ADR, фиксирующий это правило до реализации медиа-пайплайна.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Автор вводит `alt` при каждом размещении изображения | Контекстуальная точность | Большая нагрузка на автора; пропуски ведут к отсутствию `alt` |
| **AI генерирует `alt` один раз при загрузке и хранит в медиафайле; единый источник для всех размещений** | Доступность по умолчанию; нет дублирования; AI-описание привязано к самому изображению | Нельзя адаптировать `alt` под контекст конкретной статьи |
| Редактор вводит `alt` вручную при каждом размещении | Полный контроль | Ошибки и пропуски неизбежны; нет значения по умолчанию |

## Решение

1. Любая загруженная фотография проходит отдельный шаг обработки лёгкой AI-моделью: модель
   определяет, что изображено, и сохраняет описание в поле `alt` самого медиафайла. Это не
   анализ статьи и не зависит от её текста (журнал §29.11).
2. AI-описание `alt` создаётся один раз для каждого загруженного изображения и хранится
   только в свойствах медиафайла (журнал §29.13).
3. Автор не редактирует `alt`. Размещение изображения в статье не может переопределять `alt`
   (журнал §29.13).
4. Публичный вывод всегда использует единое `alt` из медиафайла (журнал §29.13).
5. В редком исключении — очевидно неверное AI-описание — скорректировать `alt` может только
   `admin` непосредственно у медиафайла; это действие аудируется (журнал §29.13).
6. Новый код события аудита при замороженном реестре не добавляется (журнал §28.3,
   см. ADR-0054).

Границы: этот ADR описывает только правило `alt`. Полный медиа-пайплайн (форматы, сжатие,
thumbnails, карантин) определяется отдельно при реализации (журнал §29.12).

## Следствия

- Медиа-сервис хранит `alt`-поле у каждого медиафайла.
- API вставки изображений в статью не принимает `alt` как параметр и не хранит
  контекстуальное значение.
- Интерфейс редактора не отображает поле `alt` при вставке изображения.
- Только `admin` видит и может изменить `alt` в интерфейсе медиафайла.

## Цена отката

Низкая: перевод к авторскому вводу `alt` требует только добавления поля в UI редактора
и изменения логики вывода; AI-описания остаются как резервные.
