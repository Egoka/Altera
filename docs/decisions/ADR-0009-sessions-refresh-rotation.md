# ADR-0009: Сессии — хранение, ротация, отзыв

- **Статус**: принято 2026-09-05
- **Этап**: 0

## Контекст

- Вход по magic link выдаёт access-JWT на 15 минут и refresh-JWT на 7 дней
  [ФАКТ: `server/src/graphql/auth/resolver.ts:86-92`], но мутаций обновления и выхода нет,
  refresh нигде не хранится и не отзывается [ФАКТ: `server/src/graphql/auth/schema.graphql:7-10`].
  Через 15 минут пользователь может только снова пройти по ссылке из письма.
- Один magic-link токен на пользователя, повторный запрос перезаписывает предыдущий
  [ФАКТ: `server/prisma/schema.prisma:29-40`, `auth/resolver.ts:39-51`]; в базе лежит сам токен,
  а не его хэш.
- Ограничений частоты нет нигде [ФАКТ: `docs/vision/00-reality-check.md` §3.5].

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Долгоживущий access-JWT без refresh | Проще всего | Отзыв невозможен до истечения; блокировка автора не действует |
| Refresh-JWT без хранения (как сейчас, но с мутацией) | Без таблицы | Отзыв невозможен; кража токена не обнаруживается |
| **Refresh-сессии в базе с ротацией** | Отзыв одной сессии и всех; обнаружение повторного использования; список устройств | Таблица и запись при каждом обновлении |
| Серверные сессии без JWT вовсе | Ещё проще для отзыва | Каждый запрос — чтение сессии; access-JWT на 15 минут даёт то же с одним чтением по `sid` |

## Решение

1. Таблица `Session`: `id` (попадает в access-JWT как `sid`), `userId`, `tokenHash` (sha256
   случайных 32 байт refresh-токена; сам токен только у клиента), `previousTokenHash`,
   `expiresAt` (30 дней от последней ротации), `revokedAt`, `userAgent`, `ip`, `createdAt`,
   `lastUsedAt`.
2. Access-JWT живёт 15 минут и несёт `userId` и `sid`; контекст запроса проверяет
   `revokedAt IS NULL` одним индексированным чтением — отзыв действует мгновенно.
3. Обновление ротирует refresh-токен: старый хэш переходит в `previousTokenHash`. Предъявление
   старого токена означает утечку: сессия отзывается.
4. `logout` отзывает текущую сессию, `logoutAll` — все сессии пользователя; блокировка
   пользователя отзывает все его сессии.
5. Magic link хранится как хэш; лимиты частоты — ADR-0024; хранение токена на клиенте и защита
   от CSRF — ADR-0023.
6. Роль и блокировка читаются из базы при каждом запросе, как сейчас
   [ФАКТ: `server/src/prisma.ts:29-31`]; клейм роли из JWT не используется.

## Следствия

- Мутации `refreshSession`, `logout`, `logoutAll` и запрос `mySessions` входят в контракт
  этапа 0; операции фронта `LOGOUT`/`REFRESH_TOKEN` переписываются под них.
- Существующие refresh-JWT перестают работать: приемлемо при нулевой аудитории.
- Строки сессий с `ip` — персональные данные: чистка через 30 дней после истечения
  (`docs/vision/08-operations.md`, housekeeping).

## Цена отката

Низкая: таблица аддитивна; возврат к бессрочным JWT — удаление проверки `sid`.
