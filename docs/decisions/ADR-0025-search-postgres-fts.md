# ADR-0025: Поиск на PostgreSQL FTS

- **Статус**: принято 2026-09-05
- **Этап**: 3

## Контекст

Поиска в схеме нет вовсе; на фронте есть три невалидные операции поиска
[ФАКТ: `web/app/query/common/search.ts`, отчёт первого плана]. Промт требует выбрать между
полнотекстовым поиском PostgreSQL и внешним движком с оценкой стоимости и момента перехода.

## Рассмотренные варианты

| Вариант | Стоимость | За | Против |
|---|---|---|---|
| **PostgreSQL FTS** (`tsvector`, конфигурации `russian` и `english`, GIN) | 0 ₽ инфраструктуры; 2–4 чд | Данные и индекс в одном месте; транзакционная согласованность; хватает на десятки тысяч документов `[ДОПУЩЕНИЕ: по опыту, проверяется бенчмарком]` | Нет опечаток из коробки (частично лечится `pg_trgm`); фасеты — отдельными запросами |
| Meilisearch / Typesense | Отдельный процесс и память; 5–8 чд плюс синхронизация | Опечатки, фасеты, скорость | Вторая истина; синхронизация индекса; ещё один сервис для одного разработчика |
| Внешний SaaS (Algolia) | Подписка | Готово | Данные за рубежом; цена |

## Решение

1. Поиск — PostgreSQL: generated-колонка `searchVector` на языковой версии из `title`, `dek`
   и плоского текста документа (`bodyText`), конфигурация по локали, GIN-индекс; ранжирование
   `ts_rank_cd`, сниппеты `ts_headline`.
2. Фильтры: рубрика, формат, тег, автор, период — обычные условия `WHERE`; фасеты — счётчики
   отдельными запросами по мере надобности.
3. Подсказки (`searchSuggestions`) — префиксный поиск по заголовкам, авторам и тегам через
   `pg_trgm` `[ДОПУЩЕНИЕ]`.
4. Контрольный набор из 50 запросов (ru/en, словоформы) с ожидаемым топ-3 — часть тестов
   этапа 3; бенчмарк на сиде 10 000 материалов: p95 < 300 мс.
5. **Критерий перехода** на внешний движок: p95 поиска > 300 мс на реальных данных после
   оптимизации, либо измеренная доля нулевых выдач из-за опечаток > 20 %, либо
   требование фасетного поиска с сортировкой по релевантности на > 100 000 документов.
   Переход — отдельный ADR.

## Следствия

- `bodyText` пишется при каждом сохранении версии (экстрактор текста из JSON — тот же, что
  для времени чтения и экспорта).
- Нулевые выдачи логируются (запрос без персональных данных) для оценки качества.
- Бюджет инфраструктуры не растёт.

## Цена отката

Переход на внешний движок — 5–8 чд плюс синхронизация; поисковые колонки в базе остаются
как резерв.
