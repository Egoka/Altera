# ADR-0031: Стратегия тестирования и честный CI

- **Статус**: принято 2026-09-05
- **Этап**: 0

## Контекст

- Тестов нет ни одного; `pnpm test` выполняет `pnpm -r test`, у пакетов скрипта нет —
  результат exit 0 [ФАКТ: `docs/vision/00-reality-check.md` §6].
- `pnpm lint` падает, потому что ESLint веба сканирует `web/.output`; `pnpm format` падает на
  четырёх файлах; pre-commit хук вызывает оба [ФАКТ: `.husky/pre-commit`, отчёт первого плана].
- CI: только PR в `app`, Node 20 при локальном 24, три разные версии pnpm, веб не собирается и
  не типизируется, старт сервера — `timeout 2s pnpm start || true` [ФАКТ: `.github/workflows/pull_request.yml`].
- Прод-сборка веба под локальным Node 24 отдаёт 500 на всех маршрутах [ФАКТ: срез §5.6].

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Продолжать без тестов, проверять руками | Быстро сегодня | Каждое подключение к API ломает страницы незаметно; один разработчик не может проверять всё руками |
| Стремиться к покрытию строк | Метрика | Дорого и не о том |
| **Пирамида по рискам проекта**: контракт → резолверы на тестовой БД → e2e ключевых сценариев → качество (a11y, бюджеты); CI как единственный судья | Тесты там, где ломалось | Каркас тестов — работа этапа 0 |

## Решение

1. Уровни и порядок внедрения:
   - **Контракт** (этап 0): валидация всех операций фронта против SDL; `codegen --check`;
     контрактные проверки SDL (нет `email` в публичных типах).
   - **Резолверы** (этап 0–1): Vitest против тестовой PostgreSQL (Docker в CI, Neon-ветка или
     локальный контейнер у разработчика), фикстуры через сид; тест на каждое правило прав и на
     видимость черновиков.
   - **Пакет `content`** (этап 1): фикстуры документов, снимки рендера, round-trip экспорта.
   - **E2E** (этап 0 smoke, далее по этапам): Playwright — вход по ссылке через фейковый
     транспорт, чтение страниц из сида, публикация, проверка, отбор, платёж в песочнице.
   - **Качество** (этап 3): axe в Playwright — 0 critical/serious; Lighthouse CI с бюджетами.
2. `pnpm test` падает, если тестов 0 (`--passWithNoTests` запрещён).
3. CI на PR в `app` и на push в `app`: установка с пином Node (`.nvmrc` + `engines`) и одной
   версии pnpm; `lint` (с `.output` в ignores), `format`, `typecheck` веба (`vue-tsc`) и
   сервера, `codegen --check`, `test` всех пакетов, сборка веба и сервера, запуск сервера с
   проверкой `GET /health = 200`, запуск собранного Nuxt с проверкой `GET / = 200`. Никаких
   `|| true`.
4. Pre-commit оставляет только быстрые проверки (lint и format изменённых файлов); тесты — в
   CI.
5. Миграции: `prisma migrate diff` пуст после каждой миграции — шаг CI; прод-миграции — шаг
   релиза, не сборки.
6. Каждый этап роадмапа добавляет тесты в свой DoD; регресс защищённого сценария — красный CI.

## Следствия

- Этап 0 включает: конфигурацию Vitest в `server`, `web`, `packages/content`; Playwright;
  Docker-compose с PostgreSQL и Mailpit для разработки; переписанный workflow.
- Появляется скрипт диагностики прод-сборки под пиновой версией Node.
- Время CI — цель до 10 минут `[ДОПУЩЕНИЕ]`.

## Цена отката

Ноль: тесты и CI — инструменты; убрать их значит вернуться к нынешнему состоянию.
