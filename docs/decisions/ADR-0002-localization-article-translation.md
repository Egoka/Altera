# ADR-0002: Локализация — материал и его языковые версии, русский без префикса

- **Статус**: принято 2026-09-05; расширено ADR-0046 (AI-перевод для pro) 2026-09-06
- **Этап**: 1 (модель данных v2), 2 (рабочий процесс перевода)

## Контекст

Продуктовая рамка требует полных переводов материалов: один материал существует как несколько
языковых версий с общими метаданными и hreflang, а не как запись с полем языка. Это решение
уровня модели данных, его нельзя отложить.

Что есть в коде:

- Материал одноязычный: `title`, `slug`, `body`, `status`, `publishedAt` — поля `Article`
  [ФАКТ: `server/prisma/schema.prisma:68-87`]; никакого признака языка нет.
- Веб: локаль по умолчанию `en` без префикса, `ru` под `/ru`, стратегия `prefix_except_default`
  [ФАКТ: `web/nuxt.config.ts:65-87`]; переводы интерфейса применены только на демо-странице
  [ФАКТ: `docs/vision/00-reality-check.md` §5.4].
- Для продукта с российским платёжным контуром и русскоязычной редакцией английский по
  умолчанию — случайность конфигурации, а не решение.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Поле `locale` на материале, переводы — отдельные материалы, связанные `groupId` | Минимальные изменения схемы | Метаданные (автор, рубрика, теги, обложка, дата первой публикации) дублируются и расходятся; отборы и подборки не знают, что это один материал |
| **`Article` + `ArticleTranslation`**: общие метаданные на материале, текст и адрес на версии | Одна сущность для отборов, подборок, прав и экономики; у каждой версии свой статус, слаг и SEO | Все публичные запросы получают аргумент локали; списки строятся по версиям |
| Обязательные обе языковые версии | Симметрия | Нереалистично при нулевой аудитории и одной редакции: материал не выйдет, пока нет перевода |
| Английский по умолчанию (как сейчас) | Ничего не менять | Противоречит продукту и аудитории; адреса менять потом дороже |

## Решение

1. `Article` хранит общие метаданные: автор, рубрика, формат, теги, контур, обложка,
   `sourceLocale`, `firstPublishedAt`. `ArticleTranslation` хранит `locale`, `slug`, `title`,
   `dek`, `excerpt`, `body`, `status`, `publishedAt`, SEO-поля, `translatorId`,
   `sourceRevisionId` (с какой ревизии оригинала сделан перевод).
2. Перевод **необязателен**: у материала всегда есть версия с `locale = sourceLocale`, остальные
   появляются по мере сил.
3. Статусный цикл `draft → review → published → archived` живёт на языковой версии.
   Отдельного статуса проверки перевода нет: перевод проходит общий `review` с признаком «это
   перевод» в очереди.
4. «Опубликованный материал» в любом списке означает «версия в локали запроса со статусом
   `published`». Материал только с английской версией на русском сайте не показывается нигде.
5. Русский — локаль по умолчанию, без префикса; английский — под `/en`. Стратегия
   `prefix_except_default` сохраняется.
6. Слаг — у каждой версии свой, уникальный в пределах локали (ADR-0004); canonical — у каждой
   версии свой; hreflang связывает только опубликованные версии.
7. Даты: `ArticleTranslation.publishedAt` — первая публикация версии, не сбрасывается при
   повторной публикации; `Article.firstPublishedAt` — первая публикация материала в любой
   локали, ставится один раз; это «дата материала» в шапке обеих версий.
8. Справочники (рубрики, форматы, теги, подборки) локализуются парой колонок `name`/`nameEn`,
   не таблицами переводов.

## Следствия

- Миграция существующих материалов: каждая строка `articles` становится парой «материал +
  русская версия» (путь в `docs/vision/03-data-model.md`).
- Все публичные резолверы получают аргумент `locale`; сегодняшние `article(slug)`,
  `latestArticles` и остальные меняют сигнатуру (единый контракт — ADR-0012).
- Смена локали по умолчанию меняет адреса: `/ru/...` исчезает, английские адреса получают
  префикс. До первых внешних ссылок это бесплатно; после — таблица редиректов.
- Перевод интерфейса (`$t`) становится обязательной частью этапа 2, иначе английская версия
  материала живёт в русском интерфейсе.
- Индикатор «оригинал обновился после перевода» строится по `sourceRevisionId`.

## Цена отката

- Свести версии обратно в одну таблицу — потеря всех переводов, кроме одного; не обратимо без
  потерь.
- Вернуть английский по умолчанию — смена всех адресов и hreflang; терпимо только до появления
  внешних ссылок.
- Ввести обязательность обеих версий — дёшево (проверка в резолвере), но продуктово вредно.
