# ADR-0003: Роли — шесть значений, единый источник, подписчик — состояние

- **Статус**: принято 2026-09-05
- **Этап**: 0 (единый источник enum), 1 (матрица прав)

## Контекст

- В базе и GraphQL роли `reader`, `author`, `editor`, `admin` [ФАКТ: `server/prisma/schema.prisma:89-94`,
  `server/src/graphql/user/schema.graphql:2-7`]; в типах страниц фронта — `"user" | "admin"`
  [ФАКТ: `web/app/types/user.ts:1`]; в фикстурах админки — `"ADMIN"`, `"AUTHOR"`, `"READER"`
  [ФАКТ: `web/app/pages/admin/users/[slug].vue:16-46`]. Три несовместимых словаря.
- Роль `editor` не имеет ни одного права: все проверки — `ensureHasRole(..., "admin")`
  [ФАКТ: `docs/vision/00-reality-check.md` §3.4 п. 3]. Любой аутентифицированный, включая
  `reader`, может создавать статьи [ФАКТ: `server/src/graphql/article/resolver.ts:507`].
- Промт требует роли гость, читатель, подписчик, автор, редактор, модератор, администратор,
  владелец и единый источник enum для сервера и фронта.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Оставить четыре роли, «подписчик» и «модератор» — через флаги | Ничего не мигрировать | Модератор нужен с этапа 1 (проверка материалов), владелец — для передачи проекта; флаги размывают матрицу |
| **Enum из шести ролей** `reader / author / editor / moderator / admin / owner`; подписчик — состояние подписки; гость — отсутствие сессии | Роль отвечает на «что можно делать», подписка — на «за что заплачено»; одна ось | Добавление значений в enum PostgreSQL — отдельными миграциями |
| Таблица прав (RBAC с permissions) | Гибко | Для одного редактора и одного разработчика — лишний слой; правила проще держать в коде |
| Свой enum на фронте | Быстро | Уже привело к трём словарям |

## Решение

1. `enum Role { reader author editor moderator admin owner }` в Prisma. GraphQL-enum `Role`
   повторяет его; типы фронта **генерируются** из схемы сервера (ADR-0012). Ручные enum ролей
   в `web/app/types` удаляются.
2. «Подписчик» — не роль, а состояние: наличие активной подписки у `Customer` (этап 4).
   «Гость» — отсутствие сессии.
3. Маршрут повышения: `reader → author` автоматически при заполнении профиля автора (имя и
   «о себе»); `editor`, `moderator`, `admin` назначает `admin` или `owner`; `owner` ровно один,
   передаётся двусторонним подтверждением (`docs/vision/04-roles-and-access.md`).
4. Права проверяются только в резолверах и на уровне данных: единый модуль видимости
   материалов (`visibleArticlesWhere(viewer)`) и хелперы `ensureAuthenticated`/`ensureHasRole`
   [ФАКТ: `server/src/exceptions/permissions.ts:9-32`]. Интерфейс скрывает кнопки, но не
   является источником прав.
5. Создавать материалы может только `author` и выше; `reader` — читает, поддерживает авторов,
   жалуется.

## Следствия

- Миграция M1 добавляет `moderator` и `owner` (значения enum добавляются отдельной миграцией и
  не используются в той же транзакции — `docs/vision/03-data-model.md` §2).
- Появляется матрица «роль × действие × данные» и список аудируемых действий (смена роли,
  снятие с публикации, сброс доверия, передача владения).
- `createArticle` начинает требовать роль `author`; существующие пользователи с ролью `reader`
  и материалами получают `author` бэкфиллом.
- Роль в JWT-клейме больше не используется: роль читается из базы на каждый запрос, как и
  сейчас [ФАКТ: `server/src/prisma.ts:29-31`].

## Цена отката

Низкая: убрать значения из enum можно только паттерном пересоздания типа с проверкой, что они
не используются [ФАКТ: `server/prisma/migrations/20250726211815_update_roles/migration.sql`];
матрица прав — код.
