# ADR-0030: Обработка изображений при загрузке вместо IPX

- **Статус**: принято 2026-09-05
- **Этап**: 1

## Контекст

- `@nuxt/image` подключён, `NuxtImg` используется в десяти компонентах
  [ФАКТ: `web/nuxt.config.ts:13`, поиск по `web/app`]; в прод-сборке `/_ipx/...` отвечает 500,
  потому что в `.output/server/node_modules/sharp` нет нативного бинарника для платформы
  [ФАКТ: `docs/vision/00-reality-check.md` §5.6]; статический файл отдаётся.
- Пользовательские изображения будут жить в объектном хранилище (ADR-0008); обработка «на
  лету» по внешним адресам — лишняя работа на каждый запрос и та же зависимость от `sharp` в
  процессе Nuxt.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| IPX на лету через `@nuxt/image` с провайдером S3 | Уже подключён | `sharp` в процессе SSR (сломан в текущей сборке); обработка при каждом промахе кеша; кеш вариантов — ещё одна забота |
| Внешний сервис трансформаций у хранилища (провайдер CDN) | Без кода | Зависит от провайдера РФ и его цен `[ДОПУЩЕНИЕ]` |
| **Варианты при загрузке** на стороне API (`sharp` как обычная зависимость сервера с пином платформенного бинарника), фиксированный набор ширин и форматов | Один раз при загрузке; предсказуемо; `srcset` из заранее известных вариантов; LQIP | Набор вариантов фиксирован; смена набора — пересчёт скриптом |

## Решение

1. При загрузке API генерирует варианты: ширины 480, 960, 1440, 2000 `[ДОПУЩЕНИЕ: набор
   уточняется по сетке дизайн-системы]` в WebP (и AVIF при доступности), сохраняет оригинал,
   пишет список вариантов в `MediaAsset.variants` и placeholder (LQIP/blurhash).
2. Веб строит `<img srcset>` из вариантов, без `NuxtImg` для пользовательских картинок;
   `@nuxt/image` остаётся только для статических файлов из `public/` или удаляется, если не
   нужен (решается на этапе 1).
3. `sharp` — зависимость сервера; CI собирает под Linux с пином платформенного бинарника;
   сборка проверяется тестом загрузки.
4. Обрезка и фокусная точка — атрибуты медиа, применяются при генерации вариантов; повторная
   генерация — скрипт по `assetId`.
5. Видео и аудио (этап 5) не транскодируются на старте: загружаются в поддерживаемых форматах
   `[ДОПУЩЕНИЕ]`.

## Следствия

- Тест этапа 1: загрузка → варианты в S3 → страница отдаёт `srcset`; `/_ipx/` для
  пользовательских картинок не используется.
- Пересчёт вариантов при смене набора — скрипт по всем ассетам (минуты на тысячи файлов).

## Цена отката

Переход на обработку на лету — провайдер `@nuxt/image` поверх того же хранилища; оригиналы
хранятся, ничего не теряется.
