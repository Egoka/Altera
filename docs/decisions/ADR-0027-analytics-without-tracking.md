# ADR-0027: Аналитика без трекеров — подсчёт прочтений

- **Статус**: принято 2026-09-05; расширено ADR-0038 (просмотры как вход рейтинга) 2026-09-06; частично заменено журналом Г4 §23 и `docs/spec/60-ranking/engagement-tracking.md` 2026-09-09 — суточный анонимный хэш заменён first-party `visitorId` (cookie на два года); отказ от внешних трекеров (п. 6) в силе; политика ПД и согласия обновляются до запуска
- **Этап**: 3

## Контекст

Счётчики просмотров всегда 0 [ФАКТ: `server/src/graphql/article/resolver.ts:114-116`]; внешних
трекеров нет. Нужны: метрика «популярное» (ADR-0016), метрики этапов роадмапа, при этом —
без профилирования читателей, с учётом 152-ФЗ и рамки «без алгоритмов».

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Внешний счётчик (Яндекс Метрика, GA) | Готовые отчёты | Данные читателей у третьей стороны, cookie-баннеры, зависимость; для «популярного» всё равно нужен свой счётчик |
| Cookie-идентификатор посетителя | Точные «уникальные» | Профилирование, согласие на cookie, хранение идентификатора |
| **Суточный хэш без cookie**: `sha256(соль дня ‖ IP ‖ user-agent)`, уникальность в пределах (день, материал), соль удаляется через 2 дня | Ничего не хранится о человеке; после удаления соли хэши необратимы; без баннеров | Читатель, вернувшийся на другой день, считается снова — это объясняется в подписи метрики |

## Решение

1. Событие прочтения отправляется клиентом после ~10 секунд на странице или прокрутки до
   середины `[ДОПУЩЕНИЕ: порог уточняется]`; известные боты отсекаются по user-agent на сервере.
2. Сервер вычисляет `visitorHash` из соли дня, IP и user-agent; IP не сохраняется; аккаунт в
   хэш не подмешивается — прочтения не привязываются к пользователям.
3. `ReadEvent(day, articleId, visitorHash)` с уникальностью — дедупликация в базе
   (`ON CONFLICT DO NOTHING`); агрегат `ArticleReadDaily(articleId, day, uniqueReads)`
   обновляется в той же транзакции. События хранятся 8 дней, соли — 2 дня, агрегаты —
   бессрочно.
4. «Популярное» — сумма `uniqueReads` за последние 7 дней; подпись читателю: «по числу
   прочтений за неделю».
5. Продуктовые метрики этапов (число авторов, публикаций, прочтений, подписок, платежей)
   считаются SQL из базы; отдельной аналитической системы нет до измеримой потребности.
6. Внешние трекеры не подключаются; если когда-нибудь понадобятся — отдельный ADR и
   согласие.

## Следствия

- Политика персональных данных описывает метод подсчёта.
- Housekeeping-скрипт чистит события и соли (`docs/vision/08-operations.md`).
- Объём: при 10 000 прочтений в день события занимают единицы мегабайт; агрегаты — сотни
  мегабайт за годы `[ДОПУЩЕНИЕ]`.

## Цена отката

Смена метода подсчёта — новая таблица; исторические агрегаты сохраняются. Введение
профилирования — не откат, а другой продукт.
