# ADR-0005: Таксономия — рубрика, формат, теги

- **Статус**: принято 2026-09-05; уточнено журналом: п. 3 — теги создаёт автор (Г7 §26.3 вернуло это после отмены в Г1 §12), сливает и архивирует `admin`/`owner`; п. 4 — рубрика обязательна перед подачей, формат необязателен (Г6 §25.3); архив рубрики только с преемником (Г7 §26.2)
- **Этап**: 1

## Контекст

- `ContentType` — единственная «рубрика» в модели и одновременно префикс адреса материала
  [ФАКТ: `server/prisma/schema.prisma:42-54`, `web/app/pages/[slugTypeContent]/`]; `SectionTag` —
  свободные теги M:N [ФАКТ: `schema.prisma:56-66,84`].
- Фикстуры смешивают темы («National Security», «Спорт») и жанры («Article», «Memoir»,
  «Analysis») в одной сущности [ФАКТ: `web/app/pages/authors/[slug].vue:47-49,70-72,93-95`,
  `web/app/components/visual/MegaMenu.vue:111-225`].
- Продукт описан шестью темами: культура, искусство, фотография, музыка, спорт, путешествия
  [ФАКТ: `package.json:4`, `README.md:5`].
- Содержимое таблицы `content_types` в базе не проверялось [НЕ ПРОВЕРЕНО].

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Оставить `ContentType` как есть, смысл — «что угодно» | Ничего не менять | Тема и жанр в одной оси; адрес материала зависит от жанра; навигация теряет структуру |
| Иерархия рубрик (дерево) | Гибко | Для журнала с шестью темами — лишний слой; адреса удлиняются |
| **Три оси**: рубрика (тема, в адресе, редакционная), формат (жанр, атрибут), теги (свободные) | Каждая ось отвечает на один вопрос: «о чём», «в каком жанре», «какими словами»; адрес стабилен | Переименование таблицы и колонок в миграции |

## Решение

1. **Рубрика** (`Section`, бывший `ContentType`, таблица `sections` через переименование):
   тема материала; задаёт первый сегмент адреса и главную навигацию; управляется редакцией;
   статусы `active | archived`; порядок вручную; локализация парой `name`/`nameEn`. Стартовый
   набор — шесть тем продукта; окончательный список и соответствие существующим строкам
   `content_types` подтверждает владелец перед миграцией (гейт этапа 1).
2. **Формат** (`Format`, таблица `formats`): жанр — эссе, обзор, фоторепортаж, интервью,
   колонка; необязательный атрибут материала; в адрес не входит; управляется редакцией;
   даёт фильтр в каталоге и подпись на карточке.
3. **Теги** (`Tag`, бывший `SectionTag`, таблица `tags`): свободные слова, создаёт автор при
   публикации, редакция сливает и удаляет (`mergeTags` уже есть
   [ФАКТ: `server/src/graphql/sectionTag/resolver.ts:415-512`]); необязательный `nameEn`.
4. У материала ровно одна рубрика, не более одного формата, любое число тегов.
5. Отдельной публичной страницы формата нет до измеренной потребности; формат — фильтр в
   каталоге и поиске.

## Следствия

- Миграция переименовывает `content_types → sections`, `typeId → sectionId`,
  `section_tags → tags`, `_ArticleToSectionTag → _ArticleToTag` через `RENAME`, без потери
  данных (`docs/vision/03-data-model.md`, M4).
- GraphQL-контракт: `contentType` → `section`, `sectionTags` → `tags`; типы фронта
  перегенерируются (ADR-0012).
- Мега-меню строится из рубрик и популярных тегов базы; фикстурные «топики» удаляются.
- Публичный запрос списка рубрик появляется на этапе 0: без него навигация не рендерится из
  API [ФАКТ: единственный `contentTypes` требует `admin`, `server/src/graphql/contentType/schema.graphql:69-75`].

## Цена отката

Обратное переименование — одна миграция без потери данных; удаление формата — `SET NULL`.
Дорого только менять роль рубрики в адресе после индексации (ADR-0004).
