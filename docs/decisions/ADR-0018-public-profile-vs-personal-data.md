# ADR-0018: Публичный профиль и персональные данные

- **Статус**: принято 2026-09-05
- **Этап**: 0

## Контекст

- `User.email: String!` в публичном GraphQL-типе; `user(slug)` отдаёт запись целиком
  [ФАКТ: `server/src/graphql/user/schema.graphql:12`, `server/src/graphql/user/resolver.ts:38-46`];
  операция фронта для страницы автора запрашивает e-mail
  [ФАКТ: `web/app/query/pages/authors/detail.ts:8`].
- Слаг пользователя — локальная часть e-mail [ФАКТ: `server/src/graphql/auth/resolver.ts:23-31`]:
  адрес частично виден в URL профиля.
- 152-ФЗ и здравый смысл: e-mail автора — не публичная информация.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Оставить e-mail в публичном типе, скрывать на фронте | Ничего не менять | Интерфейс — не граница прав; любой запрос получает адрес |
| Настройка «показывать e-mail» у автора | Гибко | Спам, утечка при смене настроек; не нужно при форме связи |
| **Публичный тип без персональных данных; e-mail только у владельца аккаунта через `me`** | Правило простое и проверяемое тестом | Связь с автором — через платформу (позже) |

## Решение

1. Публичный GraphQL-тип `Author` (или `User` без ПДн): `id`, `handle`, `name`, `bio`,
   `avatar`, `socialLinks`, `createdAt`; никаких `email`, `role` не в публичном контексте,
   `lastLoginAt`, `ip`.
2. E-mail, роль, уровень доверия, состояние блокировки, сессии — только в `me` и в админских
   запросах с проверкой роли.
3. Хэндл новых пользователей — случайный `u-{8 hex}`, редактируется в кабинете; e-mail в
   хэндл, имя и адреса не попадает (ADR-0004).
4. Перечень персональных данных и кто их видит (`docs/vision/04-roles-and-access.md`):
   e-mail, имя, IP и user-agent сессий, e-mail жалобщика, реквизиты выплат, e-mail подписчика
   рассылки. В логах — только идентификаторы.
5. Связь читателя с автором — на старте отсутствует; позже форма через платформу без
   раскрытия адреса `[ДОПУЩЕНИЕ: этап 3 или позже, по запросу]`.
6. Контрактный тест этапа 0: в SDL публичных типов нет поля `email`; валидация операций
   фронта отклоняет запрос e-mail вне `me`.

## Следствия

- Изменение SDL и операций фронта на этапе 0 (ADR-0012).
- Существующие слаги-из-e-mail нормализуются миграцией и заменяются случайными хэндлами с
  историей для реальных пользователей (`docs/vision/03-data-model.md`, M3, M7).
- Политика персональных данных (ADR-0028) перечисляет те же поля.

## Цена отката

Ноль технически: вернуть поле в тип. Продуктово и юридически — нежелательно.
