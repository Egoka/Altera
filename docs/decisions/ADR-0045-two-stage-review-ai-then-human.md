# ADR-0045: Двухступенчатая проверка — AI, затем человек, для каждой публикуемой ревизии

- **Статус**: принято 2026-09-06; частично заменено журналом Г1 #8, #14, §6 2026-09-08 — человеческий шаг перед первой публикацией отменён: статья, прошедшая AI-проверку, публикуется автоматически; ручная ветка ревьюера — только после отказа AI, снятия с публикации или повторной подачи (ADR-0047+ по журналу ещё не написаны)
- **Этап**: 1
- **Заменяет**: ADR-0013 (уровни доверия как ворота)

## Контекст

Ответ владельца (заход 0): «первичная проверка через AI, вторичная проверка через админа; все
версии изменений сохраняются». Толкование, положенное в основу: **каждая ревизия, которую
автор отправляет к публикации, проходит две ступени — AI (ADR-0039), затем человек
(`moderator` и выше); публикация происходит после одобрения человеком.** Цикл статусов
`draft → review → published → archived` уже есть в коде [ФАКТ:
`server/src/graphql/article/resolver.ts:592-658`]; публиковать может только `admin`
[ФАКТ: `:633`].

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Только AI как ворота; человек — по жалобам | Не создаёт очереди | Противоречит ответу «вторичная проверка через админа» |
| AI как ворота; человек — только для `uncertain` и оспариваний | Разгружает ревьюера | То же; но это ближайший кандидат, если владелец уточнит ответ |
| **AI, затем человек — для каждой публикуемой ревизии** | Буквально по ответу; максимальный контроль качества журнала | Очередь растёт с числом авторов при одном ревьюере; повторная проверка каждой правки опубликованного текста |

## Решение

1. Состояния версии: `draft → ai_review → review → published`; `ai_review` — техническое
   состояние ожидания вердикта AI (секунды–минуты), `review` — очередь человека. Обратные
   переходы: `ai_review → draft` (вердикт `fail`, причины автору), `review → draft` (возврат с
   причиной), `review → published` (одобрение). Существующие мутации переименовываются по
   `05-editor.md` §2.
2. Ступень 1 — AI (ADR-0039): `pass` и `uncertain` → `review` с пометкой; `fail` → `draft`
   с пояснениями; автор может оспорить `fail` — версия идёт в `review` с пометкой «оспорено»,
   лимит оспариваний в сутки `[ДОПУЩЕНИЕ: 2]`.
3. Ступень 2 — человек: `moderator`, `admin`, `owner` одобряют или возвращают с причиной;
   `editor` может править текст в `review` с ревизией `editorial` (ADR-0042 п. 3), но не
   одобряет `[ДОПУЩЕНИЕ]`. SLA — 48 часов в правилах публикации (ADR-0028).
4. **Правка опубликованной версии** создаёт ревизию, которая проходит обе ступени как новая
   публикация; до одобрения читатель видит прежнюю опубликованную ревизию (ADR-0007). Это
   прямое следствие «каждая ревизия проверяется» и главный источник нагрузки на ревьюера.
5. Все ревизии сохраняются (ADR-0007); автор видит историю решений по каждой.
6. Уровни доверия отменяются (ADR-0037); admin-роли, публикующие свои материалы, проходят
   AI-ступень и одобряют сами `[ДОПУЩЕНИЕ]`.
7. Очередь проверки в админке — обязательная часть этапа 1: сортировка по
   `reviewRequestedAt`, фильтр «оспорено» и «AI не уверен», действия «одобрить», «вернуть с
   причиной», просмотр AI-вердикта и балла.

## Следствия

- Метрика этапа 1: медиана «отправлено → решение человека»; при росте очереди владелец
  принимает решение об уточнении п. 3 (быстрый путь для проверенных авторов) новым ADR.
- Письма автору: результат AI, результат человека.
- Спецификации: `docs/spec/10-flows/write-and-publish.md`, `moderation.md`,
  `docs/spec/40-admin/review-queue.md`.

## Цена отката

Низкая: убрать ступень 2 для части авторов — одно правило; состояния остаются.
