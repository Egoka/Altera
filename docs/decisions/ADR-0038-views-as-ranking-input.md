# ADR-0038: Просмотры как вход рейтинга

- **Статус**: принято 2026-09-06; заменено журналом Г4 §21, §23 и `docs/spec/60-ranking/engagement-tracking.md` 2026-09-09 — вход рейтинга: сигналы вовлечённости с `visitorId`, автоматические исключения без ручной пометки
- **Этап**: 2
- **Расширяет**: ADR-0027 (не заменяет)

## Контекст

Рейтинг статьи учитывает просмотры (ADR-0034, ADR-0043). ADR-0027 уже определяет подсчёт
прочтений без профилирования: суточный хэш из соли, IP и user-agent, `ReadEvent` с
дедупликацией и агрегат `ArticleReadDaily(articleId, day, uniqueReads)`; в ревизии 1 это
питало только блок «Популярное» этапа 3. Счётчики в коде всегда 0 [ФАКТ:
`server/src/graphql/article/resolver.ts:114-116`].

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Сырые просмотры (каждый запрос страницы) | Просто | Накручиваются перезагрузкой; боты; противоречит ADR-0027 |
| Привязка прочтений к аккаунту | Точнее для авторизованных | Профилирование; гостей всё равно большинство |
| **Уникальные суточные прочтения ADR-0027 как единственный источник; вход рейтинга — агрегат за окно** | Уже спроектировано; без ПДн; дедупликация в базе | Читатель, вернувшийся на другой день, считается снова — допустимо для рейтинга |

## Решение

1. Источник компонента «просмотры» — `ArticleReadDaily`; сырые события в рейтинг не
   входят. Механика ADR-0027 (порог ~10 секунд или прокрутка до середины, фильтр ботов по
   user-agent, соль дня, хранение событий 8 дней) сохраняется без изменений.
2. Вход рейтинга — сумма `uniqueReads` за скользящее окно (по умолчанию 7 дней
   `[ДОПУЩЕНИЕ]`) с нормализацией относительно медианы ленты — детали в
   `docs/spec/60-ranking/views-counting.md`; окно и нормализация — параметры `RankingConfig`.
3. Подсчёт прочтений переезжает с этапа 3 на **этап 2** вместе с рейтингом.
4. Видимость: автор видит прочтения своих материалов по дням (кабинет, страница статистики
   статьи); `analyst` — агрегаты по всем материалам без персональных данных (ADR-0042);
   читателю число прочтений не показывается `[ДОПУЩЕНИЕ]`.
5. Защита от накрутки: собственные просмотры автора не отсекаются по аккаунту (аккаунт в хэш
   не входит), поэтому антинакрутка строится на аномалиях — всплеск уникальных хэшей с одного
   диапазона адресов, отсутствие прокрутки, повторяющийся user-agent; правила и логирование —
   `docs/spec/60-ranking/anti-fraud.md`; подозрительные дни помечаются и исключаются из
   рейтинга модератором с аудитом.

## Следствия

- `08-operations.md`: housekeeping событий и солей — с этапа 2.
- Политика персональных данных описывает метод подсчёта до этапа 2 (уже требовалось для
  этапа 3).
- Событие `read` попадает в реестр событий (`docs/spec/00-registries/events-and-logs.md`).

## Цена отката

Низкая: сменить окно или источник — параметр; агрегаты сохраняются.
