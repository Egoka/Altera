# ADR-0054: Реестр событий заморожен до конца этапа 1

- **Статус**: принято 2026-09-14
- **Этап**: 1

## Контекст

В проекте ведётся реестр кодов событий аудита и наблюдаемости. По результатам гейта Г8b
(журнал §28.3, 2026-09-09) введена явная заморозка реестра до конца этапа 1. Нужен ADR,
фиксирующий это правило для всех разработчиков и агентов.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Новые коды добавляются по мере необходимости без формального контроля | Гибкость | Реестр разрастается; коды дублируются; аудит теряет целостность |
| **Реестр заморожен; новый код — только при реальной необходимости после решения владельца** | Стабильный реестр; аудит предсказуем | Небольшое замедление при добавлении новых событий |
| Полная заморозка без возможности добавления | Максимальная стабильность | Блокирует важные расширения |

## Решение

1. Реестр кодов событий заморожен до конца этапа 1 (журнал §28.3).
2. Новые коды добавляются только при реальной необходимости и только после отдельного
   решения владельца (журнал §28.3).
3. При наличии замороженного реестра новые коды для сущностей, не требующих их добавления,
   не создаются. ADR-0053 (единое alt) явно следует этому правилу (журнал §29.13).

Границы: ADR не перечисляет существующие коды реестра и не задаёт их формат — это задача
отдельной спецификации или реестрового файла.

## Следствия

- Pull request с новым кодом события должен содержать обоснование реальной необходимости,
  согласованное с владельцем.
- Агенты при реализации новых сущностей проверяют реестр перед созданием нового кода.

## Цена отката

Минимальная: разморозка — решение владельца, не требующее изменений кода.
