# ADR-0016: «Избранное», «популярное» и две ленты на главной

- **Статус**: принято 2026-09-05
- **Этап**: 1 (ленты), 2 (отбор), 3 (популярное)

## Контекст

- `featuredArticles` возвращает последние опубликованные, `popularArticles` — свежие за
  период, счётчики просмотров всегда 0 [ФАКТ: `server/src/graphql/article/resolver.ts:257-258,
  333-334, 114-116`]. Главная на фикстурах [ФАКТ: `docs/vision/00-reality-check.md` §5.3].
- Рамка «без алгоритмов» буквально: ранжирование редакционное и хронологическое, объяснимое
  читателю; «популярное» — на названной прозрачной метрике, без персонализации.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Флаг `isFeatured` на материале | Просто | Нет позиции, срока, автора решения; не отличает главную от витрины |
| **`EditorialPick` с размещением, позицией, сроком и автором отбора** | Редакционное решение как запись; истекает само | Отдельная таблица |
| «Популярное» по просмотрам всех времён | Просто | Старые материалы навсегда сверху |
| «Популярное» по «хлопкам»/реакциям | Вовлекает | Реакций нет (ADR-0026); метрика непрозрачна |
| **«Популярное» = сумма уникальных прочтений за последние 7 дней** | Прозрачно, объяснимо, без профилирования | Читатель, вернувшийся через день, считается дважды — это объясняется в подписи |
| Одна смешанная лента «главное + новое» | Привычно | Читатель не отличает редакционный выбор от самопубликации |

## Решение

1. **Избранное** — ручной отбор редакции: `EditorialPick(placement: home | showcase,
   position, startsAt, expiresAt, pickedById)`. Истёкший отбор исчезает без участия людей.
   Отбирается материал; на локали показывается только при опубликованной версии в этой
   локали.
2. **Популярное** — материалы с наибольшей суммой суточных уникальных прочтений за последние
   7 дней (ADR-0027), в локали читателя, только `published`. Подпись на странице: «по числу
   прочтений за неделю». Персонализации нет; список одинаков для всех.
3. **Главная** — две явно подписанные ленты: «Выбор редакции» (отборы `home` по позиции) и
   «Свежее» (хронологический поток всех опубликованных версий локали, обоих контуров, с
   пометкой контура на карточке). На этапе 1 «Выбор редакции» имеет пустое состояние, блока
   «Популярное» нет до этапа 3.
4. Страница витрины (`/showcase` `[ДОПУЩЕНИЕ: адрес уточняется в 06]`) — отборы `showcase`
   и заказные материалы; архив витрины — часть подписки на витрину (этап 4), при этом
   отобранные материалы открытого контура остаются бесплатными.
5. Все списки сортируются хронологически по `publishedAt` версии; никаких скрытых весов.

## Следствия

- Резолверы `featuredArticles` и `popularArticles` заменяются на `editorialPicks(placement,
  locale)` и `popularArticles(locale)` с новой семантикой; кеш популярного — 10 минут, если
  Redis включён (ADR-0019).
- Подсчёт прочтений — этап 3; до него блок отсутствует, а не показывает «свежие».
- Тексты подписей лент и метрики — часть дизайн-системы (`06`).

## Цена отката

Низкая: определения — код и одна таблица. Дорого лишь продуктово: поменять смысл
«популярного» после того, как читатели к нему привыкли.
