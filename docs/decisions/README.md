# Журнал архитектурных решений (ADR)

Здесь лежат решения, которые дорого менять потом, и решения, принятые вопреки очевидной
альтернативе. Каждое — отдельный файл. Цель журнала: через год ответить на вопрос «почему так»
записью, а не памятью.

## Имя файла

```
docs/decisions/ADR-NNNN-краткое-имя.md
```

Номер — четыре цифры, сквозная нумерация, никогда не переиспользуется. Слаг — латиницей, в
нижнем регистре, через дефис.

## Шаблон

```markdown
# ADR-NNNN: Название решения

- **Статус**: принято ГГГГ-ММ-ДД | заменено ADR-NNNN ГГГГ-ММ-ДД
- **Этап**: на каком этапе роадмапа решение вступает в силу

## Контекст
Что есть в коде и в продукте, почему решение нужно именно сейчас. Факты — со ссылками
`файл:строка` или на `docs/vision/00-reality-check.md`.

## Рассмотренные варианты
Не меньше двух. Для каждого — чем хорош и чем плох в условиях одного разработчика.

## Решение
Что именно принято, в утвердительной форме. Границы: чего решение не покрывает.

## Следствия
Что становится возможным, что становится обязательным, что ломается или требует правки.

## Цена отката
Что придётся сделать, если решение окажется ошибочным, и во что это обойдётся
(в человеко-днях и в потерянных данных). Если откат невозможен без потери — сказать прямо.

## Связи
Документы, другие ADR и этапы роадмапа, которые на это решение опираются.
```

## Правила

1. ADR не редактируется задним числом. Изменилось решение — новый ADR со статусом «принято» и
   пометка «заменено ADR-NNNN» в старом.
2. Каждое утверждение о текущем состоянии кода помечается `[ФАКТ: файл:строка]`; всё, что не
   проверено, — `[ДОПУЩЕНИЕ]`.
3. Документы `docs/vision/*` и `docs/issues/*` ссылаются на ADR по номеру и не пересказывают
   обоснование.
4. Продуктовые рамки, зафиксированные владельцем в `CLAUDE.md` (гибридная модель,
   правило-арбитр по деньгам, «без алгоритмов», MIT только для кода, российский платёжный
   контур, полные переводы материалов), в ADR не пересматриваются: под них проектируют.
