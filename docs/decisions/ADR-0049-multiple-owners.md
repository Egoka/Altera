# ADR-0049: Несколько равноправных владельцев; запрет нулевого состояния

- **Статус**: принято 2026-09-14
- **Этап**: 0–1

## Контекст

Изначально модель предполагала единственного владельца системы (`owner`). По результатам
гейта Г1 (журнал #10, §2, 2026-09-08) введена возможность иметь несколько равноправных
владельцев. Нужно зафиксировать модель управления этой ролью и защиту от потери всех
владельцев.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Единственный владелец | Простота | Риск недоступности системы при единственной точке отказа |
| **Несколько равноправных владельцев; любой может назначить или отозвать другого; система запрещает нулевое состояние** | Устойчивость; нет иерархии внутри роли | Нужна защита от одновременного снятия всех владельцев |
| Иерархия суперадмин → администратор | Чёткая цепочка передачи | Лишняя сложность при одном разработчике |

## Решение

1. В системе может быть несколько равноправных `owner`. Каждый из них имеет все права
   `admin` и дополнительные исключительные полномочия (журнал #10).
2. Любой `owner` может назначить другого `owner`, отозвать роль или деактивировать
   административный доступ другого `owner` (журнал #10).
3. Система не допускает состояния с нулём владельцев: операция, которая оставила бы ноль
   активных `owner`, должна быть отклонена (журнал #10).
4. Нового `owner` назначают в два шага: сначала создаётся отдельная служебная учётная
   запись, затем ей выдаётся роль владельца. Назначение напрямую на произвольный e-mail
   без создания учётной записи не допускается (журнал §26.7).
5. Обычный `admin` не может архивировать или восстанавливать служебный аккаунт другого
   `admin`. Такие действия доступны только `owner` (журнал §26.7).
6. Все действия по назначению, отзыву и деактивации `owner` аудируются (журнал #7, раздел §2).

Границы: этот ADR описывает только модель множественных владельцев. Полный набор прав
`owner` определяют ADR-0003, ADR-0042, ADR-0048.

## Следствия

- API-операция отзыва роли `owner` должна проверять остаток активных владельцев перед
  подтверждением.
- Интерфейс назначения владельца реализуется только через форму создания служебной записи
  с последующим выбором роли, а не через прямое указание e-mail.

## Цена отката

Низкая: если понадобится вернуться к единственному владельцу, достаточно организационного
решения и удаления лишних записей; схема не меняется.

## Связи

- Журнал #10, §26.7, раздел §2.
- ADR-0003 (роли), ADR-0042 (управление администраторами).
