# ADR-0037: Грейд автора выводится из плана; уровни доверия упраздняются

- **Статус**: принято 2026-09-06
- **Этап**: 1 (грейд), 2 (грейд в рейтинге)
- **Заменяет**: ADR-0013 (уровни доверия как ворота публикации)

## Контекст

Владелец: pro-подписка «повышает грейд автора» (ADR-0043); каждая статья проходит проверку
AI, затем человеком (ADR-0045). Ревизия 1 держала ось доверия `User.trustLevel: probation |
trusted`: первые материалы через проверку, дальше — мгновенно (ADR-0013). При обязательной
двухступенчатой проверке каждой публикуемой ревизии уровень доверия перестаёт что-либо
решать. В коде поля доверия нет [ФАКТ: `server/prisma/schema.prisma:12-26` — `User` без
`trustLevel`].

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Оставить `trustLevel` как «быстрый путь» мимо человеческой проверки для проверенных авторов | Разгружает ревьюера | Противоречит ответу владельца: вторичная проверка человеком — для каждой статьи |
| Оставить `trustLevel` как пометку модератора без влияния на процесс | Дёшево | Поле без поведения — мёртвая ось; для «под наблюдением» достаточно блокировки и жалоб |
| **Одна ось — грейд автора, выводимый из плана; доверия нет** | Соответствует продукту; меньше состояний | Ручной способ выделить автора — только через грант плана |

## Решение

1. `AuthorGrade { basic pro }` **вычисляется** из `User.planTier` (`standard → basic`,
   `pro → pro`; admin-роли без подписки — `basic` `[ДОПУЩЕНИЕ]`); отдельного поля нет, чтобы
   грейд и план не расходились.
2. Грейд — вход рейтинга автора (`AuthorScore`, ADR-0034): pro-грейд даёт постоянную
   надбавку к рейтингу автора; величина — параметр `RankingConfig`. Буст на сутки (ADR-0040) —
   отдельный вход, не грейд.
3. `User.trustLevel`, `trustChangedAt`, `trustChangedById`, функция `needsReview`, бэкфилл
   доверия в M3, действия `trust.reset` / `trust.grant` — удаляются из модели, матрицы и аудита.
4. Способы реакции редакции на нарушения — возврат на доработку, снятие с публикации с
   причиной, блокировка (ADR-0014 п. 2, 4) — без промежуточного «сброса доверия».
5. Публичный бейдж pro-автора показывается на странице автора и карточке материала
   `[ДОПУЩЕНИЕ: показывать — да]`; факт буста конкретной статьи — нет (ADR-0040).

## Следствия

- Матрица прав `04-roles-and-access.md` теряет строки про доверие; очередь проверки не
  фильтрует по нему.
- Раздел «Пользователи» в админке показывает план, грейд, срок подписки вместо доверия.
- Автор, потерявший pro, теряет надбавку при ближайшем пересчёте (ADR-0044).

## Цена отката

Низкая: вернуть `trustLevel` — одна колонка и одна функция; данных не теряется.
