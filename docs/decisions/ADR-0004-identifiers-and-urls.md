# ADR-0004: Идентификаторы и схема адресов

- **Статус**: принято 2026-09-05; дополнено журналом Г7 2026-09-09 — п. 4, 6: слаги всех публичных сущностей и хэндлы уникальны навсегда, архив и удаление навсегда адрес не освобождают (§26.10); смена рубрики при её архиве — перенос в преемника с 301 (§26.2)
- **Этап**: 1

## Контекст

Адреса — самое дорогое в изменении после первых внешних ссылок и индексации. Сейчас:

- Идентификаторы — uuid в `TEXT` без DEFAULT в базе [ФАКТ: `server/prisma/schema.prisma:13,69`].
- Адрес материала `/{contentType.slug}/{article.slug}` [ФАКТ: `web/app/pages/[slugTypeContent]/[slugArticle].vue`],
  автора `/authors/{slug}`, тега `/tags/{slug}`; слаг материала приходит с клиента и
  проверяется только уникальным индексом [ФАКТ: `server/src/graphql/article/schema.graphql:105`].
- Слаг пользователя — локальная часть e-mail [ФАКТ: `server/src/graphql/auth/resolver.ts:23-31`]:
  утечка адреса и коллизия при втором `ivan@`.
- Ссылки «Popular» и «Latest» в шапке ведут на несуществующие страницы
  [ФАКТ: `web/app/components/app/header.vue:64-69`].

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Идентификатор в адресе (`/p/{uuid}` или `/{slug}-{id}`) | Никаких коллизий и редиректов | Уродливые адреса для журнала; uuid в адресе — 36 символов |
| Только слаг без рубрики (`/{slug}`) | Короче | Слаг должен быть глобально уникальным; рубрика в адресе даёт читателю контекст и структуру для SEO |
| **`/{рубрика}/{слаг}`** с историей слагов для редиректов | Читаемые адреса; рубрика — навигация; редиректы не теряют ссылки | Перенос между рубриками — редирект (таблица истории) |
| Дата в адресе (`/2026/09/slug`) | Уникальность по времени | Журнал о культуре не новостной; даты в адресах мешают обновлениям |

## Решение

1. Внутренние идентификаторы — uuid, как сейчас; в адреса они никогда не попадают.
2. Публичные адреса:

| Что | Русский | Английский |
|---|---|---|
| Материал | `/{рубрика}/{слаг}` | `/en/{section}/{slug}` |
| Рубрика | `/{рубрика}` | `/en/{section}` |
| Автор | `/authors/{handle}` | `/en/authors/{handle}` |
| Тег | `/tags/{слаг}` | `/en/tags/{slug}` |
| Подборка | `/collections/{слаг}` | `/en/collections/{slug}` |
| Поиск | `/search?q=` | `/en/search?q=` |
| Кабинет, админка, вход, юр. тексты | `/me/*`, `/admin/*`, `/login`, `/auth/verify`, `/legal/*` | те же с `/en` |

3. Слаги — латиница, нижний регистр, `[a-z0-9-]`, транслитерация русских заголовков на
   сервере; слаг предлагается автоматически, автор может править до первой публикации.
4. Уникальность слага материала — в пределах локали (ADR-0002); слаги рубрик — глобально;
   хэндлы авторов — глобально, `[a-z0-9-]{3,32}`.
5. Зарезервированные первые сегменты (`en`, `authors`, `tags`, `collections`, `search`, `me`,
   `admin`, `auth`, `login`, `legal`, `api`, `rss`, `sitemap.xml`) не могут быть слагом рубрики;
   список хранится в одном месте.
6. История слагов (`ArticleSlugHistory`) и хэндлов (`HandleHistory`): старый адрес отвечает
   301 на текущий, включая смену рубрики. Занять слаг, который сейчас редиректит на чужой
   материал, нельзя.
7. Новый пользователь получает случайный хэндл `u-{8 hex}` и меняет его в кабинете; e-mail в
   хэндл не попадает (ADR-0018).
8. Черновики зарезервированный слаг держат, но по адресу отвечают 404 гостю.

## Следствия

- Появляются таблицы истории слагов и хэндлов (`docs/vision/03-data-model.md`).
- Резолвер адреса: версия локали по `(locale, slug)` → история → 404.
- Мега-меню и ссылки шапки строятся из рубрик базы, а не из фикстур
  [ФАКТ: `web/app/components/visual/MegaMenu.vue:111-248`].
- Существующие `users.slug` нормализуются миграцией; для реальных пользователей — просьба
  сменить хэндл или замена на случайный с записью в историю.

## Цена отката

Схему адресов после индексации менять нельзя без карты редиректов: цена растёт с числом
внешних ссылок. Таблица истории делает большинство изменений (рубрика, слаг) бесплатными.
