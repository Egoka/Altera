# ADR-0001: Модель контента — JSON-документ ProseMirror вместо MDC

- **Статус**: принято 2026-09-05
- **Этап**: 1 (модель данных v2 и первый редактор)

## Контекст

Это самое дорогое решение проекта: от формата хранения материала зависят редактор, серверный
рендер, версии, переводы, совместная работа, SEO и стоимость любых будущих миграций.

Что есть в коде:

- `Article.body` — обычная строка [ФАКТ: `server/prisma/schema.prisma:73`]; никакого разбора
  на сервере, `wordCount` считается по пробелам [ФАКТ: `server/src/graphql/article/resolver.ts:108-109`].
- Ни `@nuxtjs/mdc`, ни `@nuxt/content`, ни какого-либо редактора в зависимостях нет
  [ФАКТ: `web/package.json:12-30`]; страница материала выводит только параметр маршрута
  [ФАКТ: `web/app/pages/[slugTypeContent]/[slugArticle].vue:6-10`].
- README, `package.json` и `.cursor/rules` обещают «редактор на MDC» [ФАКТ: `README.md:15`,
  `package.json:4`], но это намерение, а не состояние. Переходить не с чего: выбор делается с
  чистого листа, контента, который пришлось бы конвертировать, в модели нет.

Целевые авторы — люди пишущие и снимающие, а не программисты; авторов и читателей пока ноль;
редакции нужны замечания к тексту, ревизии и переводы; на этапе 6 — совместное редактирование.

## Рассмотренные варианты

| Вариант | За | Против для одного разработчика |
|---|---|---|
| **MDC** (Markdown + компоненты в тексте) | Текстовые диффы, переносимость, дешёвый первый шаг (textarea + предпросмотр), рендер через `@nuxtjs/mdc` | Автору нужно учить синтаксис компонентов; настройки блока — строковые пропсы без проверки типов; вложенные компоненты неудобны; визуальный редактор поверх MDC — это второй формат и потери при round-trip; пути к совместному редактированию нет (CRDT над текстом ломает синтаксис компонентов) |
| **JSON-документ ProseMirror** (редактор TipTap для Vue 3) | Схема документа строго задаёт, какие узлы, марки и атрибуты существуют; визуальный редактор из коробки; серверный рендер (`@tiptap/static-renderer` или свой рендерер JSON → Vue); ревизии — снимки JSON; совместная работа через Y.js — стандартный путь; формат общий для TipTap, BlockNote и любых ProseMirror-редакторов | Диффы структурные (человеку показываем diff экспорта); нужно поддерживать схему и рендерер самим; больше кода на старте, чем textarea |
| **Гибрид** (Markdown в хранилище + блочная надстройка) | Кажется «лучшим из двух» | Две истины и потери при каждом round-trip; самый дорогой в поддержке |
| Lexical | Сильная модель | React-first, для Vue — сторонние обёртки |
| Editor.js | Просто | Плоский список блоков без строгой вложенности и схемы марок; слабый путь к совместной работе |
| BlockNote | Готовые блоки | ProseMirror внутри, но React-first |
| FishtVue `TextEditor` (Quill 2) | Уже есть в библиотеке владельца | Delta/HTML — модель для форм, а не для материала: нет пользовательских блоков со схемой, нет вложенности, нет пути к ревизиям по блокам. Годится для коротких rich-полей админки |

## Решение

1. Каноническое хранилище материала — **JSON-документ ProseMirror** в `ArticleTranslation.body`
   (тип `Json`), одна схема на проект (ADR-0029).
2. Редактор — TipTap (`@tiptap/vue-3`, `@tiptap/pm`, StarterKit v3 как основа: параграф,
   заголовки, цитата, списки, разделитель; марки bold/italic/link) плюс собственные узлы для
   изображений с подписью и остальных блоков каталога (ADR-0017).
3. Каждый блочный узел получает стабильный `attrs.id` (uuid) при создании — к нему привязываются
   замечания редактора и якоря.
4. Изображения в документе ссылаются на `assetId` медиа-библиотеки, не на URL (ADR-0008).
5. Рендер на сервере — из JSON в Vue-компоненты дизайн-системы (SSR, SEO); тот же рендерер
   даёт HTML для RSS и писем.
6. Экспорт в Markdown и HTML — обязательная функция для переносимости и бесплатна для автора.
7. MDC не вводится ни как хранилище, ни как промежуточный формат.

## Следствия

- Появляется пакет `packages/content` со схемой, валидацией и рендерером, общий для сервера и
  веба (ADR-0029); сервер отклоняет документ с неизвестными узлами или атрибутами.
- Ревизии (ADR-0007) — снимки JSON; сравнение версий делается по блокам с показом текстового
  diff экспорта.
- Совместная работа на этапе 6 — Y.js + `@tiptap/extension-collaboration`, JSON остаётся
  снимком состояния (ADR-0033).
- README, `package.json` и правила в `.cursor/` больше не описывают продукт; их правка — пункт
  этапа 1.
- Автору не нужно знать никакого синтаксиса; цена — редактор пишется и поддерживается нами.

## Цена отката

| Куда откатываться | Что делать | Оценка |
|---|---|---|
| На MDC | Сериализатор JSON → MDC (частично с потерями для атрибутов блоков) плюс визуальный редактор поверх MDC или обучение авторов синтаксису | 3–5 чд на конвертер, редактор — с нуля |
| На другой ProseMirror-редактор (BlockNote, свой) | Формат тот же; переписать обвязку | 2–4 чд |
| На Lexical/Editor.js | Конвертер с потерями; редактор с нуля | 5+ чд плюс редактор |

Данные не теряются ни в одном сценарии: JSON — самодостаточный формат.
