# ADR-0019: Redis — необязательный кеш

- **Статус**: принято 2026-09-05
- **Этап**: 0

## Контекст

- Без `REDIS_URL` процесс падает при импорте [ФАКТ: `server/src/redis.ts:3-8`]; клиент создан
  с `maxRetriesPerRequest: null` [ФАКТ: `redis.ts:10-12`], и каждый публичный запрос начинается
  с `redis.get`, поэтому при недоступном Redis API не деградирует, а ждёт
  `[ДОПУЩЕНИЕ: семантика очереди команд ioredis]`.
- TTL везде 6 часов, включая админские списки [ФАКТ: `server/src/utils/admin.ts:7`,
  `article/resolver.ts:34`]; ключ админского кеша не включает поисковый запрос
  [ФАКТ: `article/resolver.ts:439`]; инвалидация через блокирующий `KEYS` в 13 местах; публикация
  не сбрасывает кеши страниц автора, рубрики и тега [ФАКТ: `docs/vision/00-reality-check.md` §3.6].
- Нагрузка нулевая; один разработчик; лишняя обязательная зависимость — лишняя точка отказа.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Оставить Redis обязательным и починить инвалидацию | Кеш уже написан | Точка отказа без пользы при нулевой нагрузке; `KEYS` и пропуски инвалидации всё равно переписывать |
| Убрать Redis совсем | Проще | Понадобится при росте для популярного, лимитов и сессий; переписывать дважды |
| **Redis необязателен: кеш-обёртка с таймаутом и деградацией; при отсутствии — прямые запросы; лимиты частоты в памяти процесса** | Стартует без Redis, включается одной переменной; правильная инвалидация по спискам ключей | Небольшой слой абстракции |

## Решение

1. Сервер стартует без `REDIS_URL`; кеш — обёртка `cache.get/set/del/delByTags` с реализациями
   `redis` и `noop`. Таймаут любой операции кеша — 300 мс, ошибка кеша не ломает запрос
   `[ДОПУЩЕНИЕ: значение уточняется]`.
2. Инвалидация — по тегам (список ключей на тег в Redis `SET`), без `KEYS`; публикация,
   снятие и правка версии инвалидируют теги материала, автора, рубрики, тегов, локали и
   главной.
3. TTL: публичные списки — 5 минут, страница материала — до инвалидации (не более 1 часа),
   популярное — 10 минут, админские списки — не кешируются (`[ДОПУЩЕНИЕ]`, уточняется по
   измерениям).
4. Ключи включают все аргументы запроса, включая поиск и локаль.
5. Лимиты частоты (ADR-0024): в Redis, если он есть; иначе в памяти процесса (достаточно для
   одного инстанса на старте).
6. Черновики и всё, что зависит от прав, не кешируется в общем кеше.

## Следствия

- Этапы 0–2 могут жить без Redis; включение — одна переменная окружения.
- Тест этапа 0: без `REDIS_URL` публичные запросы отвечают; при недоступном Redis ответ
  укладывается в 1 секунду.
- Бюджет инфраструктуры без Redis на старте (`docs/vision/08-operations.md`).

## Цена отката

Низкая: сделать Redis обязательным — убрать реализацию `noop`.
