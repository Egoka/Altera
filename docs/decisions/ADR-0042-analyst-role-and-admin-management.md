# ADR-0042: Роль `analyst`; управление администраторами и статистика с этапа 1

- **Статус**: принято 2026-09-06
- **Этап**: 1
- **Заменяет**: ADR-0003 п. 1 (состав enum); `02-target-architecture.md` §4.3 в части
  «назначение ролей скриптом до этапа 5» и «отчёты — этап 5»

## Контекст

Владелец: администраторы делятся на супер-админа, аналитика, ревьюера и, возможно, другие
роли; разделы «управление админами» и «статистика» — обязательные части админки
(ADR-0043). Ответы захода 0: `analyst` видит только агрегаты без персональных данных;
`editor` остаётся для работы с текстом и таксономией. Ревизия 1: шесть ролей (ADR-0003),
назначение из интерфейса — этап 5, отчёты — этап 5. В коде роли `reader | author | editor |
admin`, `editor` без прав [ФАКТ: `server/prisma/schema.prisma:89-94`;
`docs/vision/00-reality-check.md` §3.4].

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Новый enum `reader / author / reviewer / analyst / admin / superadmin` | Слово в слово как у владельца | Ломает ADR-0003 и матрицу целиком; «ревьюер» и «модератор» — одно и то же |
| **Сопоставить: супер-админ = `owner`, ревьюер = `moderator`; добавить `analyst`; оставить `editor`** | Минимальные правки; `owner` уже «ровно один» с передачей владения | Названия в интерфейсе отличаются от enum — решается подписями |
| Таблица разрешений (RBAC) | Гибко | Отклонено в ADR-0003; для одного разработчика лишний слой |

## Решение

1. `enum Role { reader author editor moderator analyst admin owner }`. Подписи в интерфейсе:
   `owner` — «Владелец (супер-админ)», `moderator` — «Ревьюер», `analyst` — «Аналитик».
2. **`analyst`**: читает разделы «Статистика», «Сводка», агрегаты по подпискам и платежам,
   разложение рейтинга; **ни одной мутации** (контрактный тест по SDL: ни одно поле
   `Mutation` не разрешено роли); не видит список пользователей, e-mail, карточки
   пользователей, тексты жалоб; экспорт агрегатов в CSV — да.
3. **`editor`**: таксономия (рубрики, форматы, теги), замечания к блокам, правка чужого
   текста на ступени человеческой проверки (ADR-0045) с ревизией `editorial`, переводы; не
   решает жалобы и не блокирует.
4. **`moderator`** (ревьюер): вторая ступень проверки (одобрить, вернуть с причиной), жалобы,
   снятие с публикации, блокировка не выше себя, переопределение AI-оценки (ADR-0039).
5. **Назначение ролей из интерфейса — этап 1**: раздел «Администраторы» в админке; `owner`
   назначает и снимает `admin`; `admin` и `owner` — `editor`, `moderator`, `analyst`; нельзя
   назначить роль выше своей или снять роль с себя; каждое изменение — `user.role.change` в
   аудит и письмо назначенному. Сид создаёт первого `owner` (ADR-0003 п. 3 сохраняется).
6. **Статистика — этап 1** в базовом виде (публикации, регистрации, подписки, прочтения с
   этапа 2) как SQL-отчёты в админке; расширенные отчёты — этап 4 ревизии 2.
7. Иерархия по включению (ADR-0003, `04-roles-and-access.md` §1) сохраняется для `editor <
   moderator < admin < owner`; `analyst` вне иерархии — параллельная роль только для чтения.

## Следствия

- Матрица прав получает колонку `analyst` и строки для управления администраторами.
- Миграция enum: значение `analyst` добавляется отдельной миграцией (`03-data-model.md` §2).
- Аудит-лог появляется на этапе 1 хотя бы для ролей и подписок (ревизия 1 — этап 2).

## Цена отката

Низкая: значение enum и один раздел админки.
