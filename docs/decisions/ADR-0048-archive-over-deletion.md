# ADR-0048: Архив как операция по умолчанию; необратимое удаление только владельцем

- **Статус**: принято 2026-09-14
- **Этап**: 1

## Контекст

В системе множество сущностей допускают удаление: статьи, аккаунты пользователей,
административные учётные записи, элементы таксономии. Нужно явно зафиксировать, что означает
«удалить» в разных контекстах и кто имеет право на необратимое удаление. Журнал §1–4 и раздел
§3 (2026-09-08) устанавливают единое правило для всех сущностей.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Физическое удаление как действие по умолчанию | Простота | Нет возможности исправить ошибку; потеря данных, аудита и истории |
| **Архивирование по умолчанию; необратимое удаление — отдельное исключительное право владельца** | Обратимость для обычных операций; данные и аудит сохраняются | Нужна явная иерархия прав на архивирование и разархивирование |
| Мягкое удаление с автоматической очисткой через период | Баланс | Случайно удалённые данные сложно восстановить в период TTL |

## Решение

1. Обычная операция «удалить» означает обратимое архивирование: сущность переходит в статус
   архива, скрывается из обычной выдачи, но сохраняет историю, версии, связи и аудит
   (журнал #1, #2).
2. Только `owner` имеет отдельное исключительное действие «удалить навсегда» для любой
   сущности. Перед выполнением требуется отдельный диалог с вводом имени удаляемой сущности;
   операция аудируется (журнал #1, #49). Подтверждение другого сотрудника или владельца
   не требуется — достаточно усиленного диалога (журнал #49).
3. При архивировании сохраняются актор и уровень его прав. Роль с меньшими полномочиями
   не может отменить архивирование, выполненное ролью с большими полномочиями (журнал #3).
4. Архивирование пользователя каскадно архивирует связанные с ним статьи (журнал #4). Возврат
   возможен; при восстановлении аккаунта статьи не возвращаются в публичный доступ
   автоматически — автор возвращает их вручную (журнал раздел §5).
5. Сущность, доступная ранее публично, но затем архивированная, получает HTTP 410 по старому
   адресу с понятной страницей (журнал §28.2).
6. Слаги и адреса всех публичных сущностей уникальны навсегда: архивирование и необратимое
   удаление не освобождают адрес для повторного использования (журнал §26.10).

## Следствия

- Каждый интерфейс «удаления» реализует архивирование, а не физическую очистку.
- Кнопка «удалить навсегда» — отдельный UI-элемент с усиленным диалогом, доступный только
  владельцу.
- Таблицы в схеме БД используют `status`-поле с историей; жёсткое `DELETE` без отдельного
  действия владельца запрещено на уровне API.
- Адресные таблицы (слаги, хэндлы) хранят все когда-либо использованные значения.

## Цена отката

Средняя: требует миграции схемы, если статус-поле не было предусмотрено изначально. После
накопления архивных данных откат к физическому удалению требует явного решения об очистке.
