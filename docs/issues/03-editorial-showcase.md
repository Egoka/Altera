# Этап 2 — Редакция ведёт витрину

- **Файл**: третий по порядку выполнения; этап 2.
- **Решения**: ADR-0002, ADR-0006, ADR-0007, ADR-0014, ADR-0016, ADR-0026.
- **Документы**: `docs/vision/05-editor.md` §4, §6, §9; `06-design-system.md` §7, §10;
  `04-roles-and-access.md` §5.

## 1. Цель и продуктовая гипотеза

**Цель.** Редакция отбирает материалы на главную и витрину, работает с авторами через
замечания к блокам и ревизии, снимает с публикации с причиной, выпускает вторую языковую
версию; интерфейс говорит на двух языках; страницы индексируются правильно.

**Гипотеза.** Редакционный отбор и замечания повышают качество материалов без отказа
авторам в голосе: авторы принимают замечания, а отобранные материалы читаются заметно больше.

## 2. Что входит

- **Отборы** (ADR-0016): `EditorialPick` для `home` и `showcase`, позиция, срок; главная —
  «Выбор редакции» + «Свежее»; страница витрины; истёкший отбор исчезает; отбор без
  опубликованной версии в локали пропускается.
- **Замечания к блокам и история решений**: `ReviewNote` по `attrs.id`, интерфейс автора и
  редактора, статусы «открыто/решено»; `rejectTranslation(reason)`, `unpublishTranslation(reason)`;
  автор видит хронологию решений по материалу.
- **Ревизии в интерфейсе**: список, просмотр, восстановление с `restoredFromId`;
  `editorial`-ревизии помечены редактором.
- **Права редактора** (ADR-0014): правка в `editorial` и `review` с ревизией; снятие с
  причиной; матрица покрыта тестами.
- **Жалобы**: резолюция модератора с записью; лимит на гостевые жалобы.
- **Вторая языковая версия** (`05-editor.md` §9): создание из оригинала, свой слаг и статус,
  `translatorId`, `sourceRevisionId`, индикатор «оригинал обновился», переключатель языка и
  hreflang только для опубликованных пар.
- **i18n интерфейса**: все тексты публичных страниц, кабинета и писем через словари; проверка
  отсутствия «сырых» строк.
- **SEO** (`06-design-system.md` §10): `useSeoMeta` везде, canonical, hreflang, `sitemap.xml`
  и `rss.xml` по локалям, дефолтное OG-изображение, `noindex` для служебных страниц, JSON-LD.
- **Аудит**: миграция M10 (`review_notes`, `audit_log`); запись действий из списка
  `04-roles-and-access.md` §5.
- **SEO-панель редактора**: `seoTitle`, `seoDescription`, предпросмотр сниппета и OG.

## 3. Что сознательно не входит

- Генерация OG-изображений, поиск, подборки, прочтения — этап 3.
- Заказные материалы как процесс с гонораром — таблица есть с этапа 1, интерфейс — этап 5.
- Машинный перевод; редакционные роли по рубрикам; интерфейс просмотра аудита (этап 5).

## 4. От чего зависит и что разблокирует

**Зависит от**: этапа 1 (модель v2, редактор, права); гейта «учётки редакции и SLA».

**Разблокирует**: этап 4 (витрина как продукт) и этап 5 (команда).

## 5. Definition of Done

1. `EditorialPick` CRUD с позицией и `expiresAt`; главная: «Выбор редакции» + подписанный
   поток «Свежее»; истёкший отбор исчезает (тест с подменой времени); отобранный материал
   открытого контура остаётся бесплатным (инвариант-тест, действует и на этапе 4).
2. Замечания привязаны к блоку по `attrs.id`, статусы «открыто/решено», автор видит их в
   редакторе; решение «вернуть» или «одобрить» с причиной пишется в `audit_log` и уходит
   письмом (тесты).
3. Ревизии: список, просмотр, восстановление создаёт новую ревизию с `restoredFromId` и
   текущим пользователем (тест).
4. Матрица ADR-0014 покрыта тестами: редактор правит `review` и `editorial`; не правит
   опубликованное `open`; снимает с публикации с причиной; каждая чужая правка — ревизия
   `editorial`.
5. Жалоба → список → резолюция с записью в аудит; гостевые жалобы ограничены по IP (тест).
6. «Создать версию на английском» копирует структуру; у версии свои слаг, статус, SEO;
   hreflang в `<head>` обеих версий только когда обе опубликованы (`curl`); sitemap содержит
   обе; переключатель языка скрыт, пока сестра не опубликована.
7. Интерфейс: проверка «нет сырых строк» в публичных компонентах, кабинете и письмах
   проходит; `/en` показывает английский интерфейс.
8. У каждого публичного маршрута `title`, `description`, canonical; `sitemap.xml` и `rss.xml`
   валидны (`xmllint`); OG с дефолтной картинкой; `/me`, `/admin`, предпросмотр — `noindex`;
   JSON-LD `Article` проходит валидатор структурированных данных.
9. `audit_log` пишется для смены роли, снятия с публикации, восстановления ревизии
   редактором, сброса доверия, отбора, резолюции жалобы (тест на каждую мутацию).

## 6. Риски и способ их снять

| Риск | Снятие |
|---|---|
| Привязка замечаний ломается при правках текста | Привязка к стабильному `attrs.id` блока, не к позиции; замечание к удалённому блоку — в общий список |
| Тонкие или пустые переводы индексируются | hreflang и sitemap только для опубликованных; предупреждение в редакторе при короткой версии |
| Правки редактора в обход автора | Ревизия `editorial` с именем и уведомление автора — без исключений |
| SEO нельзя проверить без трафика | Структурные валидаторы (sitemap, JSON-LD, hreflang) вместо трафика |
| i18n интерфейса недооценён (сейчас `$t` только на демо-странице) | Проверка «нет сырых строк» с первого дня этапа; словари как часть каждого компонента |

## 7. Оценка

14–22 человеко-дня. Из них: отборы и главная 2–3; замечания и решения 3–4; ревизии 1–2;
вторая языковая версия 2–3; i18n интерфейса 3–5; SEO и JSON-LD 2–3; аудит 1–2.

## 8. Метрики успеха

- Отборов в неделю (ориентир ≥ 3); доля отборов из открытого контура.
- Медиана «отправлено на проверку → решение» ≤ 48 часов.
- Число жалоб и медиана времени резолюции.
- Число опубликованных английских версий.
- Число снятий с публикации с причиной и доля оспоренных.
