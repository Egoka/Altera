## 1. Цель и продуктовая гипотеза

**Цель.** Веб и API соединены по единому контракту, утечки закрыты, сессия живёт и
отзывается, письма доходят, CI красный при поломке, сервер работает без Redis. Продукта на
этом этапе не прибавляется; прибавляется возможность проверять каждый следующий этап.

**Гипотеза.** Один разработчик с AI-агентами за 10–15 чд превращает две несвязанные
половины в одно приложение, если контракт генерируется, а не пишется руками, и если новые
поля API добавляются только те, без которых существующие страницы не рендерятся.

## 2. Что входит

- **Единый контракт** (ADR-0012): `graphql-codegen` из SDL сервера; операции фронта переносятся
  в `.graphql`-файлы и переписываются под существующую схему; ручные строки и типы удаляются;
  `codegen --check` и валидация операций в CI.
- **Минимальные добавления API**, без которых страницы не рендерятся: публичный список
  рубрик и меню (`sections`), `myArticles`, аргументы пагинации там, где фронт их ждёт.
  Ничего сверх этого.
- **Живое соединение** (ADR-0023): BFF-прокси `web/server/api/graphql`, `runtimeConfig` с
  адресом API, `useAsyncData` на страницах главной, рубрики, материала, автора, тега; фикстуры
  этих страниц удаляются; меню строится из рубрик базы.
- **Закрытие утечек** (ADR-0018): `article(slug)` и все публичные запросы через единый модуль
  видимости (гость — только `published`); `email` уходит из публичных типов; обработка
  коллизии слага пользователя (случайный хэндл при конфликте).
- **Сессии** (ADR-0009): миграции M1 (`moderator`, `owner`) и M2 (`sessions`, хэш magic link);
  мутации `refreshSession`, `logout`, `logoutAll`; ротация и отзыв; httpOnly-cookie через BFF.
- **Почта и лимиты** (ADR-0024): транспортная абстракция с реализациями `smtp`, `console`,
  `fake`; письмо со ссылкой для входа; лимиты на запрос ссылки, проверку токена и API; ответ
  без перечисления аккаунтов.
- **Redis необязателен** (ADR-0019): кеш-обёртка с `noop`; инвалидация по тегам без `KEYS`;
  ключи включают все аргументы; черновики не кешируются.
- **Ошибки и логи** (ADR-0032): словарь кодов, структурированный логгер, `GET /health`,
  запрет `console.log` линтером; magic link больше не печатается.
- **Честный CI** (ADR-0031): `.nvmrc` и `engines`, одна версия pnpm, `.output` в ignores
  ESLint, `vue-tsc`, `pnpm test` падает при нуле тестов, сборка веба и сервера, запуск с
  проверкой `/health` и `/`, никаких `|| true`; Vitest в `server` и `web`, Playwright smoke,
  Docker-compose с PostgreSQL и Mailpit; диагностика и починка прод-сборки под пиновой
  версией Node.
- **Сид** (`prisma db seed`): детерминированный набор ролей, рубрик, тегов, материалов во всех
  статусах.
- **Гигиена**: демо-страницы только в dev; мёртвые компоненты и `process.client` удалены;
  `@neondatabase/serverless` удалён из зависимостей; `migrate deploy` вынесен из `build`.

## 3. Что сознательно не входит

- Модель данных v2 (переводы, ревизии, медиа) — этап 1; сейчас страницы рендерятся из
  существующей схемы.
- Редактор, кабинет автора, страницы входа как продукт — этап 1 (вход по ссылке нужен только
  для тестов сессии).
- Дизайн-система сверх того, что нужно, чтобы существующие компоненты получили реальные
  данные.
- i18n интерфейса, SEO, поиск.
- Деплой в РФ и бэкапы — этап 1; здесь только каркас CI и окружений.

## 4. От чего зависит и что разблокирует

**Зависит от**: решений ADR-0003, ADR-0009, ADR-0012, ADR-0023 (утверждены); гейта «провайдер
почты РФ» (до реализации транспорта `smtp`; до него — `console` и `fake`).

**Разблокирует**: всё. Этап 1 начинается с миграций M3–M9 поверх работающего соединения.

## 5. Definition of Done

1. `pnpm codegen` генерирует типы из `server/src/graphql/**/*.graphql`; `codegen --check` в CI;
   тест валидации всех операций `web/**/*.graphql` → 0 невалидных (сейчас 25 из 35).
2. `article(slug)` для `draft`/`archived` гостю → `null`, автору-владельцу и `admin` → материал;
   резолверные тесты на каждый публичный запрос; черновики не попадают в кеш.
3. В SDL публичных типов нет поля `email`; e-mail доступен только через `me`; контрактный
   тест.
4. Миграции M1–M2 применены; `refreshSession` ротирует токен, повторное предъявление старого
   отзывает сессию; `logout` и `logoutAll` работают; тесты на все три.
5. Четвёртый `requestMagicLink` на e-mail за 15 минут и одиннадцатый с IP за час →
   `RATE_LIMITED`; тест; ответ одинаков для существующего и нового адреса.
6. Письмо со ссылкой уходит через транспортную абстракцию; в dev — Mailpit; тест с фейковым
   транспортом; `grep -rn "console.log" server/src` = 0.
7. `/`, `/{рубрика}`, `/{рубрика}/{слаг}`, `/authors/{slug}`, `/tags/{slug}` рендерятся SSR из
   API: `curl` без JS содержит заголовок сидового материала; меню — из рубрик базы
   (`grep -rn "National Security" web/app` = 0); Playwright smoke на сиде.
8. `pnpm lint && pnpm format && pnpm -r typecheck && pnpm test && pnpm -r build` — exit 0
   локально и в CI на одной пиновой версии Node; `pnpm test` при удалении всех тестов падает;
   `|| true` в workflow нет; сервер стартует и `GET /health` = 200; `node web/.output/server/index.mjs`
   отдаёт 200 на `/`.
9. Без `REDIS_URL` сервер стартует и публичные запросы отвечают; при недоступном Redis ответ
   ≤ 1 с; `grep -rn "\.keys(" server/src` = 0; ключ админского кеша включает `search` (тест).
10. `pnpm prisma db seed` создаёт детерминированный набор; демо-страницы в проде → 404;
    «чистый клон → `docker compose up` → dev с сидом» ≤ 30 минут по инструкции в README
    раздела для разработчиков (проверяет владелец).

## 6. Риски и способ их снять

| Риск | Снятие |
|---|---|
| SSR прод-сборки падает под Node 24 (`vue` без default-экспорта), причина не диагностирована | Первым делом пин Node и воспроизведение в CI; таймбокс один день; при провале — сборка в Docker-образе с фиксированной версией |
| «Раз подключаем — допишем поля»: этап разрастается в этап 1 | Правило: новые поля API только те, без которых существующие страницы не рендерятся; остальное — в список этапа 1 |
| Провайдер почты РФ не выбран | Транспортная абстракция; `console` и `fake` до выбора; гейт владельца до конца этапа |
| Смена модели сессий инвалидирует существующие токены | Приемлемо при нулевой аудитории; фиксируется в отчёте |
| Каркас тестов и CI недооценён | Оценка уже учитывает 3–5 чд на каркас; тесты пишутся вместе с правками, а не после |
