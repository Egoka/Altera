# Этап 5 — Редакция работает как команда

- **Файл**: шестой по порядку выполнения; этап 5.
- **Решения**: ADR-0003, ADR-0008, ADR-0017, ADR-0026, ADR-0029.
- **Документы**: `docs/vision/05-editor.md` §5, §7, §10; `04-roles-and-access.md`;
  `03-data-model.md` §1.5.

## 1. Цель и продуктовая гипотеза

**Цель.** Несколько редакторов и модераторов работают на одном движке без ручных обходов:
библиотека блоков закрывает фоторассказы, интервью и обзоры; медиа-библиотека, роли из
интерфейса, аудит, отчёты, рассылка и шаблоны материалов.

**Гипотеза.** Редакция из нескольких человек работает на одном движке без ручных обходов;
блоки этапа 5 используются в заметной доле новых материалов.

## 2. Что входит

- **Библиотека блоков** (ADR-0017): галерея, видео, аудио, врезка, embed из allow-list,
  таблица, колонки; каждый блок — узел схемы, рендерер, интерфейс, снимок-тест, запись в
  документах; `MediaKind` расширяется (миграция M17).
- **Медиа-библиотека**: сетка, поиск, фильтр по лицензии, переиспользование, замена файла с
  сохранением ссылок, кадрирование и фокусная точка в интерфейсе, физическая чистка
  неиспользуемых файлов; жалобы на медиа.
- **Роли из интерфейса** (ADR-0003): назначение `editor`, `moderator`, `admin`; передача
  владения с двусторонним подтверждением; инвариант «ровно один `owner`».
- **Аудит-интерфейс**: просмотр `audit_log` с фильтрами; полное покрытие списка критичных
  действий.
- **Отчёты**: контент (публикации по контурам и неделям), аудитория (прочтения, подписчики),
  платежи (из этапа 4) — SQL и экраны.
- **Рассылка** (ADR-0026): double opt-in, выпуск из отборов в том же редакторе, отправка
  через провайдера, отписка в один клик, согласие с датой и версией (миграция M16).
- **Шаблоны материалов**: заготовки структуры документа по рубрике или формату.
- **Заказные материалы как процесс**: интерфейс `Commission` (бриф, срок, гонорар, статусы).
- **Параллельная работа редакции**: простая пометка «редактирует X» до этапа 6; тесты прав на
  двух учётках.

## 3. Что сознательно не входит

- Совместное редактирование в реальном времени и сравнение версий — этап 6.
- Комментарии читателей; редакционные роли по рубрикам.
- Транскодирование видео и аудио: загрузка в поддерживаемых форматах.
- Платная рассылка отдельным продуктом.

## 4. От чего зависит и что разблокирует

**Зависит от**: этапа 2 (замечания, ревизии, отборы); этапа 4 для отчётов по платежам.

**Разблокирует**: этап 6.

## 5. Definition of Done

1. Каждый новый блок имеет узел схемы, рендерер, интерфейс, снимок-тест и запись в
   `05-editor.md` и `06-design-system.md`; embed вне allow-list доменов отклоняется (тест);
   контейнер в контейнере отклоняется схемой (тест).
2. Медиа-библиотека: сетка, поиск, фильтр по лицензии, переиспользование, замена файла с
   сохранением ссылок, кадрирование с фокусной точкой; чистка неиспользуемых файлов не
   удаляет ничего, на что есть ссылка из версии, ревизии или обложки (тест).
3. `moderator` и `owner` в матрице с тестами; передача владения требует подтверждения обеих
   сторон; в базе ровно один `owner` (инвариант-тест).
4. `audit_log` покрывает весь список `04-roles-and-access.md` §5 (тест-перечень); записи не
   изменяются и не удаляются; интерфейс просмотра с фильтрами.
5. Отчёты по контенту, аудитории и платежам считаются SQL из репозитория и открываются в
   админке.
6. Рассылка: double opt-in, выпуск собирается из отборов, отправляется через провайдера,
   отписка в один клик, согласие с датой и версией (тесты; e2e через Mailpit).
7. Шаблон создаёт заготовку структуры документа; выбирается при создании материала (тест).
8. Жалоба на изображение → скрытие → решение модератора (тест).
9. Два редактора работают параллельно: тесты прав на двух учётках; пометка «редактирует X»
   видна второму.

## 6. Риски и способ их снять

| Риск | Снятие |
|---|---|
| Взрыв блоков и их вариантов | Спецификация вида каждого блока в `06` до кода; правило границы свободы |
| Рассылка и требования к рекламе и персональным данным | Double opt-in, только редакционный контент, консультация при появлении рекламы |
| Рост `audit_log` | Ретенция и индексы по объекту и актору; архивация старше года при необходимости |
| Необратимая передача владения | Двустороннее подтверждение письмами и запись в аудит |
| Медиа-чистка удаляет нужное | Чистка только по отсутствию ссылок из всех мест хранения; сначала пометка, удаление через 30 дней |

## 7. Оценка

22–34 человеко-дня. Из них: блоки 8–12; медиа-библиотека 4–6; роли, владение, аудит 3–4;
отчёты 2–3; рассылка 3–5; шаблоны и заказы 2–4.

## 8. Метрики успеха

- Доля новых материалов с блоками этапа 5.
- Коэффициент переиспользования медиа.
- Подписчики рассылки и доля переходов по ссылкам (без пикселей).
- Медиана «отправлено на проверку → решение» при ≥ 2 редакторах.
- Покрытие аудита списка критичных действий: 100 %.
