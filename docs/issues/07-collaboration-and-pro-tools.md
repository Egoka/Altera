# Этап 6 — Совместная работа и профессиональные инструменты

- **Файл**: седьмой по порядку выполнения; этап 6.
- **Решения**: ADR-0007, ADR-0015, ADR-0033.
- **Документы**: `docs/vision/05-editor.md` §4, §10; `07-commerce.md` §2; `08-operations.md`.

## 1. Цель и продуктовая гипотеза

**Цель.** Соавторы правят один документ одновременно, редакция сравнивает версии по блокам,
авторы покупают профессиональные инструменты (статистика, отложенная публикация, вёрстка
PDF/EPUB), партнёрские материалы проходят как процесс.

**Гипотеза.** Соавторство и профессиональные инструменты нужны хотя бы части активных
авторов; спрос измерен до старта: материалы с двумя и более соавторами или регулярные
конфликты редактор/автор `[ДОПУЩЕНИЕ]`.

## 2. Что входит

- **Совместная работа** (ADR-0033): Y.js + `@tiptap/extension-collaboration`, отдельный
  процесс синхронизации, персистентность документа, снапшоты в `ArticleRevision`, курсоры
  присутствия, слияние офлайн-правок; JSON в базе остаётся снимком.
- **Сравнение версий**: визуальный diff двух ревизий по блокам с текстовым diff экспорта.
- **Профессиональные инструменты автора** (платно, ADR-0015): статистика материала
  (прочтения по дням из агрегатов), отложенная публикация (`scheduledAt`), вёрстка PDF/EPUB;
  экспорт в Markdown/HTML остаётся бесплатным.
- **Партнёрские материалы**: пометка, поля договора, отчёт; проверка правилом-арбитром.
- **Эксплуатация второго процесса**: запуск, мониторинг, деградация в одиночный режим
  (`08-operations.md`).
- **Нагрузочная проверка**: десять одновременных редакторов одного документа без потери
  правок.

## 3. Что сознательно не входит

- Комментарии читателей; чаты редакции.
- Открытый API для партнёров — только при явном спросе и отдельном ADR.
- Мобильное приложение.

## 4. От чего зависит и что разблокирует

**Зависит от**: этапов 4 (модель платных услуг) и 5 (блоки, медиа-библиотека, роли); гейта
«разрешить второй процесс; подтверждён спрос».

**Разблокирует**: следующий цикл планирования; после этого этапа роадмап пересматривается по
измерениям.

## 5. Definition of Done

1. Два браузера, один документ: слияние правок и курсоры присутствия (Playwright с двумя
   контекстами).
2. Y.js-документ персистится; снапшоты попадают в `ArticleRevision` при автосохранении и
   публикации; совместимость с optimistic lock одиночного режима описана и протестирована.
3. Офлайн-правки сливаются после восстановления сети (тест).
4. Визуальный diff двух ревизий по блокам; текстовый diff экспорта совпадает со снимками.
5. Платные инструменты: статистика, отложенная публикация, PDF/EPUB доступны по подписке;
   экспорт Markdown/HTML доступен **без** подписки (тест).
6. Партнёрский материал: пометка на странице и в RSS, поля договора, отчёт.
7. Процесс совместной работы описан в `08-operations.md`: запуск, мониторинг, деградация в
   одиночный режим; health второго процесса под проверкой.
8. Нагрузочный скрипт: десять одновременных редакторов без потери правок; результат в отчёте.

## 6. Риски и способ их снять

| Риск | Снятие |
|---|---|
| Второй процесс — отклонение от принципа «один API + один Nuxt» | Гейт владельца; ADR-0033 фиксирует границы; деградация в одиночный режим |
| Две истины: Y.js и JSON | JSON — снимок при автосохранении и публикации; Y.js — рабочее состояние; конфликт невозможен по построению |
| Платный инструмент нарушает правило-арбитр | Чек-лист в `07-commerce.md` §2; экспорт и базовый редактор бесплатны всегда |
| Совместная работа не востребована | Старт только по измеренному запросу; иначе этап откладывается без потерь |

## 7. Оценка

25–40 человеко-дней. Из них: Y.js, процесс, персистентность 8–12; сравнение версий 3–5;
платные инструменты 6–10; партнёрские материалы 2–4; эксплуатация и нагрузка 3–5.

## 8. Метрики успеха

- Сессий совместного редактирования; доля материалов с ≥ 2 соавторами.
- Потерянных правок по логам: 0.
- Конверсия активных авторов в платные инструменты (ориентир ≥ 5 % за квартал).
- Доля материалов с отложенной публикацией.
