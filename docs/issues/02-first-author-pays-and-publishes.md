## 1. Цель и продуктовая гипотеза

**Цель.** Человек входит по ссылке из письма, получает бесплатный аккаунт, на `/pricing`
оплачивает standard (или получает грант), заполняет профиль, пишет материал в визуальном
редакторе, загружает обложку, отправляет к публикации; AI выносит вердикт и оценку, ревьюер
одобряет; материал читается по адресу `/{рубрика}/{слаг}` из реальных данных. Прод живёт в
РФ, регистрация открыта, юридические тексты опубликованы.

**Гипотеза.** Автор готов платить за standard ради места, где текст выглядит как в журнале
и есть проверка качества; он опубликует хотя бы один материал и вернётся за вторым.

## 2. Что входит

- **Модель данных v2** (`03-data-model.md`): миграции этапа 1 — хэндлы, план и срок, блокировка,
  согласия; рубрики, форматы, теги; языковые версии с конверсией тела и состоянием
  `ai_review`; ревизии; история слагов и хэндлов; медиа; жалобы, закладки, AI-оценки, аудит;
  биллинг (планы, клиенты, подписки, платежи, гранты, промокоды, вебхуки). Репетиция на копии,
  `verify:legacy-bodies`, `migrate deploy` как шаг релиза.
- **Роли** (ADR-0042): enum из семи значений; `ensureActiveAuthor`; раздел «Администраторы» с
  назначением `editor`, `moderator`, `analyst`, `admin`; `owner` из сида; `analyst` без мутаций.
- **Биллинг** (ADR-0035, ADR-0010): `PaymentProvider` с реализациями ЮKassa и `fake`; вебхуки
  идемпотентны; `/pricing`, `/me/subscription`, `/me/subscription/checkout`; чеки; жизненный
  цикл — оформление, отмена, возврат, просрочка, восстановление, истечение по ADR-0044;
  гранты и промокоды; письма на каждом шаге.
- **Пакет `content`** (ADR-0029): схема блоков этапа 1, валидация, экстракторы, рендерер,
  экспорт в текст для AI.
- **Вход и кабинет**: `/login`, `/auth/verify`, `/me` (сводка с планом), `/me/settings`,
  `/me/sessions`, `/me/email`, `/me/bookmarks`, `/me/articles`, `/me/articles/{id}/review`.
- **Редактор минимально ценный** (`05-editor.md` §3, §7): блоки этапа 1, автосохранение с
  `baseRevisionId`, предпросмотр, конфликт двух вкладок, офлайн-буфер, панель проверки,
  режим чтения при истёкшей подписке.
- **Медиа**: загрузка в S3 РФ, варианты при загрузке, обязательные лицензия и атрибуция,
  обложка, аватар; лимиты по плану.
- **Двухступенчатая проверка** (ADR-0039, ADR-0045): AI-адаптер с реализациями `real` и
  `fake`; очередь заданий в базе; `ArticleAiReview`; состояния `ai_review → review →
  published`; оспаривание; очередь ревьюера в админке с вердиктом и баллом; письма автору.
- **Публичные страницы из данных** (по дате, с подписью «по дате публикации»): главная,
  рубрика, материал (рендер JSON, 404 черновику), автор с бейджем, тег, `/sections`,
  `/pricing`; RU без префикса, EN под `/en` (адреса); 301 по истории слагов; закладка на
  странице материала.
- **Ядро дизайн-системы** (`06-design-system.md` §3–4, §12): токены, одна палитра, включённая

- **Жалобы и письмо в редакцию**: форма на странице материала, список в админке; `/contact`.
- **Админка на данных**: сводка, категории, теги, статьи по версиям, очередь проверки,

## 3. Что сознательно не входит

- Рейтинг, прочтения, бусты, AI-оценка в выдаче, секции главной по рейтингу — этап 2.
- Поиск, подписка на автора, экспорт из кабинета, SEO сверх canonical, i18n интерфейса,
  AI-перевод, самоудаление — этап 3.
- Замечания к блокам, ревизии в интерфейсе, аудит-интерфейс, медиа-библиотека, библиотека
  блоков, рассылка, отчёты сверх базовых — этап 4.
- Быстрый путь проверки мимо человека, OAuth, комментарии.

## 4. От чего зависит и что разблокирует

**Зависит от**: этапа 0 целиком; гейтов «список рубрик» (до миграции таксономии), «юрлицо,
договор с ЮKassa, консультация по чекам, цены, возвраты» (до страницы оплаты), «AI-провайдер и
бюджет» (до очереди), «провайдер РФ, юридические тексты, README, РКН» (до открытия
регистрации); утверждённых реестров `docs/spec/00-registries/` (Г1) для страниц и админки.

**Разблокирует**: этап 2 (есть материалы, авторы с грейдом, AI-оценки).

## 5. Definition of Done

1. Миграции этапа 1 применяются к дампу текущей базы без потери: `count(articles) =
   count(article_translations WHERE locale = 'ru')`, контрольная сумма материалов совпадает,
   у каждой версии ревизия №1; `verify:legacy-bodies` → 0 расхождений; `migrate diff` пуст в
   CI; существующие пользователи с материалами получили грант `standard`.
2. E2E: `/login` → письмо (Mailpit) → `/auth/verify` → `/me` с планом `free`; повторный переход
   по ссылке → ошибка; `/me` без сессии → редирект (middleware реальный).
3. Оплата standard в песочнице провайдера и на фейке: вебхук → `Subscription.active`,
   `User.planTier = standard`, роль `author`; повторный вебхук не создаёт второй `Payment`;
   чек в `Payment.receiptUrl`; без подписки `createArticle` → `FORBIDDEN` (тесты).
4. Истечение (подмена времени): роль → `reader`, опубликованные версии остаются `published`,
   правка → `FORBIDDEN`, экспорт доступен, кабинет показывает `SubscriptionStatus: истекла`;
   продление возвращает роль (тесты).
5. Редактор: документ со всеми блоками этапа 1 сохраняется; неизвестный узел →
   `CONTENT_INVALID`; автосохранение ≤ 10 с по правилу ADR-0007; перезагрузка восстанавливает
   текст; устаревший `baseRevisionId` → `CONFLICT`; офлайн-черновик отправляется при
   восстановлении сети.
6. Проверка: отправка → `ai_review` → фейковый AI даёт `pass` → `review` → ревьюер одобряет →
   `published`; `fail` → `draft` с причинами, автор видит их на `/me/articles/{id}/review` и
   оспаривает → `review` с пометкой; `uncertain` → `review` с пометкой; недоступность
   провайдера → `review` без вердикта через порог (тесты всех ветвей); письма автору на обоих
   решениях; правка опубликованного → новая ревизия тем же путём, читатель видит прежнюю
   (тест).
7. Загрузка изображения → S3 → `MediaAsset` с обязательными `license`, `attribution` → варианты;
   страница отдаёт `srcset`; `/_ipx/` не используется; лимит медиа плана соблюдается (тест).
8. `/{рубрика}/{слаг}` рендерится на сервере из JSON (`curl` содержит текст абзаца); черновик
   посетителю → 404; главная показывает секции из данных по дате с подписью; бейдж pro у
   pro-автора; закладка добавляется и снимается (тест); `/en/...` работает; 301 по истории
   слагов.
9. Администраторы: `owner` назначает `admin`, `admin` — `moderator`; `analyst` не имеет ни
   одной мутации (контрактный тест по SDL); все назначения в `audit_log`.
10. `/legal/*` существуют с версией; регистрация без согласия отклоняется; README описывает
    планы, проверку, рейтинг и права на контент и не обещает MDC/Vercel/Render.
11. Прод в РФ: деплой по коммиту в `app`; `/health` = 200 под внешней проверкой; ежедневный
    бэкап; восстановление на пустой инстанс проведено, счётчики совпали (отчёт в
    `docs/reports/`).
12. Дизайн-система: одна палитра, `grep -rn "zinc-" web/app/components` = 0 (кроме
    исключений в токенах), `useTheme` и `components/demo/` удалены; Lighthouse страницы
    материала: LCP < 2,5 с (ориентир).
13. Жалоба со страницы материала попадает в список админки; `/contact` отправляет письмо.

## 6. Риски и способ их снять

| Риск | Снятие |
|---|---|
| Договор с провайдером и юрлицо вне контроля разработчика | Фейковый адаптер и гранты позволяют разрабатывать и тестировать до договора; блокируется только открытие регистрации |
| AI-провайдер: стоимость, недоступность, качество вердиктов | Фейк в тестах; порог перехода к человеку без вердикта; лимиты в сутки; бюджет с уведомлением |
| Один ревьюер — владелец: очередь растёт | Метрика «отправлено → решение»; при росте — новый ADR о быстром пути (ADR-0045 §следствия) |
| Расползание редактора | Каталог этапа 1 заморожен (ADR-0017); остальное — этап 4 |
| Миграция живых данных при непроверенном содержимом | Dry-run на копии, бэкап перед `migrate deploy`, деструктивные шаги отдельным релизом |
| `sharp` и нативные бинарники в проде | Сборка образа под Linux в CI; тест загрузки в CI |
| Юридические тексты не написаны вовремя | Placeholder-страницы и закрытая регистрация не блокируют разработку |

## 7. Метрики успеха

- Авторов с оплаченным планом и ≥ 1 опубликованным материалом; конверсия «профиль автора
  заполнен → оплата» (`07-commerce.md` §6).
- Медиана «первый вход → первый черновик», «отправлено → вердикт AI», «вердикт → решение
  человека».
- Доля ревизий с `fail` и доля оспариваний; доля ревизий, которые человек вернул после
  `pass` (качество AI-ступени).
- Доля автосохранений с ошибкой < 1 %; доля загрузок, отклонённых из-за лицензии.
- Возвраты за 14 дней; доля неуспешных автоплатежей.
