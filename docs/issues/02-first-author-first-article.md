# Этап 1 — Первый автор публикует первый материал

- **Файл**: второй по порядку выполнения; этап 1.
- **Решения**: ADR-0001, ADR-0002, ADR-0004, ADR-0005, ADR-0006, ADR-0007, ADR-0008, ADR-0011,
  ADR-0013, ADR-0014, ADR-0017, ADR-0021, ADR-0028, ADR-0029, ADR-0030, ADR-0033.
- **Документы**: `docs/vision/03-data-model.md`, `05-editor.md`, `06-design-system.md`,
  `04-roles-and-access.md`.

## 1. Цель и продуктовая гипотеза

**Цель.** Внешний автор входит по ссылке из письма, заполняет профиль, пишет материал в
визуальном редакторе, загружает обложку, публикует (или отправляет на проверку), и материал
читается по адресу `/{рубрика}/{слаг}` из реальных данных. Прод живёт в РФ, регистрация
открыта, юридические тексты опубликованы.

**Гипотеза.** Автор, которому дали красивое место и бесплатную публикацию без требований к
оформлению, опубликует хотя бы один материал и вернётся за вторым.

## 2. Что входит

- **Модель данных v2** (`03-data-model.md`): миграции M3–M9 и M11 — хэндлы, доверие,
  блокировка, согласия; рубрики, форматы, теги; языковые версии с конверсией тела; ревизии;
  история слагов и хэндлов; медиа; отборы, жалобы, заказы (таблицы). Репетиция на копии,
  `verify:legacy-bodies`, `migrate deploy` как шаг релиза.
- **Пакет `content`** (ADR-0029): схема блоков этапа 1, валидация, экстракторы, рендерер,
  экспорт (экспорт как функция кабинета — этап 3).
- **Вход и кабинет**: `/login`, `/auth/verify`, `/me`, `/me/articles`, `/me/settings` (имя, о
  себе, хэндл, аватар), `/me/sessions`; профиль автора → роль `author`.
- **Редактор минимально ценный** (`05-editor.md` §3, §7): блоки этапа 1, автосохранение с
  `baseRevisionId`, предпросмотр, конфликт двух вкладок, офлайн-буфер, публикация с проверкой
  обязательных полей.
- **Медиа**: загрузка в S3 РФ, варианты при загрузке, обязательные лицензия и атрибуция,
  обложка материала, аватар.
- **Публикация с уровнями доверия** (ADR-0013): `publishTranslation`, очередь проверки в
  админке (одобрить, вернуть с причиной), письма автору, `trusted` после двух публикаций.
- **Публичные страницы из данных**: главная (пустой «Выбор редакции» + «Свежее»), рубрика,
  материал (рендер JSON, 404 для черновика), автор по хэндлу, тег, `/types` → рубрики;
  RU без префикса, EN под `/en` (только адреса; интерфейс переводится на этапе 2); 301 по
  истории слагов.
- **Ядро дизайн-системы** (`06-design-system.md` §3–4, §12): токены, одна палитра, включённая
  типографика, единая схема отступов, тема через color-mode, `ArticleCard` в четырёх вариантах,
  атомы метаданных, `Prose*` для блоков этапа 1, состояния списков; FishtVue на общих токенах
  для кабинета и админки.
- **Жалобы и письмо в редакцию**: форма жалобы на странице материала, список в админке;
  `/contact` → письмо на адрес редакции.
- **Права**: единый модуль видимости, `assertCanEditTranslation`, матрица этапа 1; `owner` из
  сида или скрипта.
- **Прод в РФ** (ADR-0011): управляемый PostgreSQL, S3, хостинг API и Nuxt; деплой по
  коммиту в `app` с миграциями как шагом релиза; ежедневный бэкап и одно проведённое
  восстановление; `/health` под внешней проверкой.
- **Юридические тексты** (ADR-0028): `/legal/terms`, `/legal/privacy`, `/legal/content-rules`,
  `/legal/license`; согласие с версией при регистрации; README и публичные тексты переписаны
  под `01-product.md`.
- **Админка на данных**: материалы по версиям, очередь, рубрики, теги, пользователи с
  блокировкой, жалобы (таблицы FishtVue подключаются к API).

## 3. Что сознательно не входит

- Замечания к блокам, ревизии в интерфейсе, отборы, вторая языковая версия, i18n интерфейса,
  SEO сверх canonical — этап 2.
- Поиск, подборки, прочтения, «популярное», подписка на автора, экспорт из кабинета,
  самостоятельное удаление — этап 3.
- Деньги — этап 4. Галереи, видео, embed, колонки, медиа-библиотека, назначение ролей из
  интерфейса, аудит-интерфейс — этап 5.
- Машинный перевод, OAuth, комментарии.

## 4. От чего зависит и что разблокирует

**Зависит от**: этапа 0 целиком; гейтов «список рубрик и соответствие существующим
`content_types`» (до M4), «провайдер РФ» (до деплоя), «юридические тексты, README, уведомление
РКН по консультации» (до открытой регистрации).

**Разблокирует**: этапы 2 и 3 (оба строятся на модели v2 и работающем редакторе).

## 5. Definition of Done

1. Миграции M3–M9 применяются к дампу текущей базы без потери: `count(articles) =
   count(article_translations WHERE locale = 'ru')`, контрольная сумма материалов до и после
   совпадает, у каждой версии ревизия №1; `verify:legacy-bodies` → 0 расхождений; M11
   применён отдельным релизом; `migrate diff` пуст в CI.
2. E2E: `/login` → письмо (Mailpit) → `/auth/verify` → `/me`; повторный переход по ссылке →
   ошибка; `/me` без сессии → редирект на `/login` (middleware реальный).
3. Заполнение имени и «о себе» переводит `reader → author` (тест); хэндл редактируем,
   уникален, старый редиректит; два пользователя с одинаковой локальной частью e-mail
   создаются без ошибки (тест).
4. Редактор: документ со всеми блоками этапа 1 сохраняется; сервер отклоняет неизвестный
   узел с `CONTENT_INVALID` (тест); автосохранение ≤ 10 с создаёт или перезаписывает
   `autosave`-ревизию по правилу ADR-0007 (тест); перезагрузка восстанавливает текст.
5. Сохранение с устаревшим `baseRevisionId` → `CONFLICT`; вторая вкладка показывает баннер и не
   затирает; офлайн-черновик отправляется при восстановлении сети (Playwright `setOffline`).
6. Загрузка изображения → S3 → `MediaAsset` с обязательными `license`, `attribution` (без них
   мутация падает, тест) → варианты; страница отдаёт `srcset`; `/_ipx/` для пользовательских
   картинок не используется.
7. Уровни доверия: автор в `probation` видит «Отправить на проверку», материал попадает в
   очередь; модератор одобряет или возвращает с причиной, автор получает письмо; после двух
   публикаций автор `trusted` и публикует сразу (тесты обеих ветвей).
8. `/{рубрика}/{слаг}` рендерится на сервере из JSON (`curl` содержит текст абзаца); черновик
   гостю → 404; главная показывает «Свежее» из данных и пустое состояние «Выбора редакции»;
   блока «Популярное» нет; `/en/...` работает для адресов; 301 по истории слагов (тест).
9. `/legal/*` существуют с версией; регистрация без согласия отклоняется (тест); README
   описывает два контура и правило-арбитр и не обещает MDC/Vercel/Render.
10. Прод в РФ: деплой по коммиту в `app` проходит; `/health` = 200 под внешней проверкой;
    ежедневный бэкап включён; восстановление на пустой инстанс проведено, счётчики совпали
    (отчёт с командами в `docs/reports/`).
11. Дизайн-система: одна палитра, `grep -rn "zinc-" web/app/components` = 0 (кроме
    допущенных исключений в токенах), `useTheme` и `components/demo/` удалены, единая схема
    отступов; Lighthouse страницы материала на сиде: LCP < 2,5 с (ориентир, гейт — этап 3).
12. Жалоба с страницы материала попадает в список админки; форма `/contact` отправляет письмо.

## 6. Риски и способ их снять

| Риск | Снятие |
|---|---|
| Расползание редактора («ещё один блок») | Каталог этапа 1 заморожен (ADR-0017); остальное — в список этапа 5 |
| Миграция живых данных Neon при непроверенном содержимом базы | Dry-run на ветке-копии, бэкап перед `migrate deploy`, M11 только после скрипта проверки |
| `sharp` и нативные бинарники в проде | Сборка образа под Linux в CI с пином платформы; тест загрузки в CI |
| Единственный модератор — владелец | Уведомления на e-mail, SLA 48 часов в правилах, очередь видна на `/admin` сразу после входа |
| Юридические тексты и провайдер РФ вне контроля разработчика | Placeholder-страницы и закрытая регистрация не блокируют разработку; блокируют только открытие регистрации |
| Оценка занижена (много подсистем) | Диапазон 28–40 уже расширен; при выходе за 40 — деградация: перенести жалобы и `/contact` в этап 2 |

## 7. Оценка

28–40 человеко-дней. Из них: миграции и репетиция 4–6; пакет `content` и рендер 3–4;
редактор с автосохранением, конфликтами и офлайном 5–7; медиа и варианты 3–4; вход, кабинет,
профиль 3–4; уровни доверия и очередь 2–3; публичные страницы и дизайн-система 5–7; прод,
деплой, бэкапы 3–4; юридические тексты и README 1–2 (без написания текстов).

## 8. Метрики успеха

- Внешних авторов (не владелец) с ≥ 1 опубликованным материалом.
- Медиана «первый вход → первый черновик» и «отправлено на проверку → опубликовано» из
  timestamps.
- Доля автосохранений с ошибкой < 1 %.
- Доля загрузок, отклонённых из-за лицензии или атрибуции (трение формы).
- Число возвращений автора за вторым материалом.
