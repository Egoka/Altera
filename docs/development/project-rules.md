# Правила разработки Altera

- **Статус**: действующие правила, перенесённые из `CLAUDE.md` 2026-09-13.
- **Исторический источник**: [полная версия CLAUDE до переноса](sources/2026-09-13-claude-original.md).
- **Карта переноса**: [migration ledger](migration-ledger.md).

Этот документ хранит подробности, общие для coding runner. Короткие `AGENTS.md` и `CLAUDE.md`
служат адаптерами и ведут сюда. Факты о реализации всегда перепроверяются по коду и конфигурации;
намерения из `docs/` не доказывают текущее состояние.

## Источники требований

При расхождении действует порядок:

1. рабочий журнал решений владельца
   `docs/decisions/role-review-working-log-2026-09-08.md`;
2. спецификации `docs/spec/` и `docs/spec/OPEN-QUESTIONS.md`;
3. ADR в `docs/decisions/` с учётом их статуса;
4. vision в `docs/vision/` как целевая архитектура и датированные срезы.

Продуктовые решения принимает владелец. Не подтверждённое кодом или спецификацией утверждение
помечается `[ДОПУЩЕНИЕ]`; открытый вопрос владельца не закрывается догадкой. Исторические
документы получают явную пометку и ссылку на замену, а не переписываются молча.

Порядок исполнения, права и условия выпуска заданы в
[операционной модели](../multica/operating-model.md). Очередь и идентификаторы T/E/Q/F заданы в
[бэклоге](../backlog/README.md). Прямое письменное поручение владельца с зафиксированными scope
и критериями также является источником полномочий и не требует фиктивного статуса `готова`.

Личные настройки Claude Code хранятся в `.claude/settings.local.json`: это локальный
неверсионируемый override, он не переносится в общие правила и не должен попадать в commit.
Версионируемые общие настройки находятся в `.claude/settings.json`; личный override не является
основанием менять репозиторный контракт или утверждать одинаковое поведение других runner.

## Репозиторий и технические соглашения

Altera — монорепозиторий pnpm: `web` (Nuxt 4 / Vue 3) и `server` (GraphQL Yoga / Prisma /
PostgreSQL / Redis). Основные каталоги:

```text
server/   GraphQL API
web/      Nuxt-приложение
docs/     планы, отчёты, решения, спецификации, бэклог и правила процесса
```

Существующие правила серверной работы:

- новые GraphQL-домены размещаются парой `schema.graphql` и `resolver.*` в `server/src/graphql/`;
- проверки доступа выполняются сервером через `server/src/exceptions/permissions.ts`, а не
  только интерфейсом;
- административные запросы следуют `docs/guides/admin_query_standards.md`;
- Redis-ключи объявляются явно, включают необходимые аргументы, связанные ключи
  инвалидируются после мутаций;
- именованные Prisma-миграции создаются осознанно, с учётом существующих данных.

Существующие правила веб-разработки:

- структура приложения находится в `web/app/`;
- обе локали `ru` и `en` меняются согласованно, стратегия маршрутов —
  `prefix_except_default` с английским языком по умолчанию;
- Tailwind 4, шрифты и токены задаются через `web/app/assets/css/main.css`, тема — через
  `@nuxtjs/color-mode`;
- наличие GraphQL-строки в `web/app/query/` само по себе не доказывает runtime-интеграцию.

Переменные окружения сервера перечисляются по именам, без значений:
`DATABASE_URL`, `DATABASE_URL_UNPOOLED`, `REDIS_URL`, `JWT_ACCESS_SECRET`,
`JWT_REFRESH_SECRET`, `JWT_ACCESS_TOKEN_EXPIRY`, `JWT_REFRESH_TOKEN_EXPIRY`,
`MAGIC_LINK_EXPIRY_MINUTES`, `MAGIC_LINK_BASE_URL`, `FRONTEND_URL`, `CACHE_TTL`, `PORT`.
Секреты, ключи и строки подключения нельзя читать без необходимости, сохранять в репозитории
или включать в вывод, evidence и trace.

Подробный датированный старый срез пробелов реализации сохранён в
[историческом CLAUDE](sources/2026-09-13-claude-original.md). Он не считается текущим фактом;
актуальность проверяется по коду, конфигурации и свежему evidence. Текущее состояние тестов и
CI вынесено в [testing.md](testing.md).

## Команды и побочные эффекты

Канонические команды и проверенный срез находятся в [testing.md](testing.md). Для разработки:

```bash
cd server && pnpm dev
cd web && pnpm dev
pnpm format:fix
pnpm lint
cd server && npx prisma migrate dev --name <имя>
```

`pnpm format:fix` изменяет файлы; `pnpm format`, `pnpm lint` и `pnpm test` предназначены для
проверки. `server`-скрипт `build` выполняет `prisma migrate deploy`; для проверки сборки без
применения миграций используется `cd server && pnpm run build:ci`.

## План, отчёт и evidence

До изменения создаётся план в `docs/plans/` с исходной ревизией; после работы — парный отчёт в
`docs/reports/`. Пути и форматы определяют README этих каталогов. План не переписывается задним
числом: отклонение записывается в отчёте или оформляется новым планом.

Репозиторные пути `docs/plans/` и `docs/reports/` и форматы их README имеют приоритет над
путями и форматами по умолчанию из любых skills планирования или выполнения. Skill дополняет
процесс, но не переносит план, отчёт или evidence в собственный служебный каталог вместо
обязательной пары репозитория.

Evidence привязывается к AC-ID, actor/run, `check_id`, полному commit и состоянию dirty tree.
Команда, cwd, exit code, значимый вывод, ограничения и `trace_ref` обязательны по
[контрактам артефактов](artifact-contracts.md). Успешный run не означает завершённую стадию;
завершённая стадия не означает принятую задачу.

## Git, формат и язык

- Коммиты используют Conventional Commits, допустимый тип из `commitlint.config.js`, scope в
  нижнем регистре, заголовок до 100 символов без точки.
- Ветки продукта: `server/*`, `web/*`; документация: `docs/*`. Прямые коммиты в `app`
  запрещены; условия push, PR, слияния и выпуска определены §7 операционной модели.
- Prettier задаёт формат: без точек с запятой, без trailing comma, ширина 120, отступ 2 пробела,
  `bracketSameLine`.
- Документация и комментарии пишутся по-русски; идентификаторы и сообщения GraphQL-ошибок —
  по-английски.
- Спецификации создаются в `docs/spec/` по локальным шаблонам: одна сущность — один файл,
  каждая строка реестра имеет соответствующий файл. В спецификациях нет оценок в человеко-днях
  и разделов «что не делаем».

Эти правила являются инструкциями. Техническое ограничение прав, параллельных writers и
обязательных проверок появляется только после реализации и отрицательной проверки M4; наличие
текста, hook или профиля агента ещё не доказывает enforcement.
