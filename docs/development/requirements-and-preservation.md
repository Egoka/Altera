## Правило миграции без регрессивной потери

1. Снимок до правки: commit и SHA-256 файла; для Multica — ID, поле, текст, время,
   назначения и состояние. Секреты заменяются отметкой о наличии; значения не экспортируются.
2. Каждому уникальному утверждению дать строку: старое место, точный фрагмент/ссылка,
   новое место, статус (`сохранено`, `перенесено`, `историческое`, `конфликт`), основание.
3. Перенос сначала добавляет новое место и ссылку из старого. История Git дополняет карту,
   но не заменяет её: факт должен оставаться находимым без знания удалённой фразы.
4. При конфликте сохранить обе формулировки с источниками и датой; разрешение не угадывать.
   Старый факт можно датировать, когда новая проверка его опровергает. Нормативное решение
   меняет только уполномоченный владелец, а не более свежий комментарий агента.
5. Проверить все 45 R-ID, сохранность ссылок, чисел, терминов, исключений и разрешений.
   Ноль необъяснённых потерь — условие перехода этапа, включая уникальные инструкции всех ролей.
6. Откатить только изменения соответствующего этапа обычным обратным diff/commit;
   не сбрасывать чужое дерево. Внешние изменения восстанавливаются отдельно по snapshot.

Манифест этого пакета — исходная точка, а не разрешение изменять перечисленные файлы.
В текущем поручении допустимы только новые документы и добавления ссылок в два индекса.
