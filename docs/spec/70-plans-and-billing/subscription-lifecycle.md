# Политика: Жизненный цикл подписки

- **Область**: планы и биллинг
- **Статус**: утверждён (гейт Г5, 2026-09-09)
- **ADR**: ADR-0010 п. 2–4, ADR-0035, ADR-0044 (п. 6 о льготном периоде и п. 2 заменены журналом
  §8.15, §21.16); `docs/vision/07-commerce.md` §4 (доплата, льготный период, 14-дневный возврат —
  заменены журналом #35, §8.15, §8.18)
- **Этап**: 1 при платном запуске; решение о платных подписках в первой версии — отложено (§8.13)

## 1. Назначение

Единственное описание состояний подписки и переходов: оформление, продление с пятью попытками
списания, очередь оплаченных периодов, отмена, возврат, истечение, ручные операции. Правила §8.3–6
ревизии Г1 (немедленное отключение после первой неудачи, «возврат не сокращает период», понижение
со следующего периода, остаток `standard`) **отменены** журналом Г5. На файл ссылаются матрица
#56, #59–62, #109, #119, `plans.md`, `pay-and-upgrade.md`, `subscription-expires.md`,
`30-account/reader/subscription.md`, `40-admin/subscriptions.md`.

## 2. Правила

1. **Оплаченный период** — единица учёта: план (`standard` / `pro`), интервал (месяц / год),
   начало, конец, источник (платёж или ручная выдача). Подписка пользователя — упорядоченная
   **очередь** таких периодов (журнал §8.22); неиспользованные оплаченные периоды не сгорают.
   `[ДОПУЩЕНИЕ: модель — несколько записей `Subscription` на аккаунт со статусами `active`,
   `queued`, `expired`, `canceled`; `03-data-model.md` уточняется при реализации]`.
2. **Приоритет активации** (§8.22): годовой `pro` → месячный `pro` → годовой `standard` →
   месячный `standard`. Активен период с наивысшим приоритетом; после его окончания запускается
   следующий оставшийся по тому же порядку; менее приоритетные ждут в очереди. Оплата любого
   плана при действующем другом — покупка периода в очередь по полной стоимости (журнал #35),
   доплата не рассчитывается.
3. **Оформление**: `checkout.start` → платёж у провайдера (Т-Касса первым — §8.14) с сохранением
   способа оплаты → вебхук `succeeded` → период создан и, если он приоритетнее текущего,
   активирован: `planTier`, `planUntil`, роль `author` (`role-derivation.md`); чек, письмо. Отказ —
   периода нет, `checkout.failed`; провайдер недоступен — `PROVIDER_UNAVAILABLE`.
4. **Продление** (§8.15): в дату окончания активного периода при отсутствии следующего в очереди
   система делает **пять автоматических попыток списания с 10:00 до 23:00** `[ДОПУЩЕНИЕ:
   равномерно, часовой пояс сервера]`; успех любой попытки продлевает план обычным образом
   (`subscription.renewed`); если ни одна не удалась, план сохраняется до конца этой даты и
   **истекает с 00:00 следующего дня** — права истёкшего плана (`subscription-expires.md`). Если в
   очереди есть оплаченный период — списания нет, активируется он.
5. **Отмена** (матрица #59): `cancelAtPeriodEnd = true` для активного периода — автосписания не
   будет, доступ до конца оплаченного периода; периоды в очереди сохраняются и активируются по
   приоритету `[ДОПУЩЕНИЕ]`; возобновление до конца периода снимает флаг; письмо-подтверждение.
6. **Смена плана** (матрица #60): нет отдельной операции «понизить со следующего периода» —
   покупка периода другого плана ставит его в очередь по приоритету (правило 2). Покупка `pro`
   при активном `standard`: `pro` активируется сразу, остаток `standard` ждёт в очереди; покупка
   `standard` при активном `pro`: `standard` ждёт окончания `pro`.
7. **Возврат** (§8.18; `refunds.md`): пользователь запрашивает возврат из кабинета — обращение на
   ручное рассмотрение; до решения сотрудника план не меняется; **после одобренного возврата
   подписка прекращается сразу**: возвращённый период удаляется из очереди, если он активен —
   доступ к возможностям плана закрывается немедленно, активируется следующий период очереди или
   права истёкшего плана; аудит с основанием.
8. **Истечение**: планировщик по индексу окончаний переводит активный период в `expired` в 00:00
   после даты окончания при неудаче попыток или отсутствии автосписания; статьи и рейтинг не
   меняются (журнал #5, §20.8, §21.16); сессия остаётся (журнал #55); авторские разделы остаются
   на чтение с актуальной аналитикой (§8.20–21).
9. **Ручные операции** (журнал #19, #25; матрица #61, #109): выдать, продлить, изменить, отменить
   подписку; дополнительные дни прибавляются к концу действующего оплаченного периода и не
   заменяют план; ручная выдача `pro` полностью равна оплаченной (§8.16); каждое действие — с
   причиной, платёжными данными, до/после, аудит.
10. **Архив аккаунта** (журнал #48, #50): очередь не останавливается — периоды идут; при
    восстановлении права по текущему состоянию очереди.
11. **Годовой интервал** (журнал #32): цена десяти месяцев, доступ двенадцать; годовой период
    приоритетнее месячного того же плана (§8.22).
12. **Цены** (§8.12): диапазоны — гипотезы, значения хранятся централизованно; технический
    источник — при реализации; смена цены не пересчитывает оплаченные периоды `[ДОПУЩЕНИЕ]`.
13. **Триала нет** (`07-commerce.md` §4) `[ДОПУЩЕНИЕ]`.

## 3. Исключения

| Исключение | Условие | Кто может | Аудит |
|---|---|---|---|
| Ручная выдача плана без оплаты — период в очередь по тем же правилам | `PlanGrant` | `analyst`, `admin`, `owner` | `plan.grant` |
| Дополнительные дни | к концу активного периода | `analyst`, `admin`, `owner` | `subscription.extend.manual` |
| Одобренный возврат — немедленное прекращение | решение сотрудника | `analyst`, `admin`, `owner` | `payment.refund`, `subscription.cancel` |
| Повторная обработка вебхука | сбой обработки | `admin`, `owner` | `webhook.replay` |

## 5. Проверяемость

- Тесты очереди: покупка `pro` при `standard` — `pro` активен, `standard` в очереди; окончание
  `pro` без продления — `standard` активируется; годовой `pro` приоритетнее месячного.
- Тест продления: пять попыток в дату окончания; успех третьей — период продлён; все пять
  неудачны — истечение с 00:00 следующего дня, до этого права полные.
- Тест возврата: до решения план не меняется; одобрение — период удалён, доступ закрыт сразу.
- Тест ручных дней: `+N` к концу активного периода.
- Метрики: доля неуспешных серий списаний, удержание на продлении (`07-commerce.md` §6).

## 6. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Модель очереди — несколько записей `Subscription`; попытки списания равномерно
  10:00–23:00 по часовому поясу сервера; отмена не трогает очередь; смена цены не пересчитывает
  периоды; триала нет.
- Отложено (§8.13): запуск платных подписок в первой версии — вопрос бизнес-модели (заход 5b).
- Отложено (§8.12): значения цен и технический источник их хранения.
- Закрыто Г5 (§8.15, §8.18, §8.22): пять попыток и истечение с 00:00; немедленное прекращение
  после одобренного возврата; единая очередь периодов по приоритету.
