# Политика: План `free`

- **Область**: планы и биллинг
- **Статус**: утверждён (гейт Г5, 2026-09-09)
- **ADR**: ADR-0035, ADR-0041 (в части, не противоречащей журналу), ADR-0028
- **Этап**: 1; журнал §24.1

## 1. Назначение

`free` — план каждого аккаунта по умолчанию (`plans.md` #1): выдаётся при регистрации, не требует
`Subscription` и записи `Plan` (ADR-0035 п. 1), даёт роль `reader` и набор пользовательских
функций. Файл фиксирует, что входит в `free`, чего в нём нет и как он соотносится с истёкшим
платным планом. На него ссылаются `50-access/roles/reader.md`, `20-public/pricing.md`,
`role-derivation.md`, `subscription-lifecycle.md`.

## 2. Правила

1. **Получение**: первый вход по ссылке из письма создаёт аккаунт с `planTier = free`,
   `planUntil = NULL` (`50-access/session-lifecycle.md` п. 2); отдельного действия «оформить
   free» нет. Проверяется резолвером входа.
2. **Состав** (`plans.md` #1; журнал §19): чтение всего опубликованного; закладки и подписка на
   авторов (3) — только `reader` и `author` (журнал #58); письма (уведомления о решениях,
   рассылки — правила отложены); профиль, сессии, смена почты, выгрузка данных (3), «удалить
   аккаунт» с самовосстановлением (журнал §5.2). Применяется хелпером прав: `perm(user)`.
3. **Чего нет** (после включения платности): создание, редактирование, отправка к публикации,
   вторая языковая версия, медиа к статьям — отказ `PLAN_LIMIT` с указанием требуемого плана и ссылкой на `/pricing` (журнал #5,
   #55); интерфейс создания предлагает выбор или продление плана, а не скрывает кнопку.
4. **Истёкший платный план = `free` с правами истёкшего плана** (журнал #5, §8.15, §8.20–21;
   ADR-0044): статьи остаются опубликованными; авторские разделы не исчезают, если есть хотя бы
   одна статья или данные по ней — статьи, рейтинг и актуальная личная аналитика доступны на
   чтение и продолжают обновляться; архив своих и экспорт доступны; создание, правка, повторная
   публикация, возврат из архива закрыты до продления. Сессия остаётся, сервер отклоняет
   подписочные вызовы (журнал #55). Без единой статьи разделы можно не показывать — состав
   интерфейса определяется заходом 6.
5. **Цена** — 0; чеков и платежей нет; `Customer` не создаётся до первой оплаты.
6. **Публичный профиль** у `free` есть только при наличии опубликованных материалов (бывший
   автор) — `20-public/author.md` §1 `[ДОПУЩЕНИЕ]`.
6а. **Первый запуск — бесплатный** (журнал §24.1, §25.1): при регистрации аккаунт — читатель с
   `free`; при первом нажатии «Создать статью» ему автоматически и бессрочно открываются базовые
   авторские возможности без оплаты и ручного одобрения. `[ДОПУЩЕНИЕ: техническое отображение]`
   в этот момент система создаёт бессрочную базовую выдачу (`PlanGrant` уровня `standard`,
   `endsAt = NULL`, `grants-and-promo.md`; аудит `author.enabled` — события #87 `[черновик]`),
   поэтому правила 3–4 и инвариант `role-derivation.md` не меняются; при включении платности
   судьба таких выдач — отдельное решение владельца (`90-business-model/overview.md` §6).
7. **Лимиты**: только общие лимиты частоты (`50-access/rate-limits.md`); лимитов плана нет.
8. **Индивидуальные исключения** для `reader` не выдаются (журнал #7).
9. **Paywall зарезервирован** (ADR-0036): `free` читает всё целиком; при будущем включении план
   `free` останется бесплатным чтением открытых материалов — одним предложением.

## 3. Исключения

| Исключение | Условие | Кто может | Аудит |
|---|---|---|---|
| Ручная выдача плана бывшему или будущему автору | `PlanGrant` (`grants-and-promo.md`) | `analyst`, `admin`, `owner` | `plan.grant` |
| Служебные учётные записи | план `free`, но создают материалы по роли (`editor`, `owner`) без подписки | по роли | — |
| Права истёкшего плана | бывший автор: архив своих статей, история, личная аналитика на чтение (§8.20), экспорт | сам | — |

## 4. Взаимодействие с другими политиками

- `role-derivation.md` — `free` ⇔ отсутствие активной подписки и выдачи; при конфликте кэша и
  подписки главнее подписка.
- `50-access/permission-checks.md` п. 6 — `ensureActiveAuthor` и `PLAN_LIMIT`.
- `50-access/roles/reader.md` — полный перечень действий.
- `60-ranking/*` — истечение плана не влияет на рейтинг (§20.8); закладки `free` — сигнал (§21.3).

## 5. Проверяемость

- Тест: новый аккаунт после подтверждения ссылки имеет `planTier = free`, роль `reader`,
  `Subscription` отсутствует.
- Тест: `article.create` для `free` — `PLAN_LIMIT` с `requiredTier = standard`.
- Тест: бывший автор с `free` архивирует свою статью — успех; читает аналитику — успех; правит —
  `PLAN_LIMIT`.
- Тест: закладка и подписка на автора для `free` — успех; для служебной роли — `FORBIDDEN`.
- Метрика: доля `free`-аккаунтов, дошедших до `/pricing` (воронка, `07-commerce.md` §6).

## 6. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Публичный профиль у `free` только при наличии публикаций; `Customer` создаётся
  при первой оплате.
- Закрыто Г5 (§8.20–21): бывший автор сохраняет авторские разделы и актуальную личную
  аналитику в режиме чтения.
- Закрыто Г5b–Г6 (§24.1, §25.1): первый запуск бесплатный; при регистрации — читатель; базовое
  авторство открывается при первом «Создать статью»; отображение через бессрочную базовую
  выдачу в этот момент — `[ДОПУЩЕНИЕ]`.
