# Политика: Возвраты и корректность платежей

- **Область**: планы и биллинг
- **Статус**: на утверждении
- **ADR**: ADR-0010 п. 2–4, ADR-0032; `docs/vision/07-commerce.md` §4 (14-дневное правило —
  заменено журналом #21 и решением сотрудника)
- **Этап**: 1

## 1. Назначение

Правила и процедура возврата средств, пометка ошибочных платежей и их исключение из аналитики без
удаления истории (журнал #21, #26–27, §10). На файл ссылаются матрица #62, #108, события #21, #73,
`admin-sections.md` #9, `receipts-54fz.md`, `20-public/legal-refunds.md` (5b).

## 2. Правила

1. **Возврат не сокращает оплаченный период** (журнал #21): подписка остаётся активной до конца
   периода; роль и права не меняются возвратом.
2. **Кто решает**: `analyst`, `admin`, `owner` (финансовый контур, журнал #19) — в карточке
   платежа, с причиной; автоматических возвратов нет; самостоятельного возврата в кабинете нет —
   пользователь пишет в поддержку (`/contact`) `[ДОПУЩЕНИЕ]`.
3. **Основания**: правила публичной политики возвратов (`legal-refunds.md`, 5b) — двойное
   списание, техническая ошибка, обращение в разумный срок `[ДОПУЩЕНИЕ: перечень — юридический
   текст]`; прежнее правило «14 дней без публикаций» не является правилом системы.
4. **Механика**: `payment.refund(paymentId, amountMinor, reason)` → адаптер провайдера → чек
   возврата (`receipts-54fz.md`) → `Payment.refundedAt`, `refundMinor`, `status = refunded` при
   полном возврате; частичный возврат сохраняет `succeeded` с `refundMinor` `[ДОПУЩЕНИЕ]`; аудит
   `payment.refund` с суммой, причиной, сотрудником, до/после (журнал #19).
5. **Отмена подписки при возврате** — отдельное решение сотрудника (`subscription.admin.cancel`,
   матрица #61); по умолчанию подписка продолжается (правило 1).
6. **Ошибочные платежи** (журнал #26–27; матрица #108): `analyst`, `admin`, `owner` помечают
   платёж ошибочным и исключают из аналитических расчётов с причиной; запись не удаляется, факт и
   основание сохраняются; обратимо (`payment.include`); аудит `payment.exclude`. В показатели
   входят только успешные платежи.
7. **Аналитика**: MRR, конверсии и отчёты считают только `succeeded` без исключённых; возвраты —
   отдельная метрика «доля возвратов» (`07-commerce.md` §6).
8. **Провайдер недоступен** — `PROVIDER_UNAVAILABLE`, возврат ставится в очередь повтора
   `[ДОПУЩЕНИЕ]`.
9. **Письмо** пользователю о возврате — по событию (правила рассылок отложены).
10. **Финансовые записи не удаляются** ни при каких операциях, включая «удалить навсегда»
    (`roles/owner.md` §6).

## 3. Исключения

| Исключение | Условие | Кто может | Аудит |
|---|---|---|---|
| Возврат с отменой подписки | решение сотрудника | `analyst`, `admin`, `owner` | `payment.refund`, `subscription.cancel` |
| Частичный возврат | сумма меньше платежа | `analyst`, `admin`, `owner` | `payment.refund` |
| Исключение платежа из аналитики | ошибочный или тестовый платёж | `analyst`, `admin`, `owner` | `payment.exclude` |
| Возврат тестового провайдера | тесты | система | — |

## 4. Взаимодействие с другими политиками

- `subscription-lifecycle.md` п. 8 — период не сокращается; главнее журнал #21.
- `payment-provider.md` — адаптер; `receipts-54fz.md` — чек возврата.
- `60-ranking/*` — возврат и исключение платежа на рейтинг не влияют.
- `40-admin/payments-and-refunds.md` (8a) — экран.

## 5. Проверяемость

- Тест: возврат не меняет `currentPeriodEnd` и роль.
- Тест: `payment.refund` без причины — `VALIDATION_ERROR`; сумма больше платежа —
  `VALIDATION_ERROR`; повторный полный возврат — `CONFLICT`.
- Тест: `payment.exclude` убирает платёж из MRR, запись остаётся; `payment.include` возвращает.
- Тест: `moderator` вызывает `payment.refund` — `FORBIDDEN`.
- Метрика: доля возвратов ≤ порога `07-commerce.md` §6.

## 6. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Нет самостоятельного возврата в кабинете; частичный возврат сохраняет статус;
  очередь повтора при недоступности провайдера; перечень оснований — в юридическом тексте.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Нужна ли кнопка «запросить возврат» в кабинете (обращение с
  предзаполненным платежом) вместо письма в поддержку? Если да — матрица получает
  `refund.request` для аккаунта и очередь обращений; если нет — только `/contact`.
