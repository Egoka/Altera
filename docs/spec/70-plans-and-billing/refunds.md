# Политика: Возвраты и корректность платежей

- **Область**: планы и биллинг
- **Статус**: утверждён (гейт Г5, 2026-09-09)
- **ADR**: ADR-0010 п. 2–4, ADR-0032; `docs/vision/07-commerce.md` §4 (14-дневное правило —
  заменено журналом §8.18)
- **Этап**: отдельный этап платности (журнал §24.1)

## 1. Назначение

Запрос возврата из кабинета, ручное решение сотрудника, немедленное прекращение подписки после
одобрения (журнал §8.18), пометка ошибочных платежей и их исключение из аналитики без удаления
истории (журнал #26–27, §10). Правило Г1 «возврат не сокращает период» **отменено** (§8.4). На
файл ссылаются матрица #62, #108, #119, события #21, #73, `admin-sections.md` #9,
`receipts-54fz.md`, `20-public/legal-refunds.md` (5b).

## 2. Правила

1. **Запрос возврата** (§8.18; матрица #119): кнопка «Запросить возврат» в кабинете
   (`30-account/reader/subscription.md`) у платежа создаёт обращение с причиной для ручного
   рассмотрения; повторный запрос по тому же платежу при открытом обращении — `CONFLICT`; лог
   `refund.requested`.
2. **До решения план не меняется** (§8.18): подписка и права остаются прежними, обращение видно в
   разделе «Платежи» (`admin-sections.md` #9).
3. **Кто решает**: `analyst`, `admin`, `owner` (финансовый контур, журнал #19) — одобрить с суммой
   или отклонить с причиной; автоматических возвратов нет; аудит `payment.refund` /
   `refund.rejected` с основанием, сотрудником, до/после.
4. **Одобренный возврат прекращает подписку сразу** (§8.18; для активного или завершившегося
   периода — обычные правила возврата, журнал §24.4): возвращённый период удаляется из
   очереди (`subscription-lifecycle.md` п. 7); если он активен — доступ к возможностям плана
   закрывается немедленно, активируется следующий период очереди или права истёкшего плана
   (`subscription-expires.md`); статьи и рейтинг не меняются (§20.8, §21.16).
4а. **Неактивный период очереди** (журнал §24.4): оплаченный период, который ещё не
   активировался и ждёт в очереди, возвращается по запросу пользователя без отдельной причины;
   период удаляется из очереди, активный период и права не меняются; аудит `payment.refund` с
   основанием «неактивный период очереди».
5. **Механика**: адаптер провайдера (`payment-provider.md`) → чек возврата (`receipts-54fz.md`) →
   `Payment.refundedAt`, `refundMinor`, `status = refunded`; частичный возврат `[ДОПУЩЕНИЕ:
   допустим по решению сотрудника; подписка при частичном возврате также прекращается]`.
6. **Основания** — публичная политика возвратов (`legal-refunds.md`, 5b); состав документов и
   бухгалтерский контур — предрелизная проверка (§8.19).
7. **Ошибочные платежи** (журнал #26–27; матрица #108): `analyst`, `admin`, `owner` помечают
   платёж ошибочным и исключают из аналитических расчётов с причиной; запись не удаляется;
   обратимо (`payment.include`); аудит `payment.exclude`.
8. **Аналитика**: MRR и конверсии считают только `succeeded` без исключённых; возвраты —
   отдельная метрика (`07-commerce.md` §6).
9. **Провайдер недоступен** — `PROVIDER_UNAVAILABLE`, возврат ставится в очередь повтора
   `[ДОПУЩЕНИЕ]`; обращение остаётся открытым.
10. **Письмо** пользователю о решении — по событию (правила рассылок — этап почты, §8.23).
11. **Финансовые записи не удаляются** ни при каких операциях (`roles/owner.md` §6).

## 3. Исключения

| Исключение | Условие | Кто может | Аудит |
|---|---|---|---|
| Возврат без запроса пользователя | инициатива сотрудника (двойное списание, ошибка) | `analyst`, `admin`, `owner` | `payment.refund` |
| Частичный возврат | по решению сотрудника | `analyst`, `admin`, `owner` | `payment.refund` |
| Исключение платежа из аналитики | ошибочный или тестовый платёж | `analyst`, `admin`, `owner` | `payment.exclude` |
| Тестовый провайдер | тесты | система | — |

## 4. Взаимодействие с другими политиками

- `subscription-lifecycle.md` п. 7 — прекращение подписки; главнее журнал §8.18.
- `payment-provider.md` — адаптер; `receipts-54fz.md` — чек возврата.
- `60-ranking/*` — возврат и исключение платежа на рейтинг и Pro-балл не влияют.
- `40-admin/payments-and-refunds.md` (8a) — экран обращений и решений.

## 5. Проверяемость

- Тест: запрос возврата не меняет `planUntil` и роль; одобрение — период удалён, роль `reader`
  или следующий период активирован в той же транзакции.
- Тест: повторный запрос по открытому обращению — `CONFLICT`; отклонение — план не меняется.
- Тест: `payment.refund` без причины — `VALIDATION_ERROR`; `moderator` — `FORBIDDEN`.
- Тест: `payment.exclude` убирает платёж из MRR, запись остаётся.
- Метрика: доля возвратов ≤ порога `07-commerce.md` §6; время до решения.

## 6. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Частичный возврат прекращает подписку так же; очередь повтора при недоступности
  провайдера.
- Отложено (§8.19): состав документов и бухгалтерский контур возвратов — предрелизная проверка.
- Закрыто Г5 (§8.18): кнопка «Запросить возврат»; до решения план не меняется; после одобрения
  — прекращение сразу.
- Закрыто Г5b (§24.4): неактивный период очереди — возврат без отдельной причины; активный и
  завершившийся — по обычным правилам.
