# Политика: Вывод роли из плана

- **Область**: планы и биллинг / доступ
- **Статус**: утверждён (гейт Г5, 2026-09-09)
- **ADR**: ADR-0003 п. 4, ADR-0035 п. 2–4, ADR-0044 (в части, не противоречащей журналу #5, §8.15,
  §8.17, §8.20–22, #46–47, #55)
- **Этап**: 1

## 1. Назначение

Инвариант «`role = author` ⇔ активная подписка `standard`/`pro` ∨ действующая ручная выдача»
(ADR-0035 п. 2) и механика его поддержания: кэш `User.planTier`, `User.planUntil`, обновление
вебхуком и планировщиком, истечение с 00:00 после неудачной серии списаний (журнал §8.15),
сохранение сессии (журнал #55), очередь оплаченных периодов (§8.22). На файл ссылаются `50-access/permission-checks.md` п. 6,
`escalation-and-demotion.md` п. 1, `roles/reader.md`, `roles/author.md`, матрица #17.

## 2. Правила

1. **Источник истины** — активный период очереди подписки (`subscription-lifecycle.md` п. 1–2)
   либо `PlanGrant.endsAt`;
   `User.planTier` и `planUntil` — кэш для проверок прав, читается на каждый запрос
   (`session-lifecycle.md` п. 8), роль не хранится в токене.
2. **Активация**: вебхук `succeeded` → в одной транзакции `Subscription.active`, `planTier`,
   `planUntil = currentPeriodEnd`, `role = author`; лог `subscription.activated`. Ручная выдача —
   то же с `planUntil = PlanGrant.endsAt`, аудит `plan.grant`.
3. **Деактивация** (журнал §8.15): в дату окончания активного периода при пустой очереди — пять
   попыток списания 10:00–23:00, права полные; при неудаче с 00:00 следующего дня — `planTier =
   free`, `planUntil = NULL`, `role = reader`; отзыв выдачи, одобренный возврат (§8.18) —
   немедленно; планировщик проходит индекс окончаний не реже раза в минуту `[ДОПУЩЕНИЕ]`; лог
   `subscription.expired` / `.deactivated`. Если в очереди есть период — активируется он без
   смены роли.
4. **Права истёкшего плана** (журнал #5, §8.20–21): у `reader` с прежними материалами — архив
   своих, история, личная аналитика и авторские разделы на чтение, экспорт; создание, правка, повторная публикация, возврат из архива — `PLAN_LIMIT`
   (`permission-checks.md` п. 6). Сессия не отзывается; сервер отклоняет каждый вызов, требующий
   плана, с логом `plan.action.rejected` (журнал #55).
5. **Приоритет при нескольких источниках** (§8.22): выдача — такой же период очереди; активен
   период с наивысшим приоритетом (годовой `pro` → месячный `pro` → годовой `standard` →
   месячный `standard`).
6. **Служебные роли** от плана не зависят (журнал #47): `editor` и `owner` создают материалы без
   подписки; `planTier` у служебной записи — `free`; служебная запись не может приобрести или
   получить `pro` (§8.17) — `checkout.start` и `plan.grant` для неё `FORBIDDEN`; читатель или
   автор в служебную роль не повышается (журнал #46).
7. **Обратный переход `reader → author`** — только планом (`escalation-and-demotion.md` п. 1);
   ручное назначение роли `author` невозможно — только выдача плана.
8. **Грейд** `basic | pro` вычисляется из `planTier` (ADR-0037); в рейтинге используется снимок при
   публикации (§21.15), а не текущий грейд.
9. **Расхождение кэша** (подписка активна, а `planTier = free`, или наоборот) — ошибка
   инварианта: тест-инвариант и ночная сверка `[ДОПУЩЕНИЕ]` с записью в журнал ошибок
   (`admin-sections.md` #22).
10. **Архив аккаунта**: кэш не меняется; подписка идёт (журнал #50); при восстановлении права
    определяются текущим `planUntil`.

## 3. Исключения

| Исключение | Условие | Кто может | Аудит |
|---|---|---|---|
| Ручная выдача плана | `PlanGrant` со сроком и причиной | `analyst`, `admin`, `owner` | `plan.grant` |
| Отзыв выдачи | `PlanGrant.revokedAt` | `analyst`, `admin`, `owner` | `plan.revoke` |
| Служебная роль без подписки | `editor`, `owner` создают материалы | по роли | — |
| Ночная сверка кэша | расхождение | система | журнал ошибок |

## 4. Взаимодействие с другими политиками

- `subscription-lifecycle.md` — события, порождающие активацию и деактивацию; главнее он.
- `50-access/permission-checks.md` — порядок проверок; `PLAN_LIMIT`, не `FORBIDDEN`.
- `50-access/escalation-and-demotion.md` — служебные роли отдельно от плана.
- `60-ranking/author-score.md` — план в рейтинг не входит (§20.8).

## 5. Проверяемость

- Инвариант-тест на фикстуре: для каждого пользователя `role = author` ⇔ активная подписка ∨
  выдача.
- Тест: после неудачной серии списаний роль `reader` с 00:00; в день попыток права полные;
  `translation.save` после истечения — `PLAN_LIMIT`, сессия валидна.
- Тест: вебхук возвращает `author` без нового входа.
- Тест: `staff.create` даёт служебную роль с `planTier = free`; `article.create` для `editor` —
  успех без подписки.
- Метрика: число расхождений кэша за сутки — ноль.

## 6. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Планировщик раз в минуту; ночная сверка кэша.
- Закрыто Г5 (§8.17): служебная запись `pro` не покупает и не получает; редакционные статьи —
  всегда базовый режим.
