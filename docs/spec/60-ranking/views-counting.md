# Рейтинг: Просмотры

- **Реестр**: таблица компонентов в `60-ranking/README.md` #5
- **Статус**: на утверждении
- **ADR**: ADR-0027, ADR-0038 (в части, не противоречащей журналу #26–27, §10)
- **Этап**: 2 (маяк, агрегаты, компонент), статистика автора — по плану (матрица #9)

## 1. Что ранжируем и где применяется

Компонент `V` — уникальные суточные прочтения версии материала за скользящее окно, без
профилирования читателей (ADR-0027): суточный хэш из соли дня, IP и user-agent, дедупликация в
базе, IP не хранится, аккаунт в хэш не входит. Применяется: вход `V` в `article-score.md`,
«Популярное за неделю» на главной напрямую (`home-sections.md`), статистика автора (сумма для
`standard`, по дням для `pro` — матрица #9), агрегаты для `analyst`. Не применяется: в
показателях читателю (число прочтений на странице не показывается `[ДОПУЩЕНИЕ]` по ADR-0038
п. 4), в закладках. В расчёты входят только валидные записи: исключённые дни (`ReadExclusion`,
журнал #26–27) не влияют ни на рейтинг, ни на статистику автора, ни на отчёты, но история
сохраняется.

## 2. Входы

| Вход | Источник (таблица / поле) | Обновление (событие / расписание) | Диапазон | Нормализация |
|---|---|---|---|---|
| Маяк прочтения | `POST /api/read` (`routes.md` #67), условие — `20-public/article.md` §7 | по действию читателя | — | — |
| Сырые события | `ReadEvent(day, articleId, visitorHash)` уникальность в базе; 8 дней | вставка `ON CONFLICT DO NOTHING` | — | — |
| Суточный агрегат | `ArticleReadDaily(articleId, day, uniqueReads)` бессрочно | в той же транзакции, что вставка | ≥ 0 | — |
| Исключения | `ReadExclusion(articleId, day, reason, excludedById)` | `reads.exclude` / `reads.include` (матрица #71) | — | вычитание дня |
| Опорное значение | `viewsReference` — P90 `uniqueReads` за окно по всем материалам локали на момент пересчёта `[ДОПУЩЕНИЕ]` | каждый пересчёт | ≥ 1 | — |
| Параметры | `RankingConfig.weights.viewsWindowDays`, `viewsReferencePercentile` | смена конфигурации | 1–90 дн; 50–99 | — |

## 3. Формула

```
reads = Σ uniqueReads(articleId, day)  за day ∈ [today − viewsWindowDays + 1, today]
        минус дни из ReadExclusion
V     = min(1, log(1 + reads) / log(1 + viewsReference))
```

По умолчанию `viewsWindowDays = 7`, `viewsReferencePercentile = 90` `[ДОПУЩЕНИЕ]`. Логарифм
сглаживает разрыв между материалами с десятками и тысячами прочтений; опорное значение —
перцентиль по локали, чтобы «много» означало «много для этого издания сейчас», а не абсолютное
число (ADR-0038 п. 2 говорит о медиане ленты — заменено на перцентиль по локали, чтобы
компонент был контекстно-независимым и хранился в `ArticleScore` `[ДОПУЩЕНИЕ]`). Нет
прочтений — `V = 0`; `viewsReference < 1` (пустая база) — `V = 0` для всех. Округление до 6
знаков. Текущий незакрытый день учитывается по текущему значению агрегата `[ДОПУЩЕНИЕ]`.

## 4. Окно времени и затухание

Окно 7 дней скользящее, границы — календарные дни UTC (ADR-0027). Внутри окна дни равноправны
(затухания нет — оно задано компонентом `F`). За окном прочтения выпадают из `V`, но остаются в
`ArticleReadDaily` для статистики и «истории» автора и для окна автора (`author-score.md`, 90
дней). «Популярное за неделю» использует тот же семидневный расчёт без нормализации — сумму
(`home-sections.md`).

## 5. Бусты и переопределения

Надбавок нет. Единственные ручные действия — пометить день ошибочным и исключить из расчётов
(`reads.exclude`, `analyst`/`admin`/`owner`, с причиной и аудитом — журнал #27) и вернуть
(`reads.include`); запись не удаляется (журнал #26). Исключение действует немедленно на
следующий пересчёт затронутого материала и автора. «Досчитать» прочтения вручную нельзя.

## 6. Пересчёт

Событийно: вставка маяка обновляет только агрегат, не `ArticleScore`; исключение или возврат
дня — пересчёт материала и автора. По расписанию: закрытие дня (00:05 UTC `[ДОПУЩЕНИЕ]`) —
пересчёт `V` для всех материалов с прочтениями в окне и `viewsReference`; часовой пересчёт
затухания использует текущее значение `reads`. Хранение: события 8 дней, соли 2 дня, агрегаты
бессрочно (housekeeping — `08-operations.md`). Детерминизм — при фиксированных агрегатах,
исключениях и опорном значении; `viewsReference` сохраняется в записи пересчёта
(`recompute.md`).

## 7. Объяснимость читателю

Фраза при доминирующем `V` — «много читают на этой неделе» (`explainability.md`); число не
показывается. Подпись «Популярного» — «по числу прочтений за неделю» (ADR-0027 п. 4). Автору —
сумма (`standard`) или по дням (`pro`) с пометкой исключённых дней «не учитывается: {причина}»
`[ДОПУЩЕНИЕ: причина видна автору в общей формулировке]`.

## 8. Защита от накрутки

| Вектор | Контрмера | Что логируется | Кто разбирает |
|---|---|---|---|
| Перезагрузки и повторные заходы | дедупликация по (день, материал, хэш) | — | — |
| Боты | фильтр по user-agent до записи; лимит маяков на IP (`rate-limits.md` п. 6) | `rate_limit.hit` | — |
| Смена IP/UA скриптом | аномалия «всплеск уникальных хэшей из одного диапазона» — `anti-fraud.md` | `read.anomaly` (черновик) | `analyst`, `admin`, `owner` |
| Самопросмотры автора | аккаунт в хэш не входит; ловится только как аномалия; маяк не шлётся автору своей статьи в его сессии (`article.md` §11) | — | `analyst` |
| Прочтения без прокрутки | условие маяка на клиенте; сервер не проверяет `[ДОПУЩЕНИЕ]` | — | — |

## 9. Тесты и проверяемость

- Тест: два маяка одного хэша в один день дают `uniqueReads = 1`; на следующий день — 2.
- Тест: исключённый день не входит в `reads`, возврат дня — входит; запись `ArticleReadDaily`
  не удаляется.
- Тест: `V = 1` при `reads ≥ viewsReference`; `V = 0` при отсутствии прочтений.
- Тест: ответ статистики автору с `standard` — сумма; с `pro` — по дням; читателю поле
  недоступно.
- Метрика: доля маяков, отсечённых фильтром ботов и лимитом.

## 10. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Окно 7 дней; опорное значение — P90 по локали вместо медианы ленты; текущий день
  учитывается; закрытие дня в 00:05 UTC; число прочтений читателю не показывается; сервер не
  проверяет условие прокрутки.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Утвердить окно 7 дней и нормализацию по P90 локали? Если да — сид
  конфигурации; если нет — окно в диапазоне 1–90 дней и перцентиль 50–99 на выбор владельца.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Показывать ли читателю число прочтений на странице материала? Если да —
  поле в публичном типе и строка в подвале статьи; если нет — как описано (ADR-0038 п. 4).
