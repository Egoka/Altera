# Рейтинг: Принципы лент

- **Реестр**: таблица компонентов в `60-ranking/README.md` #9
- **Статус**: на утверждении
- **ADR**: ADR-0002, ADR-0019, ADR-0034 (в части, не противоречащей журналу §20.4–5)
- **Этап**: 1 (по новизне), 2 (по рейтингу после Г4)

## 1. Что ранжируем и где применяется

Общие правила всех списков материалов, кроме подборок главной: лента рубрики, лента тега,
страница автора, RSS, «Ещё по теме» на странице материала, поиск (только пагинация и языковая
граница — релевантность в заходе 5b). Правила: одна лента без персонализации (ADR-0034), строгая
языковая граница (журнал §20.5), порядок — до Г4 только по новизне без переключателя (журнал
§20.4), после Г4 — по рейтингу с контекстом (`article-score.md`, `topic-relevance.md`);
стабильная пагинация по страницам; одинаковый ответ для всех (ADR-0019).

## 2. Входы

| Вход | Источник (таблица / поле) | Обновление (событие / расписание) | Диапазон | Нормализация |
|---|---|---|---|---|
| Кандидаты | `ArticleTranslation` в `published` с `locale` запроса | публикация, снятие, архив | — | — |
| Контекст | рубрика (`Article.sectionId`), тег (`ArticleTag`), автор (`Article.authorId`) | на чтении | — | — |
| Порядок | до Г4 — `firstPublishedAt desc, id desc`; после — `score(context) desc, firstPublishedAt desc, id desc` | пересчёт | — | — |
| Фильтры | `?format=`, `?tag=` (рубрика) | на чтении | — | — |
| Страница | `?page=N` | на чтении | 1…`totalPages` | — |
| Параметры | `RankingConfig.weights.feedPageSize`, `feedSortMode` (`date` / `score`) | смена конфигурации | 12–48; enum | — |

## 3. Формула

Лента — упорядоченный список кандидатов контекста с ключом сортировки:

```
до Г4:     key = (firstPublishedAt desc, id desc)
после Г4:  key = (score + topicWeight · T(context) desc, firstPublishedAt desc, id desc)
страница N = элементы [(N−1)·feedPageSize, N·feedPageSize)
```

`feedPageSize = 24` `[ДОПУЩЕНИЕ]`; `feedSortMode` переключается владельцем на `score` после Г4
одной сменой конфигурации — без релиза кода `[ДОПУЩЕНИЕ]`. Пользовательского переключателя
сортировки на этапе 1 нет (журнал §20.4); появится ли он после Г4 — вопрос владельца (§10).
`totalPages` считается по числу кандидатов; `page > totalPages` — 404 (`section-feed.md` §8).
Стабильность: страницы одного запроса читают снимок `ArticleScore` на момент последнего
завершённого пакета пересчёта (`recompute.md`), поэтому материал не «прыгает» между
страницами внутри одной сессии просмотра; ключ с `id` исключает дубли при равных баллах.

## 4. Окно времени и затухание

Окон у лент нет: показывается вся история опубликованного в контексте, порядок задают давность
(`freshness-decay.md`) и остальные компоненты. RSS — последние 50 по дате `[ДОПУЩЕНИЕ]`
независимо от `feedSortMode` (ADR-0034: RSS по дате).

## 5. Бусты и переопределения

Буст действует во всех лентах через `score` (`pro-boost.md`). Закрепления, ручного порядка и
«редакционных подборок» нет. Владелец управляет лентами только параметрами конфигурации:
размер страницы, режим сортировки. Фильтры ленты (формат, тег) сужают кандидатов и не меняют
ключ.

## 6. Пересчёт

Ленты не материализуются: запрос по индексам (`ArticleScore.score desc`,
`ArticleTranslation(locale, status, firstPublishedAt)`, `ArticleTag(tagId, position)`).
Ответ каждой страницы кешируется по (контекст, фильтры, страница, локаль) до инвалидации:
публикация или снятие в контексте, завершение пакета пересчёта, правка таксономии материала
(`recompute.md` §6). Ответ не зависит от сессии — общий кеш (ADR-0019). Стоимость запроса —
константа на страницу; `totalPages` — счётчик по индексу.

## 7. Объяснимость читателю

Подпись ленты (`caption`) называет принцип словами: до Г4 — «по дате публикации»; после —
«по рейтингу: свежесть, прочтения, рейтинг автора» в ленте автора и «… и соответствие теме» в
лентах рубрики и тега (`explainability.md`). Под карточкой — `RankExplainer` по доминирующему
компоненту (после Г4). Число и веса не раскрываются.

## 8. Защита от накрутки

| Вектор | Контрмера | Что логируется | Кто разбирает |
|---|---|---|---|
| Массовые публикации в рубрику | лимит очереди (`plans.md`), `anti-fraud.md` — правило «массовые публикации» | `translation.submit` | `moderator` |
| Подмешивание чужой локали ради охвата | языковая граница на уровне запроса; вторая версия — отдельная публикация с проверкой | — | — |
| Перебор страниц ботами | лимиты запросов по IP (`rate-limits.md`) | `rate_limit.hit` | — |
| Манипуляции фильтрами | фильтры не влияют на `score`; результат — подмножество | — | — |

## 9. Тесты и проверяемость

- Тест: две страницы подряд не содержат общих материалов и не пропускают ни одного при
  неизменном снимке.
- Тест: лента `ru` не содержит версий `en` при любых баллах; материал с двумя версиями
  присутствует в обеих локалях по одному разу.
- Тест: `feedSortMode = date` даёт порядок по `firstPublishedAt`; `score` — по ключу §3.
- Тест: ответ ленты идентичен для гостя, читателя и владельца.
- Тест: `page > totalPages` — 404; `page = 0` — 404.

## 10. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Размер страницы 24; переключение режима сортировки конфигурацией; RSS —
  последние 50 по дате; страницы читают снимок последнего пакета пересчёта.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Нужен ли после Г4 пользовательский переключатель «по рейтингу / по дате»
  в лентах рубрик и тегов? Если да — `?sort=` возвращается в `section-feed.md`, `tag-feed.md`,
  `author.md` и компонент `FeedControls` получает переключатель; если нет — порядок задаёт только
  `feedSortMode`.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Утвердить размер страницы 24 карточки? Если да — сид; если нет —
  значение 12–48.
