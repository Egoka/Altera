# Рейтинг: Принципы лент

- **Реестр**: таблица компонентов в `60-ranking/README.md` #9
- **Статус**: утверждён (гейт Г4 — принципы, 2026-09-09)
- **ADR**: ADR-0002, ADR-0019, ADR-0034 (в части, не противоречащей журналу §20.4–5, §21.21, §21.25,
  §22.5)
- **Этап**: 1 (по новизне), 2 (по рейтингу после запуска движка)

## 1. Что ранжируем и где применяется

Общие правила списков материалов, кроме подборок главной: ленты рубрик и тегов, страница автора,
RSS, «Ещё по теме» на странице материала. Правила: одна лента без персонализации (ADR-0034);
строгая языковая граница (§20.5); до запуска движка — только по новизне без переключателя
(§20.4); после запуска пользователь выбирает «по рейтингу» или «по дате», по умолчанию — по
рейтингу (§22.5); стабильная пагинация; одинаковый ответ для всех (ADR-0019). Поиск —
отдельная спецификация (заход 5b): порядок результатов определяет только релевантность
Meilisearch, рейтинг статьи вторым ключом не используется (§21.21).

## 2. Входы

| Вход | Источник (таблица / поле) | Обновление (событие / расписание) | Диапазон | Нормализация |
|---|---|---|---|---|
| Кандидаты | опубликованные версии локали запроса | публикация, снятие, архив | — | — |
| Контекст | рубрика, тег (с порядком тегов), автор | на чтении | — | — |
| Режим порядка | `date` (до запуска движка и по выбору) / `score` (по умолчанию после запуска — §22.5) | выбор пользователя; признак запуска движка — конфигурация развёртывания | enum | — |
| Ключ порядка | `score`: сохранённый рейтинг + соответствие теме, затем дата, затем `id`; `date`: дата первой публикации, затем `id` | пересчёт раз в час | — | — |

## 3. Формула

Лента — упорядоченный список кандидатов контекста:

- режим `score`: сохранённый `ArticleScore` плюс контекстное соответствие теме
  (`topic-relevance.md`) по убыванию; при равенстве — дата первой публикации, затем `id`;
- режим `date`: дата первой публикации по убыванию, затем `id`;
- страницы читают последний завершённый снимок пересчёта, поэтому материал не «прыгает» между
  страницами; ключ с `id` исключает дубли при равных значениях;
- слой открытия новых материалов (§21.25) может вставлять в ленты показы сильных незамеченных
  статей — доля и правила отдельный этап; до него ленты строго по ключу.

Размер страницы — конфигурация развёртывания `[ДОПУЩЕНИЕ]`; `page > totalPages` — 404. Выбор
режима хранится в адресе (`?sort=rating|date`) и не персонализирует выдачу: два читателя с одним
адресом видят одинаковый список `[ДОПУЩЕНИЕ: параметр адреса, без запоминания в профиле]`.
Переключатель появляется в интерфейсе только после запуска движка (§20.4, §22.5); до него URL
без параметра сортировки.

## 4. Окно времени и затухание

Окон у лент нет: показывается вся история опубликованного в контексте; порядок в режиме `score`
задают сохранённый рейтинг (свежесть внутри него — `freshness-decay.md`) и соответствие теме.
RSS — последние публикации по дате `[ДОПУЩЕНИЕ: число — конфигурация]` независимо от режима.

## 5. Бусты и переопределения

Pro-балл действует через сохранённый рейтинг (`pro-score.md`). Закрепления, ручного порядка и
редакционных подборок нет; веса не настраиваются через интерфейс (§21.32). Фильтры сужают
кандидатов и не меняют ключ.

## 6. Пересчёт

Ленты не материализуются: запрос по индексам сохранённых значений и связей; ответ страницы
кешируется по (контекст, режим, фильтры, страница, локаль) до инвалидации — публикация или
снятие в контексте, завершение часового пересчёта, правка таксономии материала. При сбое
пересчёта ленты читают последние успешные значения; новая статья без значения встаёт по дате
(§21.40) и не может исчезнуть из выдачи.

## 7. Объяснимость читателю

Подпись ленты называет режим: «по рейтингу» или «по дате публикации» `[ДОПУЩЕНИЕ: тексты]`.
Позиция конкретной статьи не объясняется, чисел нет (§21.18); компонент `RankExplainer` ревизии 2
не реализуется.

## 8. Защита от накрутки

| Вектор | Контрмера | Что логируется | Кто разбирает |
|---|---|---|---|
| Массовые публикации в контекст | лимит очереди (`plans.md`); `anti-fraud.md` | `translation.submit` | `moderator` |
| Подмешивание чужой локали | языковая граница на уровне запроса | — | — |
| Перебор страниц ботами | лимиты запросов по IP (`rate-limits.md`) | `rate_limit.hit` | — |
| Манипуляции фильтрами | фильтры не влияют на рейтинг | — | — |

## 9. Тесты и проверяемость

- Две страницы подряд не содержат общих материалов и не пропускают ни одного при неизменном
  снимке.
- Лента `ru` не содержит версий `en`; материал с двумя версиями присутствует в каждой локали по
  одному разу.
- До запуска движка параметр сортировки не принимается; после — режим по умолчанию `score`,
  `date` по выбору (§22.5).
- Ответ идентичен для гостя, читателя и владельца; не содержит балла.
- Сбой пересчёта не убирает опубликованную статью из ленты.
- Режим `date` даёт одинаковый порядок до и после запуска движка при тех же кандидатах.
- Фильтр по формату или тегу в рубрике не меняет относительный порядок оставшихся материалов.

## 10. Открытые вопросы и допущения

- Отложено (§21.25): слой открытия новых материалов в лентах.
- `[ДОПУЩЕНИЕ]` Размер страницы и длина RSS — конфигурация развёртывания; тексты подписей;
  режим сортировки — параметр адреса без запоминания в профиле.
- Закрыто Г4 (§22.5): переключатель «по рейтингу / по дате» после запуска, по умолчанию — по
  рейтингу; (§21.21) поиск без рейтинга.
