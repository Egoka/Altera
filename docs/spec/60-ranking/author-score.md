# Рейтинг: Рейтинг автора

- **Реестр**: таблица компонентов в `60-ranking/README.md` #4
- **Статус**: на утверждении
- **ADR**: ADR-0034, ADR-0037, ADR-0044 (в части, не противоречащей журналу #31, §20.8)
- **Этап**: 2

## 1. Что ранжируем и где применяется

Ранжируется **автор** (аккаунт): `AuthorScore(userId, score, components, configVersion,
computedAt)`. Применяется как вход `A` в рейтинг статьи (`article-score.md`) и как порядок
каталога авторов после Г4 (`20-public/authors-index.md`). Не применяется: в «Новом» и
«Популярном» главной, в очереди проверки, в решениях ревьюера (уровней доверия нет —
ADR-0037). Ключевое правило владельца: **окончание плана никак не влияет на рейтинг автора или
статей** (журнал §20.8), при этом `pro` усиливает рейтинговый статус автора (журнал #31). Оба
требования совмещаются тем, что грейд учитывается **на момент публикации каждого материала**, а
не по текущему плану (§3). Редакционные статьи журнала не имеют автора-пользователя и в
`AuthorScore` не входят `[ДОПУЩЕНИЕ]`.

## 2. Входы

| Вход | Источник (таблица / поле) | Обновление (событие / расписание) | Диапазон | Нормализация |
|---|---|---|---|---|
| Грейд при публикации | `ArticleTranslation.publishedGrade` (`basic` / `pro`, снимок `User.planTier` в момент первой публикации) `[ДОПУЩЕНИЕ: поле]` | первая публикация версии | 0 / 1 | доля pro-публикаций |
| Прочтения материалов автора | `ArticleReadDaily` минус `ReadExclusion`, по всем опубликованным версиям | суточное закрытие; исключения | ≥ 0 | логарифм к опорному |
| Число опубликованных версий | `ArticleTranslation` в `published` | публикация, снятие | ≥ 0 | логарифм с насыщением |
| Окончательные отказы и архивы ревьюера | `translation.reject.final`, `article.archive` актором `moderator`/`admin`/`owner` | решения | ≥ 0 | штраф `[ДОПУЩЕНИЕ]` |
| Параметры | `RankingConfig.weights.proGradeBonus`, `authorTopK`, `authorHistoryWeight`, `authorVolumeWeight`, `authorPenaltyWeight`, `authorViewsWindowDays` | смена конфигурации | см. §3 | — |

## 3. Формула

```
G   = доля версий автора, опубликованных с грейдом pro (0–1)
H   = среднее нормированных прочтений V_i по top-K материалам автора за authorViewsWindowDays
N   = log(1 + published) / log(1 + authorVolumeRef)            (обрезка до 1)
P   = min(1, finalRejects · 0.5 + staffArchives · 0.5) / authorPenaltyRef  (обрезка до 1)
A   = proGradeBonus · G + authorHistoryWeight · H + authorVolumeWeight · N − authorPenaltyWeight · P
A   = clamp(A, 0, 1)
```

По умолчанию `[ДОПУЩЕНИЕ]`: `proGradeBonus = 0.20`, `authorHistoryWeight = 0.50`,
`authorVolumeWeight = 0.20`, `authorPenaltyWeight = 0.30`, `authorTopK = 5`,
`authorVolumeRef = 20`, `authorPenaltyRef = 3`, `authorViewsWindowDays = 90`. `V_i` — по
`views-counting.md` с окном автора вместо окна статьи. Автор без публикаций — `A` не
вычисляется, статья при первой публикации берёт `authorDefault` (`article-score.md`). Все
компоненты 0–1, сложение аддитивное, округление до 6 знаков. Активность подписки в формулу не
входит нигде: истечение, отмена или неуспешный платёж не меняют ни один вход (журнал §20.8).

## 4. Окно времени и затухание

Прочтения для `H` берутся за скользящее окно `authorViewsWindowDays` (90 дней), чтобы старые
сильные публикации продолжали поднимать автора (журнал §20.8), но не бессрочно `[ДОПУЩЕНИЕ]`.
Затухания по дате у `G`, `N`, `P` нет: доля pro-публикаций и штрафы — за всю историю. Часовой
пояс — UTC. Архивированные автором собственные статьи выпадают из `published` и из `N`, но их
прочтения за окно остаются в `H` `[ДОПУЩЕНИЕ]`.

## 5. Бусты и переопределения

Буста автора нет: `pro` действует через `G` (постоянно, по истории публикаций) и через буст
статей (`pro-boost.md`). Ручного изменения `AuthorScore` редакцией нет; косвенное влияние —
только решения ревьюера (штраф `P`) и исключение прочтений (`anti-fraud.md`). Штраф `P` —
`[ДОПУЩЕНИЕ]`: журнал не говорит о влиянии отказов на рейтинг автора; включён как защита от
авторов, регулярно публикующих недопустимое; параметр `authorPenaltyWeight = 0` отключает его.

## 6. Пересчёт

Событийно — публикация и снятие версии автора, окончательный отказ, архив статьи служебной
ролью, исключение прочтений; по расписанию — раз в сутки после закрытия дня прочтений
(`recompute.md`). После пересчёта `AuthorScore` пересчитываются `ArticleScore` его статей
(зависимость `A`). Детерминизм — инвариант-тест. Хранится разложение
`components = { grade, history, volume, penalty }`. Каталог авторов читает `score` по индексу;
кеш каталога инвалидируется пакетом.

## 7. Объяснимость читателю

Читателю рейтинг автора числом не показывается (журнал: только бейдж pro и словесное
объяснение); в ленте при доминирующем `A` — фраза «автор с высоким рейтингом»
(`explainability.md`). Автору в кабинете — числа `G`, `H`, `N`, `P` и подсказки: «доля
pro-публикаций», «прочтения лучших материалов за 90 дней». Штраф показывается автору с
формулировкой «решения редакции по вашим материалам» без деталей чужих решений
`[ДОПУЩЕНИЕ]`.

## 8. Защита от накрутки

| Вектор | Контрмера | Что логируется | Кто разбирает |
|---|---|---|---|
| Массовые короткие публикации ради `N` | логарифм с насыщением `authorVolumeRef`; массовые публикации — `anti-fraud.md`; ревьюер снимает | `translation.submit` частота | `moderator` |
| Накрутка прочтений своих статей | `H` использует те же исключения `ReadExclusion` | `reads.exclude` | `analyst`, `admin`, `owner` |
| Покупка `pro` на один месяц ради `G` | `G` — доля за всю историю, разовая покупка даёт малую долю; буст ограничен | — | — |
| Удаление отклонённых статей ради `P` | окончательный отказ — не архив и не удаление, запись остаётся (журнал #12) | `translation.reject.final` | — |

## 9. Тесты и проверяемость

- Детерминизм `AuthorScore` на фикстуре.
- Тест: истечение плана автора не меняет `AuthorScore` и `ArticleScore` его статей (журнал §20.8).
- Тест: публикация с активным `pro` увеличивает `G`; последующее окончание `pro` — нет.
- Тест: `authorPenaltyWeight = 0` даёт `A` без штрафа; окончательный отказ при весе > 0 снижает.
- Тест: автор без публикаций не имеет `AuthorScore`; первая статья использует `authorDefault`.
- Инвариант: `0 ≤ A ≤ 1`.

## 10. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Все веса и опорные значения §3; поле `publishedGrade`; окно 90 дней; прочтения
  архивированных автором статей остаются в `H`; редакционные статьи вне `AuthorScore`.
- `[ДОПУЩЕНИЕ]` Штраф за окончательные отказы и архив служебной ролью — журналом не задан.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Утвердить, что грейд учитывается по снимку на момент публикации (доля
  pro-публикаций), а не по текущему плану? Если да — поле `publishedGrade` в модели; если нет —
  `G` берётся из текущего плана, и тогда окончание `pro` снижает рейтинг, что противоречит
  журналу §20.8 — потребуется уточнение журнала.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Оставить ли штраф `P` за решения редакции? Если да — вес 0.30 и опорное
  значение 3; если нет — `authorPenaltyWeight = 0` в сиде.
