# Рейтинг: Итоговый рейтинг статьи

- **Реестр**: таблица компонентов в `60-ranking/README.md` #1
- **Статус**: на утверждении
- **ADR**: ADR-0034, ADR-0037, ADR-0038, ADR-0040 (в части, не противоречащей журналу #41, §20.2–4,
  §20.8); ADR-0039 в рейтинге не участвует
- **Этап**: 2 (до него ленты — по новизне, журнал §20.4)

## 1. Что ранжируем и где применяется

Ранжируется **языковая версия материала** в статусе `published` внутри своей локали (языки не
смешиваются — журнал §20.5); итог хранится в `ArticleScore(articleId, score, components,
configVersion, computedAt)` — одна запись на материал, где `score` — контекстно-независимая
часть, а компонент «соответствие теме» добавляется на чтении по контексту ленты
(`topic-relevance.md`). Применяется: главный топ главной (`home-sections.md`), ленты рубрик и
тегов, страница автора (`feed-principles.md`), поиск — как вторичный ключ после релевантности
(заход 5b). Не применяется: «Новое» (только дата), «Популярное» (только прочтения), кабинет и
админка — там разложение показывается, но не сортирует; закладки в рейтинг не входят
(ADR-0041). AI-вердикт в рейтинг не входит и балла не даёт (журнал #41).

## 2. Входы

| Вход | Источник (таблица / поле) | Обновление (событие / расписание) | Диапазон | Нормализация |
|---|---|---|---|---|
| Давность `F` | `ArticleTranslation.firstPublishedAt` (`freshness-decay.md`) | каждый пересчёт (время идёт) | 0–1 | экспоненциальное затухание |
| Рейтинг автора `A` | `AuthorScore.score` (`author-score.md`) | при публикации, пересчёте автора | 0–1 | уже нормирован |
| Просмотры `V` | `ArticleReadDaily` за окно минус `ReadExclusion` (`views-counting.md`) | суточное закрытие; исключение записи | 0–1 | логарифм к опорному значению |
| Буст `B` | `ArticleBoost` активный на момент расчёта (`pro-boost.md`) | `startsAt`, `endsAt`, `endedEarlyAt` | 0 или 1 | — |
| Соответствие теме `T` | рубрика и теги материала против контекста ленты (`topic-relevance.md`) | на чтении | 0–1 | по позиции тега |
| Веса | `RankingConfig.weights` | смена конфигурации (аудит `ranking.config.change`) | см. §3 | — |

## 3. Формула

Базовый балл (хранится):

```
base = freshnessWeight · F + authorWeight · A + viewsWeight · V + boostWeight · B
```

В ленте с контекстом (рубрика, тег) итог на чтении:

```
score(context) = base + topicWeight · T(context)
```

Все компоненты в диапазоне 0–1, сложение аддитивное (ADR-0040: буст аддитивен, чтобы не усиливать
уже высокие баллы), округление до 6 знаков при сохранении, сравнение при сортировке — по
`score`, затем по `firstPublishedAt` по убыванию, затем по `id` (стабильность —
`feed-principles.md`). Значения по умолчанию `[ДОПУЩЕНИЕ]`, диапазон допустимых 0–1 для каждого
веса, сумма весов не нормируется:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `freshnessWeight` | 0.30 | вклад давности |
| `authorWeight` | 0.15 | вклад рейтинга автора |
| `viewsWeight` | 0.30 | вклад прочтений |
| `boostWeight` | 0.20 | надбавка pro-буста на срок буста |
| `topicWeight` | 0.25 | вклад соответствия теме только в контекстных лентах |

Отсутствие входа: нет прочтений — `V = 0`; автор без `AuthorScore` (первая публикация) —
`A = authorDefault` `[ДОПУЩЕНИЕ: 0.3]`; нет буста — `B = 0`. Компонентов AI нет: поле
`components.ai` из `03-data-model.md` не заполняется и удаляется при ревизии модели
`[ДОПУЩЕНИЕ]`. Разложение `components = { freshness, author, views, boost, grade }` хранится для
объяснимости и кабинета автора; `topic` в нём отсутствует (контекстный).

## 4. Окно времени и затухание

Функция давности и горизонт — `freshness-decay.md`: полураспад `freshnessHalfLifeHours` (72 ч
`[ДОПУЩЕНИЕ]`), горизонт `freshnessHorizonDays` (30 дней), после которого `F` считается нулём и
материал держится в ленте только за счёт прочтений и автора. Повторная публикация после
доработки не обновляет `firstPublishedAt` `[ДОПУЩЕНИЕ]`. Часовой пояс расчёта — UTC; «день» для
прочтений — календарный день UTC (ADR-0027).

## 5. Бусты и переопределения

Pro-буст — единственная надбавка (`pro-boost.md`): `B = 1` на 24 часа с первой публикации версии
автором с активным `pro`, не более `boostDailyLimit` публикаций в сутки. Ручного переопределения
позиции нет: ни ревьюер, ни администратор, ни владелец не «поднимают» статью — единственные
рычаги редакции: досрочное завершение буста (`boost.end`, матрица #72), исключение
подозрительных прочтений (`reads.exclude`, #71) и смена конфигурации владельцем (#69). При
конфликте (буст и исключённые прочтения одновременно) компоненты считаются независимо.

## 6. Пересчёт

По `recompute.md`: событийно — публикация, снятие, старт и конец буста, исключение записи,
пересчёт автора; по расписанию — каждый час `[ДОПУЩЕНИЕ]` для затухания и раз в сутки после
закрытия дня прочтений; полный пересчёт — при смене конфигурации (`ranking.recompute`).
Детерминизм: одинаковые входы и `configVersion` дают одинаковый `score` — инвариант-тест на
фикстуре. Стоимость: одна запись на материал, обновление пакетами по 500 `[ДОПУЩЕНИЕ]`. Кеш лент
инвалидируется после завершения пакета; между пересчётами читатель видит прежний порядок.

## 7. Объяснимость читателю

`explainability.md`: читателю — фраза по доминирующему компоненту («свежая публикация»,
«много читают на этой неделе», «автор с высоким рейтингом», «соответствует теме рубрики»);
числа и веса не раскрываются; факт буста не называется (ADR-0040), бейдж pro показывается.
Автору — числа своих компонентов и веса текущей конфигурации в кабинете (матрица #7).

## 8. Защита от накрутки

| Вектор | Контрмера | Что логируется | Кто разбирает |
|---|---|---|---|
| Накрутка прочтений | `views-counting.md` (дедупликация), `anti-fraud.md` (аномалии, `ReadExclusion`) | `read`, `reads.exclude` | `analyst`, `admin`, `owner` |
| Массовые публикации ради буста | `boostDailyLimit`; повторная публикация не даёт нового буста | `boost.start`, отказ буста в логе публикации | `moderator`, `owner` (`boost.end`) |
| Повторные ревизии ради свежести | `firstPublishedAt` не обновляется | — | — |
| Взаимные подписки и закладки | не входят в рейтинг (ADR-0041) | — | — |

Подробно — `anti-fraud.md`.

## 9. Тесты и проверяемость

- Детерминизм: два пересчёта на одной фикстуре и версии дают равные `score` и `components`.
- Монотонность: рост `uniqueReads` при прочих равных не уменьшает `score`; истечение буста
  уменьшает ровно на `boostWeight`.
- Отсутствие персонализации: ответ `feed` не зависит от сессии — контрактный тест.
- Пустые входы: материал без прочтений и без `AuthorScore` получает конечный балл без ошибок.
- Языковая граница: в ленте `ru` нет версий `en` при любых баллах.
- Окончание плана автора не меняет `ArticleScore` его статей (журнал §20.8).

## 10. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Веса по умолчанию (§3), `authorDefault = 0.3`, пакет пересчёта 500, часовой
  пересчёт затухания; `components.ai` удаляется из модели.
- `[ДОПУЩЕНИЕ]` Аддитивная формула без нормировки суммы весов; сортировка при равенстве — по
  дате, затем по `id`.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Утвердить веса по умолчанию из §3 как стартовую конфигурацию версии 1?
  Если да — они попадают в сид `RankingConfig`; если нет — владелец задаёт свои значения в
  диапазоне 0–1, формула не меняется.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Нужен ли поиску рейтинг как вторичный ключ (после релевантности FTS) или
  поиск сортируется только по релевантности и дате? Если нужен — `search.md` (5b) читает
  `ArticleScore`; если нет — рейтинг в поиске не участвует.
