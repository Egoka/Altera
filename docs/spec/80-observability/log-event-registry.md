# Политика: Реестр событий — правила ведения и закрытие

- **Область**: логирование
- **Статус**: на утверждении
- **ADR**: ADR-0032, ADR-0027; `00-registries/events-and-logs.md` (заход 1 — скелет, заходы 2–8a —
  дополнение, 8b — закрытие); `docs/spec/00-registries/README.md` (колонки); журнал #6, §14,
  §23, §26.1
- **Этап**: 0–1

## 1. Назначение

Правила, по которым живёт реестр `events-and-logs.md`: как именуются коды, какие поля
обязательны, кто и когда добавляет строку, как строка переходит из «черновик» в «утверждён» и
что означает закрытие реестра в 8b. На политику ссылаются `logging-policy.md`,
`error-dictionary.md`, `audit-vs-logs.md`, все спецификации, использующие коды `(#N)`.

## 2. Правила

1. **Один код — одна строка**: код в нижнем регистре с точками, префикс подсистемы из перечня
   в шапке реестра (`auth.`, `user.`, `article.`, `translation.`, `review.`, `payment.`, `ai.`,
   `mail.`, `ranking.`, `engagement.`, `job.`, `system.` и другие); группы вариантов одной
   строкой (`subscription.activated / .expired / …`) допустимы, если поля и ретенция совпадают.
2. **Тип** определяет судьбу записи: `error` — код ответа API (`error-dictionary.md`); `audit` —
   таблица `audit_log`, бессрочно, неизменяемо (журнал §14, #59); `log` — поток логов
   (`logging-policy.md`), 30 дней; `metric` — агрегаты без ПДн (`engagement-tracking.md`).
3. **Обязательные колонки**: тип, уровень, источник, кто инициирует, поля без ПДн, ретенция,
   где смотреть, файл спецификации, статус. Строка без файла — недоделка (правило 3 программы).
4. **Кто добавляет**: заход, которому понадобилось событие, — строкой в статусе «черновик» с
   пометкой захода; гейт владельца переводит в «утверждён»; отмена — «отменено: причина»,
   отсрочка — «отложено: причина» (как #13, #26, #29–33, #38, #47, #55, #62–63).
5. **Спецификации ссылаются** на события как `` `код` (#N) ``; ссылка на несуществующую строку —
   дефект проверки захода (скрипт сверки в отчётах).
6. **Аудит** (журнал #6, §14): любое административное изменение — код `audit` с `diff` до/после
   плюс общая оболочка `admin.change` (#75); любое чтение ПДн через административный инструмент
   — `admin.read.personal` (#67) с контекстом и целью от системы (§14.4); просмотр самого
   аудита не логируется (§27.5).
7. **Закрытие реестра в 8b**: строки «черновик» заходов 6–8a (#81, #85–87) и добавленные здесь
   (`admin.enter` #88) переводятся в «на утверждении (8b)» до гейта; все строки имеют файл;
   после 8b новая строка — только через отдельный проход (почта, каталог блоков, жалобы) с
   пометкой прохода.
8. **Ретенция по типу** — `retention-and-pd.md`; отклонение в строке реестра — только с
  обоснованием там же.
9. **Без ПДн в значениях** полей (`logging-policy.md` п. 4); e-mail — хэш, IP — хэш соли дня,
   тексты — не пишутся; исключение — `audit_log`, где субъект и `diff` хранятся по журналу #6
   (это ПДн — доступ по зонам, §14.3).

## 3. Исключения

| Исключение | Условие | Кто может | Аудит |
|---|---|---|---|
| Событие без строки реестра в dev | отладка, не попадает в прод | разработчик | — |
| Строка со статусом «отложено» без файла | тема отложена владельцем (жалобы #33, #63; рассылки #38) | — | — |
| Строка «отменено» | заменена другой строкой; остаётся в реестре как история | — | — |

## 4. Взаимодействие с другими политиками

- `logging-policy.md` и `audit-vs-logs.md` — что куда пишется; `retention-and-pd.md` — сроки;
  `error-dictionary.md` — коды `error`; `00-registries/README.md` — колонки главнее этой
  политики.

## 5. Проверяемость

- Скрипт сверки (отчёты заходов): каждая ссылка `` `код` (#N) `` в `docs/spec` совпадает с
  кодом строки #N; каждая строка «утверждён» / «на утверждении» имеет существующий файл.
- Тест кода: перечень кодов в коде (константы) совпадает с реестром — падение CI при
  расхождении `[ДОПУЩЕНИЕ: генерация констант из реестра]`.
- Метрика: записи с неизвестным кодом в логах — ноль.

## 6. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Генерация констант кодов из реестра; группировка вариантов одной строкой.
- Отложено: события почты (§25.13), жалоб, рассылок, каталога блоков — добавляются своими
  проходами.
- Закрыто Г1–Г8a (журнал #6, §14, §27.5): аудит с `diff` и оболочкой; чтение ПДн с контекстом;
  без аудита просмотра аудита.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Считать ли реестр после 8b «замороженным» до конца этапа 1 (новые коды
  только отдельными проходами с вашим гейтом) или позволить заходу 9 добавлять коды медиа
  «черновиком» без гейта? Если заморозить — заход 9 приносит коды в отчёт и ждёт Г9; если нет —
  как в заходах 2–8a.
