# Политика: Словарь ошибок

- **Область**: логирование
- **Статус**: утверждён (гейт Г8b, 2026-09-09)
- **ADR**: ADR-0032 (словарь кодов, маскирование), ADR-0033 (`CONFLICT` ревизий), ADR-0029
  (`CONTENT_INVALID`); `00-registries/events-and-logs.md` #1–11; `docs/vision/06-design-system.md`
  §6 (состояния по кодам), `08-operations.md` §9; журнал #55 (`PLAN_LIMIT`)
- **Этап**: 0–1

## 1. Назначение

Единственный источник кодов ошибок API: что означает код, кто его видит, какие поля несёт, как
показывается пользователю и как логируется. Все спецификации страниц, разделов и сценариев
ссылаются на коды отсюда; новый код добавляется только здесь и в реестре событий (правило 9
программы), не «по месту». На политику ссылаются `logging-policy.md`, `error-collector.md`,
`20-public/error.md`, все `20-public/*`, `30-account/*`, `40-admin/*`, `10-flows/*`.

## 2. Правила

1. **Форма**: каждая ошибка — `GraphQLError` с `extensions.code` из словаря, английским
   сообщением без ПДн и `requestId` (ADR-0032 п. 1); человеческие тексты — на фронте по коду и
   локали.
2. **Словарь** (реестр #1–11):

| Код | Смысл | Поля | HTTP-аналог на страницах | Пользователю |
|---|---|---|---|---|
| `UNAUTHENTICATED` (#1) | нет сессии | `requestId` | 302 на `/login?next=` | «войдите» |
| `FORBIDDEN` (#2) | нет права | `requestId`, `action` | 403 | пояснение роли; кнопок нет заранее |
| `NOT_FOUND` (#3) | объекта никогда не было или доступ скрыт как отсутствие (журнал §28.2) | `requestId`, `entity` | 404 | `not-found.md` |
| `ARCHIVED` (#89) | публичная сущность существовала, но архивирована или снята: материал или профиль больше не публичен, доступ закрыт (журнал §28.2) | `requestId`, `entity` | 410 | `gone.md` |
| `VALIDATION_ERROR` (#4) | неверные данные | `requestId`, `field`, `rule` | 200 (форма) | подсветка поля |
| `CONFLICT` (#5) | состояние изменилось: устаревшая ревизия (ADR-0033), уже решено, занято | `requestId`, `entity`, `expected`, `actual` | 200 / 409 | «обновите» с вариантами |
| `RATE_LIMITED` (#6) | лимит частоты (`rate-limits.md`) | `requestId`, `retryAfter` | 429 | таймер |
| `CONTENT_INVALID` (#7) | пакет контента не по схеме (ADR-0029) | `requestId`, `path`, `node` | 200 | указание на блок |
| `DUPLICATE` (#8) | уникальность (слаг, хэндл, тег) | `requestId`, `entity`, `field` | 200 | «уже существует» |
| `INTERNAL_ERROR` (#9) | всё немаскированное; стек в логе | `requestId` | 500 | `error.md` с `requestId` |
| `PLAN_LIMIT` (#10) | действие требует плана или превышает лимит плана (журнал #5, #55) | `requestId`, `requiredTier`, `limit`, `current` | 200 | уведомление о плане, `/pricing`; лог `plan.action.rejected` (#78) |
| `PROVIDER_UNAVAILABLE` (#11) | внешний провайдер недоступен | `requestId`, `provider` (psp / ai / mail / storage — журнал §29.3) | 200 / 503 | «попробуйте позже» |

3. **Маскирование**: Yoga маскирует всё вне словаря в `INTERNAL_ERROR` (ADR-0032 п. 2); в
   production включён `blockFieldSuggestions` (CLAUDE.md).
4. **Не раскрывать существование**: там, где спецификация требует (чужая версия в редакторе —
   `article-edit.md` §3; служебная запись по `id` в «Пользователях»), отвечать `NOT_FOUND`, а не
   `FORBIDDEN`. **`ARCHIVED` только для бывших публичных адресов** (§28.2): материал, профиль,
   рубрика, тег, которые были публичны и ушли в архив или сняты, — 410 и страница `gone.md`;
   никогда не существовавшее — `NOT_FOUND` и 404; в админке состояние «в архиве» — не ошибка, а
   статус объекта.
5. **Ошибка ≠ событие**: коды ошибок — тип `error` реестра; они не аудируются, логируются на
   уровне по `logging-policy.md` п. 3 (`INTERNAL_ERROR` — `error`, `PROVIDER_UNAVAILABLE` —
   `warn`, остальные — `info` в составе `http.request` `[ДОПУЩЕНИЕ]`).
6. **Фронт**: состояние по коду (`06-design-system.md` §6, `08-operations.md` §9); коды не
   переводятся в текст на сервере.
7. **Новый код** — только через эту политику и строку реестра со статусом «черновик»; заход,
   которому он понадобился, перечисляет его в отчёте. Проверка: тесты резолверов сверяют коды, а
   не тексты (ADR-0032).

## 3. Исключения

| Исключение | Условие | Кто может | Аудит |
|---|---|---|---|
| Вебхуки провайдеров (`POST /api/webhooks/psp/*`) | ответ по протоколу провайдера, не GraphQL | система | лог `webhook.*` (#49) |
| `/health` | HTTP 200/503 без словаря (`health-and-alerts.md`) | внешняя проверка | лог `system.health` (#53) |
| `POST /api/engagement` | 204 / 429 без тела (`engagement-tracking.md` §8) | все | нет |

## 4. Взаимодействие с другими политиками

- `logging-policy.md` — как логируется; `error-collector.md` — куда попадает `INTERNAL_ERROR`;
  `50-access/permission-checks.md` — когда `FORBIDDEN`, когда `NOT_FOUND`; `50-access/rate-limits.md`
  — `RATE_LIMITED`; `70-plans-and-billing/role-derivation.md` — `PLAN_LIMIT`.

## 5. Проверяемость

- Контрактный тест: SDL и резолверы используют только коды словаря; неизвестный код — падение
  CI.
- Тест: немаскированное исключение в резолвере → `INTERNAL_ERROR` с `requestId`.
- Тест фронта: каждому коду соответствует состояние компонента.
- Метрика: доля `INTERNAL_ERROR` в ответах за период (`errors-and-health.md`).

## 6. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Уровни логирования ошибок словаря; HTTP-аналоги для SSR-страниц.
- Закрыто Г1–Г3 (журнал #55, §20.15–17): `PLAN_LIMIT` при сохранённой сессии; 404/410 и
  страница ошибки с `requestId`.
- Закрыто Г8b (§28.2): код `ARCHIVED` — 410 и понятная страница для бывших публичных адресов;
  `NOT_FOUND` — только для никогда не существовавшего.
