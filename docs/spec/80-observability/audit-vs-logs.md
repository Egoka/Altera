# Политика: Граница аудита и логов

- **Область**: логирование
- **Статус**: на утверждении
- **ADR**: ADR-0032 п. 4 (аудит — таблица, не логи), ADR-0018; журнал §3.4, §14, #6, #22, #37,
  #39, #59, §27.5; `40-admin/audit-log.md`; `00-registries/events-and-logs.md` (типы `audit` /
  `log` / `metric`); `50-access/visibility.md` п. 10
- **Этап**: 1

## 1. Назначение

Проводит границу между тремя потоками: **аудит** — неизменяемая история действий сотрудников и
чтений персональных данных, доступная в интерфейсе по зонам (журнал §14); **логи** —
технический поток для эксплуатации (`logging-policy.md`); **метрики** — агрегаты без ПДн для
статистики и рейтинга. На политику ссылаются `audit-log.md`, `logging-policy.md`,
`log-event-registry.md`, `retention-and-pd.md`, все разделы админки (§8 «Аудит действий»).

## 2. Правила

1. **Что аудируется** (журнал #6, §14): любое административное изменение — сущность, актор,
   время, поля до/после (`admin.change` #75 плюс конкретный код); любое чтение персональных
   данных через административный инструмент — актор, время, субъект, контекст, цель
   (`admin.read.personal` #67; контекст и цель заполняет система — §14.4); решения ревьюера и
   переписка (#24–25, #69–70); финансовые операции (#18–23, #73–74); роли и исключения (#12,
   #65–66, #76); архив и восстановление аккаунтов и статей (#14, #16, #27, #79); удаление
   навсегда (#68); открытие карточки платежа (§27.2); смена рабочего статуса ошибки (§27.7).
2. **Что не аудируется**: просмотры публичных данных (журнал §3.4 — аналитика); просмотр
   агрегатов и списков без раскрытия ПДн (сводка, статистика, очередь); просмотр самого аудита
   (§27.5 — без рекурсии); технические события системы (логи); действия пользователей над
   своими данными — они логируются или считаются метриками (`bookmark.*`, `translation.submit`),
   кроме тех, что реестр относит к аудиту (`user.archive.self` #16, `user.restore.self` #79,
   `translation.reedit` #72, `author.enabled` #87).
3. **Аудит неизменяем** (журнал #59, §14.4): записи не создаются, не правятся и не удаляются
   вручную, включая `owner`; хранение бессрочно (`retention-and-pd.md`); при «удалить навсегда»
   субъекта записи остаются (`permanent-delete.md`).
4. **Аудит — таблица `audit_log`** (ADR-0032 п. 4), не поток логов: у него свои индексы, зоны
   видимости (`visibility.md` п. 10) и интерфейс (`audit-log.md`); дублирование записи аудита
   в лог допустимо только как `info` без ПДн `[ДОПУЩЕНИЕ]`.
5. **Логи не заменяют аудит**: если действие сотрудника попало только в лог — дефект;
   проверка: каждая мутация административного API помечена кодом `audit` из реестра.
6. **Метрики не содержат ПДн** и не служат аудитом: события вовлечённости идут в агрегаты
   (`engagement-tracking.md`), `visitorId` — не идентификатор пользователя (§23.7).
7. **ПДн в аудите**: субъект и `diff` могут содержать ПДн (это их смысл) — доступ по зонам,
   e-mail в `diff` — хэш там, где реестр указывает (#17, #76) `[ДОПУЩЕНИЕ]`; экспорт CSV аудита
   — без `diff` с ПДн (`audit-log.md` §5).
8. **Зоны** (§14.3, `visibility.md` п. 10): служебная роль — своя зона; `admin`, `owner` —
   полный журнал; `analyst` — финансы, чтения ПДн, AI-метрики.

## 3. Исключения

| Исключение | Условие | Кто может | Аудит |
|---|---|---|---|
| Автоматические действия системы | истечение исключения (#66 `expire`), исключение аномалии (#84), решение AI (#71), базовое авторство (#87) | система | пишется с актором «система» |
| Открытие карточки статьи в админке | ПДн автора — только имя и хэндл (публичные) | служебные роли | не аудируется (журнал #51) |
| Чтение аудита | — | по зонам | не логируется (§27.5) |

## 4. Взаимодействие с другими политиками

- `log-event-registry.md` — тип строки определяет поток; `logging-policy.md` — правила логов;
  `retention-and-pd.md` — сроки (аудит бессрочно, логи 30 дней); `50-access/visibility.md` —
  зоны; `40-admin/audit-log.md` — интерфейс.

## 5. Проверяемость

- Тест: каждая административная мутация пишет запись `audit_log` с `diff`; открытие карточки
  пользователя, платежа и письма пишет `admin.read.personal`.
- Тест: попытка изменить или удалить запись `audit_log` через API — нет такой мутации в SDL.
- Тест: просмотр `/admin/audit` не создаёт записей.
- Метрика: число мутаций без записи аудита (по трассировке `requestId`) — ноль.

## 6. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Дублирование аудита в лог как `info`; хэш e-mail в `diff`.
- Закрыто Г1–Г8a (журнал #6, §3.4, §14, #59, §27.2, §27.5, §27.7): состав аудита; чтение ПДн с
  контекстом от системы; неизменяемость; без аудита просмотра аудита; карточка платежа и
  рабочие статусы ошибок аудируются.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Считать ли чтением ПДн открытие карточки статьи с полным e-mail автора
  где-либо кроме раздела «Пользователи» (сейчас e-mail есть только там)? Если да — правило
  распространяется на любую страницу, где появится e-mail; если нет — только #6, #9, #21.
