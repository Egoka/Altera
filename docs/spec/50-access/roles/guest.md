# Роль: Посетитель (нет сессии)

- **Реестр**: `00-registries/roles.md` #1
- **Статус**: на утверждении
- **Источник правил**: журнал Г1 `docs/decisions/role-review-working-log-2026-09-08.md`
  (сводка §1 «Гость»), матрица `00-registries/access-matrix.md` #1, #4–5, #10–12, #16, #45–46,
  #54, #67; ADR-0018, ADR-0022, ADR-0024 (в части, не противоречащей журналу)

## 1. Определение и как получается

Посетитель — любой запрос без действующей сессии: нет cookie сессии, сессия истекла, отозвана
или аккаунт архивирован. Это не значение `enum Role`, а отсутствие пользователя в контексте
запроса (`currentUser = null`); все проверки прав трактуют его как минимальный уровень доступа.
Посетитель становится читателем (`reader`) после подтверждения ссылки из письма (ADR-0022) и
принятия действующей версии оферты и политики персональных данных (матрица #54). Ничего не
хранится: ни идентификатор, ни история — прочтения считаются суточным хэшем без привязки к
человеку (ADR-0027).

## 2. Что видит

| Область | Видит | Не видит |
|---|---|---|
| Публичные страницы | главную и все ленты, опубликованные версии материалов в своей локали, страницы авторов, рубрик, тегов, поиск (3), цены, юридические тексты, «о проекте», контакты, страницы ошибок | черновики, версии на проверке, архивированные и отклонённые материалы — для них адрес отвечает 404 или 410 без раскрытия существования (политика `visibility.md`); предпросмотр по `?preview=` — 404 |
| Кабинет | ничего: любой маршрут `/me/*` перенаправляет на `/login` с возвратом после входа | — |
| Админка | ничего: `/admin/*` отвечает так же, как закрытая страница кабинета — редирект на вход, без раскрытия существования раздела `[ДОПУЩЕНИЕ: редирект, а не 404]` | — |
| Персональные данные других пользователей | публичный профиль автора: имя, хэндл, «о себе», аватар, соцсети, грейд (ADR-0018) | e-mail, роль, план, состояние аккаунта, сессии — никогда |

Посетитель видит бейдж pro-автора и словесное объяснение позиции материала в ленте (2), но не
числа рейтинга и не разложение по компонентам (матрица #7).

## 3. Что может

- Читать всё опубликованное (#1, #4), пользоваться навигацией и поиском (#10–11), читать
  юридические тексты (#12).
- Запросить ссылку для входа по e-mail (#45) и подтвердить её (#46); при первом входе принять
  оферту и политику (#54).
- Отправить маяк прочтения (#67) — событие без персональных данных.
- Отправить письмо в редакцию через `/contact` (`pages.md` #14) в пределах лимита.
- Пожаловаться на материал (#16) — действие сохранено в матрице в статусе «отложено»: сценарий
  жалоб проектируется отдельным разбором; до него кнопка на странице материала не проектируется.

## 4. Чего не может (явно)

- Ставить закладки и подписываться на авторов (#13–15): это действия аккаунта; интерфейс
  показывает приглашение войти, сервер отвечает `UNAUTHENTICATED`.
- Видеть чужие черновики, версии на проверке, архив и отклонённые материалы даже по прямой
  ссылке — только `NOT_FOUND`/410, никогда `FORBIDDEN` (инвариант матрицы: существование не
  раскрывается).
- Открывать предпросмотр `?preview=` (#3): токен привязан к сессии автора или ревьюера.
- Создавать, оплачивать, писать — всё это начинается со входа (`flows.md` #1) и, для авторства,
  с плана (`flows.md` #2).
- Обходить лимиты запросов ссылки и писем: превышение — `RATE_LIMITED` с указанием времени
  (`rate-limits.md`).
- Читать материалы «под paywall»: paywall зарезервирован и не включён (ADR-0036); посетитель
  читает всё целиком.

## 5. Путь повышения и понижения

| Из | В | Триггер | Кто инициирует | Автоматически / вручную | Что с данными и материалами | Аудит |
|---|---|---|---|---|---|---|
| посетитель | `reader` | подтверждение ссылки из письма + согласие с версией оферты | сам посетитель | автоматически | создаётся `User` с планом `free`, случайным хэндлом, версией и временем согласия | лог `auth.login`; аудита нет |
| `reader` (любая роль) | посетитель | выход, истечение или отзыв сессии, архивирование аккаунта | сам пользователь / система / `admin`, `owner` | автоматически | данные не меняются; для архивированного аккаунта повторный вход отвечает сообщением о поддержке | лог `session.revoked`; при архиве — аудит `user.archive` |

Понижения «ниже посетителя» нет: посетитель — базовый уровень для любого запроса.

## 6. Ограничения и лимиты

- Запрос ссылки для входа — лимит по e-mail и по IP (`rate-limits.md`; значения —
  `[ДОПУЩЕНИЕ]` до захода 2 политик: 5 писем в час на адрес, 20 в час на IP).
- Письмо в редакцию — лимит по IP `[ДОПУЩЕНИЕ: 3 в час]`.
- Маяк прочтения — лимит на IP, фильтр ботов по user-agent (ADR-0027).
- Поиск (3) — лимит запросов в минуту на IP `[ДОПУЩЕНИЕ]`.
- Кеш публичных страниц и списков одинаков для всех посетителей: он не может содержать ничего,
  что зависит от прав (ADR-0019).

## 7. Блокировка, удаление, восстановление

Не применимо, потому что у посетителя нет аккаунта: блокировать и архивировать нечего. Единственная
мера воздействия — лимиты запросов по IP и фильтр ботов; отдельного «бана по IP» журнал не
вводит и реестры не содержат `[ДОПУЩЕНИЕ: не проектируется до запроса владельца]`.
Если аккаунт посетителя ранее был архивирован, попытка входа по ссылке завершается сообщением
«аккаунт закрыт, обратитесь в поддержку» (матрица #46, журнал §5.2), а не созданием нового
аккаунта на тот же e-mail.

## 8. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Маршруты `/admin/*` для посетителя ведут себя как маршруты кабинета: редирект
  на вход. Альтернатива — 404 для полного сокрытия админки; выбор — при проектировании
  `40-admin/dashboard.md`.
- `[ДОПУЩЕНИЕ]` Значения лимитов (ссылка для входа, письмо в редакцию, поиск) — предварительные,
  фиксируются в `rate-limits.md`.
- `[ДОПУЩЕНИЕ]` Бан по IP не проектируется.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Показывать ли посетителю кнопку «Пожаловаться» до разбора сценария жалоб?
  Если да — кнопка ведёт на `/contact` с предзаполненной ссылкой на материал; если нет — кнопки
  нет до отдельного разбора.
