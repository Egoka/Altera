# Политика: Видимость данных

- **Область**: доступ
- **Статус**: утверждён (гейт Г2, 2026-09-08)
- **Источник правил**: журнал Г1 (#2, #6, #11, #13, #22; §3.4, §9), журнал Г2 (#45, #51–52,
  #56, #59), матрица #1–12, #34, #81, #104, #111, инварианты матрицы; ADR-0018 (публичный профиль без ПДн), ADR-0019 (кеш без прав),
  ADR-0036 (paywall зарезервирован) — в части, не противоречащей журналу
- **Этап**: 0 (единый модуль видимости — закрытие утечки черновиков), 1 (роли и аудит чтения)

## 1. Назначение

Единый ответ на вопрос «кто какие данные видит», чтобы ни один резолвер, страница или кеш не
решал это по-своему. Политика закрывает утечку черновиков и e-mail через публичный API
[ФАКТ: `server/src/graphql/article/resolver.ts:38-58`; `docs/vision/00-reality-check.md` §3.4],
задаёт правило «существование не раскрывается» и обязательный аудит административного чтения
персональных данных (журнал #6). На неё ссылаются все спецификации страниц (`20-public/`,
`30-account/`), разделов админки (`40-admin/`) и файлы ролей.

## 2. Правила

1. **Публичные данные** — опубликованные версии в локали запроса, публичные профили авторов,
   таксономия, юридические тексты, ленты, поиск. Видны всем ролям без исключений. Применяется:
   единый конструктор условия `visibleTranslationsWhere(viewer, locale)` во всех публичных
   резолверах; нарушение невозможно по построению — резолвер без него не проходит контрактный
   тест.
2. **Неопубликованные материалы** (`draft`, `ai_check`, `review`, `archived`, отклонённые):
   автор — только свои; `editor` — все редакционные статьи журнала (журнал #45); `moderator`,
   `admin`, `owner` — все; `analyst` — в карточке автора с аудитом. Для всех остальных адрес и API отвечают `NOT_FOUND` (черновик) или 410
   (снято, архив) — **никогда `FORBIDDEN`**, чтобы не раскрывать существование. Применяется:
   резолвер материала, страница материала, предпросмотр.
3. **Предпросмотр** `?preview=<token>`: токен короткоживущий, привязан к сессии автора версии
   или служебной роли с правом чтения неопубликованного; посетителю — `NOT_FOUND`.
4. **Публичный профиль** (ADR-0018): имя, хэндл, «о себе», аватар, соцсети, грейд (`pro`-бейдж).
   E-mail, роль, план, срок, состояние аккаунта, сессии — **никогда** в публичных типах;
   контрактный тест по SDL проверяет отсутствие `email` в публичных типах.
5. **Свои приватные данные** видит сам пользователь: e-mail, версия согласия, устройства и
   сессии (без IP), подписка, платежи и чеки, история и вердикты по своим статьям.
6. **Административное чтение персональных данных** (журнал #6, #22): `analyst`, `admin`,
   `owner` видят полные карточки; **каждое** открытие карточки, списка с ПДн или экспорта
   пишет аудит `admin.read.personal` с актором, временем, чьими данными и контекстом (раздел,
   действие); контекст и цель заполняет система, сотрудник ничего не вводит (журнал #59).
   `moderator` видит только базовый профиль автора проверяемого материала — имя и публичный
   хэндл рядом со статьёй, историей и диалогом (журнал #51; матрица #111); e-mail, контакты,
   финансы и общий список пользователей ему недоступны. `editor` ПДн не видит (матрица #6, #81).
7. **Рейтинг** (2): читатель и посетитель видят словесное объяснение позиции; автор — числа по
   своим статьям; служебные роли с доступом к статистике — по всем (матрица #7).
8. **Вердикт AI и причины отказа** (журнал #42): автор — по своим; `editor` — по редакционным;
   `moderator`, `admin` (журнал #56), `owner` — по всем; `analyst` — причины отказа и статусы на
   чтение (журнал #52; матрица #8, #75).
9. **Прочтения** (2): только валидные записи входят в показ; исключённые (журнал #26) не
   влияют ни на статистику автора, ни на отчёты; автор видит сумму (`standard`) или по дням
   (`pro`).
10. **Аудит** (журнал #39, #59): служебная роль видит записи своей зоны; `admin` и `owner` —
    полный журнал; аудит доступен только для просмотра — записи не создаются и не правятся
    вручную. Зоны: `editor` — редакционные статьи; `moderator` — решения по материалам и AI;
    `analyst` — финансы, чтения ПДн, AI-метрики.
11. **Кеш** (ADR-0019): в кеше публичных страниц и списков нет ничего, что зависит от прав или
    сессии; персональные и административные ответы не кешируются.
12. **Paywall зарезервирован** (ADR-0036): поле `Article.access` не читается; все опубликованные
    материалы видны целиком всем.

## 3. Исключения

| Исключение | Условие | Кто может | Аудит |
|---|---|---|---|
| Служебная роль читает данные вне своей зоны | индивидуальное исключение, выданное `owner` (журнал #7) | `editor`, `moderator`, `analyst`, `admin` с исключением | `permission.exception.grant`; чтение ПДн — `admin.read.personal` |
| IP сессий другого пользователя | расследование инцидента | только `owner` | `admin.read.personal` с контекстом «расследование» |
| Чтение архивированного или отклонённого материала автором | всегда для своих (журнал #5, #12) | автор | — |
| Экспорт CSV статистики | без ПДн | `analyst`, `admin`, `owner` | `stats.export` |

## 4. Взаимодействие с другими политиками

- `permission-checks.md` определяет, **где** выполняется проверка; эта политика — **что** видно.
  При конфликте видимость уже проверок: право на действие не даёт права видеть больше, чем
  здесь.
- `permission-exceptions.md` расширяет видимость только для служебных ролей и только решением
  `owner`.
- `session-lifecycle.md`: отозванная или истёкшая сессия делает запрос запросом посетителя;
  архивированный аккаунт — тоже.
- `60-ranking/explainability.md` задаёт тексты словесного объяснения для правила 7.

## 5. Проверяемость

- Контрактные тесты: в каждом публичном резолвере используется `visibleTranslationsWhere`;
  в публичных типах SDL нет `email`, `role`, `planTier`, `sessions`.
- Тесты резолверов: черновик, версия на проверке, архив, отклонённая — посетителю и читателю
  `NOT_FOUND`/410, автору — своя видна, чужая — `NOT_FOUND`; `moderator` видит любую.
- Тест аудита: открытие карточки пользователя ролью `analyst` создаёт запись
  `admin.read.personal` с актором, субъектом и контекстом; без записи — тест красный.
- Тест кеша: ответ с сессией и без сессии для одного публичного адреса совпадает; ответы
  кабинета не имеют заголовков кеширования.
- Метрика нарушения: число ответов `FORBIDDEN` на публичных маршрутах должно быть нулём
  (они означают раскрытие существования).
