# Бизнес-модель: Риски

- **Область**: бизнес-модель
- **Статус**: на утверждении
- **ADR**: ADR-0011, ADR-0025 (заменяется Meilisearch — §21.21), ADR-0031, ADR-0035;
  `docs/vision/00-reality-check.md`; журнал §8.13, §8.19, §21.25, §23.7
- **Этап**: 0–1

## 1. Назначение

Перечень рисков, которые могут обесценить модель, с признаком срабатывания и ответом. Не список
задач: приоритизация — `docs/issues/`. На файл ссылаются `overview.md`, `00-roadmap.md` §4–5.

## 2. Правила

| Риск | Признак | Ответ |
|---|---|---|
| Нулевая аудитория: некому читать первых авторов | вторая страница за визит и квалифицированные прочтения не растут | контент до открытия (владелец и выдачи), SEO-инфраструктура (`feeds-and-sitemap.md`), сценарий Б в `overview.md` |
| Цена отвергнута | конверсия ниже порога `metrics.md` | пересмотр цены/состава (`pricing-hypotheses.md`), не отключение проверки |
| Платный старт до продукта (§8.13) | авторов нет, доход ноль, расходы идут | решение А/Б владельцем до этапа 1 |
| Стоимость AI выше 20 % цены | сверка `costMinor` | лимиты переводов, очередь при бюджете, цена `pro` |
| Зависимость от провайдеров (платежи, AI, почта) | недоступность, смена условий | адаптеры (ADR-0010), `PROVIDER_UNAVAILABLE`, `fake` для тестов |
| Юридический: 152-ФЗ, `visitorId`, 54-ФЗ | претензия, отсутствие уведомления РКН, чеки | `legal-152-54.md`; предрелизная проверка §8.19; политика ПД до открытой регистрации |
| Накрутка рейтинга и монополизация выдачи | аномалии, один автор в топе | `anti-fraud.md` автоматически; слой открытия (§21.25) |
| Один разработчик | остановка работы | документация как источник истины, ADR и спецификации, CI с тестами (ADR-0031) |
| Прод-сборка и связка веб–API не работают | 500 на SSR, фикстуры вместо данных (`00-reality-check.md`) | этап 0 роадмапа |
| Поиск на PostgreSQL не масштабируется | — | заменён Meilisearch по решению владельца (§21.21) |
| Оспаривания блокировок и споры о правах | жалобы правообладателей | сценарий жалоб — отложено; форма оспаривания (§48) |
| Переход из сценария Б в А | первые авторы по выдаче не готовы платить | выдачи с явным сроком; интервью до включения платности |

Правила чтения таблицы: признак — измеримый в базе или журнале; ответ — ссылка на существующую
спецификацию или решение владельца, не новое правило.

## 4. Взаимодействие с другими политиками

- `overview.md` — стратегический выбор запуска; `metrics.md` — признаки.
- `docs/issues/00-roadmap.md` — этап 0 как ответ на технические риски.
- `80-observability/*` (8b) — алерты как признаки.

## 5. Проверяемость

- Каждому риску — метрика или алерт из `metrics.md` / `health-and-alerts.md`; ежеквартальный
  пересмотр таблицы владельцем `[ДОПУЩЕНИЕ]`.
- Тест на сиде: сценарии «нулевая аудитория» и «провайдер недоступен» воспроизводятся тестами
  `fake`-адаптеров (ADR-0031) без падения выдачи (§21.40).
- Признак «один автор в топе» — отчёт статистики: доля материалов одного автора в главном топе
  за неделю `[ДОПУЩЕНИЕ: порог — Г4, слой открытия]`.
- Юридические риски проверяются чек-листом `legal-152-54.md` §5 до открытой регистрации и до
  платежей.

## 6. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Периодичность пересмотра.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Считать ли отсутствие штатного ревьюера риском этапа 1 (очередь ручной
  ветки растёт при владельце-единственном ревьюере)? Если да — метрика «возраст старшей заявки»
  с порогом и план найма к этапу 4; если нет — SLA правил публикации рассчитан на владельца.
- Отложено (§8.13, §8.19, §21.25): платный старт, бухгалтерия, слой открытия.
