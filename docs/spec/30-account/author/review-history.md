# Страница: Проверка и история решений

- **Реестр**: `00-registries/pages.md` #38 · `00-registries/routes.md` #37
- **Статус**: на утверждении
- **ADR**: ADR-0039 (в части, не противоречащей журналу: балла нет — #41), ADR-0045; журнал §6,
  §16, #12, #14, #16, #18, #40–42, §24.3; `50-access/roles/moderator.md`; `10-flows/write-and-publish.md`
  (#3), `moderation.md` (#5)
- **Этап**: 1

## 1. Назначение

История проверки одной языковой версии: вердикт автоматической проверки с текстом причин
(журнал §16.4, §24.3), сообщения ревьюера — запрос доработки с рекомендациями, снятие с
публикации, ручная публикация, окончательный отказ с комментарием (журнал §6.5–6, #16), в
хронологии. Главное действие — понять, что исправить, и вернуться в редактор. Оспаривания
решения AI нет (журнал #40): единственный путь — правка и ручная ветка.

## 2. Аудитория и роли

| Роль | Видит | Может | Не может |
|---|---|---|---|
| Гость | — (302 на `/login?next=…`) | — | — |
| Читатель (free) | бывший автор — историю своих версий | читать | подавать повторно (`PLAN_LIMIT`) |
| Автор (standard / pro) | вердикт и причины по категориям с текстом (§24.3); сообщения ревьюера по роли, без имени сотрудника `[ДОПУЩЕНИЕ]`; даты; текущий статус | перейти в редактор; отметить прочитанным | ответить ревьюеру в переписке `[ДОПУЩЕНИЕ: переписка односторонняя]`; видеть пороги и внутренние признаки проверки (§24.3) |
| Администраторы (по ролям, если отличаются) | `editor` — по редакционным; `moderator`/`owner` — ту же историю в `/admin/review` (не здесь) | — | — |

Условие видимости: `article.aiCheck.read` (#8) — свои; `review.message` (#102) — сообщения
автору; служебные заметки ревьюера, не адресованные автору, не показываются `[ДОПУЩЕНИЕ]`.

## 3. Точки входа и маршруты

- `/me/articles/{id}/review`, `/en/me/articles/{id}/review` — `id` языковой версии; `#decision-{n}`
  — якорь решения из письма.
- Редиректы: без сессии — 302 на `/login?next=…`; ограниченная сессия — `/me/archived`; чужая
  версия — 404.
- Приходят: письма о решениях (журнал §16.5), «Мои материалы» («есть причины»), редактор
  (панель «Проверка» → «вся история»), сводка. Уходят: редактор, `/legal/content-rules#…`
  (категория причины), `/me/articles`.

## 4. Данные и запросы к API

| Запрос / мутация | Аргументы | Поля | Права | Кеш | Ошибки (коды ADR-0032) |
|---|---|---|---|---|---|
| `translation.aiCheck(id)` | версия | `decision: publish \| reject \| pending \| none`, `checkedAt`, `reasons[] { category, anchor, text }` (текст формирует проверка — §24.3), `attempt` (первая / после «перередактировать») | #8 свои | нет | `UNAUTHENTICATED`, `NOT_FOUND` |
| `translation.reviewHistory(id)` | версия | `items[] { id, kind: rework_request \| unpublish \| manual_publish \| final_reject \| message \| ai_decision \| submitted \| withdrawn \| published_auto, text, recommendations, byRole, createdAt, readAt }` | #8, #102 свои | нет | — |
| `markReviewRead(translationId)` | версия | `readAt` | свои | — | — |

Категории причин — те же, что в правилах публикации (`legal-content-rules.md` §4, §24.3); текст
причины — сформированный проверкой, без порогов и признаков; для окончательного отказа ревьюер
может добавить комментарий (§24.3) — он и есть `text` записи `final_reject`. Все записи хранятся
с автором решения и временем (журнал §6.7); автору показывается роль.

## 5. Структура экрана по зонам

1. **Шапка сайта** и меню кабинета.
2. **Карточка версии**: заголовок, язык, статус, «открыть в редакторе» (или «только чтение» для
   `rejected`, истёкшего плана).
3. **Текущее решение**: крупно — «проверяется» / «опубликовано автоматически» / «не прошла
   проверку: N причин» / «на доработке: рекомендации» / «снята с публикации» / «отклонена
   редакцией» с комментарием; кнопка следующего шага («исправить и отправить», «отозвать»).
4. **Причины отказа проверки** (когда есть): список по категориям — название категории со ссылкой
   на правила, текст причины; пояснение «после правки материал посмотрит ревьюер, повторной
   автоматической проверки не будет» (журнал #14).
5. **История**: хронология всех записей `reviewHistory` с ролью и датой; рекомендации ревьюера —
   раскрываемые; непрочитанные — отмечены.
6. **Что дальше**: короткие правила — окно «перередактировать» (журнал #9), нет оспаривания AI
   (журнал #40), окончательный отказ — чтение и копирование (журнал §4.5).
7. **Футер**.

## 12. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Ревьюер показан ролью, без имени; переписка односторонняя (автор отвечает
  правкой); служебные заметки не показываются; якоря `#decision-{n}`.
- Отложено (§8.23): письма о решениях — шаблоны; (жалобы) — не касается.
- Закрыто Г1–Г5b (журнал #14, #40–42, §16.4, §24.3): нет оспаривания AI; причины — текст
  проверки по категориям; комментарий ревьюера при окончательном отказе; пороги не показываются.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Нужна ли автору возможность ответить ревьюеру сообщением (двусторонняя
  переписка — журнал §6.8 говорит о «рабочем диалоге»)? Если да — мутация `authorMessage` и
  лимит частоты; если нет — только правка и подача.
