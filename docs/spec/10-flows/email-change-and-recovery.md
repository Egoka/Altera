# Flow: Смена почты и восстановление доступа

- **Реестр**: `00-registries/flows.md` #13
- **Статус**: утверждён (гейт Г6, 2026-09-09)
- **ADR**: ADR-0022, ADR-0024, ADR-0032; журнал §3.4, §25.8, §25.13; `30-account/reader/email-change.md`,
  `20-public/contact.md`; `50-access/session-lifecycle.md` п. 10; матрица #49, #50, #104
- **Этап**: 1

## 1. Цель пользователя и роль на входе / выходе

Пользователь любой роли хочет сменить e-mail (единственный способ входа — ADR-0022) или
вернуть доступ, потеряв старую почту. Вход: аккаунт с сессией (смена) или посетитель без доступа
(восстановление). Выход: аккаунт с новым адресом; роль, план и сессии не меняются (журнал §25.8).
Смена — самообслуживание: код на новый адрес, ввод в том же окне; восстановление — ручная
процедура `admin`/`owner` с аудитом (матрица #50; журнал §3.4), автоматизации нет.

## 2. Предусловия

Смена: сессия; новый адрес не равен текущему; лимит запросов кода (`rate-limits.md` п. 8).
Восстановление: обращение через `/contact` с темой «восстановление доступа»; сотрудник с правом
`email.change.admin` (#50); проверка личности — по данным, известным только владельцу аккаунта
`[ДОПУЩЕНИЕ: состав проверки определяет редакция вне спецификации]`.

## 3. Шаги

| Шаг | Экран (файл страницы) | Действие пользователя | Система делает | Данные / мутация | Событие (код) |
|---|---|---|---|---|---|
| 1 | `30-account/reader/email-change.md` | вводит новый адрес, «Отправить код» | одноразовый код (хэш) с ограниченным сроком; письмо на новый адрес | `requestEmailChange(newEmail)` | `mail.queued` (#51) |
| 2 | то же окно | вводит код | проверяет код и занятость адреса; меняет e-mail сразу; сессии сохраняются; аудит | `confirmEmailChange(code)` | `user.email.change` (#17) |
| 3 | то же окно | видит «адрес изменён» | уведомление на прежний адрес — состав в проходе почты (§25.13) | — | `mail.queued` |
| Р1 | `20-public/contact.md` | пишет «потерял доступ к почте», указывает хэндл и новый адрес | обращение сотруднику | `createSupportRequest(topic: access_recovery)` | `support.request.created` (#80) |
| Р2 | `40-admin/users.md` (заход 7) | — | `admin`/`owner` проверяет личность, меняет e-mail с причиной; чтение ПДн — аудит (#104) | `adminChangeEmail(userId, newEmail, reason)` | `user.email.change` (#17, by admin), `admin.read.personal` (#67) |
| Р3 | `20-public/login.md` | входит по новому адресу | обычный вход | `requestMagicLink` | `auth.login` (#42) |

## 4. Развилки

| Точка | Условие | Ветка А | Ветка Б |
|---|---|---|---|
| Шаг 1 | адрес равен текущему / формат | `VALIDATION_ERROR` | код отправлен |
| Шаг 1 | открытый запрос | `CONFLICT` — отменить прежний или ввести его код | код отправлен |
| Шаг 2 | код неверен | `VALIDATION_ERROR`; попытки ограничены `[ДОПУЩЕНИЕ]`, затем запрос закрыт | смена |
| Шаг 2 | код истёк | `NOT_FOUND` — «отправить ещё раз» | смена |
| Шаг 2 | адрес занят другим аккаунтом | `CONFLICT` — другой адрес | смена |
| Шаг 1 | пользователь отменяет | `cancelEmailChange` | — |
| Р1 | аккаунт в архиве / заблокирован | восстановление доступа не отменяет архив: сначала оспаривание (журнал #48) | процедура |
| Р2 | личность не подтверждена | отказ с ответом в обращении | смена |

## 5. Ошибки и восстановление

| Ошибка (код ADR-0032) | На каком шаге | Что видит пользователь | Как продолжить |
|---|---|---|---|
| `VALIDATION_ERROR` | 1, 2 | подсветка / «код неверен» | исправить |
| `CONFLICT` | 1, 2 | «запрос уже открыт» / «адрес занят» | отменить / другой адрес |
| `NOT_FOUND` | 2 | «код истёк» | отправить ещё раз |
| `RATE_LIMITED` | 1 | таймер | подождать |
| `FORBIDDEN` | Р2 | (сотруднику) нет права #50 | `admin`/`owner` |

## 7. Схема

```mermaid
flowchart TD
  A[/me/email: новый адрес] --> B{Валидация, лимит, нет открытого}
  B -- ошибка --> A
  B -- ок --> C[Код на новый адрес]
  C --> D[Ввод кода в том же окне]
  D -- неверен / истёк --> C
  D -- адрес занят --> E[CONFLICT: другой адрес]
  D -- ок --> F[Адрес изменён сразу, сессии сохранены]
  R1[/contact: потерян доступ/] --> R2[admin/owner: проверка личности, смена с причиной, аудит]
  R2 -- отказ --> R3[Ответ в обращении]
  R2 -- ок --> R4[Вход по новому адресу]
```

## 8. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Срок кода и число попыток — общие параметры, здесь не задаются; состав проверки
  личности при восстановлении — редакция.
- Отложено (§25.13): письма; (заход 7) экран смены e-mail в карточке пользователя.
- Закрыто Г1, Г6 (журнал §3.4, §25.8): чтение ПДн сотрудником — аудит; смена кодом без
  подтверждения со старой почты, без повторного входа, без завершения сессий и без отката.
