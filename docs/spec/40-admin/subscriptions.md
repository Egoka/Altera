# Раздел админки: Подписки и планы

- **Реестр**: `00-registries/admin-sections.md` #8 · `00-registries/routes.md` #48
- **Статус**: утверждён (гейт Г8a, 2026-09-09)
- **ADR**: ADR-0010, ADR-0035, ADR-0044 (в части, не противоречащей журналу); журнал #19, #25,
  #35, §8.2, §8.12, §8.15–17, §8.20–22, §24.1, §24.4, §25.11; `70-plans-and-billing/subscription-lifecycle.md`,
  `role-derivation.md`, `plan-standard.md`, `plan-pro.md`; `10-flows/pay-and-upgrade.md` (#6),
  `subscription-expires.md` (#7)
- **Этап**: отдельный этап платности (§24.1); на первом запуске раздел показывает только ручные
  выдачи (`grants-and-promo.md`); базовое авторство — в карточке пользователя (§27.1)

## 1. Назначение и минимальная роль

Финансовый контур подписок (журнал #19, §8.2): состояние подписки любого пользователя —
активный период, очередь оплаченных периодов по приоритету (§8.22, §24.4), серия попыток
списания в дату окончания (§8.15), автопродление, истечение; ручные операции — выдать,
продлить (дни в конец периода — журнал #25), изменить, отменить подписку; условия и цены планов
(`Plan`) — значения централизованы, сами цены остаются гипотезами (§8.12). Минимальная роль —
`analyst` и `admin` (оба с действиями — финансовый контур), `owner`; для `analyst` раздел не
read-only (журнал #19). `moderator`, `editor` — недоступен. Каждое решение аудируется с
причиной, платёжными данными и значениями до/после (§8.2).

## 2. Маршруты

- `/admin/subscriptions` — список подписок (по пользователям); `/admin/subscriptions/{id}` —
  карточка подписки пользователя с очередью периодов; `/admin/subscriptions/plans` — условия и
  цены планов `[ДОПУЩЕНИЕ: вложенный маршрут в составе #48]`; `?tier=`, `?state=`, `?renewal=`,
  `?q=`, `?sort=`, `?page=`.
- Из карточки пользователя (#6, вкладка «подписка») — сюда; из платежа (#9) — к подписке.
- `noindex`; без сессии — 302; `moderator`, `editor`, обычный аккаунт — 403; неизвестный `id` —
  404.

## 3. Сущности и данные

| Сущность | Поля в списке | Поля в карточке | Источник (запрос) | Персональные данные (кто видит) |
|---|---|---|---|---|
| Подписка пользователя | пользователь (имя, хэндл), активный период (план, интервал, конец), источник (платёж / выдача), очередь: число ожидающих, `cancelAtPeriodEnd`, состояние продления (следующее списание / попытки сегодня N из 5 / истекла) | очередь периодов по приоритету с датами и источниками (§8.22); история периодов; попытки списания в дату окончания (§8.15) со статусами; платежи (ссылка в #9); выдачи и дни (ссылка в #10); ручные операции с причинами | `adminSubscriptions(filters)`, `adminSubscription(id)` | имя, хэндл, e-mail — `analyst`, `admin`, `owner`; открытие карточки — `admin.read.personal` (#67) |
| `Plan` (условия и цены) | план, интервал, цена (гипотеза, §8.12), активен, обновлён | состав возможностей, лимиты (очередь, медиа), цены месяц/год (год = 10 месяцев — журнал #32), история изменений с `diff` | `adminPlans`, `adminPlan(tier)` | нет |
| Попытка списания | дата, номер попытки (1–5), результат, причина отказа (класс) | — | в карточке | нет |

Источник истины — очередь периодов (`subscription-lifecycle.md` п. 1–2); `User.planTier` /
`planUntil` — кэш (`role-derivation.md`). На первом запуске (§24.1) платных периодов нет —
раздел показывает ручные выдачи; базовое авторство (`author.enabled`, #87) — признак в
карточке пользователя (#6), отдельного списка и ручного отзыва здесь нет; закрытие доступа —
только архивированием аккаунта (журнал §27.1).

## 4. Список: фильтры, сортировки, поиск, пагинация

| Фильтр | Тип | Значения | По умолчанию | Сохраняется в URL |
|---|---|---|---|---|
| План активного периода | выбор | standard, pro, выдача, нет | все | да |
| Состояние | выбор | активна, отменена с конца периода, истекает сегодня (серия списаний), истекла | активна | да |
| Есть очередь | флажок | да | — | да |
| Интервал | выбор | месяц, год | — | да |
| Дата окончания | даты | по стандарту дат | — | да |

Сортировка: дата окончания активного периода (по умолчанию, ближайшие первыми), пользователь,
план; поиск по имени, хэндлу и e-mail от 3 знаков (e-mail — с аудитом `admin.read.personal`
`[ДОПУЩЕНИЕ: как в #6]`); пагинация `limit` 20, максимум 100; экспорт CSV — `analyst`, `admin`,
`owner` (`stats.export` #94), без e-mail.

## 5. Карточка объекта и действия

| Действие | Роль | Предусловие | Мутация | Результат | Аудит (`action`) | Письмо / уведомление |
|---|---|---|---|---|---|---|
| Выдать подписку (период) | `analyst`, `admin`, `owner` | план, интервал, срок, причина; не служебная запись (§8.17) | `adminGrantSubscription(userId, tier, interval, endsAt, reason)` | период в очередь по приоритету; равен оплаченному по правам (§8.16) | `subscription.grant` (#20) с до/после | пользователю — проход почты (§25.13) |
| Продлить (дни в конец периода) | `analyst`, `admin`, `owner` | активный период; число дней; причина | `extendSubscription(id, days, reason)` | `periodEnd` сдвинут (журнал #25) | `subscription.extend.manual` (#74) | пользователю |
| Изменить | `analyst`, `admin`, `owner` | причина | `adminChangeSubscription(id, input, reason)` | `cancelAtPeriodEnd`, интервал ожидающего периода `[ДОПУЩЕНИЕ: состав изменяемого]` | `subscription.change` (#20) | пользователю |
| Отменить | `analyst`, `admin`, `owner` | активный период; причина | `adminCancelSubscription(id, reason, immediate: false)` | `cancelAtPeriodEnd = true`; доступ до конца периода; немедленное прекращение — только через одобренный возврат (§8.18, #9) | `subscription.cancel` (#20) | пользователю |
| Изменить условия и цены плана | `analyst`, `admin`, `owner` | причина; цена — новое значение гипотезы (§8.12) | `updatePlan(tier, input, reason)` | новые периоды по новой цене; оплаченные не пересчитываются | `plan.update` (#19) с `diff` | — |
| Открыть платежи / выдачи / пользователя | по роли | — | — | переход в #9 / #10 / #6 | `admin.read.personal` при карточке пользователя | — |

Что здесь нельзя: покупать за пользователя, менять приоритет очереди (фиксирован §8.22),
отключать серию попыток списания (§8.15), выдавать план служебной записи (§8.17), возвращать
деньги (#9).

## 6. Массовые операции

Массовых операций нет: каждая ручная операция с подпиской — поштучно с причиной и аудитом до/после
(§8.2).

## 7. Опасные операции и подтверждения

- **Отмена и изменение подписки** — деньги и права пользователя: модальное окно с причиной и
  последствиями («доступ до {дата}», «период в очереди начнётся …»).
- **Изменение цен и условий плана** — затрагивает всех будущих покупателей: двухшаговое
  подтверждение с показом до/после `[ДОПУЩЕНИЕ]`; цены остаются гипотезами (§8.12).
- **Выдача подписки** — модальное окно с планом, сроком и причиной.
- Никто не может: прекратить подписку немедленно без возврата (§8.18), изменить порядок
  очереди, выдать Pro служебной записи (§8.17).

## 8. Аудит действий

Коды: `subscription.grant` / `subscription.change` / `subscription.cancel` (#20 — причина,
платёжные данные, до/после), `subscription.extend.manual` (#74), `plan.update` (#19 с `diff`),
`admin.read.personal` (#67) при открытии карточки и поиске по e-mail, оболочка `admin.change`
(#75). Логи системы: `subscription.activated` / `.expired` / `.renewed` / `.queued` / `.retry`
(#50). Не аудируется: просмотр списка без раскрытия e-mail `[ДОПУЩЕНИЕ]`.

## 9. Состояния

| Состояние | Когда | Что показано |
|---|---|---|
| Загрузка | список / карточка | скелеты |
| Пусто | подписок нет (первый запуск — только выдачи) / фильтр пуст | `EmptyState` с пояснением «платные подписки — отдельный этап (§24.1)» |
| Ошибка | запрос или мутация | `ErrorState` с `requestId`; введённая причина сохраняется |
| Нет прав на часть действий | не применимо: у всех допущенных ролей полный финансовый контур (журнал #19); служебная запись как цель — кнопки выдачи нет (§8.17) | пояснение |
| Конфликт (объект изменён другим администратором) | операция поверх изменённой очереди (вебхук активировал период, другой сотрудник отменил) | `CONFLICT`: «состояние изменилось, обновите карточку» |
| Лимит / превышение | экспорт CSV чаще лимита (`rate-limits.md` п. 12) | `RATE_LIMITED` с таймером |

## 10. Мобильный

Чтение списка и карточки (с аудитом), продление днями; выдача, изменение, отмена и цены планов —
десктоп `[ДОПУЩЕНИЕ: операции с деньгами и правами]`.

## 12. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Вложенный маршрут планов; состав изменяемого в «изменить»; поиск по e-mail с
  аудитом; двухшаговое подтверждение цен; на первом запуске — ручные выдачи вместо подписок;
  операции с деньгами — десктоп.
- Отложено (§8.12, §8.19, §24.1, §25.13, промокоды): значения цен, чеки, платный запуск, письма,
  механика промокодов.
- Закрыто Г1–Г5b (журнал #19, #25, §8.2, §8.15–18, §8.22, §24.4): финансовый контур трёх ролей с
  аудитом; дни в конец периода; пять попыток; очередь по приоритету; прекращение только через
  возврат.
- Закрыто Г8a (§27.1): базовое авторство — признак в карточке пользователя; списков и ручного
  отзыва здесь нет; закрытие доступа — только архив аккаунта.
