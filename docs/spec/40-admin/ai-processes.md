# Раздел админки: AI-процессы

- **Реестр**: `00-registries/admin-sections.md` #14 · `00-registries/routes.md` #54
- **Статус**: утверждён (гейт Г8a, 2026-09-09)
- **ADR**: ADR-0039 (в части, не противоречащей журналу: балла нет), ADR-0045, ADR-0046; журнал
  §6.2–3, §13, §16, #14, #34, #41, #52, #56, §24.3, §25.4, §25.12; матрица #73–76; события #46–47,
  #71, #85; `40-admin/review-queue.md`, `jobs.md`
- **Этап**: 1

## 1. Назначение и минимальная роль

Все действия, генерации и ответы, проходящие через AI (журнал §13.2): проверки допустимости
первой подачи с вердиктом «публиковать / не публиковать» и текстом причин (§24.3), переводы
второй языковой версии (3; §25.12 — повторная генерация как новая ревизия), автоматические
проверки имени и аватара (§25.4, события #85) — с актуальным статусом каждой записи «создано /
начато / в работе / выполнено / ошибка» (журнал #34); стоимость — только в агрегатах (§27.4).
Балла нет (журнал #41),
переопределения и оспаривания нет (#40), повторного запуска проверки как способа изменить
вердикт нет (журнал #14). Минимальная роль: `moderator` — своя зона (записи по материалам в
ручной ветке), `admin` — чтение всего, `owner`; `analyst` — чтение статусов, причин отказа и
агрегатов (§13.4); `editor` — записи по редакционным статьям. Запуск, повтор и изменение
процессов — только `owner` или по исключению (§13.5; технический повтор упавшего задания —
`jobs.md`).

## 2. Маршруты

- `/admin/ai` — список; `/admin/ai/{id}` — карточка записи; `?kind=check|translate|profile`,
  `?status=`, `?verdict=`, `?period=`, `?q=`, `?page=`; `?tab=stats` — агрегаты `[ДОПУЩЕНИЕ]`.
- Из карточки статьи (#4), очереди (#5), заданий (#13), сводки (#1).
- `noindex`; без сессии — 302; обычный аккаунт — 403; `moderator`/`editor` вне зоны — 404
  `[ДОПУЩЕНИЕ]`.

## 3. Сущности и данные

| Сущность | Поля в списке | Поля в карточке | Источник (запрос) | Персональные данные (кто видит) |
|---|---|---|---|---|
| AI-запись (`ArticleAiReview` / задание перевода / проверка профиля) | вид, объект (статья с языком; пользователь — для проверки профиля), статус, вердикт (`publish` / `reject` для проверки; `ok` / `needs_review` / `rejected` для профиля), создано, длительность, модель и версия промпта (`promptVersion`); стоимость отдельной записи не показывается никому — финансовая и операционная информация только агрегированно для `owner`, `admin`, `analyst` (журнал §27.4) | причины по категориям с текстом (§24.3); для профиля — поле и решение сотрудника; технические признаки и пороги — только `owner` `[ДОПУЩЕНИЕ: как в `review-queue.md` §3]`; ошибка провайдера (класс); ссылка на задание (#13) и на объект | `adminAiRecords(filters)`, `adminAiRecord(id)` | имя и хэндл автора — служебные роли своей зоны; текст статьи в карточке — не показывается (открыть в #4); проверка профиля содержит имя/аватар — `moderator`, `admin`, `owner` |
| Агрегаты | число записей по видам и статусам, доля отказов по категориям, медиана длительности, стоимость за период и доля от цены плана (`unit-economics.md`), ошибки провайдера | — | `aiStats(period)` | нет |

Что уходит провайдеру: текст без имени и e-mail (`legal-content-rules.md` §4) — в карточке
показывается только факт и версия промпта, не сам запрос `[ДОПУЩЕНИЕ]`.

## 6. Массовые операции

Массовых операций нет: раздел — наблюдение; массовый повтор технических ошибок — `jobs.md` §6.

## 7. Опасные операции и подтверждения

Опасных операций в разделе нет. Повтор упавшего задания подтверждается в `jobs.md`; несогласие с
отказом AI выражается ручной публикацией ревьюером в #5 (журнал #14, #44), не здесь.

## 8. Аудит действий

Аудит пишет система: `ai.decision` (#71 — вердикт и категории причин), `profile.check` (#85);
чтение карточки записи по материалу не аудируется (ПДн — имя и хэндл, публичные); открытие
карточки пользователя из проверки профиля — `admin.read.personal` (#67). Логи: `ai.job.created` /
`.started` / `.running` / `.done` / `.failed` (#46 — `model`, `promptVersion`, `costMinor`,
`durationMs`), `ai.translate.*` (#47). Не аудируется: просмотр списка и агрегатов.

## 9. Состояния

| Состояние | Когда | Что показано |
|---|---|---|
| Загрузка | список / карточка | скелеты |
| Пусто | записей нет / фильтр пуст | `EmptyState` |
| Ошибка | запрос не ответил; провайдер недоступен (записи «ошибка») | `ErrorState`; записи с ошибкой — класс ошибки без деталей провайдера |
| Нет прав на часть действий | все, кроме `owner`, — без повтора; `analyst` — без действий | кнопок нет |
| Конфликт (объект изменён другим администратором) | не применимо: раздел не редактирует записи; повтор — конфликт в #13 | — |
| Лимит / превышение | экспорт CSV чаще лимита | `RATE_LIMITED` |

Дополнительно: запись «в работе» дольше обычного — пометка «задерживается» с ссылкой в #13
`[ДОПУЩЕНИЕ: порог — 8b]`.

## 12. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Технические признаки и пороги — только `owner`; сам запрос провайдеру не
  показывается; период 7 дней; 404 вне зоны; записи хранятся бессрочно, логи 30 дней; порог
  «задерживается» — 8b.
- Отложено (журнал #41, §13.3, этап 4): правила проверки, провайдер и бюджет — `system-settings.md`;
  лимиты переводов (Г4); критерий «подозрительного» имени и аватара (§25.4) — в правилах
  проверки.
- Закрыто Г1–Г6 (журнал #14, #34, #40–41, #52, #56, §13, §24.3, §25.4, §25.12): статусы записей;
  без балла, оспаривания и повторного запуска; `analyst` — чтение; `admin` — чтение; проверка
  профилей; повторная генерация — ревизия.
- Закрыто Г8a (§27.4): стоимость отдельной проверки или генерации не показывается рецензенту;
  агрегаты — `owner`, `admin`, `analyst`.
