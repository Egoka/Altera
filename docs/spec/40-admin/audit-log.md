# Раздел админки: Аудит

- **Реестр**: `00-registries/admin-sections.md` #16 · `00-registries/routes.md` #56
- **Статус**: утверждён (гейт Г8a, 2026-09-09)
- **ADR**: ADR-0032 (`audit_log`), ADR-0018; журнал §3.4, §14, #6, #22, #37, #39, #59, §26.1;
  `50-access/visibility.md` п. 10; `80-observability/audit-vs-logs.md` (8b); матрица #92;
  `events-and-logs.md` (все строки типа `audit`)
- **Этап**: 1 (журнал #37 — интерфейс с первого этапа)

## 1. Назначение и минимальная роль

Неизменяемый журнал произошедших действий (журнал #59): все записи типа `audit` из
`events-and-logs.md` и сведения о том, как они были обработаны (§14.2) — актор, время, сущность,
поля до/после (журнал #6), а для чтения персональных данных — чьи данные, контекст и цель,
заполненные системой (§14.4). Только просмотр: записи не создаются, не правятся и не удаляются
вручную (§14.4, журнал #59). Минимальная роль — любая служебная в своей зоне (§14.3; зоны —
`visibility.md` п. 10: `editor` — редакционные статьи; `moderator` — решения по материалам и AI;
`analyst` — финансы, чтения ПДн, AI-метрики); `admin` и `owner` — полный журнал по всем зонам
(журнал #39). Для `analyst` раздел read-only с одним действием — экспорт CSV по фильтру (`admin`,
`owner` — `admin-sections.md` #16 `[ДОПУЩЕНИЕ: analyst без экспорта]`). Компактный блок критичных
записей у `owner` — на сводке (§26.1); полный аудит — здесь.

## 2. Маршруты

- `/admin/audit` — список; карточка записи — боковая панель `?id=` `[ДОПУЩЕНИЕ]`; `?action=`,
  `?actor=`, `?subject=`, `?entity=`, `?period=`, `?zone=`, `?critical=1`, `?page=`.
- Из карточек сущностей (#4, #6, #7, #8, #9) — «аудит по объекту» с предзаполненным `?entity=`.
- `noindex`; без сессии — 302; обычный аккаунт — 403; запись вне зоны служебной роли — 404
  `[ДОПУЩЕНИЕ]`.

## 3. Сущности и данные

| Сущность | Поля в списке | Поля в карточке | Источник (запрос) | Персональные данные (кто видит) |
|---|---|---|---|---|
| `AuditLog` | время, `action` (код из реестра), актор (роль и служебное имя; «система» для автоматических), сущность и её идентификатор (ссылка), краткое описание, признак «критичная» `[ДОПУЩЕНИЕ: набор критичных кодов — отдельный проход §26.1]` | `diff` — поля до/после (журнал #6); причина; для `admin.read.personal` — субъект, контекст и цель (§14.4); `requestId`; сведения об обработке: когда записано, чем инициировано (§14.2) | `auditLog(filters)`, `auditEntry(id)` | записи содержат хэндлы, имена, хэши e-mail субъектов — по зонам; полный журнал — `admin`, `owner`; чтение аудита само по себе не логируется (журнал §27.5) |
| Сводка по фильтру | число записей, по кодам, по акторам | — | `auditSummary(filters)` | нет |

Записи хранятся бессрочно (реестр событий, ретенция); ошибочные записи не удаляются, а
помечаются в связанных сущностях (журнал #26).

## 4. Список: фильтры, сортировки, поиск, пагинация

| Фильтр | Тип | Значения | По умолчанию | Сохраняется в URL |
|---|---|---|---|---|
| Зона | выбор | по ролям (`visibility.md` п. 10); `admin`/`owner` — все | своя зона | да |
| Код действия | выбор | все `audit`-коды реестра | все | да |
| Актор | выбор служебной записи / «система» | — | — | да |
| Субъект / сущность | тип и идентификатор | пользователь, статья, подписка, платёж, рубрика, тег, служебная запись | — | да |
| Период | даты | по стандарту дат | 7 дней `[ДОПУЩЕНИЕ]` | да |
| Критичные | флажок | да | — | да |

Сортировка: время (убыв., по умолчанию; иной сортировки нет — журнал хронологический); поиск по
идентификатору сущности и `requestId`; пагинация `limit` 20, максимум 100 (курсорная по времени
`[ДОПУЩЕНИЕ]`); экспорт CSV по фильтру — `admin`, `owner` (`stats.export` #94 — код для аудита
`[ДОПУЩЕНИЕ: тот же]`), лимит `rate-limits.md` п. 12.

## 6. Массовые операции

Массовых операций нет: журнал только для чтения (§14.4); экспорт — по фильтру.

## 7. Опасные операции и подтверждения

Опасных операций нет. Экспорт CSV с записями о чтении ПДн — подтверждение «файл содержит
сведения о персональных данных» `[ДОПУЩЕНИЕ]`; сам экспорт аудируется.

## 8. Аудит действий

Раздел показывает аудит и почти не порождает его: `stats.export` (#40) при экспорте;
`admin.read.personal` (#67) — только при переходе в карточку пользователя. Просмотр журнала не
логируется (журнал §27.5): рекурсивный «аудит просмотра аудита» не создаётся, контекст и цель
уже зафиксированы у исходных действий (§14.4). Что сознательно не входит в аудит:
просмотры публичных данных (журнал §3.4 — это аналитика), логи `log`/`metric` (8b, `audit-vs-logs.md`).

## 9. Состояния

| Состояние | Когда | Что показано |
|---|---|---|
| Загрузка | список / карточка | скелеты |
| Пусто | по фильтру записей нет | «за период действий не было» |
| Ошибка | запрос не ответил | `ErrorState` с `requestId` |
| Нет прав на часть действий | служебная роль вне своей зоны; `analyst` без экспорта | записи других зон не показываются; кнопки экспорта нет |
| Конфликт (объект изменён другим администратором) | не применимо: журнал не редактируется | — |
| Лимит / превышение | экспорт чаще лимита | `RATE_LIMITED` |

## 10. Мобильный

Чтение списка и карточек в своей зоне; экспорт — десктоп `[ДОПУЩЕНИЕ]`.

## 12. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Набор «критичных» кодов — отдельный проход (§26.1);
  `analyst` без экспорта; курсорная пагинация; период 7 дней; 404 вне зоны; код экспорта аудита
  — `stats.export`; CSV без `diff` с ПДн; подтверждение экспорта.
- Отложено (8b): граница аудита и логов (`audit-vs-logs.md`), ретенция и хранение
  (`retention-and-pd.md`), критерий критичности (§26.1).
- Закрыто Г1–Г7 (журнал #6, #37, #39, #59, §14, §26.1): аудит с этапа 1; зоны; только чтение;
  контекст и цель заполняет система; полный аудит — отдельный раздел, критичное — на дашборде.
- Закрыто Г8a (§27.5): просмотр журнала аудита отдельно не логируется, рекурсивного аудита нет;
  журнал неизменяем.
