# Политика: Выгрузки данных

- **Область**: хранение
- **Статус**: утверждён (гейт Г9, 2026-09-09)
- **ADR**: ADR-0011 (право на копию), ADR-0029 (пакет контента), ADR-0044 п. 3–4 (экспорт при
  истёкшем плане); журнал §5, §25.9 (переписка и причины — с ролью); `30-account/reader/export.md`,
  `40-admin/jobs.md`, `80-observability/retention-and-pd.md`; матрица #37, #53
- **Этап**: 3 (`routes.md` #39); экспорт материалов Markdown/HTML (#37) — раньше `[ДОПУЩЕНИЕ]`

## 1. Назначение

Как собираются, где хранятся и как выдаются файлы выгрузок: полная выгрузка аккаунта (JSON +
материалы + медиа + переписка) и экспорт отдельных материалов (Markdown/HTML). На политику
ссылаются `export.md`, `30-account/author/articles.md` (экспорт статьи), `delete-account.md`
(«сначала выгрузите»), `legal-license.md` («выгрузить мои материалы»), `access-and-signed-urls.md`.

## 2. Правила

1. **Состав полной выгрузки** (`export.md` §4; журнал §25.9): профиль, согласия, закладки,
   список сессий (без IP), платежи без реквизитов, статьи во всех версиях и ревизиях в формате
   пакета контента (ADR-0029) и Markdown/HTML, **мастер-оригиналы изображений и метаданные медиа**
   (лицензия, атрибуция, `alt`, подпись, фокус) без технических thumbnails и адаптивных вариантов
   (журнал §29.6), причины отказов и переписка
   с рецензентом — с ролью сотрудника, без имени; без сырых событий вовлечённости
   (`engagement-tracking.md` §10), без чужих данных и служебных заметок.
2. **Сборка** — фоновое задание (`jobs.md`, вид `export`): ZIP `[ДОПУЩЕНИЕ]` в бакете по ключу
   `exports/{userId}/{exportId}.zip` (`storage-layout.md` п. 4); задание дольше десяти минут —
   уведомление по готовности (§25.13 — проход почты).
3. **Выдача** — только по подписанной ссылке с ограниченным сроком (`access-and-signed-urls.md`),
   владельцу аккаунта; сотрудникам файл не выдаётся — выгрузка чужих данных по запросу субъекта
   делается через карточку пользователя с аудитом (#104) `[ДОПУЩЕНИЕ: тем же механизмом на
   e-mail субъекта]`.
4. **Срок хранения файла** — 7 дней `[ДОПУЩЕНИЕ]` (`retention-and-pd.md`), затем `expired`;
   запись о запросе остаётся в истории; повторный запрос — новое задание; лимит — 1 в сутки
   `[ДОПУЩЕНИЕ]`.
5. **Экспорт материала** (#37, `articles.md`): Markdown или HTML одной версии с медиа по
   подписанным ссылкам `[ДОПУЩЕНИЕ: без вложения файлов]`; доступен автору, бывшему автору и для
   отклонённых редакцией (#110) — чтение и копирование (журнал §4.5).
6. **При истёкшем плане** выгрузка и экспорт доступны (ADR-0044 п. 3–4; `plan-free.md` п. 4).
7. **При архиве аккаунта** — через обращение в редакцию (`export.md` §3 `[ДОПУЩЕНИЕ]`); при
   удалении навсегда — файлы выгрузок удаляются вместе с аккаунтом.
8. **Секреты и токены** в выгрузку не входят (§27.6); e-mail пользователя — входит (это его
   данные).

## 3. Исключения

| Исключение | Условие | Кто может | Аудит |
|---|---|---|---|
| Выгрузка по запросу субъекта сотрудником | пользователь без доступа к аккаунту | `admin`, `owner` | `admin.read.personal` (#67) |
| Ответ уполномоченному органу | юридический контур (`legal-152-54.md`) | `owner` | вне продукта |

## 4. Взаимодействие с другими политиками

- `retention-and-pd.md` — сроки и права субъекта главнее; `access-and-signed-urls.md` — ссылки;
  `jobs.md` — задания; `audit-vs-logs.md` — аудит при действиях сотрудника.

## 5. Проверяемость

- Тест: выгрузка содержит все версии статей и переписку с ролью, не содержит имени рецензента,
  IP и сырых событий.
- Тест: ссылка после срока — `NOT_FOUND`; чужая — `NOT_FOUND`.
- Тест: бывший автор может запросить выгрузку.

## 6. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` ZIP; 7 дней; 1 в сутки; экспорт материала без вложения медиа; выгрузка из архива
  по обращению; сотрудник — тем же механизмом на e-mail субъекта.
- Отложено (§25.13): письмо о готовности; (этап 3) сама страница выгрузки.
- Закрыто Г2, Г6 (ADR-0044, §25.9): экспорт при истёкшем плане; переписка с ролью.
- Закрыто Г9 (§29.6): в выгрузке — мастер-оригиналы и метаданные медиа, без thumbnails и
  вариантов.
