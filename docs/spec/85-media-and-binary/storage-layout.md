# Политика: Раскладка хранилища

- **Область**: хранение
- **Статус**: на утверждении
- **ADR**: ADR-0008 (S3-совместимое хранилище РФ, `MediaAsset`), ADR-0011 (данные в РФ), ADR-0030;
  `docs/vision/03-data-model.md` (`MediaAsset`: `storageKey`, `variants`, `sha256`),
  `08-operations.md` §1, §2, §5; журнал §11, #28
- **Этап**: 1

## 1. Назначение

Где физически лежат бинарные данные и как они называются: бакеты, префиксы ключей, связь файла с
записью `MediaAsset`, что хранится в объектном хранилище, а что — только в базе. На политику
ссылаются `upload-pipeline.md`, `image-variants.md`, `avatars.md`, `article-covers.md`,
`exports.md`, `receipts-and-documents.md`, `retention-and-orphans.md`, `backups.md`,
`access-and-signed-urls.md`.

## 2. Правила

1. **Один прод-бакет** в S3-совместимом хранилище российского провайдера (ADR-0008 п. 1,
   ADR-0011) для медиа; окружения dev/ci/preview — свои бакеты или MinIO без ПДн
   (`08-operations.md` §2). Второй бакет — копия для резервирования (`backups.md`).
2. **Истина о файле — запись `MediaAsset` в PostgreSQL** (`08-operations.md` §1): ключ
   (`storageKey`), MIME, размер, размеры, `sha256`, варианты, лицензия и атрибуция, владелец
   (`ownerId` — загрузивший, ответственный за права — ADR-0008 п. 4), `deletedAt`. Файл без записи —
   сирота (`retention-and-orphans.md`); запись без файла — дефект целостности.
3. **Ключи** непрозрачны и не содержат ПДн и названий файлов пользователя:
   оригинал — `{yyyy}/{mm}/{id}.{ext}` (`03-data-model.md`), варианты — `{yyyy}/{mm}/{id}/w{width}.{format}`
   `[ДОПУЩЕНИЕ: раскладка вариантов]`; аватары, обложки и иллюстрации — в одном пространстве ключей,
   назначение определяется связью в базе (`User.avatarAssetId`, `Article.coverAssetId`, узлы
   документа `attrs.assetId`).
4. **Отдельные префиксы** для не-медиа бинарных данных: выгрузки аккаунтов — `exports/{userId}/…`
   (`exports.md`), документы и чеки — не в бакете, а по ссылкам провайдера
   (`receipts-and-documents.md`); резервные дампы базы — отдельный бакет (`backups.md`).
5. **Медиа привязано к статье** (журнал #28): отдельной библиотеки нет; `MediaAsset`
   используется узлами документа и обложкой; аватар — единственное медиа вне статьи
   (`avatars.md`).
6. **Дедупликация** — по `sha256` в пределах владельца (`03-data-model.md`): повторная загрузка
   того же файла возвращает существующую запись `[ДОПУЩЕНИЕ: без повторного хранения]`.
7. **В хранилище нет ПДн** (ADR-0011 п. 3): только медиа; метаданные и права — в базе;
   EXIF с координатами и устройством вырезается при загрузке (`upload-pipeline.md`).
8. **Публичный доступ** — только к вариантам опубликованных материалов и аватарам через CDN
   или прямой URL; оригиналы и медиа неопубликованных / архивированных материалов — по
   подписанным ссылкам (`access-and-signed-urls.md`).

## 3. Исключения

| Исключение | Условие | Кто может | Аудит |
|---|---|---|---|
| Файл системы (дефолтная обложка, OG-изображение) | лежит в репозитории, не в бакете | разработчик | — |
| Тестовый бакет / MinIO | dev, ci | разработчик | — |
| Ручная правка ключей | миграция раскладки — отдельный план с отчётом | `owner` (эксплуатация) | вне продукта |

## 4. Взаимодействие с другими политиками

- `retention-and-pd.md` — ПДн и сроки главнее; `retention-and-orphans.md` — чистка;
  `access-and-signed-urls.md` — доступ; `03-data-model.md` — поля главнее этой политики при
  расхождении.

## 5. Проверяемость

- Тест: загрузка создаёт запись и объект с ключом по шаблону; ключ не содержит имени файла.
- Проверка целостности (`retention-and-orphans.md`): записи без объектов и объекты без записей —
  ноль после чистки.
- Тест: EXIF-координаты отсутствуют в сохранённом оригинале.

## 6. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Раскладка вариантов; дедупликация без повторного хранения; один прод-бакет.
- Отложено (этап 5): видео, аудио, файлы (`MediaKind` — ADD VALUE, ADR-0008 п. 6).
- Закрыто Г1 (журнал #28): медиа не существует отдельно от статьи.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Хранить ли оригинал изображения бессрочно рядом с вариантами (ADR-0008 п. 5)
  или удалять его после генерации вариантов для экономии? Если хранить — повторная генерация
  вариантов возможна при смене набора ширин; если удалять — набор ширин фиксируется навсегда.
