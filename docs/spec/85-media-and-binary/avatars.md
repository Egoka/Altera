# Политика: Аватары

- **Область**: хранение
- **Статус**: на утверждении
- **ADR**: ADR-0008, ADR-0018 (публичный профиль), ADR-0030; журнал §25.4 (автопроверка имени и
  аватара), §25.2, §26.10; `30-account/reader/profile-edit.md`, `20-public/author.md`,
  `40-admin/review-queue.md` (проверки профилей), `40-admin/ai-processes.md`; `03-data-model.md`
  (`User.avatarAssetId`)
- **Этап**: 1

## 1. Назначение

Единственное медиа вне статьи: изображение профиля пользователя. Как загружается, проверяется,
отображается, заменяется и удаляется. На политику ссылаются `profile-edit.md`, `author.md`
(`AuthorHeader`), карточки материалов (`Byline`), очередь проверок профиля.

## 2. Правила

1. **Один аватар на аккаунт**: `User.avatarAssetId → MediaAsset` (`03-data-model.md`); замена
   создаёт новую запись, прежняя помечается `deletedAt` (`retention-and-orphans.md`);
   аватар необязателен (журнал §25.4) — без него показываются инициалы.
2. **Загрузка** — `uploadAvatar(file)` по `upload-pipeline.md` (форматы и размер те же
   `[ДОПУЩЕНИЕ]`); лицензия и атрибуция для аватара не запрашиваются `[ДОПУЩЕНИЕ: ответственность
   загрузившего по оферте]`, EXIF вырезается.
3. **Обрезка** — квадрат по фокусной точке или центру; варианты — квадратные размеры
   `[ДОПУЩЕНИЕ: 64, 128, 256, 512]` в WebP (`image-variants.md` §3).
4. **Автоматическая проверка** (журнал §25.4): результат `ok` — аватар применяется сразу;
   `needs_review` — уходит рецензенту (`review-queue.md`, вкладка проверок профиля; матрица
   #120), до решения публично показывается прежний аватар или инициалы; `rejected` — не
   применяется, пользователю — причина словами без внутренних признаков (§24.3 по аналогии).
   Критерий «подозрительного» — правила проверки, не эта политика.
5. **Служебные записи** аватара не имеют — публичного профиля у них нет (§25.2); имя сотрудника
   задаётся при создании записи (`admins.md`).
6. **Публичность**: аватар опубликованного автора — публичный вариант через CDN
   (`access-and-signed-urls.md`); у читателя без публикаций страницы нет (`plan-free.md` п. 6),
   аватар виден только ему в кабинете.
7. **Архив аккаунта** (журнал §5): страница профиля — 410 `ARCHIVED` (§28.2), аватар публично не
   отдаётся; при восстановлении — снова публичен. **Удаление навсегда** — файл и запись
   удаляются (`permanent-delete.md`).
8. **Удаление аватара** пользователем — `removeAvatar` (`profile-edit.md`), запись помечается
   `deletedAt`, файл чистится по `retention-and-orphans.md`.
9. **Претензии** к аватару (чужое изображение) — сценарий жалоб, отложено.

## 3. Исключения

| Исключение | Условие | Кто может | Аудит |
|---|---|---|---|
| Замена или удаление аватара сотрудником | по итогам дополнительной проверки (`rejected`) или претензии (отложено) | `moderator`, `owner` (#120) | `profile.check` (#85) |
| Инициалы вместо аватара | аватара нет или он на проверке | система | — |

## 4. Взаимодействие с другими политиками

- `upload-pipeline.md`, `image-variants.md` — обработка; `access-and-signed-urls.md` — доступ;
  `retention-and-orphans.md` — чистка прежних; `50-access/roles/*` — служебные без профиля;
  `20-public/author.md` — показ.

## 5. Проверяемость

- Тест: загрузка аватара → квадратные варианты; `needs_review` → публично прежний; `rejected` →
  не применён, причина без признаков.
- Тест: архив аккаунта → аватар недоступен публично; восстановление → доступен.
- Тест: служебная запись — `uploadAvatar` отвечает `FORBIDDEN`.

## 6. Открытые вопросы и допущения

- `[ДОПУЩЕНИЕ]` Размеры вариантов; без лицензии и атрибуции; лимиты как у медиа статьи.
- Отложено: претензии к аватару — жалобы; критерий подозрительного — правила проверки AI.
- Закрыто Г6 (§25.2, §25.4): служебные записи без профиля; автопроверка с дополнительной проверкой.
- `[ВОПРОС ВЛАДЕЛЬЦУ]` Должен ли аватар при `needs_review` быть виден самому пользователю в
  кабинете (как «на проверке») или тоже скрыт до решения? Если виден — состояние в
  `profile-edit.md`; если скрыт — только уведомление о проверке.
