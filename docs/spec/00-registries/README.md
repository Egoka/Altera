# Реестры

Реестр — таблица всего, что должно существовать в своём контуре. Он утверждается владельцем
построчно **до** написания спецификаций; после утверждения каждая строка обязана получить файл.
Реестр — единственный способ ответить на вопрос «всё ли спроектировано».

## Правило полноты

1. Каждая строка со статусом выше «черновик» имеет существующий файл в колонке «Файл».
2. Каждый файл в папке контура упомянут ровно в одном реестре (страница — в `pages.md`, её
   маршруты — дополнительно в `routes.md`).
3. Пустая ячейка «Файл» или несуществующий путь — недоделка; заход, которому поручена строка,
   перечисляет её в отчёте с причиной.
4. Строка удаляется только с пометкой «отменено: причина, дата» — не стирается.

Проверка выполняется скриптом в отчёте каждого захода: извлечь пути из колонки «Файл», проверить
существование; перечислить файлы папок `10-`…`90-`, не встречающиеся ни в одном реестре.

## Статусы строки

`черновик` (предложено заходом) → `на утверждении` (заход закончен) → `утверждён` (владелец) →
`отменено`. Файл спецификации наследует статус строки.

## Колонки реестров

### `routes.md` — маршруты

| # | Маршрут (ru / en) | Тип | Роли с доступом | Состояния | SEO | Файл спецификации | Этап | Статус |

- Тип: `public` / `account` / `admin` / `infra` / `dev`.
- Состояния: какие из обязательных состояний страницы применимы (загрузка / пусто / ошибка /
  нет доступа / не найдено / ограничение плана / заблокирован / paywall-зарезервировано).
- SEO: `index` / `noindex`, canonical, hreflang.

### `pages.md` — страницы

| # | Страница | Маршрут(ы) | Аудитория | Главное действие | Данные (запросы / мутации) | Зоны экрана (число) | Мобильный (обычный / особый) | Файл | Статус |

### `admin-sections.md` — разделы админки

| # | Раздел | Маршрут | Минимальная роль | Read-only для analyst (да / нет / недоступен) | Сущности | Массовые операции | Опасные операции | Аудит (коды action) | Файл | Этап | Статус |

### `access-matrix.md` — роль × действие × данные

Одна строка на действие.

| # | Действие (код) | Данные / сущность | Гость | Reader | Author | Editor | Moderator | Analyst | Admin | Owner | Где проверяется (хелпер / резолвер) | Аудит | Ошибка (код) | Файл политики |

Обозначения в ячейках ролей: `✓` — может; `свои` — только над своими объектами; `—` — не может;
`(В?)` — зависит от ответа владельца, вопрос назван.

### `events-and-logs.md` — события, логи, ошибки

| # | Код события | Тип (log / audit / metric / error) | Уровень | Источник (api / web / worker) | Кто инициирует | Поля (без ПДн) | Ретенция | Где смотреть | Файл |

### `plans.md` — планы подписки

| # | План | Цена (гипотеза) | Интервал | Роль при активной подписке | Грейд автора | Возможности | Буст | Лимиты | Что при истечении | Файл |

### `flows.md` — пользовательские маршруты

| # | Flow | Роль на входе | Роль на выходе | Точка входа | Экраны (ссылки на `pages.md`) | Развилки | Ошибки | Файл | Статус |

### `roles.md` — роли

| # | Роль (`enum`) | Как получается | Как теряется | Разделы админки | Файл | Статус |

## Порядок утверждения

Реестры пишутся одним заходом (см. `docs/prompts/fable-spec-01-registries.md`), все строки в
статусе «на утверждении». Владелец вычёркивает, добавляет и переименовывает строки, после чего
переводит их в «утверждён». Заходы 2–9 работают только с утверждёнными строками; новая строка,
возникшая по ходу захода, добавляется в статусе «черновик» и попадает в отчёт.
