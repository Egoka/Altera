# Task 5 — metadata-only discovery без запуска Claude

**Статус: design, не реализация и не разрешение.** Изучены task-5-brief, официальные Multica docs и help bundled CLI v0.4.43. Внешних изменений, probes, запусков моделей, shell/MCP дочерних процессов и чтения credentials здесь не было.

**Рекомендация:** допустимая к подготовке materially safer альтернатива — отдельный диагностический executable с нулевой способностью исполнять модель/команды, затем проверка регистрации **до** изменения reviewer. Документы не позволяют утверждать, что только `--version`/`--help` обеспечат регистрацию: discovery handshake Claude custom profile не опубликован. Поэтому это gated experiment, а не гарантированно рабочий путь. Непризнанный профиль — конкретный blocker; включение настоящего host-Claude для обхода запрещено.

## Что установлено по источникам

- [Daemon and runtimes](https://multica.ai/docs/daemon-runtimes): custom profile выбирает существующее protocol family и executable; компьютер регистрирует профиль, если разрешает executable. Есть локальный absolute-path override. Аргументы Multica идут после аргументов профиля; command field не выполняет shell-синтаксис. Установку и login профиль не обеспечивает. Документ требует совместимость протокола, но не даёт Claude registration handshake или dry-run launch API.
- [Install AI coding tools](https://multica.ai/docs/install-agent-runtime): Claude требует версию не ниже 2.0.0, слишком старый runtime не регистрируется. Custom profiles синхронизируются после запуска daemon. Проверка `--version` рекомендована, но не названа достаточным условием custom-profile регистрации. Уже работающий desktop daemon не надо перезапускать ради первого эксперимента.
- [Providers](https://multica.ai/docs/providers): model catalog приходит из runtime, MCP managed, Claude skills — `.claude/skills/`. Подмена профиля может упереться в валидацию сохранённого model/effort. Не очищать эти поля и не объявлять диагностический executable авторизованным Claude ради прохождения проверки.
- [Runs](https://multica.ai/docs/tasks): назначение запускает run; изменение assignee не останавливает начатый run. Transient failures могут породить retry, обычные process/config errors не перечислены как automatic-retry причины. Завершение run не означает приёмку задачи. Документы не уточняют, закрепляет ли retry прежний runtime при последующем изменении agent binding.
- [Project resources](https://multica.ai/docs/project-resources): daemon до child launch может писать служебные инструкции/skills/resources в `in_place`. Поэтому даже безопасный executable не даёт обещания «native run вообще не пишет в checkout»; граница здесь — отсутствие модели и произвольных исполняемых действий. Это должно быть явно названо в concrete reviewable action.

Проверенный help CLI: `runtime profile create` (command-name/protocol-family/display-name), `set-path`, `profile list/delete`; `runtime list`; `agent update --runtime-id`; `agent tasks`; `issue assign --no-start / --unassign / --to-id`; `issue runs`; `issue cancel-task <run-id>`. `agent update` не имеет revision/If-Match/CAS. `issue runs --active` перечисляет queued/dispatched/running/waiting_local_directory, но не deferred; для preflight нужна полная история и agent tasks. Скрытый `daemon probe-runtimes` существует, однако help не обещает фильтра только diagnostic profile: не использовать общий probe, способный вызвать другие runtime executables.

## Контракт executable D0

Рекомендуется один небольшой бинарник без интерпретатора либо скрипт с явным доверенным interpreter и отключённой загрузкой пользовательских/site startup modules. Не использовать shell wrapper, `/usr/bin/env` PATH lookup или fallback executable. Хэш самого executable/interpreter фиксируется до регистрации и повторно до trigger.

- Ровно `--version` или ровно `--help`: статический ответ с явным именем `altera-metadata-probe`, без filesystem/env/stdin чтения. Не запускать реальную CLI для получения версии. Версия — собственная версия probe; не выдавать её за установленный Claude. Если parser требует Claude brand/version deception или дополнительные действия, регистрация blocked.
- Любой другой argv: не читать stdin/prompt, не подключаться к API/network, не импортировать tool SDK, не вызывать spawn/exec/system, не открывать config/auth files и не запускать MCP. Сразу сформировать очищенный manifest и завершиться с заранее фиксированным ненулевым кодом, например 78 (диагностический выбор; это не документированный специальный Multica код).
- Manifest: schema version, probe hash, current cwd, argc, **только известные имена флагов** и порядок, наличие/тип значений. Значения `--flag=value` разделять до журналирования. Любые positional, prompt, JSON/settings/MCP inline values, URL, неизвестные flags/values — `redacted`, без содержимого и хэшей секретных строк.
- Пути разрешены только для заранее перечисленных path-bearing flags: принимать лишь абсолютный путь в известных task roots либо текущем checkout, без control characters; выводить нормализованный путь и позицию argv, не читать target и не следовать symlink. Значение inline JSON, URL или неизвестного формата — redacted + `unresolved_path_input`. Точные неизвестные флаги нельзя определить эвристикой «строка похожа на путь»; неполный manifest честно остаётся неполным.
- Env values не читать/не выводить, включая token и даже полный HOME. Можно сообщить только presence для фиксированных ключей без значений. Если существенный managed path передаётся только env и его получение не разрешено scope, отметить `env_path_unresolved`; не расширять discovery молча.
- Выводить одну ограниченную по размеру запись с маркером `ALTERA_METADATA_ONLY_V1` в stderr; stdout пуст. Это намеренно не успешный Claude stream-json. Не имитировать completion, tool calls или auth/model capabilities. Если daemon не сохраняет stderr, discovery blocked; не писать полный argv в запасной лог. Добавление фиксированного защищённого metadata sink — отдельная явная поправка дизайна, не скрытый fallback.

D0 не нуждается в login. Его безопасный сбой может дать требуемый native argv даже без execution handshake. Регистрация профиля и запуск task — два разных gate; успешный `--version` локально не доказывает ни один из них.

## Протокол контроллера

1. **Локальная приёмка D0.** Синтетические argv/env/stdin с secret-canaries и командами, включая inline MCP JSON, `--x=SECRET`, newline, symlinks и неизвестные флаги. Проверить отсутствие canaries в обоих потоках, отсутствие дочерних процессов/network/file opens вне executable runtime, немедленный фиксированный exit при незакрытом stdin. Source/fixture hashes неизменны. Зафиксировать manifest schema и executable SHA. Все сценарии выполняются без модели.
2. **Регистрация без agent binding.** Создать уникальный private custom profile семейства Claude и pin абсолютного D0 path; исходные builtin runtime пути не менять. Проверить readback profile ID/command и отдельный runtime ID на том же daemon, `profile_id` точный, online, provider Claude. Регистрационные вызовы D0 безопасны при любом argv. Если discovery требует неподдержанный handshake, model catalog, sign-in либо не создаёт runtime — остановиться до reviewer update, сохранить очищенную причину. Никакого общего probe/restart или перехода к host-Claude ради успеха.
3. **Quiescence и baseline.** Проверить reviewer `db94a617-807c-4eec-981f-51fd4b3217d4` idle; полные agent tasks и ALTE-11 history без active/deferred/queued/retry. Все автопилоты paused. Зафиксировать current runtime `fd14b334-b79c-47ae-aad9-a98340bbb7d4`, model `claude-opus-4-6`, medium, остальную nonsensitive конфигурацию и fingerprints; snapshot родителя не заменяет fresh read. ALTE-11 должна оставаться единственной диагностической issue, без активных mentions и иных triggers.
4. **Временная привязка.** Снова сравнить baseline, изменить **только** runtime-id, немедленно readback. Сохранённые model/effort/роль/skills/MCP/permissions должны совпасть. CLI даёт optimistic read→update→read, **не atomic CAS**. Единственный controller и paused автоматика уменьшают гонку, но не дают server lock. Если настоящий CAS обязателен либо другой пользователь/контроллер может параллельно перепривязать агента, этот маршрут blocked до verified conditional API; не называть его CAS.
5. **Один native trigger.** Только после подтверждённого D0 binding и profile path/hash разрешён один trigger ALTE-11. У `issue assign` нет per-run runtime pin, поэтому непосредственно перед вызовом повторно прочитать binding. Это новый materially different action с D0, не повтор отклонённого назначения на host-Claude. Если reviewer неожиданно перепривязан, не запускать. Никаких rerun/comment mention/chat в качестве обхода.
6. **Собрать результат и закрыть хвосты.** Manifest должен связаться с конкретным native run и runtime/profile. Ожидаемый outcome — terminal failed из-за намеренного diagnostic exit, а не «модель ответила». Сохранить только очищенный stderr. Проверить полные runs на auto retry/deferred и native outcome. Обнаруженный лишний запуск диагностического executable безопасно заканчивается, но нарушает criterion «ровно один»; отменить именно этот run по полному ID и зафиксировать дефект, не вручную перезапускать.
7. **Restore только после дренирования.** Убрать диагностическое назначение ALTE-11 через `--unassign --no-start` с readback; это само по себе не отмена run. По полным issue/agent runs убедиться в terminal status и отсутствии retry/deferred. Сравнить текущую конфигурацию с ожидаемой временной, восстановить только runtime-id, повторно readback всех сохраняемых полей. Если состояние разошлось, не затирать чужие изменения и не возвращать host runtime при pending work. Оставить безопасный D0 binding как recovery blocker с точным журналом.
8. После успешного восстановления убрать только созданный diagnostic profile/path/runtime при отсутствии bindings; readback отсутствия профиля и runtime. Не использовать cascade. ALTE-11 оставить unassigned Backlog; комментарии/Done не нужны для discovery.

## Acceptance и точные blockers

| Проверка | Проход | Иначе |
| --- | --- | --- |
| D0 local | Никаких model/child/network/config reads, секретов в output; фиксированный bounded exit | Исправить локально, без регистрации |
| Registration | Отдельный online runtime с точным D0 profile/path, без настоящего Claude | `diagnostic_profile_not_registered`; сохранить только безопасную причину |
| Model preservation | Runtime switch сохраняет `claude-opus-4-6`/medium и остальные поля | `diagnostic_profile_model_validation`; не менять модель |
| Routing | One native run связан именно с D0, manifest получен | `diagnostic_routing_unproven` или `manifest_capture_unavailable` |
| Completeness | Path-bearing argv доказаны по manifest, неизвестные inputs явно перечислены | `managed_paths_unresolved`; не угадывать MCP/auth paths |
| Restore | Нет pending/deferred/retry; baseline runtime/model/roles readback совпадают; ALTE-11 unassigned | `restore_precondition_conflict`; safe binding остаётся до разбирательства |

**Главный предел:** в разрешённом read-only исследовании удалось установить отсутствие документированного Claude custom-profile handshake и отсутствие CLI CAS. Нельзя утверждать, что D0 обязательно признается runtime. Можно локально подготовить и проверить D0, затем провести регистрацию без binding как минимальный следующий проверяемый шаг. При любых препятствиях продолжать независимую container-wrapper работу; actual Claude managed argv остаётся blocked. Этот эксперимент не доказывает авторизацию модели, протокольную совместимость рабочего wrapper, наличие trace или filesystem isolation.
