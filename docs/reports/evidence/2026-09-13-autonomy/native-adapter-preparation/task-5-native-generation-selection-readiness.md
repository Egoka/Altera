# Native Claude generation selection — dispatch readiness

Prepared against accepted commit `6e197f8f42660da0fe7fd7c21c545f02ed156651`. This is a bounded API/brief clarification after the successful live publication, not a new source review. The next implementation should use its root-assigned cumulative base and newly pinned module identities, rather than reverting other accepted work to this historical commit.

**Conclusion:** existing selection is usable for a one-invocation adapter, but the brief must explicitly distinguish a short exclusive selection lock from the lifetime of an open credential descriptor. It must also use separate adapter/store/runtime manifest layers. Existing `runtime.launch()` cannot supply the full process/quiescence completion proof currently described in the adapter brief.

## Existing selection API and exact lifetime

| Symbol at the accepted revision | Actual contract |
| --- | --- |
| `credential_refresh.Store.__init__`, lines 90–117 | Requires exactly nine refresh-manifest fields: `schema_version`, `store`, `policy`, `policy_sha256`, `run_root`, `image`, `network`, `check_id`, `attempt_id`. Requires schema 1, fixed refresh image, `provider-proxy`, valid check/attempt IDs. Opens/validates store and generation directory metadata. It can create a missing store/generations directory; it is not a read-only existence probe. Construction alone does not attest the referenced refresh policy contents or execute refresh. |
| `Store.locked`, lines 136–161 | Opens `refresh.lock`, takes blocking `fcntl.flock(..., LOCK_EX)`, rechecks held/named store, lock and generation-root identity/metadata, and holds that exclusive lock through its own `yield`. It releases the lock and closes the lock fd on exit. There is no timeout/nonblocking acquisition parameter. |
| `Store.current`, lines 206–210 | Reads and validates the non-secret `current.json` pointer and returns a 32-character generation ID. It does not acquire a lock itself. |
| `Store.credential`, lines 228–234; `generation`, lines 212–226; `file`, lines 123–133 | Opens the selected generation and `.credentials.json` with no-follow/metadata validation, returning a namespace with `path` and an open `fd`. No credential content read or hash is needed. The caller owns the returned credential fd unless using `select_current`. |
| `Store.select_current`, lines 237–243 | Enters `locked`, reads current, opens the credential, then **exits `locked` before yielding** the selected namespace. The context retains only the credential fd until its finalizer closes it. It does not exclude refresh during the subsequent model/native run. |
| CLI `select`, lines 499–507 | Uses that context, constructs `{status: selected, auth_file: PATH}`, exits the context, closes the store, then prints the result. Neither the lock nor the selected fd survives into a later adapter process. A printed path is not a lease. |

Current `runtime-isolation.md` says selection occurs under the same exclusive lock and published generations are neither replaced nor removed by the cooperative store. That is consistent with the code when understood as an atomic selection, not a whole-run lock. “Shared lock” means the shared locking mechanism/file used by refresh and selection; the actual lock mode is `LOCK_EX`, not `LOCK_SH`.

The selected fd pins an opened inode for the host, but `runtime.command()` receives and mounts a pathname; it does not accept that fd or use it as Docker mount authority. Cooperative generation retention is therefore part of this contract. No claim of protection against a hostile process of the same host UID follows from keeping the fd open. Local retention also does not establish that an old provider credential remains valid after later rotation.

## Minimal prepare/adapter call contract

Recommended root ruling for this one-invocation milestone: **select current at actual launch using the existing short-lock API; retain the selected fd through the synchronous launch; do not refresh from the adapter.** Keep refresh as an externally controlled operation. If the one-use canary must exclude concurrent refresh, state that as a controller operating constraint, rather than claiming existing `select_current` enforces it for the entire run.

1. Prepare a private, hash-pinned **adapter envelope**. It contains the already planned trusted invocation/actor/workspace, probe/module/source/policy/image identities and claim/completion destinations, plus an explicit selection policy such as “current at launch.” It references a private pinned **store-selection manifest** with the existing nine-field refresh schema and an existing store. These names describe proposed adapter fields, not an already implemented schema.
2. Validate the store reference exists and has the required trusted metadata before constructing `Store`; fail preparation rather than silently provision a new empty store. No bootstrap, refresh, credential copy, credential digest or original-login fallback belongs in this prepare operation. A metadata-only preflight selection may be performed and closed, but must not be described as reserving that generation for the later native invocation.
3. Keep the **runtime manifest** as a separate object containing only the fields accepted by `runtime.command()`. Put no adapter IDs, store manifest, claim path or completion fields directly into it. Do not freeze an authoritative `auth_file` during preparation if the declared policy is “current at launch.” The adapter supplies exactly one selected `auth_file` in memory after selection, just as the brief already proposes an in-memory verified D1 `path_map`.
4. At actual invocation, validate envelope/hash, fixed artifacts, one-use claim and native/D1 inputs under the existing brief rules. Then construct `Store` from the validated selection manifest, call `with store.select_current() as selected`, set `auth_file` to `str(selected.path)` in a local runtime-manifest copy, and synchronously call `runtime.launch(runtime_manifest, incoming)` inside that context. Always close `Store` in a `finally` after the context. Do not nest `select_current()` inside `Store.locked()`; that would acquire another exclusive flock on a separate open lock fd and can deadlock.
5. Refuse failure to select or validate the current generation. Do not scan generations, use a pending generation, silently choose the retained old generation, read the original login, parse credentials on the host, or exchange a token to repair admission. The accepted refresh coordinator is the separate owner of those transitions.
6. Record selection provenance only in trusted private evidence: selection mechanism and, if root requires it, the non-secret generation ID derived from the selected path. Do not put credential path/content/hash into model protocol output. The adapter's selected path is an input to the existing single-file RO mount, not authority to mount a home/store directory.

This preserves current selection semantics. It does not turn the open fd into a full-run refresh lock or a verified worker-quiescence lease.

## Manifest and completion claims to correct before dispatch

`runtime.command`, lines 363–369, requires exactly the existing runtime fields with only `network`, `fixture`, `auth_file`, and `operation` optional. It has no native actor, invocation, store, claim or completion-record API. The new adapter envelope must validate its own schema and construct the accepted runtime input explicitly; handing the envelope wholesale to `runtime.launch` would fail validation.

`runtime.execute`, lines 506–515, forwards stdin/stdout/stderr directly and waits for the Docker client. It normalizes a negative subprocess return code to `128 + signal`; it returns only one integer. That loses the distinction between a signal and a normal exit with the same numeric status.

`runtime.launch`, lines 518–537, returns that status unless a post-run source/policy check returns 78. Therefore its result does **not** expose the raw Docker-client exit, raw signal, whether 78 originated from the child or a freshness refusal, child PID/container identity, or a structured lifecycle record. It does not capture stdout/stderr or independently validate the semantics/completeness of arbitrary model-written evidence. The existing return cannot truthfully fill all of the brief's “actual exit/signal” completion fields.

The generic launch uses `docker run --rm` without a durable exact worker name (`sandbox_arguments`, lines 236–240). `provider_network`, lines 466–503, records network/proxy inspection artifacts and attempts cleanup, but returns no verified absence result. The refresh coordinator's stronger named-worker quiescence API is specific to refresh; it is not an ordinary `runtime.launch` API. A returned runtime status or a model-written file is not proof that the ordinary worker and its descendants no longer have write authority.

Minimum truthful record with the interface as it stands: trusted invocation/input identities, wrapper timestamps, returned **runtime status**, exception/refusal classification if captured by the adapter, and an inventory explicitly labeled as observed/untrusted evidence. Set unavailable raw process/signal/quiescence facts to unknown; do not call this a complete accepted process receipt. Exact native run/issue attribution still requires the already planned external binding/readback.

If root keeps full process/quiescence proof as a requirement of this adapter milestone, explicitly add the already planned small runtime lifecycle observer/container-drain extension to owned scope. It must expose actual process outcome separately from runtime freshness refusal and provide durable exact worker identity plus quiescence evidence. Do not invent that API in the adapter implementation, infer it from successful protocol output, or redesign the collector/gate here.

## Root decisions and narrow owned scope

- **Selection policy:** adopt current-at-launch and generation retention as above, or explicitly require a prepared-generation identity and fail if current changes. Do not silently mix those two policies. Current-at-launch is the smallest useful integration after publication.
- **Refresh overlap:** retain the existing short selection lock. For a controlled one-use canary, root can keep refresh operations out of that invocation window. A requirement for whole-run serialization needs an explicit API/operational contract; wrapping the current context does not provide it, and holding a lock only until Docker-client exit is not quiescence proof after abrupt termination.
- **Lock wait:** existing acquisition can block indefinitely. Root must either document that existing behavior for the controlled milestone or specify a bounded admission wait and add the minimal lock-acquisition change to owned scope. The D1 five-second timeout does not bound `Store.locked()`.
- **Completion scope:** either limit this milestone to the truthful runtime-result record and keep process-proof acceptance pending, or include the minimal lifecycle observer/drain extension before promising accepted completion. This is a concrete interface decision, not a new scheduler or general collector rewrite.
- **Files:** use the already proposed `prepare_native_claude.py`, `native_claude_adapter.py`, `test_native_claude_adapter.py` and `runtime-isolation.md`. No change to `credential_refresh.py` is needed for short-lock current-at-launch selection. Add that file only for an explicitly ruled lock API requirement. Add `runtime.py` and its focused tests only if the lifecycle/completion requirement is retained for this dispatch; the current brief permits only a parsing helper there and must be amended before broader runtime edits.

Suggested future focused checks for the writer's scope, not executed here: preparation followed by a changed pointer selects the new current at launch; selection metadata failure refuses before model launch; the selected fd closes on success/refusal; refresh can take the lock after selection under the existing contract; CLI path output is not treated as a held lease; adapter metadata is stripped from the runtime manifest; unsupported completion fields remain unknown unless the separately scoped observer supplies them. Use synthetic stores and a fake synchronous runtime for these contract checks. Existing live refresh need not be repeated to test them.
