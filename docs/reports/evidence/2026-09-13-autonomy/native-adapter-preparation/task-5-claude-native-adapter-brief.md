## Smallest concrete design

Use the existing runtime manifest/snapshot/policy boundary, prepared by the trusted coordinator before the native invocation. The RO MCP policy is already deterministic: context7 at its exact observed public HTTP endpoint and trace /usr/local/bin/trace-mcp with [serve], no headers/env. The native adapter does not copy or hash raw daemon config. It runs the accepted pinned D1 executable on the actual native argv, consumes only its bounded descriptor and requires the exact expected two-server roster, build/source IDs, no unknown/unreviewed fields and expected78. It then creates the one live `path_map` entry in memory pointing at that prebuilt RO policy. D1 validates the actual file again in this invocation; yesterday's descriptor never grants permission.

Adapter invocation is fixed coordinator manifest path + SHA256, delimiter `--`, then native argv. To avoid assuming unverified CLI fixed-argument parsing, the coordinator may generate a private executable bootstrap whose only action is a fixed `/usr/bin/python3 -I ABS_ADAPTER ABS_MANIFEST SHA -- "$@"`; every fixed path is safely quoted and pinned in preparation evidence. There is no eval, PATH search or shell interpretation of native values. Profile command is the bootstrap's exact absolute executable path. No bootstrap/native profile is installed by the implementer.

The manifest references existing private source snapshot, RO policy, fresh run root, one RO Claude credential, pinned image and exact accepted runtime/probe artifacts. It also declares workspace/agent IDs and one coordinator invocation ID. Validate private owner/modes/non-symlink roots/files and manifest hash before using paths. Refuse extra schema fields, arbitrary CLI operation, fixture mode, mismatched model/effort, altered module/probe/policy/image identities, wrong cwd, stale source/snapshot, reused claim and nonempty evidence. Environment presence CODEX_HOME/CLAUDE_CONFIG_DIR must be absent, as in the observed D0 reviewer invocation; newly present unmapped values refuse without printing them. Never read MULTICA_TOKEN or forward it; read only declared non-secret integration IDs and strip other inherited env before children.

Static truthful --help/--version probes return without reading a manifest/config or consuming the claim. For a real launch, claim one invocation atomically in a coordinator-only sibling path outside all container RW mounts. The claim remains consumed on any outcome, including refusal after claim; same-check recovery needs a new trusted authorization with preserved failure history, never blind daemon retry. Native protocol argv retain exact opaque scalar values; use a finite arity parser so prompt/disallowedTools values cannot become option authority. Unknown/duplicate options fail. No arbitrary native --settings or inline MCP config.

Run pinned D1 with sanitized environment, no stdin, bounded stderr capture8192 bytes and fixed timeout5s. Check binary identity before and after and document the same-UID host trust limitation. Do not broaden D1 itself. On accepted descriptor and identities, use existing runtime.launch with in-memory verified path_map, existing source/snapshot/policy/image and unchanged Claude Opus4.6/medium. Preserve stdout/stdin protocol, stderr separation, signals and exit codes. The container remains the only location where model/shell/MCP execute.

## Trusted completion record

Bind invocation/native task ID/agent/workspace, source full SHA/dirty fingerprint, snapshot, policy/runtime/probe/image IDs, start/end, exit/signal, and newly produced evidence inventory. Values come from trusted inputs/actual outcome, never model-supplied actor/path fields. Missing/stale/mutated source/policy or malformed/missing required evidence prevents process-proof acceptance. Native task ID may be captured from the daemon's own non-secret environment, but issue/run attribution still requires external root readback before gate record/finish. No automatic task_done or gate mutation in this bounded adapter.

The model has neither gate write paths nor Multica API authority. Its returned text/evidence remains untrusted content for independent assessment. Successful native exit and a completion record are not task acceptance. Trusted external collector/gate orchestration must still be wired and tested before full autonomy is declared.
