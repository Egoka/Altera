## Limits and remaining acceptance

- Same-UID host writer compromise is out of scope. Descriptor-relative O_NOFOLLOW and inode/mode/time checks reject tested replacement/truncation; they are not a lock or protection against every malicious same-UID timing/metadata restoration. Coordinator must serialize and trust daemon producer. Root-dir concurrent mutation may safely refuse a run.
- Synthetic modes, hardlinks, root/directory/file symlinks, FIFO/socket and process UID mismatch are tested. This unprivileged harness cannot manufacture a file owned by another UID or a device node. File-owner and special-kind branches are present; do not claim those privileged fixtures executed. No sudo or ownership changes were attempted.
- D1 exact candidate match is diagnostic, not permission to execute a matched npx/@latest/host trace command, transfer credentials, bind roles or accept auth/MCP. Unknown values remain unresolved. Candidate strings were supplied by root; actual managed semantics require root-controlled native discovery later.
- D1 deliberately reads the bounded live JSON into memory, which may contain opaque secret fields; it never logs their values/hashes or accesses auth/cache/Keychain. Raw token buffers are wiped before return, core dumps disabled. Stdlib loader environment and binary pinning must be trusted by the coordinator.
- Only one minor runtime-isolation.md correction is included: guard edits require fresh RO policy hash/runtime evidence, not a Docker image rebuild when image contents are unchanged. The earlier fix report's contrary instruction is superseded by this correction; historical text remains intact.
- No original D0, runtime/guard, source/product/gate/auth logic, profile, binding or native state changed. No model or MCP was launched. M4/M7 and full Task5/native acceptance remain open.
