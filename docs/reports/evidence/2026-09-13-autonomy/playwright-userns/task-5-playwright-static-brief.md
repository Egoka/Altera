## Build and static command contract

The build may use network only in the separately authorized image-build step.
First perform `npm ci --omit=dev --ignore-scripts` from the isolated lock. Then,
before the final `USER 1000:1000`, invoke
`/usr/local/bin/node /opt/playwright-mcp/node_modules/playwright-core/cli.js install-deps chromium`
and invoke that same absolute CLI with
`install chromium --only-shell` and
`PLAYWRIGHT_BROWSERS_PATH=/ms-playwright`. This selects the headless shell that
Playwright documents for headless use without a channel. Do not invoke `npx`,
`latest`, a shell-resolved package binary, or a host cache. Run the browser
installer once; retain its bounded build log, the resolved `browsers.json`
descriptor and hashes in trusted build evidence.

At runtime mount `/opt/playwright-mcp` and `/ms-playwright` from the immutable
image/rootfs and execute exactly:

```text
/usr/local/bin/node
/opt/playwright-mcp/node_modules/@playwright/mcp/cli.js
--headless
--isolated
--block-service-workers
--allowed-origins=http://altera-web:3000
--codegen=none
--image-responses=omit
--output-dir=/runtime/evidence/playwright
--output-max-size=16777216
```

The TOML command is `/usr/local/bin/node`; the remaining lines are the exact args
in order. Do not add `--browser`: the documented CLI values select branded or
alternate channels, while this closure uses the Playwright-versioned default
Chromium artifact. Do not add `--no-sandbox`, `--allow-unrestricted-file-access`,
`--config`, `--secrets`, `--storage-state`, `--user-data-dir`, `--init-page`,
`--init-script`, `--cdp-endpoint`, `--extension`, proxy flags, extra `--caps`,
or environment-derived MCP options. Reject any such native field or override.

Pass only fixed environment needed by the image:

```text
PLAYWRIGHT_BROWSERS_PATH=/ms-playwright
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1
PLAYWRIGHT_SKIP_BROWSER_GC=1
npm_config_offline=true
HOME=/runtime/cache/playwright-home
```

The fixed browser path and disabled GC select the image-owned browser; the skip
and offline settings, immutable mounts and no-egress boundary prevent package or
browser acquisition at task time. `--isolated` and a fresh private HOME prevent
profile reuse; evidence and cache remain distinct RW mounts. Keep source, policy,
`/opt/playwright-mcp`, `/ms-playwright`, and rootfs read-only. The MCP
`--output-dir` is an organization/cap control, not a filesystem boundary; OS
mount permissions must make source writes fail even if a tool accepts an
explicit filename.

Do not weaken the current nonroot, `cap-drop=ALL`, `no-new-privileges` contract
to make Chromium start. The pre-build sandbox ruling below must be resolved
before treating the default-seccomp canary as viable; `--no-sandbox`, root,
broad capabilities and unconfined seccomp are not fallbacks.

as Docker's default profile plus user-namespace cloning permissions and shows
one unconditional `SCMP_ACT_ALLOW` rule for exactly `clone`, `setns`, and
`unshare`. The current documented file is byte-identical to the immutable file
whose last modifying commit is Microsoft's verified commit
`ae935a43d9e376e4759548f6b3c6905c7b282333`:

With no `CAP_SYS_ADMIN`, that Moby profile has these relevant rules:

| Syscall | Default-policy result under `cap-drop=ALL` |
|---|---|
| `clone` | allowed only when `(flags & 0x7e020000) == 0`; the mask covers `CLONE_NEWNS`, `CLONE_NEWCGROUP`, `CLONE_NEWUTS`, `CLONE_NEWIPC`, `CLONE_NEWUSER`, `CLONE_NEWPID`, and `CLONE_NEWNET` |
| `unshare` | no non-`CAP_SYS_ADMIN` allow rule, so default `SCMP_ACT_ERRNO` |
| `setns` | no non-`CAP_SYS_ADMIN` allow rule, so default `SCMP_ACT_ERRNO` |
| `clone3` | explicit `SCMP_ACT_ERRNO` with errno 38 (`ENOSYS`) for non-`CAP_SYS_ADMIN`, preserving caller fallback to `clone` |

The static analysis predicted that the accepted default combination would block
the user-namespace prerequisite Microsoft documents. Root's later bounded
control proved that prediction for the saved `unshare` probe on the accepted
image and runtime: built-in seccomp returned child status 1 with
`Operation not permitted`, while the candidate profile returned child status 0.
This is not a Chromium launch result. Even after seccomp allows the calls, the
Linux VM kernel, unprivileged-userns sysctls, LSM policy, UID mapping, Chromium
build, and `no-new-privileges` behavior can still prevent launch. The allow rule
grants no Linux capability; ordinary kernel authorization continues to apply.

### Narrow policy candidate

The prepared candidate is a full custom profile derived from the verified Docker
29.4.3 default bytes with only this Microsoft-authored rule inserted before the
existing syscall rules:

```json
{
  "comment": "Allow create user namespaces",
  "names": ["clone", "setns", "unshare"],
  "action": "SCMP_ACT_ALLOW",
  "args": [],
  "includes": {},
  "excludes": {}
}
```

Docker accepts a complete seccomp JSON, not an additive fragment. The saved
`task-5-playwright-seccomp-candidate-proof.json` proves semantic equality with
the pinned current default for every other top-level value and rule, plus
exactly this one inserted rule. The candidate SHA-256 is
`ff9cc602bfbd54007f4894c121d9f3013e4e7a2a9b9b7a7d3fcd7c2f0f3b7140`;
implementation must pin that exact hash and fail closed on any other bytes. The
candidate retains the `clone3 -> ENOSYS` fallback rule, default errno,
architecture map, AF_ALG/socket rules and all other current restrictions. The
`docker run --security-opt seccomp=<ABSOLUTE_COORDINATOR_HOST_PATH>` value is a
host-side path consumed by the Docker CLI/daemon before container start; it is
not a path inside the container and must not use `/runtime/policy/...` unless
that happens to be the verified host path. The coordinator stages this regular
file at a private absolute host path outside every source, cache, evidence, and
model-writable mount; rejects symlinks, wrong owner/mode, or changed descriptor
identity; and hashes the held file before invocation and again after container
removal. The run record binds both the validated host-path identity and those
matching hashes. The policy is never mounted into the model container. Apply it
only to the tester that declares Playwright. Keep `cap-drop=ALL`, nonroot,
`no-new-privileges`, read-only rootfs and all network/mount limits.

This three-name rule is the smallest compatibility change Microsoft documents,
but its empty `args` allow each syscall regardless of flags; it is broader than
a proven Chromium syscall trace. Do not invent narrower argument filters:
Chromium's exact `clone`/`unshare`/`setns` sequence has not been observed for the
pinned alpha browser.

Root's saved `task-5-playwright-userns-proof.json` compared the same accepted
image
`sha256:0baed89d66accc9338e938d6c0a81924014836561890d12005063b0b7bdb409a`

The static pre-build verifier must fail unless the base hash is
`536529b665dd0972c37bfb569f5d4ac8a53592e7b00752bc39ff063ca9864c74`,

The future canary must additionally inspect the applied container security

## Origin and network contract

For this milestone the only browser web origin is exactly
`http://altera-web:3000`. `altera-web` is a coordinator-created local fixture or
the reviewed local Nuxt preview service, never an external DNS name. Do not add
Context7 or provider domains to browser origins; they are MCP/model transports,
not the tested web application. A changed scheme, host or port needs a new
manifest value, origin row and acceptance record rather than a permissive
default.

Microsoft states that `--allowed-origins` is not a security boundary and does
not affect redirects. The actual boundary is Docker networking:

- create a fresh `--internal` bridge with
  `com.docker.network.bridge.gateway_mode_ipv4=isolated`;
- attach only the runtime, `altera-web`, and explicitly declared synthetic
  control fixtures; publish no ports and expose no Docker socket or host-gateway
  alias;
- the no-model MCP proof has no provider proxy and therefore no egress path;
- a later real Codex acceptance may also require the existing isolated
  provider-proxy path for the model. Its browser boundary is then only the
  topology plus the proxy's exact CONNECT allowlist, not “local-only” and not
  the MCP origin flag. Inspect and record both networks and proxy policy. If an
  unintended route, host service, DNS path or proxy destination is reachable,
  the tester is not accepted.

This does not claim that a browser sharing the model container has a stronger
per-process network boundary than the model. If such separation is required by
the final threat model, use a separately reviewed browser sidecar/network
design; do not silently label the shared namespace local-only.
