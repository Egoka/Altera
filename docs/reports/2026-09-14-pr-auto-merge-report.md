## Что настроено

Контракт [pr-auto-merge](../multica/pr-auto-merge.md) добавлен в действующие инструкции
релиз-инженера, оркестратора, squad, очереди и восстановления. Полный контракт включён в
native инструкции, чтобы старый checkout не возвращал требование отдельного разрешения.

После локальных проверок релиз-инженер публикует ветку и создаёт/обновляет один PR. PR может
быть открыт до финального review для получения CI. Слияние разрешено только после всех
обязательных стадий, успешного CI и независимого review текущего SHA. Команда фиксирует
reviewed SHA через --match-head-commit; --admin и отложенный --auto не используются.
Отсутствующий, ожидающий, пропущенный или неуспешный обязательный check не считается зелёным.

Ожидание CI хранится в существующем parent; очередь и восстановление проверяют его перед
обычным no-op из-за занятой цепочки. Новое состояние возвращает ту же работу лидеру один раз,
без дублирования активного run. Прежние расписания сохранены: queue каждый час, recovery
каждые четыре часа на 15-й минуте, Europe/Moscow; оба active. Done, настройки GitHub protection,
модели, доступы и полномочия production-выпуска не менялись.

У релиз-инженера убраны устаревшие утверждения о фиксированных 24 тестах и текущем SSR 500;
реальное состояние требуется проверять по ревизии, workflow и выводу команд.

## Ограничения

Это применение инструкций к действующим native агентам, а не добавление нового runner или
техническая приёмка экспериментального M4. Новый native model run, rerun issue и ручной trigger
для проверки не выполнялись. Работающие run могут завершаться со старым контекстом; новый
контракт применяется в следующих запусках. События GitHub не предполагаются: периодический
просмотр обеспечивает существующая очередь при доступных daemon, сети и квоте.

Другие активные задачи и `.worktrees/autopilot` не изменялись. Старые настройки сохранены,
секреты/env в snapshot не включены. Для отката вернуть только пять текстовых полей before.json.
