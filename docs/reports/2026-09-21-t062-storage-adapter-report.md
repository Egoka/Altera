## Что сделано

Новый модуль `server/src/storage/`:

- `keys.ts` — ключи по `storage-layout.md` п. 3–4: мастер `{yyyy}/{mm}/{id}.{ext}`, вариант
  `{yyyy}/{mm}/{id}/w{width}.{format}`, выгрузка `exports/{userId}/{exportId}.zip`. Идентификатор
  только UUID, расширения из белого списка (мастер — форматы ADR-0008 п. 6, варианты — AVIF и WebP
  по §29.4, выгрузка — ZIP `[ДОПУЩЕНИЕ]` `exports.md`). Имя файла пользователя в ключ не попадает;
  разбор ключа отклоняет всё вне раскладки, включая `..`.
- `types.ts` — интерфейс `ObjectStorage` (`put`, `get`, `exists`, `delete`, `signedGetUrl`) и
  `StorageUnavailableError`; в API сбой отдаётся как `PROVIDER_UNAVAILABLE: storage` (§29.3).
  Срок подписанной ссылки задаёт вызывающий: журнал чисел не фиксирует, в коде нет выдуманных
  сроков; верхняя граница — 7 суток, технический предел SigV4.
- `local.ts` — файловая реализация для разработки и CI: подпись HMAC-SHA256 над методом, ключом
  и сроком, сравнение за постоянное время.
- `gateway.ts` — раздача `GET|HEAD /media/<key>` локальной реализацией как модель CDN
  (`access-and-signed-urls.md` п. 1–3): верная подпись — объект с `private, no-store`; без
  подписи — только публичный вариант с `public, no-cache`, иначе 404 без раскрытия существования;
  неверная или просроченная подпись — 403; сбой проверки — 503. Обработчик ничего не логирует,
  а трассировка запросов пишет только `pathname`, так что подпись в логи не попадает (п. 7).
- `s3.ts` — S3-совместимый провайдер без SDK и без новых зависимостей: SigV4 для запросов и
  query-подпись для ссылок, virtual-host и path-style. Конкретный провайдер не выбран (Q-01).
- `access.ts` — публичен только вариант готового неудалённого медиа, которое служит обложкой
  опубликованной статьи или аватаром неархивированного аккаунта; оригиналы и выгрузки публичными
  не бывают. Резолвер по Prisma проверяет доступ при каждом запросе, поэтому архив закрывает
  ссылку сразу, а восстановление открывает снова.
- `config.ts` — `STORAGE_DRIVER=local|s3` по образцу почты: вне production без значения —
  `local`; в production без значения — `unconfigured` (операции падают как недоступный
  провайдер), `local` в production запрещён.

Подключение: `server.ts` раздаёт `/media/*`, когда выбрана локальная реализация. Группа
`storage` системных настроек админки показывает адаптер и параметры, секреты маскируются.
Переменные описаны в `server/env.example` и `server/ENV_SETUP.md`, `.storage` добавлен в
`.gitignore`. Первый прогон CI уронил e2e `admin-settings.spec.ts`: тест брал `storage` как
пример группы без провайдера. Пример перенесён на `payments`, а текст пустой группы хранилища
больше не говорит, что хранилище не подключено.

## Критерии

| Критерий | Статус | Доказательство |
|---|---|---|
| 1. Ссылка на оригинал без подписи → отказ | passed | `server/tests/storage-access.test.ts`, «критерий 1»: без подписи — 404 без содержимого; с подписью — 200; просроченная, с подделанным сроком и с подписью другого ключа — 403 |
| 2. Архивирование материала закрывает публичные ссылки на его медиа | passed | `server/tests/storage-access.test.ts`, «критерий 2»: вариант обложки опубликованной статьи — 200, после архива — 404, после восстановления — 200; то же для аватара архивированного аккаунта и медиа черновика |

Тесты критериев проверены мутацией: если убрать проверку публичного доступа в `gateway.ts`,
падают 6 из 6 сценариев доступа.

## Остаток

- Реальный провайдер S3 — Q-01 владельца; адаптер против живого S3 не проверялся, только на
  эталонных векторах подписи и двойнике `fetch`.
- Как закрывать публичные файлы в CDN провайдера при архиве, зависит от провайдера (Q-01).
  Сейчас это гарантируют выдача ссылок через API и раздача `/media/*` в локальной реализации.
- Связи медиа с узлами документа (`attrs.assetId`) в базе не хранятся; резолвер доступа
  учитывает обложку и аватар. Иллюстрации в теле статьи добавятся вместе с конвейером (T-063).
- Предпросмотр и доступ `editor` и `moderator` к медиа черновиков (п. 4–5) — выдача подписанной
  ссылки после проверки прав в API. Выдающих ссылки мутаций пока нет: они появятся в T-063 и
  T-034.
- Независимое ревью проверенного SHA и запись Done остаются за контроллером. Миграций задача
  не добавляет, отдельная выкладка не требуется.
