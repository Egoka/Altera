## Кратчайший путь к первому автономному пилоту

1. Завершить приёмку runtime для выбранной задачи. Если задача требует браузер,
   нужна успешная полная проверка исправленной версии в обеих топологиях.
2. Подключить постоянные native adapters, фактическую managed-конфигурацию
   Codex и выбор актуального поколения Claude credentials; проверить context/hooks.
3. Завершить доверенный сборщик: ticket → workspace/agent/issue/run → реальные
   процессы и результаты проверок → существующий gate → сверка terminal status.
4. Применить необходимые для пилота настройки Multica, прочитать их обратно
   и провести одну разрешённую задачу с независимым ревью и настоящими AC.

Product auth **не является обязательным предшественником первого пилота**,
если паспорт выбранной задачи не требует авторизации. Это уточнение сокращает
критический путь, сохраняя весь продуктовый backlog.
[Обоснование минимального пути](evidence/2026-09-13-autonomy/minimum-pilot-audit/task-closure-minimum-pilot-audit.md).

## Почему сессия затянулась

Проверка браузера последовательно выявляла неверные предположения самого тестового
стенда: формат снимков, ответы действий, capabilities внутри user namespace,
перезапись argv и пустой каталог после failed launch. Исправления и доказательства
полезны, но они вытеснили реализацию native adapters и сборщика. Дополнительно
первый пилот был излишне связан с полным продуктовым auth; этот порядок исправлен.
Сессия завершается сохранением результата, без дальнейших проб и заявления о
полной автономии. Это честный промежуточный результат, а не выполнение всего запроса.

Независимый итоговый разбор: последнее offline-исправление — spec/quality PASS;
общая приёмка runtime — FAIL / INCOMPLETE.
