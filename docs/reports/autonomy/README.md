# Суточные отчёты автономной работы

Точка входа — [PROGRESS.md](../../../PROGRESS.md). Порядок сбора, метрики, доверенные receipts и ограничения описаны в
[инструкции суточного аудита](../../multica/daily-audit.md).

| Файл                                        | Назначение                                                                 |
| ------------------------------------------- | -------------------------------------------------------------------------- |
| `YYYY-MM-DD.md`                             | Читаемый аудит суток, заканчивающихся в 10:00 Europe/Moscow указанной даты |
| `YYYY-MM-DD.json`                           | Канонические машинные значения, cohort, evidence и coverage                |
| `periods.json`                              | Пересчитанные агрегаты за последние 7/30 суток и отсутствующие даты        |
| `.history/YYYY-MM-DD/<content_sha256>.json` | Предыдущие версии исправленных суточных JSON                               |

Один и тот же вход даёт те же байты и revision. Новые данные заменяют канонический файл даты, увеличивают revision и
сохраняют старый JSON в `.history`. Файлы публикуются атомарной заменой по одному; render следует запускать одним
controller publisher. Пути публикации проверяются после разрешения symlink и должны оставаться внутри `--root`. История не удаляется автоматически. Старый Markdown восстанавливается из JSON функцией
`render_report`; Git также сохраняет версии после коммита.

Отсутствие файла суток означает отсутствие среза. `null` в метрике означает неизвестное значение, а не ноль. Полнота
инвентаря источников и полнота usage проверяются отдельно. Исправление старой даты не откатывает последний день в
PROGRESS и пересчитывает агрегаты при попадании в их окно.

Здесь хранятся только безопасные отчёты и machine evidence. Секреты, сырые логи, тексты prompts и необработанные API
payloads остаются вне репозитория. Публикация файлов не меняет issue или runtime Multica.
