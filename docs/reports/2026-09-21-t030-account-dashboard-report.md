## Что сделано

### Сервер

`server/src/account/dashboard.ts` — вывод карточки плана из выдач `PlanGrant`:
`deriveAccountSubscription` возвращает `state` (`free` — выдач не было, `base` — бессрочная
базовая выдача первого запуска, `active` — выдача со сроком, `expired` — последняя выдача
закончилась или отозвана), `tier`, `until`, `endedAt` и очередь периодов. Действует выдача с
наивысшим приоритетом (`pro` раньше `standard`, журнал §8.22), остальные действующие и будущие —
очередь «затем: …». Статус выдачи берётся из того же `deriveGrantStatus`, что и в админке.
Источник — выдачи, а не кэш `users.planTier`: административная выдача кэш не обновляет.

`server/src/graphql/account/` — `AccountUser.hasArticles` и `AccountUser.subscription`. Поля
отдают только данные владельца (сверка `parent.id` с текущим пользователем), ограниченная сессия
получает `FORBIDDEN`, у служебной записи `subscription = null` (§8.17, §25.2). Вариантов «серия
списаний» и `cancelAtPeriodEnd` в контракте нет: платежей на первом запуске нет (§24.1).

### Веб

`web/app/middleware/account-dashboard.ts` читает сводку до рендера, поэтому первый ответ — 302:
служебная запись → `/admin`, ограниченная сессия → `/me/archived`, гость → `/login?next=/me`.
Служебную запись определяет роль, а не пустой план. Отказ `me` даёт страницу 500 с `requestId`
(ошибка помечена `fatal`, иначе клиентский переход просто отменяется).

`web/app/pages/me/index.vue` собирает зоны §5: `AccountCard` (без e-mail, §4),
`SubscriptionStatus`, `AttentionList` (на проверке, отклонённые с непрочитанным объяснением, окно
«перередактировать» с отсчётом — по каждой языковой версии), пять последних материалов
(`MyArticleRow`), пять закладок, `LinkList`. Материалы и закладки читаются независимо: отказ зоны
показывает «не удалось загрузить» с повтором, остальные карточки остаются. Без статей авторские
разделы скрыты (§8.21), вместо них — «Создать статью» → `/me/articles/new` без плана (§24.1, §25.1);
при истёкшем плане — «продлить» и «выбрать план» → `/pricing`. Раскладка: одна колонка в порядке
зон 2–7, на `lg` — две (§9). `title` «Кабинет — Altera», `noindex, nofollow` (§10).

### Побочные исправления

- **Цикл редиректов при устаревшей сессии.** Если cookie есть, а API сессию не признаёт
  (отозвана или истекла), серверный рендер ходил по кругу: `/me` → `/login` → `/me`, потому что
  страница входа видит cookie и возвращает назад. `useAuthSession().clear()` стирает cookie прямо
  в ответе до редиректа. Сценарий нашёл CI на `noindex-meta.spec.ts`.
- **`noindex-meta.spec.ts`** ставил токен без `sid`, то есть без сессии; для заглушки `/me` это
  было неважно. Сценарий получает живую сессию, утверждения те же.

## Остаток

- **Дефект вне задачи: `createArticle` на живой базе.** Резолвер создаёт статью вместе с
  вложенной языковой версией, а триггер `t015_sync_legacy_article` на вставку сам создаёт
  исходную версию с тем же `(articleId, locale)` и slug. Вторая вставка нарушает уникальность,
  поэтому «Создать статью» на реальной базе, судя по коду и миграции, должно падать; все
  существующие браузерные сценарии создания подменяют API. Сценарий нажатия снят из T-030;
  нужна отдельная задача с проверкой на живой базе.
- Экрана `/me/archived` в репозитории нет: редирект соответствует спецификации, но экран не
  собран (как и для T-022, T-025, T-032).
- Мутации «перередактировать» (`reeditTranslation`) в API нет: строка окна ведёт на страницу
  материала, диалога с подтверждением нет.
- Разделы `/me/settings`, `/me/subscription`, `/me/export`, `/me/delete` пока не собраны; ссылки
  взяты из реестра маршрутов.
- `[ДОПУЩЕНИЕ]` §9: свёрнутая карточка плана и нижняя навигация телефона не сделаны; текст
  «Базовый план, без оплаты» — `[ДОПУЩЕНИЕ]` §12. Счётчик `unreadDecisions` отдельным полем не
  вводился: зона «Требует внимания» выводит непрочитанные решения из `myArticles`.
- Кандидаты в «Требует внимания» читаются первыми двадцатью материалами на проверке, отклонёнными
  и опубликованными по дате изменения.
- Независимое native-ревью проверенного SHA и запись Done остаются за контроллером. Миграций
  задача не добавляет, отдельная выкладка не требуется.
