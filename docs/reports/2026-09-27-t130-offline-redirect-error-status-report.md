## Что сделано

**Разбор `?from=` (`web/app/composables/useOfflinePage.ts`).** Появилась чистая экспортируемая
функция `sameSitePath`. Значение принимается только как путь своего источника: сначала
отбрасываются не-строки, значения без ведущего `/` и значения с управляющими символами (браузер
такие символы из адреса выбрасывает молча, поэтому `/\t/evil.example` прошло бы посимвольную
проверку), затем адрес разбирается правилами WHATWG — теми же, по которым его прочитает браузер, —
и источник сравнивается с опорным. Дополнительно отклоняется результат, который после нормализации
снова становится протокол-относительным (`/..//evil.example` → `//evil.example`). Наружу уходит
нормализованный `pathname + search + hash`, то есть на `location.assign` попадает значение, которое
не может увести за пределы сайта. `requestedPath` composable теперь вызывает эту функцию, поэтому
закрыты оба пути перехода — кнопка «Попробовать снова» и слушатель события `online`.

**Статусы страницы ошибки (`web/app/error.vue`, `web/app/components/service/Forbidden.vue`).**
Обработчик разводит три случая: 404 — страница «не найдено» (#21), 403 — новая страница отказа в
доступе, всё остальное — страница 500 (#23). Страница 403 запросов к API не делает (403 приходит из
route middleware, и шапка не должна упасть следом), кода запроса не показывает, уводит на главную и
в редакцию. `serviceRequestId` перестал вычислять код для любого статуса ниже 500: журнал §28.4
оставил `requestId` техническим сбоям, а «нет такой страницы» и «нет доступа» — обычные
пользовательские состояния.

**Жизнь `requestId` (`web/app/error.vue`).** `useState` по-прежнему переносит серверное значение в
разметку — заголовок `x-request-id` клиентскому коду недоступен, — но принадлежит оно ровно тому
отказу, который отрисовал сервер. Экземпляр страницы забирает значение при создании и отпускает
общее состояние после гидратации; смена самого отказа тоже сбрасывает унаследованное значение.
Следующая ошибка той же SPA-сессии показывает свой код из отказа либо обходится без кода. Сброс
идёт в `onMounted`, уже после гидратационной отрисовки, поэтому код, пришедший с сервера, на глазах
у читателя не исчезает.

Локали пополнились ключами `service.forbiddenMetaTitle`, `service.forbiddenTitle` и
`service.forbiddenDescription` в `ru.json` и `en.json`.

## Остаток

- **Независимое ревью** с маркером `ALTERA_REVIEW_V1` на финальном head ещё не получено — его
  назначает контроллер, исполнитель свою работу не принимает.

  #22 410, #23 500, #24 офлайн) и не имеет своей спецификации в `docs/spec/20-public/`. Это работа
  хранителя документации: реестр и спецификации здесь не правились. Строка «Нет доступа» в
  `error.md` §8 остаётся верной — она описывает состояние самой страницы 500, у которой такого
  состояния по-прежнему нет.
- **Тексты страницы 403** (`service.forbiddenTitle`, `service.forbiddenDescription`) —
  `[ДОПУЩЕНИЕ]` исполнителя: задача требует «страницу отказа в доступе», но формулировок ни журнал,
  ни спецификации не задают. Пояснение §25.2 «админка только для служебных записей» в тексте не
  раскрывается, потому что страница общая для всех источников 403.
- **Повторная приёмка T-058** (ALTE-105) идёт в своей карточке.
- **Q-09(в)** (публичная `/offline` в срезе первого запуска) остаётся вопросом владельца: эта
  задача закрывает редирект, но не решает, входит ли страница в срез.
