# Отчёт: автоматическое закрытие и продолжение очереди

- План: [продолжение после merge](../plans/2026-09-14-post-merge-continuation.md).
- Baseline: `85d3af44b20e4ddae6adc7f67cb87c8192d1d186`.
- Scope: инструкции Multica и документация, без изменения исходного кода приложения.

## Причина остановки

Run очереди 22:00–22:05 MSK, task `01a0a14a-bfa6-749f-bdaf-20e4ca7b9fe2`, завершился
`already_ready / active / busy`. ALTE-12 уже была Todo. PR #26 был слит в app, но ALTE-6/7/8
оставались In Review. Агент назвал их активной цепочкой и ожидал Done от владельца, хотя
следующих активных native run не было. Недостающую финализацию он не назначил.

В истории T-097 также отсутствовало повторное независимое review после исправлений;
условное поручение «если всё готово — сливай» было ошибочно представлено как отказ от review.
Merge не выдаётся за доказательство приёмки: восстановление направлено на недостающие стадии.

## Изменение поручения во время работы

Первый план разделял ручной Done и закрытие исполнения. Затем владелец явно потребовал
полностью убрать ожидание его Done и создавать несколько готовых задач. Поэтому итоговый
контракт предусматривает автоматический Done после приёмки, интеграции и финализации,
запас до трёх готовых Todo и немедленное назначение следующей после освобождения слота.
План сохранён как история; актуальное решение — [post-merge-continuation](../multica/post-merge-continuation.md).

Ограничение одного writer, индивидуальные проверки готовности, Q/F, бюджет ошибок и
сохранение грязного checkout T-003 остаются обязательными. Новое исполнение получает чистый
checkout от app. Чтение правил из старой ветки заменяется чтением файлов из зафиксированного
app SHA. Исходные задачи не переоткрываются и не объявляются принятыми без доказательств.
