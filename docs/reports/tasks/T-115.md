## Результат

Вход по паролю — второй равный способ наряду с одноразовой ссылкой (журнал §34 п. 6–8).
Регистрация с паролем заводит аккаунт и подтверждает адрес письмом до первого входа; забытый
пароль сбрасывается письмом; аккаунт без пароля продолжает входить по ссылке и может задать
пароль в кабинете. Требования к паролю (15…128 code points после NFC, без обязательных классов
символов, локальный blocklist, Argon2id `m=19456,t=2,p=1` PHC-строкой) и лимит неуспешных
попыток (5 за 15 минут на адрес, 30 на IP) — утверждённые владельцем значения журнала §44 п. 1.
Argon2id взят из `node:crypto` Node 24: новой зависимости не потребовалось.

## Критерии

| Критерий | Статус | Доказательство |
| --- | --- | --- |
| 1. Регистрация по ссылке и с паролем обе создают аккаунт; при регистрации с паролем вход до подтверждения адреса невозможен | passed | e2e `web/tests/e2e/115-password-login.spec.ts` шаги 1–4 на настоящем стеке с Mailpit: аккаунт заведён с `emailVerifiedAt = null` и хэшем `$argon2id$v=19$m=19456,t=2,p=1$…`, вход по паролю до подтверждения не создаёт сессии (`data-login-state='unconfirmed'`, `sessions` пусто), переход по ссылке `/auth/confirm?token=` подтверждает адрес и выдаёт сессию, повтор ссылки — `invalid`. Дублирующие тесты резолвера — `server/tests/auth-password.test.ts` |
| 2. Аккаунт без пароля входит по ссылке | passed | e2e-сценарий «an account created by a link stays passwordless and signs in by link»: аккаунт создан ссылкой, `passwordHash = null`, вход по ссылке доходит до `/me`; там же — установка первого пароля в `/me/password` без потери входа по ссылке |
| 3. Сброс пароля идёт письмом; ответы не раскрывают существование аккаунта | passed | `server/tests/auth-password.test.ts`: ответ `requestPasswordReset` идентичен для существующего и неизвестного адреса, письмо уходит только существующему; `loginWithPassword` отвечает одинаковым `UNAUTHENTICATED` на неизвестный адрес и на неверный пароль (сверены extensions и текст); регистрация на занятый адрес отвечает как на свободный и чужой пароль не меняет. e2e: сброс письмом, новый пароль по `/auth/reset?token=`, прежний пароль перестаёт подходить |
| 4. Попытки входа ограничены лимитом, утверждённым владельцем | passed | `server/tests/auth-password.test.ts`, раздел «лимит попыток входа по паролю»: пять неуспехов дают `UNAUTHENTICATED`, шестая попытка — `RATE_LIMITED` с `retryAfter`; успешная проверка очищает корзину адреса (постоянной блокировки нет); тридцать первая попытка с одного адреса запроса по разным аккаунтам — `RATE_LIMITED`; `rate_limit.hit` содержит корзину и не содержит ни адреса, ни пароля |
