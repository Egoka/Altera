## Result

- A session is now a stored row: `verifyMagicLink` creates `Session` with the sha256 hash of an opaque 32-byte refresh token and puts the session id into the access JWT as `sid`. The `role` claim was dropped — the role is read from the database on every request (ADR-0003 §4, ADR-0009 §6).
- `createContext` authenticates a request only through a live session: one indexed read by `sid` returns the user with active permission exceptions. A revoked, expired or foreign session, and a token without `sid`, make the request a visitor request, so revocation takes effect immediately (ADR-0009 §2).
- `refreshSession` rotates the token — the previous hash moves to `previousTokenHash` and the expiry moves 30 days forward. Presenting an already rotated token revokes **every** session of that user and logs `session.reuse_detected` and `session.revoked` (ADR-0009 §3).
- `logout` revokes the current session (by the `sid` of the access token, otherwise by the refresh token supplied from the cookie); `logoutAll` revokes all sessions of the user including the current one (ADR-0009 §4).
- The Nuxt BFF route `POST /api/graphql` moves the issued refresh token into an `httpOnly`, `Secure`, `SameSite=Lax` first-party cookie, substitutes the cookie value into `refreshSession`/`logout` instead of the client's, and clears the cookie after logout and after a rejected refresh (ADR-0023 §2, §5). Mutations are now checked against `Origin`/`Sec-Fetch-Site` (ADR-0023 §4), because cookie authentication makes them CSRF-reachable.
- The proxy forwards the browser `user-agent` and the client address; both are stored on the session row (ADR-0009 §1).
- The refresh token stopped being a JWT, so `JWT_REFRESH_SECRET` and `JWT_REFRESH_TOKEN_EXPIRY` are no longer read and were removed from CI, `playwright.config.ts`, `env.example`, `ENV_SETUP.md` and `project-rules.md`.

No migration is added: the `Session` table arrived with T-012 and already holds every needed field.

### Criteria

- **AC-1 — presenting an old refresh token revokes all of the user's sessions:** `server/tests/session-rotation.test.ts` and `server/tests/session-mutations.test.ts` assert `reuse_detected`, the empty active-session set, the untouched session of another user, and the `session.refresh → session.reuse_detected → session.revoked` log order; the Playwright scenario repeats it in a browser and confirms revocation with a direct database query.
- **AC-2 — the cookie is unreachable from JavaScript:** Playwright `web/tests/e2e/23-session-cookie.spec.ts` — after login `document.cookie` contains neither the cookie name nor its value, the jar entry is `httpOnly: true` / `sameSite: "Lax"`, and the mutation returns `refreshToken: null`.
- **AC-3 — `logoutAll` leaves no active session:** `server/tests/session-mutations.test.ts` and the Playwright scenario with two parallel browser contexts and a database check.
