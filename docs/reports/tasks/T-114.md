## Результат

Рядом с драйвером `noop` из T-089 есть адаптер внешнего сборщика ошибок по Sentry-протоколу для собственного GlitchTip/Sentry (журнал §34 п. 3). `ERROR_COLLECTOR_DRIVER=sentry` с `ERROR_COLLECTOR_DSN` отправляет вхождение одним POST на `/api/<проект>/envelope/` без SDK; публичный ключ DSN уходит только в заголовок `X-Sentry-Auth`, поля `dsn` в теле конверта нет. Группировка своя: `fingerprint` — сигнатура T-089, поэтому группы сборщика совпадают с группами собственной истории `backend.error`. ПДн в событии нет: сообщение и стек приходят в адаптер после `sanitizeLogValue`, контекст — поток, сервис, код, событие, `requestId`, `jobId` и маршрут по шаблону, `server_name` не отправляется. Отказ сборщика не ломает запрос: история сохраняется, сбой уходит в журнал как `backend.error`. Локальный сборщик поднимается профилем `errors` в `docker-compose.yml` (GlitchTip 6.2.6 одним контейнером со своей базой, интерфейс на 28000). Развёртывание на сервере в РФ отложено вместе с хостингом (§34 п. 1, T-103), поэтому `noop` остаётся драйвером по умолчанию во всех окружениях.
