## Что сделано

**Веб.** `/admin/tags` работал на моковом массиве из шести тегов. Раздел переведён на
`GetAdminTags`: список с фильтром по статусу (`?status=`), поиском по названию, `nameEn` и
слагу (`?q=`), слиянием выбранных, архивом и восстановлением, боковой карточкой с журналом
`tag.*`. Состояния §9 воспроизводимы — скелет загрузки, два пустых состояния, ошибка с
`requestId`, отдельные сообщения конфликта и запрета, лимит выбора. Слияние и массовые
операции скрыты ниже `lg` (§10). Создание тега из админки не добавлено: теги создают авторы
через автодополнение (журнал §26.3).

**Сервер.** `tag.merge`, `tag.archive` и `tag.restore` пишут аудит: слияние — `sourceTagIds`,
`targetTagId` и число перенесённых связей отдельной записью на каждый источник (§6, §8),
архив — число материалов. Восстановление слитого тега и архива, сделанного владельцем,
отклоняется: `admin` восстанавливает только свой архив (§5). Повторный архив уже
архивированного тега даёт `CONFLICT`. Предел массового слияния приведён к спецификации —
50 источников вместо прежних 10. `taxonomyAudit` принимает `entityType: "Tag"`.

**301.** Публичный запрос `tag(slug)` отдаёт цель слияния, и страница `/tags/[slug]`
перенаправляет адрес источника на слаг цели кодом 301 — тем же способом, что рубрика после
архивирования (ADR-0004; слаг тега занят навсегда, журнал §26.10).

**Попутно.** `buildOrderBy` не умел составные поля: `_count.articles` превращалось в плоский
ключ с точкой, который Prisma не принимает, и любой список с сортировкой по числу материалов
падал целиком. Счётчик связи теперь строится как `{ articles: { _count } }`. Проверка токенов
`AppTable` (`web/tests/e2e/app-components-theme.spec.ts`) переехала с раздела тегов на раздел
типов контента: раздел тегов больше не использует этот компонент.
