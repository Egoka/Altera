## Результат

- **`/offline?from=` больше не уводит с сайта.** `sameSitePath` принимает значение только как путь
  своего источника: отбрасываются не-строки, значения без ведущего `/` и значения с управляющими
  символами, дальше адрес разбирается правилами WHATWG и источник сравнивается с опорным.
  Отклоняется и результат, который после нормализации снова становится протокол-относительным
  (`/..//evil.example`). Наружу уходит нормализованный путь, поэтому закрыты оба пути перехода —
  кнопка «Попробовать снова» и слушатель события `online`.
- **403 — своя страница отказа в доступе.** `error.vue` разводит 404, 403 и 5xx; страница 403
  запросов к API не делает, кода запроса не показывает, уводит на главную и в редакцию.
  `serviceRequestId` перестал вычислять код для любого статуса ниже 500 (журнал §28.4).
- **Код запроса не переезжает между ошибками.** Серверное значение из `useState` принадлежит тому
  отказу, который отрисовал сервер: экземпляр страницы забирает его при создании и отпускает после
  гидратации, смена отказа сбрасывает унаследованное значение.
- Сохраняемый контракт не тронут: маршруты `/offline` и `error.vue` на месте,
  `web/server/plugins/error-cache-control.ts` не менялся, `no-store` ставится только для 5xx.
  Service worker в границы не входит (журнал §35 п. 3).
