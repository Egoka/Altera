**Админка и сценарии** (12 файлов → «утверждён (гейт Г7)»):

- §26.1 — `dashboard.md`: карточка дашборда владельца (динамика, важные изменения, события,
  компактный блок критичных записей аудита); состав метрик — отложен в отдельный проход.
- §26.2 — `categories.md`: архив рубрики только с активным преемником, статьи переносятся в той
  же транзакции, старые адреса — 301; матрица #83.
- §26.3 — `tags.md`: очередь предложений убрана, автор создаёт тег из редактора;
  `article-edit.md` (`TagPicker` с созданием), `article-new.md`, `write-and-publish.md`,
  `roles/author.md`, `tags-index.md`, `tag-feed.md`, `topic-relevance.md`, матрица #30, #85;
  ADR-0005 — строка статуса переписана (п. 3 снова действует).
- §26.4 — `articles.md`, `review-queue.md`, `explainability.md`: точные прочтения в рабочих
  списках.
- §26.5 — `review-queue.md`, `moderation.md`: закрепление `in_review`, статус `rework`, снятие
  закрепления при запросе доработки, продолжение любым рецензентом; фильтр «кто ждёт» и срок
  ожидания убраны; в кабинете — вкладка «на доработке» (`articles.md`), `readOnlyReason:
  in_review` `[ДОПУЩЕНИЕ]` (`article-edit.md`), `reviewState` (`review-history.md`).
- §26.6 — `users.md`, `roles/analyst.md`: сессии пользователей `analyst` недоступны.
- §26.7 — `admins.md`, `appoint-admin.md`, `roles/admin.md`, матрица #52, #106: архив и
  восстановление служебных записей — только `owner`; владелец — в два шага из существующей
  служебной записи.
- §26.8 — `statistics.md`, `explainability.md`: таблицы топ-авторов и топ-статей за период для
  служебных ролей.
- §26.9 — `users.md`, `archive-account.md`, `blocked-appeal.md`, события #14: категория (одна из
  четырёх базовых), короткое объяснение, сообщение сотрудника по желанию; названия категорий
  отложены.
- §26.10 — `permanent-delete.md`, `profile-edit.md`, `categories.md`, `tags.md`; ADR-0004 —
  строка статуса: слаги и хэндлы уникальны навсегда.

**Реестры**: `admin-sections.md` — пометка о Г7. Новых строк нет.

- Состав метрик дашборда владельца и критерий «критичной» записи аудита — отдельный проход
  (§26.1); названия четырёх категорий блокировки — будущий вопрос (§26.9).
- Числовые параметры не вводились (по указанию владельца).
- Новые статусы `in_review` и `rework` не добавлены в `03-data-model.md` — vision-документы не
  входили в объём синхронизации; отмечено как отложенная работа.
