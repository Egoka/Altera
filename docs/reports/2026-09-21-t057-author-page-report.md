## Результат

Страница автора перестала быть витриной мока: `web/app/pages/authors/[slug].vue` брала одного
захардкоженного автора и демо-ленту главной, выводила «о себе» через `v-html` и рисовала кнопку
подписки, которой в продукте нет. Теперь страница собирается из двух публичных запросов —
профиль `author(handle)` и лента `feed(scope: author)` — и воспроизводит строки состояний §8.

### Сервер

| Что | Где |
|---|---|
| Тип `AuthorProfile` и запрос `author(handle)` | `server/src/graphql/author/schema.graphql`, `resolver.ts` |
| Значение `author` в `FeedScope`, аргумент `handle`, лента автора | `server/src/graphql/feed/schema.graphql`, `resolver.ts` |
| Снятые черновые `author`, `articlesByAuthor`, `authorStats` | `server/src/graphql/user/schema.graphql`, `resolver.ts` |

Профиль отдаёт `id`, `handle`, `name`, `bio`, `avatar`, `links[] { kind, url }`, `grade`,
`publishedCount`, `firstPublishedAt` и `redirect`. E-mail, роли, плана, срока и сессий в ответе
нет (`visibility.md` п. 4, ADR-0018); уровень автора виден бейджем, чисел рейтинга публичный тип
не содержит (журнал §21.18). Счётчик и дата первой публикации считаются по всем языкам: у запроса
нет аргумента локали, а условие существования страницы (§1) от языка не зависит — лента же
остаётся строго локальной (журнал §20.5).

Состояния адреса разведены по кодам: неизвестный хэндл и аккаунт без публикаций — `NOT_FOUND`
(404), архивированный аккаунт — `ARCHIVED` (410, журнал §28.2), прежний хэндл — `redirect` на
нынешний (301, `routes.md` #7). Отдельного поля «архивирован» публичный тип не получил: снятому
аккаунту страница показывает только текст «страница автора недоступна», и профиль отдавать
незачем. Ссылки соцсетей собираются из `socialLinks` только для схем `http` и `https` и уходят
наружу в разобранном виде — адрес со скриптом в разметку не попадает.

Кеш — общий, `readThroughPublicCache`, TTL `publicList`, тег `author:{handle}`, который
публикация и архивирование материала уже сбрасывают (`cache/key.ts`). Аргумент `handle` вошёл в
ключ `query.feed`, поэтому ожидаемый ключ в `server/tests/home-feed.test.ts` обновлён.

### Веб

Шапка `ReadingAuthorHeader` (§5 зона 2): аватар или инициалы, имя, `ProBadge`, хэндл, «о себе»
текстом, «публикуется с {месяц год}», число материалов и ссылки соцсетей с
`rel="nofollow noopener noreferrer"`. Под ней — подпись «по дате публикации» (журнал §20.4),
хроника по месяцам из однорядных раскладок ритма автора (§5 зона 4, решения владельца
2026-09-13), пустое состояние с переключателем языка, пагинация и `ErrorState` с кодом запроса.
301 отрабатывается и на прежний хэндл, и на запись не в том регистре (§3). `throwOnFeedError`
научился коду `ARCHIVED`: теперь это 410, а не 500.

Фрагмент `ArticleCard` снят — операций у него не осталось, последней была старая страница
автора; форма карточки витрины раскладок переехала в `~/types/reading` как `DemoArticleCard`.
Вместе с моком ушли `web/app/components/header/user.vue` и фрагмент `AuthorSummary`.

## Как проверено

`pnpm format`, `pnpm lint`, `pnpm test`, `pnpm --filter server run build:ci`,
`pnpm --filter nuxt-app run typecheck`, `pnpm --filter nuxt-app run build` — exit 0 локально.
Числа набора: server 616 passed и 25 skipped, web 420 passed. Playwright локально не
запускался — на машине нет Docker и PostgreSQL; браузерный набор выполняется в CI.

CI на проверенном head `3f9d854` — зелёный целиком:
[run 35545655538](https://github.com/Egoka/Altera/actions/runs/35545655538); браузерный джоб —
145 passed и 9 skipped из 154 сценариев, семь из них — новые сценарии страницы автора.

Два прогона до этого отказывали на собственных новых сценариях, и оба отказа — о самой
проверке, а не о странице:

1. Список авторов открывался прямым заходом, а перехват `**/api/graphql` не видит SSR-запрос,
   поэтому карточка автора не появлялась. Список открывается ссылкой шапки — клиентским
   переходом, как в проверке публичных лент (`371ab4c`).
2. Проверка «бейджа pro нет» считала шесть бейджей карточек ленты: уровень автора приходит в
   каждой карточке. У истёкшего плана уровень снят и в профиле, и в карточках (`3f9d854`).

## Остаток

- Подписка на автора, `FollowButton` и `followerCountShort` — этап 3 и F-10, прямо исключены
  §3 задачи; модели подписок в базе нет.
- `title`, `description`, `canonical`, `hreflang`, Open Graph и JSON-LD `Person` (§10) — задача
  T-100, которая зависит от T-057; страница ставит только `title`, как соседние публичные.
- Ссылки «редактировать профиль» и «карточка в админке» (§5 зона 2, §7): страницы
  `/me/settings` в проекте нет, идентичность сессии на вебе не подключена (T-023).
- Иконки соцсетей (§5 зона 2): в собственной коллекции `a-icon` их нет, ссылки выводятся
  подписью вида. Замена на иконки — за стадией дизайна.
- Сортировка `?sort=rating|date` (§3) — после запуска движка рейтинга, журнал §22.5.
- Автор в `sitemap.xml` (§10) — T-099.
- Инвалидация профиля при смене имени, «о себе» и плана держится на TTL кеша: мутаций профиля
  и плана, которые сбрасывали бы тег `author:{handle}`, в коде пока нет.
