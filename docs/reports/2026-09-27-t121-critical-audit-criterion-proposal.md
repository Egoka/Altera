- **Источник задачи**: `docs/backlog/tasks/T-121-critical-audit-criterion-proposal.md`
- **Ревизия источника**: `2093e49e5407f7340e0b08afb4bdd769914ad00b`

- **Baseline**: `2c4076561e3069282b9c835596ac5b59e6004134` (`origin/app`, 2026-09-27)
- **Статус предложения**: ожидает утверждения владельцем по журналу §37 п. 15

## Предлагаемый критерий

Запись считается критичной для компактного блока дашборда владельца, если её точный `action`
входит в allowlist ниже. В allowlist входят действия хотя бы одного из четырёх классов:

1. меняют полномочия, служебный доступ или состояние безопасности;
2. необратимо удаляют данные либо меняют внешне значимое обязательство проекта;
3. вручную меняют деньги, тарифные права или финансовый учёт;
4. дают доступ к персональным данным или выгружают их.

Критичность определяется по коду, а не по тексту, роли актора, содержимому `diff` или уровню
логирования. Поэтому правило детерминировано и одинаково применяется при записи аудита, в
`auditLog(critical: true)` и в компактном блоке `adminSummary.owner`.

## Предлагаемый allowlist

### Полномочия и безопасность

| Код                           | Основание                                                                                          |
| ----------------------------- | -------------------------------------------------------------------------------------------------- |
| `user.role.change`            | Изменяет роль и доступ существующей записи.                                                        |
| `user.sessions.revoke`        | Принудительно завершает активные сессии в ответ на риск безопасности или административное решение. |
| `user.email.change`           | Меняет идентификатор входа, в том числе через восстановление.                                      |
| `role.assign.owner`           | Выдаёт максимальные полномочия.                                                                    |
| `role.revoke.owner`           | Снимает максимальные полномочия.                                                                   |
| `owner.deactivate`            | Деактивирует служебную запись владельца.                                                           |
| `permission.exception.grant`  | Выдаёт исключение из штатной ролевой модели.                                                       |
| `permission.exception.revoke` | Досрочно меняет действующее исключение доступа.                                                    |
| `settings.change`             | Меняет системную настройку.                                                                        |
| `secrets.rotate`              | Меняет активный секрет без раскрытия его значения в аудите.                                        |
| `user.create.staff`           | Создаёт служебную запись.                                                                          |

`permission.exception.expire` не включён: это ожидаемое автоматическое окончание заранее
ограниченного исключения, а не новое или внеплановое расширение полномочий.

### Состояние аккаунтов, удаление и обязательства

| Код                       | Основание                                                                                                          |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `user.archive`            | Административно прекращает доступ пользователя и может каскадно затронуть статьи.                                  |
| `user.restore`            | Административно возвращает доступ ранее архивированной записи.                                                     |
| `entity.delete.permanent` | Необратимо удаляет сущность.                                                                                       |
| `legal.update`            | Создаёт черновик или публикует новую версию юридического текста; оба действия чувствительны для правового контура. |
| `job.cancel`              | Вручную прекращает системное задание; повтор `job.retry` остаётся штатной операционной записью.                    |
| `user.appeal.decide`      | Окончательно подтверждает блокировку либо восстанавливает аккаунт по апелляции.                                    |

Self-service-коды `user.archive.self`, `user.restore.self`, обычные архивирование/восстановление
статей и штатные решения модерации не включены: это доменные потоки, для которых предусмотрены
профильные разделы, а не исключительные действия владельца.

### Деньги, тарифные права и финансовый учёт

| Код                          | Основание                                           |
| ---------------------------- | --------------------------------------------------- |
| `plan.grant`                 | Вручную выдаёт тарифное право.                      |
| `plan.revoke`                | Вручную отзывает тарифное право.                    |
| `plan.update`                | Меняет параметры тарифного плана.                   |
| `subscription.grant`         | Вручную создаёт подписку.                           |
| `subscription.change`        | Вручную меняет действующую подписку.                |
| `subscription.cancel`        | Сотрудник отменяет подписку.                        |
| `payment.refund`             | Возвращает деньги и немедленно прекращает подписку. |
| `refund.rejected`            | Сотрудник отклоняет запрос на возврат.              |
| `promo.create`               | Создаёт условие, влияющее на цену.                  |
| `promo.disable`              | Отключает условие, влияющее на цену.                |
| `webhook.replay`             | Повторно запускает обработку платёжного события.    |
| `payment.exclude`            | Вручную исключает платёж из финансового учёта.      |
| `payment.include`            | Вручную возвращает платёж в финансовый учёт.        |
| `subscription.extend.manual` | Вручную продлевает оплачиваемое право.              |

`refund.requested` не включён: реестр определяет его как пользовательский лог, а не audit-запись.
`subscription.price.confirmed` и `subscription.price.declined` не включены как штатные решения
самого пользователя.

### Персональные данные и выгрузки

| Код                   | Основание                                             |
| --------------------- | ----------------------------------------------------- |
| `admin.read.personal` | Фиксирует служебное чтение персональных данных.       |
| `stats.export`        | Создаёт выгрузку данных по административному фильтру. |

## Что сознательно не считается критичным

- отменённые и отложенные строки реестра;
- типы `log`, `metric` и `error`: блок строится только по `audit`;
- ожидаемые автоматические события и self-service пользователя;
- штатная модерация, редакционные операции, системные AI-решения, проверки профиля и
  антифрод-исключения — они наблюдаются в профильных разделах;
- повтор задания `job.retry`: это восстановительная операция, а не остановка процесса;
- общая оболочка `admin.change`: по действующим правилам она записывается для каждого
  административного изменения вместе с конкретным кодом; её включение сделало бы критичными
  все административные мутации и обесценило allowlist;
- коды, добавленные в реестр после утверждения T-121, пока владелец отдельно не включит их в
  allowlist. Новая строка не должна становиться критичной неявно.

## Следствие для реализации T-069 и T-079

После утверждения владельцем правило можно хранить как один общий набор точных `action`, который
используют запись/чтение аудита и дашборд. Не следует независимо дублировать список в web и server.
Изменение allowlist является продуктовым изменением правила и требует явного решения владельца.
Порядок, лимит и период компактного блока в T-121 не определяются: они относятся к реализации
дашборда и составу метрик, а не к критерию записи.

## Остаток

Критерий станет правилом только после явного утверждения владельцем и записи решения в журнале.
До этого T-069 и T-079 не должны реализовывать признак `critical` по этому предложению.
