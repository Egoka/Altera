content навыка altera-project-rules. Очередь остаётся active, триггер `0 * * * *`, Europe/Moscow,

Автопилот может при свободной цепочке подготовить следующую Todo из существующей T-задачи:
проверяет источники, фактические зависимости, уже сделанное и дубли; записывает source SHA и
authorization. Создание — backlog без assignee; перевод в Todo — с `--no-start`; запуск —
однократным назначением squad. При неопределённом ответе API сначала перечитывает состояние.
Старое ограничение только ALTE-10 и только ручного допуска заменено новым разрешением.

Согласованы backlog README, ready-candidates, операционная модель и статус ограничения Q-10;
прежняя подготовка сохранена как история. Журнал решений и продуктовые Q-блокеры не переписаны.
В docs README добавлен указатель на [контракт и карту чтения](../multica/backlog-autofill.md).

безусловного format:fix перед каждой проверкой.

Полезные материалы: roadmap/ready-candidates — порядок; owner-blockers/OPEN-QUESTIONS — границы;

## Как проверено

- `multica ... get`: перед записью значения совпали с сохранёнными исходными; после записи
  все три поля совпали с целевыми текстами. SHA-256, время и неизменность расписания записаны
  в `docs/multica/snapshots/2026-09-14-backlog-autofill/verified.json`.
- `multica issue create --help` и `issue status --help`: create не поддерживает `--no-start`;
  учтена двухшаговая подготовка без assignee и последующий status с `--no-start`.
- `git diff --check` — exit 0; проверка относительных Markdown-ссылок в восьми документах:
  отсутствующих целей нет.
- Независимая статическая проверка `/root/infra_preflight`: PASS после уточнения обязательных
  source refs и применимости Q из исключённого scope. Рассмотрены существующая Todo,
  отсутствие допустимого кандидата, missing source, merged In Review без финализации,
  устаревшая готова после завершения, timeout create и активный writer. Это проверка текста,
  не сквозной модельный запуск.
- Сетевой таймаут чтения squad устранён повторным чтением; инструкций squad менять не потребовалось.

## Ограничения и сохранность

Ручного trigger и новых model run для этой настройки не выполнялось. Первый фактический проход
с новым разрешением проверяется по истории следующего scheduled run. Активные и чужие изменения
в `.worktrees/autopilot` не затронуты. История старых инструкций и целевые значения сохранены
в snapshots рядом с readback. В snapshot нет env и credential values.

Уже идущий run может использовать прежний контекст; новый контракт рассчитан на следующий run.
Правило допуска не снимает незавершённую финализацию предыдущего parent и не разрешает вторую
активную цепочку. Для отката можно вернуть только три текстовых поля из before.json; расписание
не менялось. Документы публикуются обычной веткой/PR в app отдельно от применённых настроек.
