# Заход 0. Перебазирование основания Altera под ревизию 2

Ты — ведущий продуктовый архитектор Altera. Работаешь в репозитории
`~/WebstormProjects/Altera`, ветка `docs/platform-design`, с полным доступом к коду и
документации. Весь вывод — на русском.

**Результат захода:** документация основания (`docs/decisions/`, `docs/vision/`,
`docs/issues/`) приведена в соответствие с ревизией 2 продуктовых рамок — так, чтобы вторая
фаза (поштучные спецификации по `docs/prompts/phase-2-program.md`) могла ссылаться на ADR по
номеру и пользоваться единым словарём, не встречая отменённых понятий.

Это не переписывание с нуля. Модель данных (`03-data-model.md`, 992 строки), срез реальности,
ADR по контенту, локализации, медиа, сессиям, логированию, тестам — остаются. Меняется то, что
держалось на трёх отменённых решениях: гибридная модель с редакционной витриной, правило-арбитр
«никогда за право публиковаться», «без алгоритмов» с хронологической лентой.

## 2. Вопросы владельцу — одним пакетом, затем остановиться

Задай их первым сообщением, до любых правок. Только эти (или меньше, если ответ уже следует из
документов); каждый — с последствием для модели.

1. **Истечение подписки.** Что с опубликованными статьями бывшего автора: остаются
   опубликованными / снимаются / остаются, но выпадают из рейтинга? Может ли он их
   редактировать без подписки? → определяет flow `subscription-expires`, инвариант
   «роль author ⇔ активная подписка», состояние кабинета «истёкшая подписка».
2. **AI-проверка при провале.** Статья отклоняется с причиной автору, уходит в очередь
   ревьюера, или и то и другое по порогу? Может ли автор оспорить? Проверяется каждая ревизия
   опубликованной статьи или только первая публикация? → `review-queue`, статусы версии,
   `ArticleAiReview`, стоимость на статью.
3. **AI-оценка как компонент рейтинга.** Видит ли автор балл и критерии? Переопределяет ли
   модератор? → `author/ai-review-view`, `admin/ai-reviews`, поля `ArticleAiReview`.
4. **Pro-буст.** Одна публикация в сутки или каждая; помечается ли бустнутая статья для
   читателя; действует ли на ленты рубрик и тегов или только на главную? → `ArticleBoost`,
   формула, честность объяснения читателю.
5. **Роль `analyst`.** Видит агрегаты просмотров и денег — а список пользователей и e-mail?
   → матрица прав, `admin/users` для analyst.
6. **Роль `editor` без витрины.** Нужна ли отдельная роль редактора, или её функции
   (замечания к тексту, правка чужого опубликованного текста — ADR-0014) уходят к `moderator`
   и `admin`? → enum ролей, ADR-0014.
7. **Переводы и планы.** Даёт ли standard право публиковать обе языковые версии, или вторая
   версия — возможность pro? → `plan-standard` / `plan-pro`, лимиты.

После ответов — **остановись и дождись подтверждения**, что можно приступать к правкам.

## 5. Модель данных — что удаляется и добавляется

Точечная ревизия `03-data-model.md`: каталог сущностей, enum, инварианты, индексы, миграции.

**Удаляется:** enum `Contour`, `CommissionStatus`, `PlanKind`; `Article.contour`;
`Commission`; `EditorialPick`; `Plan.authorId`; `PaymentKind.donation`; CHECK
`articles_open_contour_is_free`, `plans_author_support_has_author`; инварианты «Commission ⇒
editorial», «редактор правит чужое только при contour = editorial», «open никогда не members»;
индексы под отборы; миграции, вводившие перечисленное, перепланируются.

**Добавляется:** `Role.analyst`; `PlanTier { free standard pro }`; `User.planTier`,
`User.planUntil`; `AuthorGrade` (или вычисление из `planTier` — решить и обосновать);
`Bookmark`; `ArticleAiReview`; `ArticleBoost`; `ArticleScore(articleId, score, components
Json, computedAt)` — материализованный результат, пересчёт по расписанию и по событию, не на
чтении; `AuthorScore`; `RankingConfig(version, weights Json, changedById, changedAt)`.

**Новые инварианты:** «`role = author` ⇔ активная подписка standard / pro или ручной грант с
`grantedById`»; «`ArticleBoost` только при активной pro и не более N на автора в сутки»;
«`analyst` не имеет ни одной мутации — контрактный тест по SDL»; «закладки не участвуют в
`ArticleScore`»; «пересчёт `ArticleScore` детерминирован: одинаковые входы и конфигурация —
одинаковый балл (тест)»; «ровно один `owner`» — остаётся.
