# Штатный запуск Autopilot — решение владельца 2026-09-14

Владелец согласовал переход на штатные Claude/Codex runtime Multica и старт с ALTE-10 / T-001.
Подготовка не включает запуск: все три autopilot должны оставаться paused до включения владельцем.

## Действующий режим

Это native Multica с правилами стадий, одним implementation parent и независимым review.
Экспериментальные isolated adapters, их tickets и trusted collector не являются условием
этого запуска и не используются очередью. Контейнерная изоляция и принудительный gate для
штатных runtime не приняты. Старые M4 чек-листы сохраняются как незавершённая отдельная работа;
их незаполненные пункты не требуют бесконечно перезапускать ALTE-11.

ALTE-11 отменён по выбору владельца. Восстановление его не перезапускает. Предыдущие ошибки,
snapshot и evidence сохраняются. Это не успешная приёмка M4.

Runtime тестировщика — штатный Codex, модель gpt-5.6-terra; ревьюера — штатный Claude,
модель claude-opus-4-6. Остальные модели и роли сохраняются, concurrency каждого агента — 1.
В custom environment всех десяти агентов закреплён PATH с установленным
`/Users/egorbondarenko/.nvm/versions/node/v24.12.0/bin` первым. Ранее custom environment
был пуст. Перед проверками всё равно сверять `node --version` и `pnpm --version`.
В выделенном checkout локальный `.claude/settings.local.json` задаёт `disableAllHooks=true`:
это отключает экспериментальный Stop-hook, требующий M4-паспорт. Общие permission rules
из `.claude/settings.json` остаются. Override не коммитится и не меняет настройки основного дерева.

## Рабочее дерево и передача стадий

Local resource проекта направлен на `/Users/egorbondarenko/WebstormProjects/Altera/.worktrees/autopilot`
в режиме in_place. Начальная ветка — `codex/autopilot-start`, подготовленная из
`docs/agent-loop-autonomy`. Основное дерево владельца не используется для записи.
Не выполнять `reset --hard`, `clean` или checkout поверх чужих незакоммиченных изменений.
Перед стадией сверять branch, HEAD, статус и handoff. Коммиты одной задачи передаются всем
её стадиям в этом checkout; ревью всегда относится к точному diff/SHA. Одновременно один writer.
После задачи следующая ветка создаётся от согласованного актуального основания, а не наугад.

Первой разрешена только ALTE-10. Источник — T-001; реализованные части не переписывать.
Ветка содержит накопленные изменения до запуска: не выдавать весь её diff к app за результат
T-001 и не сливать чужие непроверенные изменения. Изменения T-001 отсчитываются от её baseline.

## Включение

1. Держать Mac включённым, подключённым к питанию и сети, Multica — работающей.
2. Включить «Altera — очередь разработки». Единственная Todo — ALTE-10. Расписание —
   каждый час; для немедленного первого прохода после включения использовать штатный Run now,
   если он доступен, один раз. Отдельно ALTE-10 вручную не запускать.
3. Можно включить «Altera — актуальность контекста»: запись только Project description.
4. «Altera — восстановление работы» включать после наблюдения первой передачи стадий;
   оно возобновляет только ту же стадию после устранения причины, сохраняет бюджет двух ошибок.

Остановка: перевести соответствующий autopilot в paused. Это запрещает будущие срабатывания,
но уже активный run при необходимости отменяется отдельно штатным действием Multica.

Статус in_review остаётся до подтверждённых обязательных стадий. Новую задачу брать можно
после доказанного освобождения parent, а не просто появления комментария. Разрешения на
продуктовые решения, доступ к секретам, покупки и внешние сообщения не расширяются.
