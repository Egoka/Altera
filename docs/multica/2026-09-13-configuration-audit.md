## 5. Squad

Один [сквад «Altera — автономная разработка»](https://multica.ai/altera/squads/c6dd97bf-75c1-45cd-8d4a-3d00d26dd2f0),
лидер — оркестратор, десять участников. UI сообщает: инструкции сквада внедряются **лидеру**,
когда он работает над issue, назначенной скваду. Их наследование всеми исполнителями не доказано.

Полный текст уже содержит стадии по необходимости, одну implementation parent, проверку
активных run, native mention из roster, запрет двойного назначения, идемпотентность callback,
историю попыток, точную ревизию, независимое review и переход в In Review. Done оставлен
человеку/действующей интеграции. В чужой issue через @squad статус остаётся её исполнителю.
Эти уникальные правила маршрутизации нужно сохранить при сокращении текста.

Есть неоднозначности: after-two-failures автоматически назначается диагностика архитектору;
operating-model требует остановку и условия восстановления. Надо явно отличить read-only
диагностику от возобновления проваленной стадии. Краткая подпись релиз-инженера говорит
о зафиксированном разрешении на выпуск, основной текст ссылается на автономию §7:
уточнить ссылкой, что действующее разрешение сохраняется, без нового гейта на каждый выпуск.

Поле Next показывает прошедшие даты 5–6 сентября при выключенных автопилотах. Из этого
нельзя сделать вывод о неисправности scheduler; при включении потребуется проверить

**Контекст:** меняет описание проекта Multica по завершённым результатам с ревизиями;
планы не считаются фактами, no-op тихий, нет polling. Это расходится с operating-model §6,
где разрешено менять только «Текущее состояние» в `docs/backlog/README.md`. Чек-лист уже
говорит об описании Multica. Нужно решение об одной области записи и соответствующий diff.

**Восстановление:** не перезапускает queued/dispatched/running и живой процесс; требует
наблюдаемого изменения среды/квоты/причины; не создаёт новую parent, сохраняет счёт двух
попыток и SHA, не выдумывает native API. Условие «нет своей issue» и отсутствие polling
сохраняются. Открытый Q-NN стоит запретить явно, список разрешённых причин ещё требует сверки.

**Очередь:** выбирает Todo, проверяет зависимости и одну implementation parent, не освобождает
слот только из-за In Review, назначает существующую задачу существующему скваду; назначение
само будит лидера, mention не дублируется. Ссылка на файл T-NNN есть, совместный гейт
`готова` в файле + Todo в Multica нужно сделать явным.
