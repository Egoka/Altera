Работай в scope текущей задачи. Операционный контракт: /Users/egorbondarenko/WebstormProjects/Altera/.git/autonomy-runtime/current/contracts/autonomy-controller.md. Не подключай прежние operating-model, gate, ритуал плана/отчёта или правила очереди; отдельные планы и паспорта не обязательны. Сохраняй исторические артефакты.

Продуктовые решения принимает владелец. Используй актуальные технические правила, testing guide, package.json и источники задачи из репозитория; при расхождении проверяй ревизию и решение владельца. Не придумывай требования, числа и провайдеров. Незакрытый Q/F блокирует зависящий от него шаг, а не независимые проверки.

Перед новой реализацией получи свежую origin/app и отдельный worktree; один product writer. Ветки и PR следуют текущему заданию, PR направлен в app. Не коммить прямо в app, не очищать и не включать чужие изменения. Conventional Commit следует актуальному commitlint; соблюдай действующие hooks и branch protections.

Команды выбирай из текущих manifests и testing guide: применимые format/lint/test, typecheck, build и smoke. Проверяй точный итоговый SHA и сохраняй результат команды и evidence. Отсутствующий скрипт, ноль тестов, skip и простой exit 0 не доказывают прохождение. Не повторять полный набор без изменения или причины.

Перед сборкой проверь команды текущего package.json: сборка не должна неожиданно применять миграции к живой БД. Миграции запускаются только в явно выбранной разрешённой среде; CI использует временную БД. Не применять миграции к неизвестной или неразрешённой БД. HTTP/GraphQL ответ не заменяет DB/Redis readiness; deploy подтверждается точным SHA и отдельными health checks. Текущая среда development не становится production по названию провайдера.

Документация и комментарии — русские, идентификаторы и GraphQL errors — английские; форматирование задаёт текущий Prettier. Секреты, env и строки подключения не попадают в Git, вывод и задачи.

К итоговому ответу не оставляй фоновых команд. Ожидание CI или деплоя — на переднем плане (`gh pr checks --watch`, `gh run watch`), без `sleep N` в фоне; перед финальным сообщением останови все фоновые задачи. Уведомление фоновой задачи после итогового ответа обрывает run сбоем протокола (`input/control protocol failed`): работа сделана, но run помечен failed, и контроллер не получает завершённый run исполнителя.

Передай короткий receipt и финальный артефакт по контракту. Нужны реальные execution IDs, CI и независимый review итогового SHA. Merge/Done — только controller; поля verified/accepted_at не устанавливай. Не повторять уже подтверждённое действие и не запрашивать формальное ручное Done.
