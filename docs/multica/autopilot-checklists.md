## Восстановление работы

- [x] Принятый контракт требует ту же задачу и стадию, устранённую конкретную причину,
      отсутствие живого дубля и сохранение счётчика между run.
- [ ] Эти условия записаны в целевую конфигурацию и подтверждены readback.
- [ ] На сохранённой остановленной стадии проверены отказ до устранения причины и
      разрешённое продолжение после наблюдаемого изменения условий.
- [ ] Открытый вопрос владельца в scope не снимается, диагностика не становится третьей
      попыткой после двух неудач, новый run не сбрасывает счёт.
- [ ] Дублирующее событие не создаёт второго исполнителя или новой parent.

## Порядок включения и остаток

Контекст → очередь → восстановление. Включение каждого выполняется отдельно с readback и
наблюдением его первого результата. Если нет реальной границы прав, устойчивого gate или
необходимой авторизации, соответствующий автопилот остаётся paused; независимые исправления
документов и конфигурации можно завершать. Один ручной update Project description не закрывает
сразу проверки контекста, очереди и восстановления.
