# Чек-листы перед включением автопилотов Multica

- **Статус**: подготовлено 2026-09-09; все три автопилота на паузе, включение — отдельное решение
  владельца по каждому
- **Контракт автопилотов**: `docs/multica/operating-model.md` §6

Каждый пункт помечается «да» с ссылкой на подтверждение (файл, коммит, запись в Multica) или
«нет». Автопилот не включается, пока есть хотя бы одно «нет».

## Общие условия для любого автопилота

- [ ] Владелец прочитал `docs/multica/operating-model.md` и подтвердил состав сквада и роли.
- [ ] `docs/backlog/README.md` и `docs/backlog/matrix.md` соответствуют файлам задач (скрипт
      проверки из отчёта ревизии выполнен без ошибок).
- [ ] У автопилота нет прав менять спецификации, журнал, ADR и настройки других автопилотов.
- [ ] Определён способ остановки автопилота владельцем и место, где автопилот пишет записи.
- [ ] Секреты не доступны автопилоту через репозиторий и контекст задач.

## 1. Актуальность контекста

- [ ] Раздел «Текущее состояние» в `docs/backlog/README.md` существует и заполнен вручную
      подтверждёнными фактами с датой и коммитом.
- [ ] Перечень источников, которые автопилот читает, закрыт: журнал, `docs/spec/README.md`,
      статусы задач, отчёты `docs/reports/`; ничего другого.
- [ ] Правило «факт только со ссылкой на коммит или отчёт» проверено на пробном обновлении,
      сделанном вручную.
- [ ] Автопилот не пишет ни в один файл, кроме раздела «Текущее состояние».
- [ ] Пробный запуск в режиме «только показать изменение» просмотрен владельцем.

## 2. Восстановление работы

- [ ] Определение «реально остановленная стадия» проверяемо: нет активного агента, нет
      незакрытой ветки в работе, есть запись об остановке с причиной.
- [ ] Список причин, при которых восстановление разрешено (например, устранённая ошибка
      окружения, восстановленный доступ к сервису), утверждён владельцем; блокер владельца
      `Q-NN` в этот список не входит.
- [ ] Автопилот возобновляет только ту же стадию той же задачи; переход к следующей задаче
      запрещён технически или правилом с проверкой.
- [ ] Есть хотя бы один зафиксированный случай остановки, на котором сценарий проверен вручную.
- [ ] Повторный запуск идущей работы исключён: проверка активной цепочки выполняется до
      возобновления.

## 3. Очередь разработки

- [ ] Хотя бы одна задача переведена владельцем в статус `готова` (не `кандидат`).
- [ ] У готовых задач все зависимости `завершена`, раздел «Требует решения владельца» — «нет».
- [ ] Правило единственного writer продуктового кода реализовано: очередь видит активную
      кодовую цепочку и не стартует вторую.
- [ ] Очередь не создаёт задач и не меняет их текст; scope берётся только из файла задачи.
- [ ] Стадии назначаются по шапке задачи (роль-исполнитель, участники), а не всем агентам.
- [ ] Завершение задачи требует актуальной проверки и независимого ревью там, где оно указано.
- [ ] Первый запуск — на одной задаче документации или подготовки тестов, не меняющей продуктовый
      код, с ручным просмотром результата владельцем.
