# Локальная разработка

## Зависимости

В корне репозитория запустите локальные PostgreSQL, Redis и Mailpit:

```bash
docker compose up -d
docker compose ps
```

Compose публикует сервисы на собственных портах Altera (схема «2 + стандартный порт», чтобы не
конфликтовать с другими локальными проектами): PostgreSQL на `localhost:25432`, Redis на
`localhost:26379`, SMTP Mailpit на `localhost:21025`, а интерфейс просмотра писем — на
`http://localhost:28025`.

Том `postgres_data` сохраняет данные между остановками. Для обычной остановки используйте
`docker compose down`. Удаление тома (`docker compose down -v`) удаляет только локальные данные
Compose и нужно лишь когда требуется чистая база.

## Сервер

Создайте локальный файл окружения из примера и примените миграции к поднятой базе:

```bash
cp server/env.example server/.env
cd server
pnpm prisma:migrate:deploy
pnpm dev
```

Сервер слушает `http://localhost:4000/`. В отдельном терминале GraphQL можно проверить так:

```bash
curl -sS -X POST http://localhost:4000/ \
  -H 'Content-Type: application/json' \
  --data '{"query":"{ __typename }"}'
```

Пример содержит только локальные учётные данные Compose; секреты JWT нужно заменить для любого
окружения, отличного от личной локальной разработки.

## Веб-приложение

В отдельном терминале из корня репозитория запустите Nuxt:

```bash
cd web
pnpm dev
```

Nuxt выводит локальный URL при старте. На текущем этапе у веб-приложения нет отдельной настройки
адреса API; сервер, PostgreSQL и Redis запускаются по предыдущим шагам без внешних сервисов.

## Почта

Mailpit готов принять SMTP-письма на `localhost:21025` и показать их на `http://localhost:28025`.
До T-021 сервер выводит magic link в консоль и не использует SMTP-транспорт, поэтому появление
письма в Mailpit пока не является проверяемым сценарием.
